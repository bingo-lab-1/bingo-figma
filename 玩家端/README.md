# 玩家端 · 当前主分支功能

## 1. 定位与边界

本目录按玩家仓库最新 `main` 描述本人可见的页面、操作和当前限制。实际入口包括 Profile、顶部钱包弹窗、Bonus、VIP Club、Affiliate、自营游戏与第三方游戏。当前没有 `/account`、`/promotions`、统一奖励历史或客服聊天页面。

玩家界面语言为英文 `en` 和繁体中文 `tc`；后台内容配置使用 `en`/`zh`，两端语言代码并未完全统一。钱包按币种分开，可切换；第三方游戏使用 USD。本文不将功能分支页面写成主分支能力。

## 2. 术语

| 术语 | 当前含义 |
|---|---|
| Account | 本需求目录及编号；实际主分支个人资料由 Profile 承载 |
| 钱包 | 每币种分别记录本金、彩金和占用；顶部按钮打开充值、提现、刮刮乐 |
| 活动中心 | 当前为 `/bonus` 的固定内容、活动链接及升级奖励；不是 CMS Promotions 列表 |
| 未接入 | 后端或后台已有能力，当前玩家路由及组件尚未消费 |

## 3. 依赖关系

M2 提供身份、限制和账户事实，M5 提供资金、充提和币种，M4 提供活动资格及 VIP，M7 提供邀请佣金，M10 提供游戏目录与启动，M11 提供通知和 Metadata，M12 提供后台客服处理。CMS 首页配置、统一奖励记录、完整 VIP 概览和客服聊天接口的存在，不等于主分支已完成玩家展示。

## 4. 数据归属

本人身份由当前会话确定，资金和权益以服务端事实为准。玩家页面只负责查询、展示及提交。部分 VIP 宣传、首页推荐和偏好表单仍是静态或本地状态；对应正文明确说明，不作为真实奖励、账务或保存结果。

## 6. 访问与操作边界

本人接口按当前会话限定身份，不能通过指定 UID 获得其他玩家数据；玩家不使用 M6 后台角色权限。后台可以调整余额、清除流水或管理活动，不代表玩家拥有这些操作。首次访问不自动创建游客，主分支提供邮箱注册和登录。

## 7. 决策清单

| # | 规则主题 | 执行结论 |
|---|---|---|
| D95 | 终端、资金范围与业务归属 | 按 main：Profile 与钱包弹窗承担个人事务，支持多币种；Crypto 入金、Crypto 提现和商品充值已接入。没有 Account 独立路由。业务事实归各原模块。 |
| D106 | 游客与普通注册 | 后端游客策略不等于玩家自动游客流程；主分支只读取已有会话，通过邮箱注册/登录，邀请码可填写。普通注册为新 UID，不合并其他账号权益。 |
| D140 | 默认昵称 | 注册时没有提交昵称的账号（含游客）由服务端生成“英文形容词+英文名词+4 位数字”的昵称，生成时与现有昵称不重复；游客注册正式账号沿用游客当时的昵称（空白或旧默认值除外）；旧规则生成且仍未修改的默认昵称由运维脚本统一替换。见[账号与游客](Account/游客账号.md#默认昵称)。 |
