# Account · 玩家账户

## 1. 用途

Account是玩家登录后的个人中心，用于查看余额、充值提现、查询记录、领取奖励和管理账户。玩家打开页面后，应能清楚知道：自己有多少钱、能否提现、还有多少打码量没有完成，以及订单或奖励处理到了哪一步。

运营提供的存款、取款、用户信息、手机号与邮箱、投注与交易记录、VIP和佣金均纳入本版,同时补齐打码明细、订单详情、个人奖励、收款账户、帮助和异常状态。Account首页呈现摘要,具体操作进入对应二级页面,不把全部活动和表单堆在首页。

运营、设计、开发和测试统一使用本文。影响玩家操作和页面显示的规则在这里直接说明，无需先读其他需求文档；文末只保留必要的业务依据，方便核对。具体位置、尺寸、颜色与组件由Figma表达。

| 范围 | 本版规则 |
|---|---|
| 终端与语言 | 游戏端Web,移动端优先并适配桌面;首期界面英文,本文中文名称解释业务含义。桌面与移动端使用相同资金和资格规则 |
| 币种 | 仅USD法币,金额显示如`USD 1,060.34`,两位小数;无币种切换、汇率、换汇、转账、Crypto地址或网络选择,无GC/SC双币模式 |
| 钱包 | 本版只向玩家展示一个USD钱包。充值、彩金、游戏派彩和佣金都进入这个钱包，不另设奖金钱包或代理钱包 |
| 时间 | 记录时间、每日额度和奖励周期统一使用平台业务时区，当前为GMT−3，并在页面注明。切换手机或电脑时区，不会重置额度或延长奖励时间 |
| 业务规则 | Account展示玩家已有的资金、等级和奖励，不另算一套结果。后台仍可管理其他币种，但本期玩家页面只使用USD，不把其他币种直接当作美元 |
| 文档用途 | 本文说明需要实现的功能。设计图里有某个按钮，或后台能查到某个字段，都不代表玩家已经可以完成对应操作 |

本期不提供玩家自助取消提现、取消已到账奖励、清除打码或跨活动一键领取。额外的双重身份验证、在线设备管理、安全评分、自助设置存款限额和自助销户也不在本版范围内。玩家可以绑定联系方式、管理密码、提交身份资料，并通过客服申请暂停或关闭账户。页面不放没有实际功能的按钮或开关。

### 文中几个常用说法

| 说法 | 含义 |
|---|---|
| 本金、彩金 | 本金是充值实际进入钱包的金额，彩金是平台赠送的奖金。它们进入同一个USD钱包，不是两份可以分别提现的余额 |
| 打码量，也称流水要求 | 提现前需要完成的有效投注金额。例如剩余USD 100.00打码量，表示还需要有USD 100.00有效投注计入任务，不是还要充值或支付USD 100.00 |
| 有效投注 | 已完成结算，并按游戏规则计入流水要求的投注金额。它可能少于实际下注金额；未结算、取消、作废或退款的投注不计入 |
| 提现占用 | 已申请提现、还在处理的钱。这部分金额暂时不能再次使用或重复申请提现 |
| 待处理奖励 | 已经记录到玩家名下，但还没有完成领取或使用的奖励。可能还需要等待开放或满足条件；只有当前确实可以领取的才标为“可领取”，实际到账前不计入钱包余额 |
| 冲正、冲回 | 原交易撤销或出错后，系统增加一条对应的调整记录。原记录仍保留，页面同时说明调整原因和实际金额 |

## 2. 查询与处理信息

### 首页内容与二级页面

| 首页内容 | 展示信息 | 点击后的目的地 |
|---|---|---|
| 身份与VIP | 头像或昵称首字母、昵称、可复制UID、当前VIP名称;存在账户限制时展示可公开的状态 | 个人资料与安全、VIP中心 |
| USD钱包 | 单一余额、Deposit、Withdraw、当前提现条件摘要;可隐藏金额 | 钱包详情、充值、提现 |
| 当前需处理事项 | 需要补充资料、充提结果需要关注、临近到期的本人奖励;没有事项则不占区块 | 对应订单、资料补充或原奖励详情 |
| 我的记录 | 投注记录、充提订单、余额变动的统一入口 | 记录中心,三类分别查询 |
| 我的奖励 | 本人当前可领奖励数量,无奖励时仍可查历史 | 我的奖励 |
| 邀请与佣金 | 有可用邀请功能或历史佣金时显示入口,可领金额作为摘要 | 邀请与佣金 |
| 资料、服务与设置 | 个人资料与安全、收款账户、消息、帮助与客服、设置和退出登录 | 对应视图或操作 |

充值套餐只放充值页;VIP只保留一处主入口;签到、转盘、邀请宝箱等玩法入口由活动中心承载。Account中的奖励记录可以返回对应活动,不新增“参加活动”步骤。钱包详情不是另一种钱包,记录中心也不产生第二份资金记录。

首页优先表达身份、余额和存取款,再呈现当前事项及功能入口;USD是固定币种标识,不画成选择器。首页不展开全部交易明细或活动规则全文,帮助与退出登录应容易找到。

### 关键字段

| 信息 | 含义与来源 |
|---|---|
| 余额 | 显示资金系统确认的USD余额，不含冻结金额和提现占用，也不包含尚未领取的奖励 |
| 当前可提现金额 | 显示资金系统检查后的金额；还有任何未完成打码任务时显示USD 0.00。实际提交还要检查单笔限额、当日额度和身份验证等条件 |
| 提现占用、冻结说明 | 钱包详情分别说明尚占用金额及可公开原因;不能从已经扣除占用的余额再减一次,也不能将占用加回可用余额 |
| 打码任务 | 这笔要求来自哪里、关联订单或奖励、到账金额、适用倍数、总要求、已完成量、剩余量、创建时间和状态。后台直接增加流水要求时，若没有对应到账金额或倍数，显示“不适用” |
| 充值预览 | 支付方式、选中档位、实际支付USD、到账本金USD、预计赠金USD、本金和赠金各自的打码倍数与要求、获得赠金的条件 |
| 提现填写与确认 | 可用收款方式、本人收款账户、申请金额USD、手续费USD、预计到账USD、单笔范围、当日剩余次数及金额、提款密码与必要验证 |
| VIP | 当前等级、下一启用等级、充值与有效投注两项升级进度、个人保级周期与进度、等级权益、四类奖励状态 |
| 奖励 | 来源、奖励名称、所属期或轮次、金额或非现金权益、领取条件、开放与截止时间、打码要求、当前状态 |
| 佣金 | 直接邀请人数、充值与投注两类佣金、统计日、开放领取时间、该笔佣金适用的打码倍数、可领取及已领取金额 |
| 资料与安全 | UID、登录账号、昵称、隐藏部分字符的手机号和邮箱、各自验证状态、登录密码与提款密码是否设置、身份审核状态 |

本金与彩金在充值或奖励详情中分别说明，方便玩家了解钱从哪里来、增加了多少流水要求。金额还没查到时显示“加载中”或“暂时无法获取”，不能显示为`USD 0.00`。剩余打码量按两位小数向上显示，例如还剩USD 0.001时显示USD 0.01；实际已经完成时显示0。是否完成以系统保存的准确数值判断，避免显示为0但实际还不能提现。

## 3. 处理规则

### Account-R1 · 登录、本人数据与页面恢复

未登录进入Account显示登录入口,不展示上一个玩家的金额、资料或记录。登录成功返回原来需要访问的页面;退出、切换账户或登录失效时清除上一账户的敏感展示与缓存。

系统只允许玩家查看和操作自己的账户。即使修改链接中的UID、订单号或奖励编号，也不能看到别人的资料。直接打开个人页面、记录或消息链接时，同样检查登录身份；没有权限时提示无法访问，不泄露对应记录的姓名或金额。

从支付页、游戏或二级页面返回时，重新获取余额、打码任务、订单和奖励状态。重新打开或刷新页面只查询上一次结果，不重新充值、提现或领奖。加载失败时保留“重试”入口；如果还显示上一次数据，要注明更新时间和“需要刷新”，不能凭旧数据允许资金操作。

提现时如果需要先补资料或新增收款账户，完成后回到原提现表单，再检查费用和提现条件。可以保留已选方式、已填金额等非敏感信息，但不保留密码、验证码和完整证件信息。回到表单不代表订单已提交。从记录详情返回时保留筛选条件；查看奖励或佣金结果后，回到对应的原记录。

### Account-R2 · 首页摘要与当前需处理事项

首页优先显示USD余额、存取款和需要玩家处理的事项。VIP卡显示当前等级和“查看权益”，详细升级、保级进度放在VIP中心。钱包摘要直接说明目前能否申请提现；不能提现时说明是打码未完成、账户受限、身份资料未完成，还是暂时查不到结果。有多个原因时，详情一起列出，不只提示“条件不满足”。

当前需处理事项优先显示需玩家补充的身份或收款资料,其次显示需关注的充提订单,再显示截止时间在未来24小时内的可领奖励。资料按最近状态更新时间、订单按最近受理时间倒序,奖励按最早截止排序,时间相同时按稳定来源标识排序。首页最多显示3条,“查看全部”展开同一事项列表并沿用排序及跳转,不另建任务中心。没有截止时间或超过24小时的奖励仍在我的奖励查询。同一订单或权益只显示一次,处理中事项打开详情查询,不伪装成可再次执行的按钮。

“可领取”数量只统计玩家现在确实能领取的奖励。条件不足、领取时间未到、正在处理和已经过期的奖励都不计入。查询失败时说明暂时无法获取，不显示固定红点或示例数量。佣金单独显示可领金额，不与活动奖励合并。

### Account-R3 · 钱包与提现条件

钱包详情显示余额、当前可提现金额、提现占用说明及提现限制原因。金额隐藏开关只改变展示,不修改任何余额或交易权限。

只要还有一笔打码任务没有完成，整个USD钱包都暂时不能提现，不开放“先提一部分”。所有任务完成，或后台按规定免除剩余要求后，还需要检查资金冻结、账户限制、身份资料、收款方式和提现额度。页面不能承诺“完成打码就一定能全部取出”。没有进行中的任务时，显示“当前无未完成流水要求”。

因打码未完成而不能提现时，直接显示剩余总量，例如“还需完成USD 680.00有效投注，当前暂不可提现”，并提供“查看打码明细”。余额不足、当日额度不足、资料不全或已有提现在处理，分别说明原因并提供对应入口。不要用“继续充值”笼统地引导玩家解决提现限制。

如果平台要求玩家先完成一次真实充值才能投注，即使奖励已经到账，也可能暂时不能用于游戏。此时钱包要说明具体原因。钱是否到账、能否投注和能否提现要分别显示，不能混为一个状态。

### Account-R4 · 打码任务明细

默认显示尚未完成的任务，也可以查看“已完成”和“已清空”。系统先用有效投注完成最早创建的任务，再继续抵扣下一笔；创建时间相同时按任务编号顺序处理。同一笔有效投注不能重复计算，玩家不需要自己选择任务，也不能手动分配、取消或清空要求。“已清空”表示后台按规定免除了这笔剩余要求，不代表玩家通过投注完成。

每笔任务分别显示总要求、已完成量和剩余量。剩余量等于总要求减去已计入的有效投注，最低为0；进度百分比只表示这一笔任务完成了多少。没有流水要求的任务直接显示“已完成”。已清空任务保留原要求、实际完成量和清空结果，不显示为“投注完成100%”。首页只合计尚未完成任务的剩余量，不把不同时间新增的任务拼成一个总进度百分比。

示例:一条任务总要求USD 2,000.00、已完成USD 680.00,进度为34%,尚需USD 1,320.00;若尚需USD 680.00,则已完成66%。有效投注不一定等于下注金额,以游戏折算及最终结算结果为准。

每笔充值和赠金分别产生打码任务。过去多完成的投注不能留着抵扣以后新产生的任务，任务也不会因为等待而自动到期。如果之前计入的投注后来被撤销，剩余要求可能重新增加；后台免除要求后则相应减少。页面要同步更新任务与提现状态，不能一直显示之前的100%进度。

### Account-R5 · 充值

1. 选择支付方式。页面只显示当前可用的USD法币方式，以及该方式支持的充值档位。切换方式后重新展示可用档位。本版从已配置的档位中选择金额，不提供任意金额输入。
2. 选择充值档位。页面分别说明实际支付多少、本金到账多少、预计赠送多少，以及获得赠金的条件。“固定赠金”和“按比例赠金”只能获得其中一种，不能把两者相加宣传。
3. 核对流水要求。本金和赠金各自显示适用倍数。例如到账本金USD 100.00、要求1倍流水，赠金USD 20.00、要求5倍流水，分别产生USD 100.00流水要求，合计新增USD 200.00。不能只给整笔充值标一个“1倍”。没有赠金时不要求赠金倍数；本金或实际赠金的倍数未配置完整时，暂时不能下单。
4. 确认并创建订单。系统再次检查账户、支付方式、充值档位和金额，保存本次订单号及下单时的条件。若档位失效或条件改变，说明原因并让玩家重新选择，不直接替换档位或增加支付金额。
5. 完成支付。连续点击或网络重试只创建一笔订单，结果未确定时继续查询原申请。普通充值的商品赠金随充值一起到账，不需要再到“我的奖励”领取。
6. 查看结果。支付结束、关闭收银台或重新打开页面后，都查询原订单。平台确认到账后才显示成功并更新钱包和打码任务。如果支付方已扣款、平台还在核实，显示“支付结果确认中”，提供查询和客服入口，不要求玩家再付一次。

有次数限制的比例赠送，要让玩家知道自己正在使用第几次优惠。“第N次”指这个赠送方案第N次成功发放比例赠金，不是账号第N次充值。只有比例赠金成功发放才消耗一次；只获得固定赠金、没有赠金或金额计算后为0，都不消耗比例赠送次数。

同一方案的次数在不同充值档位和支付方式之间共享，切换方式不会重新获得次数。预览不会占用次数；多笔充值同时支付时，系统在结算时依次确定各单适用的优惠，前一笔还在处理时，后续订单可能需要等待。未达到当前优惠门槛时不跳到下一次，只检查是否符合固定赠送条件。

如果结算失败，不增加已使用次数，但为这笔订单确定的第几次优惠和原计数周期继续保留；同一周期的后续订单先等待。恢复处理时沿用原条件，即使已经跨日，也不重新分配优惠或改发固定赠金。不能换一笔申请重复使用同一次优惠，也不能因退款自行重置已使用次数。

预览要说明最终优惠以订单结算结果为准；订单详情显示实际本金、赠金和采用的优惠。不能把最高赠送比例当作每个玩家都能获得的优惠。下单后修改配置，不改变原订单已经保存的金额与条件。

如果从首充补助活动进入“翻倍充值”，订单须清楚标注活动用途：这笔充值不发商品固定或比例赠金，也不使用比例赠送次数；补助需要回活动页单独领取。普通充值订单创建后，就不能改成翻倍专用订单。

充值订单分别显示待支付、支付中、成功、失败、已取消和已关闭。只有系统确认原订单仍能支付时才提供“继续支付”。订单已明确失败或关闭后，玩家可以重新发起充值；仅凭页面倒计时结束，不能自行判断订单已经关闭。

### Account-R6 · 提现与收款账户

玩家点击Withdraw后，先看到当前可提现金额、剩余打码总量、可用收款方式、每笔金额范围、手续费和当日剩余额度。打码未完成时，直接说明“还需完成多少有效投注”，并提供“查看打码明细”；没有任务时显示“当前无未完成流水要求”。不满足提现条件时可以查看原因、补资料或查询原订单，但不能提交申请。

在“收款账户”中管理提现去向。页面按所选方式要求填写账户类型、持有人、银行或支付机构等资料，已有账号只显示部分字符。新增或修改时要验证本人身份并检查账户信息；已经核验的姓名不能在这里改成他人姓名。本版不提供加密货币收款，也不新增存储银行卡快捷支付功能，密码和验证码不能保存下来供下次显示。

已经提交的提现继续使用提交时确认的收款账户。修改默认账户只影响以后申请，不能把正在处理的钱改转到另一个账户。有提现仍在使用的收款账户不能删除。收款方式停用后不接受新申请，原有订单仍能查询，并继续完成处理。

提现流程是：选择收款账户、输入USD金额、核对费用与到账信息、输入提款密码并完成必要验证，最后提交。确认页必须列出申请金额、本次占用的余额、手续费、预计到账、收款账户，以及当日剩余次数和金额。

手续费从申请金额中扣除，不在申请金额之外另扣。例如申请USD 100.00、手续费USD 2.00，本次占用余额USD 100.00，预计到账USD 98.00。所有金额使用资金系统提供的结果；费用或收款条件变化时，重新请玩家确认，不能直接扣钱。申请金额须大于0且最多两位小数，手续费不得为负，扣费后的到账金额也须大于0。金额范围或费用暂时查不到、报价失效或支付方式不支持这种扣费方式时，暂停提交；不能默认免手续费或无限额。

提交时，系统再次检查玩家身份、账户限制、提款密码、打码任务、余额、收款方式和最新VIP额度。同一申请重复点击只处理一次，多笔同时申请也不能超过总余额和当日额度。受理后显示“提现申请已提交”和订单号，这时还不代表钱已到收款账户。

每笔受理成功的申请会暂时占用对应余额、当日1次提现机会和手续费前的申请金额额度。待审核、审核中、放款中和结果核查中都继续占用；放款成功后记为当日已使用。余额和额度由系统一起更新，页面不能再次扣减。

| 订单状态 | 玩家看到的信息与允许操作 |
|---|---|
| 待审核、审核中 | 申请已受理或正在审核,可查详情和联系客服 |
| 放款中 | 正在向收款账户付款,可查进度,不显示重新提现原单按钮 |
| 结果核查中 | 结果正在核查,保留原订单和占用;超时不等于失败 |
| 放款成功 | 已完成,显示实际完成时间与结果金额 |
| 放款失败、已拒绝、已取消 | 说明原因，以及申请中的钱是否已经恢复可用；余额仍在处理时，不提示资金已退回 |

只有确认没有付款、且资金已经恢复可用后，才释放这笔申请对应的次数和金额额度。额度始终归申请被受理的那一天：昨天申请的提现今天失败，只修正昨天的记录，不增加今天的额度。VIP变更不会清空当天已经使用或仍被占用的额度，也不撤销原有申请；新申请使用最新限额，剩余额度最低显示为0。

本版不提供玩家取消提现按钮；“已取消”只用于显示系统已处理的结果。超时或暂时查不到付款结果时，显示“结果核查中”，保留占用并继续查原订单，不能直接显示钱已退回。

### Account-R7 · 记录中心与详情

记录中心只查本人USD数据,分为投注记录、充提订单、余额变动。默认最近7个业务日,包含今天;可选今天、近7日、近30日及自定义起止日期,开始不得晚于结束。日期包含完整业务日,按平台业务时区解释。默认每次加载20条,按时间倒序及稳定记录标识排序,加载更多沿用原条件;从详情返回保留筛选和位置。

| 分类 | 筛选与列表 | 详情必须说明 |
|---|---|---|
| 投注记录 | 时间、游戏、结算状态;列表显示游戏、投注时间、投注额、派彩额、净输赢与状态 | 局号、所属游戏及厂商、有效投注、结算时间、取消或退款状态、关联本人的资金流水;未结算显示处理中,不以派彩0判输 |
| 充提订单 | 时间、充值或提现、订单状态、完整平台订单号;金额按类型注明实付或申请金额 | 订单号、创建及状态更新时间、支付或收款方式、实付或申请金额、费用和实际资金结果、可公开原因;充值拆开本金与赠金,提现区分申请与到账 |
| 余额变动 | 时间、类型;显示发生时间、原因、带正负号的变动金额、变动后余额 | 变动前后余额、账变编号、关联订单或奖励、冲正与原记录的关联;只变动打码量的记录标明流水要求调整,不呈现成扣钱 |

投注净输赢使用游戏最终确认的结果。正常完整结算时，净输赢等于总派彩减实际投注扣款。例如下注USD 2.00、派彩USD 1.40，净输赢为−USD 0.60，不能因为有派彩就显示盈利。未结算、分次派彩、取消或退款时，按该局实际处理状态显示，不提前判断输赢。这里的实际投注金额也不等于用于完成打码的折算后有效投注。

充值和提现订单中要能查到尚未到账的申请，不能只显示余额已经发生变化的记录。一笔订单可能产生多条余额变动，例如本金和赠金分别记录，但仍只算一笔充值。

商品充值的本金、赠金、各自的打码要求和优惠次数必须一起处理完成。任何一步失败，都不能把订单标成已完成，也不能先消耗优惠次数、遗漏应发赠金。如果支付方已收款、平台结算还没完成，显示“结算处理中”，继续恢复原订单，保留原支付事实和金额条件。后续发生撤销或纠错时，同时保留原记录与调整记录。

订单号和局号可以复制。点击“对此记录有疑问”时，自动带上当前记录编号，方便客服查询。玩家只能查看，不能删除或修改资金记录；记录详情不提供补单、重复放款或导出他人数据的操作。暂时没有完整结果时提示“记录同步中”，不填入猜测的数据。

### Account-R8 · 个人资料与联系方式

个人资料显示UID、登录账号、昵称、手机号、邮箱及验证状态。UID和登录账号不能修改；昵称可以修改，输入时说明允许的字数和字符，系统保存成功后才更新首页。首期使用已有头像或昵称首字母，不新增头像上传和裁剪功能。

手机号和邮箱分别显示未绑定、已绑定未验证、已验证或正在处理，页面只显示部分号码或字符。首次绑定时，先确认是玩家本人操作，再验证新联系方式。更换时先用原来的可靠方式确认身份，再验证新手机号或邮箱；新信息验证成功前，旧信息继续保留。原联系方式已不能使用时，引导玩家联系客服找回账户，不能直接跳过验证。

验证码有效多久、多久可以重发、输入错误后的限制，都使用账户系统给出的规则，并在需要时明确显示。发送验证码成功不等于联系方式已验证。发送失败后可以修改信息或重试；验证超时先查询上次结果，不重复绑定。

### Account-R9 · 登录密码与提款密码

登录密码和提款密码分别显示“未设置”或“已设置”，并提供对应的设置、修改入口，不显示密码本身。首次设置任何一种密码，都要先通过已验证联系方式或系统提供的其他方式确认是本人。没有可用验证方式时，进入账户找回帮助。

修改登录密码时输入当前密码，并两次输入新密码。提款密码用于确认提现，修改时同样验证原提款密码和两次输入的新密码。两种密码用途不同，不能把修改其中一个当作同时修改另一个。

输入前展示账户系统要求的密码格式；输入错误或被锁定时，说明当前限制及可恢复时间。规则暂时取不到时暂停操作并提供帮助，不能自行设定更宽松的规则。设计稿不固定写成“6位数字密码”，要使用实际支持的格式。

忘记密码或原验证方式不能使用时，提供“找回账户”入口，由客服核对身份后协助重置。本期不提供跳过身份验证的重置方式。关闭再打开页面不会清除错误次数，也不会提前解除锁定。

密码修改成功后，旧密码立即失效。修改登录密码后，原有登录状态全部失效，页面清除个人资料并要求重新登录；修改提款密码不改变已经受理的提现订单。

### Account-R10 · 身份核验

资料与安全页显示“未提交”“审核中”“需补充资料”“已通过”或“未通过”，告诉玩家要提供哪些资料、当前结果是什么、接下来怎么做。是否需要先完成身份核验才能充值或提现，由账户和交易的实际要求决定；需要时在操作前明确提示。使用USD不代表必须提交某个国家的指定证件。

玩家按页面要求填写或上传资料，提交后显示“审核中”，并可以随时查看结果。审核期间不重复提交。需要补充时，只要求补齐指定项目；未通过时，说明原因和是否可以重新申请。资料提交成功不等于审核通过，身份审核通过也不代表其他提现条件已全部满足。

已经核验的姓名和身份资料不能在普通资料页直接改写，需要更正时联系人工客服。首页、消息预览和订单备注中不显示身份材料或完整证件号。审核原因应使用玩家能理解的说明，不直接暴露内部风控规则或工作人员备注。

### Account-R11 · VIP中心

VIP中心显示当前等级和下一个可以升入的等级。充值和有效投注分别显示当前金额、目标和还差多少，两项都达标才能升级。最高等级直接显示“已达最高等级”，不显示虚构的下一等级或经验值。

正常成长使用累计充值和累计有效投注。发生保级降级或运营迁移后，从那一刻重新统计新增充值和有效投注；两项分别达到“目标等级门槛减降级或迁移后的起始等级门槛”的差额，且两项都必须有新增，才能重新升级。差额小于0时按0计算。之后连续升级仍沿用这个起点，直到再次降级或迁移，不能凭过去累计金额立即升回。

保级进度与升级进度分开展示。页面显示本次保级的开始和截止时间、需要完成的有效投注及已完成量。周期从升级时刻起计算一个完整日历月，例如9月12日15:00升级，在10月12日15:00检查保级；次月没有对应日期时取该月最后一天的相同时刻。期间再次升级，就从新的升级时刻开始计算。到期未完成时按已配置的目标等级降级；没有设置降级目标时保留原等级。检查结束后继续下一个保级周期，不按自然月统一清零。

等级权益显示实际提供的奖励、每日提现次数和金额上限。当日已用、处理中占用和剩余额度都取真实资金结果，不因升级重新给一份完整额度。

升级奖、周奖、月奖和投注返现分别显示金额、领取时间、全额领取条件及新增打码要求。投注返现对应昨天的有效投注；周奖对应上一个完整自然周，月奖对应上一个自然月。判断能否领全额时，返现看领取当天已经成功到账的充值，周奖、月奖和升级奖看领取所在自然月已到账的充值，不能把充值统计期间混用。

周奖、月奖和返现的基础奖金、打码要求及领取条件在当期开放领取时确定，升级奖在升级时确定；之后调整等级或配置，不重新计算这份已确定的奖励。是否满足全额领取的充值条件，仍在实际领取时检查。每个等级的升级奖只产生一次；跨级升级可以分别获得首次跨入的启用等级奖励，降级后再升回、已经领取或错过期限，都不会重新获得同等级升级奖。

充值未达到全额门槛时，页面显示当前可领的免费部分。确认领取前提示“领取后，本期不再补差”，同时说明新增打码要求；之后再充值达标，也不会补足这一期差额。如果计算结果为0，不扣除领取机会，玩家在原领取时间内满足条件后仍可领取。

VIP暂停期间，不升降级、不累计保级投注，也不接受新的VIP领奖；已经到账的奖金保留，每日提现限额仍执行。恢复后保级截止时间按暂停时长顺延，并可根据真实充值和投注重新判断升级。奖励领取时间不会跟着顺延，暂停期间没有开放的奖励不补发，已经过期的不能补领；暂停或到期前已受理的领奖申请继续处理。页面分别显示保级时间和领奖时间，不能用同一个倒计时表示。

### Account-R12 · 我的奖励

“我的奖励”集中显示已经记录到玩家名下的活动和VIP奖励，方便查看条件、领取及查询结果。已经有奖励记录，不代表现在就可以领取，仍要看该笔奖励的条件和开放时间。找活动、阅读完整玩法、签到或转盘抽奖仍进入相应活动页面。佣金在“邀请与佣金”中单独处理；随充值自动到账的赠金在充值详情和余额变动中查看，不再出现领取按钮。

默认显示尚未处理完的奖励，也可以查看历史记录。根据每份奖励的实际情况，显示“尚未开放”“条件未满足”“可领取”“处理中”“已到账”“已过期”或“已失效”。尚未开放时写清何时可以领取，条件不足时说明还差什么。转盘券等非现金奖励显示种类和数量，不计入钱包余额；需要抽奖时提供“去使用”等准确入口，不写成“领取现金”。

领取前显示本次实际能得多少USD、打码倍数、新增流水要求，以及准确截止时间或“不过期”。说明领取后如果产生新的打码任务，整个USD钱包会暂时不能提现。系统先检查当前是否符合条件；不符合时说明玩家可以处理的原因，不公开内部标签或风控阈值。

只有能完整显示条件并直接完成领取的奖励，才在这里提供“领取”。VIP免费部分领取后不补差等提示必须保留。需要选择方案或多步操作的奖励，例如首充补助的普通与翻倍模式，进入原活动完成选择，不能由一个通用领取按钮替玩家决定。

同一份奖励，无论从VIP页、活动页、消息还是“我的奖励”打开，都显示同一份领取结果，只能到账一次。网络中断或结果暂未确定时显示“处理中”，继续查询或恢复原申请，不重新发一份奖励。截止前系统已经受理的申请继续处理，不能因为处理时超过截止时间就作废；截止前未受理的申请，到时不再接受领取。

玩家逐份决定是否领取，本页不自动代领、不统一代替玩家参加活动，也不提供“全部领取”。领取成功后更新钱包和打码任务，并保留历史记录；玩家不能再取消这笔已到账奖励或清除对应任务。领取资格可能过期，但已经到账的彩金不会因为一直没用而过期，这两种情况要明确区分。

### Account-R13 · 邀请与佣金

邀请功能对当前玩家开放时，显示个人邀请链接、复制入口、直接邀请的人数，以及充值佣金和投注佣金汇总。功能未开放且没有历史记录时，首页不显示入口。有历史佣金时，即使不再产生新佣金，也保留查询和原有佣金的处理入口。

本版只统计玩家直接邀请的人，不展示二级、三级团队，也不提供申请成为代理、补绑或更换邀请关系的操作。邀请列表只显示隐藏部分字符的用户标识、建立邀请关系的时间，以及与本人佣金有关的汇总，不公开对方的联系方式、收款账户或完整投注记录。邀请宝箱等活动奖励与佣金分别记录。

佣金按实际进度显示“统计中”“等待开放”“可领取”“领取处理中”“已领取”“已作废”或“已冲回”。尚未结算的金额不加入可领金额。每条记录说明是哪一天、按多少充值或有效投注、以什么比例计算出的佣金，以及开放时间和适用打码倍数。

来源充值被退款后，未领取的对应佣金可能作废，已领取的可能发生追回。页面显示原佣金、实际调整金额和处理结果；作废或已冲回的记录不能再次领取。不能仅凭原佣金金额，就显示已经全额追回。

每天产生的佣金在下一业务日平台设定的时间开放领取，页面显示准确时间，不能把当日计算出的金额写成已到账。玩家按每条结算记录手动领取，未领取的佣金不会过期，本版不提供合并领取。重复点击或查询结果时继续处理原记录，不重复入账。

领取后佣金进入同一个USD钱包，按该记录生成时确定的倍数产生打码要求；领取前要显示这项影响。之后按普通钱包规则提现，不另设佣金提现流程。

关闭返佣活动后，不再对关闭后的充值或投注计算新佣金；关闭前的有效投注仍完成当期结算，原有合法佣金按原定时间开放、继续可以领取。活动关闭本身不会收回已到账佣金，也不会清除原待领记录。

### Account-R14 · 消息、帮助与账户停用申请

消息页分为个人通知和平台公告，显示标题、时间、已读状态和详情。充值、提现、奖励或身份审核有变化时可以发通知；点击后打开对应记录，显示最新结果。阅读消息不会再发一次钱，也不会替玩家领取奖励。本版支持标记已读，不提供通过消息删除业务记录的操作。

帮助页提供充值不到账、提现进度、流水要求、领奖条件和账户找回等常见问题，以及当前可用的客服联系方式。从某笔订单或奖励详情咨询时，带上记录编号和问题类型，发送前让玩家检查说明，不自动附带证件、密码、验证码或完整收款信息。

问题成功提交给客服后，显示受理编号和当前状态。暂时无法提交时明确说明，并提供其他仍可使用的联系渠道。

玩家也可以通过客服申请暂停游戏或关闭账户。申请前说明处理方式，以及钱包余额、未完成订单会如何处理，再由客服核对身份并办理。提交申请时显示“申请已提交”，实际停用或关闭后再通知玩家并更新账户状态。退出登录只是结束当前登录，不代表暂停或关闭账户，也不会删除资金记录。

设置页本期只保留金额隐藏偏好、条款与隐私说明、退出登录。单语言时无语言切换器,不展示没有对应通知能力的消息开关,不将营销通知关闭等同于不再接收交易结果。

### Account-R15 · 能力提供与运营配置边界

页面上的金额、奖励数量、可用次数、开放时间和功能入口，都使用系统确认的实际结果，不能填固定示例数，也不能由页面自己推算资格。功能未对某位玩家开放时，即使他直接打开链接，系统也要检查是否允许操作。活动关闭或入口隐藏后，已经受理的订单和历史奖励仍须能查询。

本版可购买的充值档位须以USD支付并到账，现金奖励也须以USD发放，支付和收款方式必须支持对应流程。如果误配了其他币种，暂不允许购买或领取，并请运营检查配置。已经产生的奖励保留原记录及暂时无法处理的说明，不能直接当成USD、自动换币或删除。

如果缺少完成操作所必需的信息，例如提现费用、密码要求或奖励结果，暂停对应操作并说明原因，其他正常页面仍可使用。网络中断、刷新页面或重复点击时，继续查询和处理原申请，不再扣一次钱，也不再发一次奖励。不能查询或处理的功能不得用“已完成”占位。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 新用户没有余额、记录、奖励或佣金 | 如实显示“暂无记录”或“暂无奖励”，不展示示例金额、虚假进度或待领数量 |
| 网络错误，或某部分加载失败 | 只在对应位置显示失败与重试；查不到不等于余额为0、没有任务或没有记录 |
| 打开页面后新增打码、投注被撤销或条件变化 | 更新显示；真正提交提现或领奖时，再检查一次当前条件 |
| 支付方通知成功，但平台还没确认到账 | 显示确认中并查询原订单，不要求重复支付，也不提前把钱加进余额 |
| 提现被拒绝，但钱还没恢复可用 | 分别说明拒绝原因和资金处理进度，不直接提示余额已经恢复 |
| 重复提交时查到上一次已经成功 | 显示原成功结果并更新余额、任务，不再次扣钱、发奖或占用额度 |
| 账户受限或登录过期 | 限制对应操作；登录过期后要求重新登录。无法登录时仍可从公开帮助入口联系客服 |
| 赠送或VIP配置变化 | 尚未受理的操作重新显示最新条件；已经保存的订单条件或奖励金额继续保留，不因新配置重算旧记录 |
| 暂时查不到订单、游戏或奖励的确定结果 | 显示“结果核查中”或“同步中”，继续查询原记录，不猜测成功、失败或钱已退回 |
| 更换联系方式或身份审核时离开页面 | 重进后显示原申请进度；新联系方式未验证成功前不替换旧信息，资料未通过审核前不显示已通过 |
| 活动或邀请入口关闭，但有历史记录 | 保留本人历史及已受理申请的处理结果；能否发起新操作按当前条件检查 |
| 玩家修改设备日期或时区 | 按平台实际时间判断领取期限和当日额度，不因此延长领奖时间或增加次数 |

## 5. 验收场景

设计与功能共同按下表验收,并覆盖第2节的视图状态。每条操作须连接入口、表单或预览、必要确认、提交中、结果及恢复路径;重点完整走通新用户充值、打码拦截提现、结果未知的提现、奖励跨入口领取和联系方式更换失败。以实际行为和结果验收,不以画板数量或按钮齐全代替。

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| Account-R1 | 未登录时直接打开钱包链接，登录后返回；退出后换另一个账号 | 回到原页面，只显示当前玩家资料，不残留前一个账号的金额和记录 |
| Account-R1 | 修改订单号访问他人订单,或支付返回后重复刷新 | 前者拒绝且不暴露详情;后者只查原订单,不重复建单 |
| Account-R2 | 有补资料、两笔在途订单及不同截止时间的奖励 | 首页按规则最多3条,仅未来24小时内可领奖励进入事项;查看全部展开同一列表,同一来源不重复 |
| Account-R2 | 奖励列表中有可领、未开放、处理中和过期权益 | 只有可领计入数量;数据失败不显示假0或固定红点 |
| Account-R3 | 钱包有余额且仅剩USD 0.01未完成流水 | 整个USD钱包不可提,显示剩余要求和详情,无部分可提金额 |
| Account-R3 | 任务均完成但有冻结或VIP额度不足 | 仍展示真实限制,不承诺全额可提,不重复减掉已扣占用 |
| Account-R3 | 领取赠金但平台要求先真实充值才能投注 | 钱已到账与投注限制分别显示,不将到账当成已可投注或可提现 |
| Account-R4 | 任务总量USD 2,000.00、完成USD 680.00 | 显示34%完成、剩余USD 1,320.00;零要求任务显示已完成 |
| Account-R4 | 两笔任务依次计入有效投注后，投注被撤销或后台免除剩余要求 | 同笔有效投注不重复计算；任务和提现条件随结果更新，免除的要求不能显示为玩家已完成投注 |
| Account-R5 | 切换支付方式或商品在下单前停用 | 按生效套餐更新档位,提交重新校验;无可用USD方式时明确不可充值 |
| Account-R5 | 本金USD 100.00要求1倍，赠金USD 20.00要求5倍 | 分别产生USD 100.00和USD 100.00流水要求，不把合计120直接按1倍计算 |
| Account-R5 | 多笔充值同时支付、连续点击提交，或付款通知延迟 | 预览不占优惠次数，结算时依次确定优惠；不重复建单或发奖，结果未确定时继续处理原订单 |
| Account-R5 | 同一赠送方案切换充值档位或支付方式，或一笔只获得固定赠金 | 次数仍共享，不因切换方式重置；固定赠金不消耗比例赠送次数 |
| Account-R5 | 已确定第几次优惠的订单结算失败，跨日后继续处理 | 不先增加成功次数；保留原优惠和计数周期，同周期后续订单等待，不重新分配优惠或改发固定赠金 |
| Account-R5 | 从首充补助活动创建翻倍专用充值 | 明示不享受商品赠金且不占比例赠送次数；补助返回活动页领取，普通订单不能事后改用途 |
| Account-R6 | 有未完成打码任务时进入提现页 | 直接显示剩余总量和查看明细入口，禁止提交；没有未完成任务时明确显示无剩余要求 |
| Account-R6 | 完成提现表单并提交;之后关闭页面 | 显示申请受理而非已到账,原订单和占用保留;无自助取消按钮 |
| Account-R6 | 两笔提现并发超出日额度,或回执超时 | 总额及次数不能绕过限额;未知结果继续占用,不自动退回或重付 |
| Account-R6 | 昨天提交并受理的提现，今天确认未付款且余额已恢复 | 修正昨天的额度，不增加今天的额度；余额显示实际恢复结果 |
| Account-R6 | 修改在途订单所用账户或支付方费用变化 | 原订单目的地不变且引用账户不能删除;新费用需要重新确认 |
| Account-R6 | 申请USD 100.00、费用USD 2.00,或无法取得费用 | 前者确认占用100、预计到账98;后者不可提交,不默认免费或改为额外扣费 |
| Account-R7 | 本人一笔充值含本金与赠金,另有待审核提现 | 订单中心均可查,与多条账变关联但不重复计订单;所有金额为USD |
| Account-R7 | 注单尚未结算、分次派彩或已取消退款 | 分别显示真实状态及最终事实,不把缺失派彩算净亏损,能追溯关联流水 |
| Account-R7 | 更改日期、加载更多并从详情返回 | 按业务时区筛选,保持条件与位置;空结果和取数失败明确区分 |
| Account-R7 | 支付方已收款，但充值的本金、赠金和流水要求还没一起处理完成 | 显示结算处理中并恢复原订单，不能遗漏赠金或先消耗优惠次数后就显示完成 |
| Account-R8 | 首次绑定或更换邮箱,新验证码错误或发送失败 | 只显示实际验证状态,新验证成功前旧绑定不变,不能绕过本人核验 |
| Account-R9 | 提款密码锁定、修改登录密码或忘记密码 | 锁定按服务端显示;改登录密码后重新登录;找回经核验,无虚构6位PIN或后台重置按钮 |
| Account-R9 | 登录密码未设置且有或没有可信验证方式 | 有可信方式先核验本人再设密;无验证方式进入账户找回,不凭当前页面直接设密 |
| Account-R10 | 身份资料提交、要求补充、审核通过 | 分别呈现处理中、指定补充项和通过结果,不直接覆盖已核验资料或公开内部原因 |
| Account-R11 | 充值升级条件达标但投注不足,或等级发生降级 | 两项进度分别显示,单项不升级;降级后按新增金额进度而非旧累计值 |
| Account-R11 | 9月12日升级、查看保级与VIP奖励 | 周期按个人日历月;返现看领取日充值,周月升级奖看领取月;免费部分领取前说明不补差 |
| Account-R11 | 降级后重新充值和投注，随后连续升两级 | 从本次降级时刻累计新增金额，两项都须新增并达到相应门槛差额；中途升级不重置这个起点 |
| Account-R11 | VIP暂停2天后恢复，期间某份奖励超过领取截止时间 | 保级截止时间顺延2天，暂停期间投注不计保级；领奖截止时间不顺延，已受理申请仍继续处理 |
| Account-R11 | 领取时间内升级或修改奖励配置，或降级后重新升回原等级 | 已确定的基础奖励不重算，全额资格仍检查领取时充值；同等级升级奖不重复产生 |
| Account-R12 | VIP页与我的奖励同时提交同一权益 | 仅一笔资金和任务;未知结果查原申请,截止不取消已受理处理 |
| Account-R12 | 充值自动赠金、待使用转盘券和手动现金奖励并存 | 自动赠金不再领,券不计钱包,现金领取显示打码影响;不提供跨活动全部领取 |
| Account-R12 | 奖励涉及免费部分不补差或领取模式选择 | 简单领取保留来源确认;模式选择跳原活动完成,不由聚合页替玩家决定 |
| Account-R13 | 已有佣金未到次日开放时间，随后关闭返佣活动 | 不提前允许领取；关闭前的投注完成原结算，旧佣金按原时间开放且不过期 |
| Account-R13 | 玩家查看直接邀请的人并领取佣金 | 对方标识隐藏部分字符，不暴露个人敏感资料；佣金进入同一个USD钱包，不另设提现入口 |
| Account-R13 | 来源退款导致未领佣金作废或已领佣金冲回 | 展示原金额与实际修正结果,移出可领并禁止再次领取,不假设全额已收回 |
| Account-R14 | 从提现详情咨询客服，或申请暂停账户 | 带上本人订单编号，不发送密码等敏感信息；显示真实受理结果，申请提交不等于账户已停用 |
| Account-R14 | 阅读旧到账消息,或仅退出登录 | 查看当前订单状态;不由消息重复入账;退出不表示账户关闭 |
| Account-R15 | 误配USDT商品或非USD奖励,关键费用或密码规则缺失 | 不当作USD处理或默认放行;保留历史权益并交来源处理,其他可用模块不受牵连 |
