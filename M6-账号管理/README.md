# M6 · 账号管理

## 1. 定位与边界

**做什么**:后台账号、角色与权限的管理,以及全站操作日志。
**本模块是全平台权限模型的唯一定义方** —— 其余模块只声明自己有哪些权限节点,不重复描述模型。

**不做什么**
- 不做玩家账号(那是 M2 用户管理,后台账号与玩家是两回事)
- 不定义各业务模块具体有哪些节点(各模块在自己的 README 第 6 段声明,本模块只定模型与规则)
- 不做登录认证流程本身(登录页、找回密码归玩家端与基础设施)

**铁律**
- **权限判定一律在服务端**。权限树同时被用来渲染菜单与按钮,
  但界面隐藏只是体验,不构成防护 —— 每个节点都要在服务端独立判定
- **数据范围与功能权限是两个维度**,缺一不可:
  能做什么由**角色**决定,能看谁的数据由**账号绑定的推广商**决定

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 后台账号 | 运营人员用来登录后台的账号,**不是玩家** | 后台账号 |
| 角色 | 一组被勾选的权限节点。账号通过绑定角色获得功能权限 | 角色 |

| 操作日志 | 全站后台操作的留痕,按操作者、路径、请求参数与接口描述记录 | 操作日志 |
| 到期时间 | 账号的有效期,过期后不能登录 | 后台账号.到期时间 |

## 6. 权限点汇总

### 权限模型

角色配置里是一棵**四层勾选树**,层级与后台菜单完全一致
(见 `截图/角色配置-权限树.png`,财务管理展开后的样子见
`截图/角色配置-权限树-财务管理展开.png`):

```
模块        财务管理
└ 分组      提现管理          (无分组时页面直接挂模块下)
  └ 页面    提现订单
    └ 操作  批量审批 · 审核 · 提交审查
```

- **分组层可有可无**。冻结资金解锁配置直接挂在财务管理下,没有中间分组;
  提现订单则挂在提现管理分组下
- **操作层可有可无**。人工充值、操作记录、通道三页都是叶子,没有操作子节点;
  充值商品配置则有新增、编辑、删除、状态切换四个
- **父节点是子节点的前提**:勾中任一操作节点必须同时持有其页面节点,
  否则出现「能审核但打不开页面」的空权限

### 授权模型

| 维度 | 挂在哪 | 取值 | 说明 |
|---|---|---|---|
| 功能权限 | **角色** | 一组权限节点 | 一个账号**只能绑一个角色**(单选) |
| 数据范围 | **账号** | 推广商,**多选必填** | 决定能看到哪些推广商的数据 |
| 来源限制 | 账号 | IP白名单,选填 | 多个地址用英文逗号隔开 |
| 二次验证 | 账号 | 谷歌验证码开关 | 新建账号时**默认关闭** |
| 有效期 | 账号 | 到期时间 | 过期不能登录 |

账号配置界面见 `截图/账号配置-新增账号.png`。

**角色单选意味着**:没有多角色并集,权限来源唯一、不存在叠加歧义;
代价是临时授予某个操作只能换整个角色,不能在原角色上追加。
