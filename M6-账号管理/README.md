# M6 · 账号管理

## 1. 定位与边界

**做什么**:后台账号、角色与权限目录的管理,以及全站操作日志。
**本模块是全平台权限模型的唯一定义方** —— 其余模块只声明自己有哪些权限节点,不重复描述模型。

**不做什么**
- 不做玩家账号(那是 M2 会员管理);后台账号新建时附带测试玩家身份,规则见 [6.1 新增账号](6.1-用户管理/README.md)
- 不定义各业务模块具体有哪些节点(各模块在自己的 README 第 6 段声明,本模块只定模型与规则)
- 不做审批流 —— 开号、改角色即时生效；当前账号和角色增删改未统一写入操作日志
- 不做登录认证流程本身(登录页、找回密码归玩家端与基础设施)

**铁律**
- **权限判定一律在服务端**。权限树同时被用来渲染菜单与按钮,
  但界面隐藏只是体验,不构成防护 —— 每个节点都要在服务端独立判定
- **数据范围与功能权限是两个维度**,缺一不可:
  能做什么由角色决定；哪些业务另有运营商范围限制，由所属服务显式校验，不推断全站统一行级过滤

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 后台账号 | 运营人员用来登录后台的账号;新建时默认是官方渠道下的测试账号,拥有玩家钱包,供员工以玩家身份测试([M4决策D111](../M4-活动管理/README.md#7-决策清单)) | 后台账号 |
| 角色 | 一组被勾选的权限节点。账号通过绑定角色获得功能权限 | 角色 |
| 权限节点 | 权限树上的一个可勾选项,四层结构见 `6.2-角色管理/权限模型.md` | 权限节点 |
| 系统角色 | 系统预置的超级管理员角色,鉴权时视同拥有全部权限 | 角色.系统角色 |
| 推广商范围 | 本页不维护全站通用范围；具体业务见权限模型 | — |
| 运营商范围 | 账号可操作哪些运营商的数据。**挂在账号上,不在角色上** | 账号-运营商关联 |
| 操作日志 | 全站后台操作的留痕,按操作者、操作类型、模块、描述与变更前后数据记录 | 操作日志 |
| 会话期限 | 后台会话从登录起最长 30 天，不因活跃延长 | 会话创建时间 |

## 6. 权限点汇总

**权限模型的定义在 [`6.2-角色管理/权限模型.md`](6.2-角色管理/权限模型.md)** ——
四层树结构、授权规则、数据范围、判定规则与已知边界都在那里。本段只做节点索引。

| 权限码 | 树节点路径 | 名称 | 页面 |
|---|---|---|---|
| `permission:account:view` | 系统管理/用户管理 | 查看后台用户 | 6.1 |
| `permission:account:create` | 系统管理/用户管理 | 新增后台用户 | 6.1 |
| `permission:account:edit` | 系统管理/用户管理 | 编辑后台用户 | 6.1 |
| `permission:role:view` | 系统管理/角色管理 | 查看角色 | 6.2 |
| `permission:role:create` | 系统管理/角色管理 | 新增角色 | 6.2 |
| `permission:role:edit` | 系统管理/角色管理 | 编辑角色 | 6.2 |
| `permission:role:delete` | 系统管理/角色管理 | 删除角色 | 6.2 |
| `permission:catalog:view` | 系统管理/权限管理 | 查看权限目录 | 6.4 |
| `permission:log:view` | 系统管理/操作日志 | 查看操作日志 | 6.3 |

模块和菜单分组只是权限树的展示层级,没有独立的入口节点;
操作日志与权限目录是纯只读页,没有操作子节点。

**其余模块的节点在各自模块 README 第 6 段声明**,本模块不重复列举 ——
未声明的模块在本仓库范围外。

## 7. 决策清单

| # | 规则主题 | 涉及范围 | 执行结论 |
|---|---|---|---|
| D18 | 「角色类型」与「账号类型」的语义 | 6.1 · 6.2 字段清单 | 不设角色类型与账号类型。角色以全局唯一的角色标识区分,不据标识授予权限;系统角色是唯一的特殊角色。 |
| D19 | 权限树里「提交审查」对应什么动作 | M5 的 5.1 | 提交审查不作为独立业务动作开放,权限目录不设该节点。提现使用5.8自动转人工及5.1审核入口,不增加第二条重复提交路径。 |
| D20 | 界面已有、权限树缺失的操作节点如何补齐 | M5 的 5.1 · 5.2 · 5.3 | **执行规则**。权限目录由系统预置,页面已接入真实查询或配置、操作在界面有入口且服务端有处理时才收录;M5 的节点差异见 M5 第 6 段,补节点的动作在本模块 |
| D21 | 财务类账号是否强制开启二次验证 | 6.1-A6 | 当前账号页与资金操作链路未提供该设计中的二次验证功能；不作为已实现的账号能力，保留为历史候选。 |
| D22 | 操作日志是否受推广商范围过滤 | 6.3-R1 | 当前日志查询按查看权限及筛选条件执行，不附加推广商范围过滤；没有导出入口。原范围设计保留为历史候选，不覆盖 6.3 当前规则。 |
