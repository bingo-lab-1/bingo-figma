# M6 · 账号管理

## 1. 定位与边界

**做什么**:后台账号、角色与权限目录的管理,以及全站操作日志。
**本模块是全平台权限模型的唯一定义方** —— 其余模块只声明自己有哪些权限节点,不重复描述模型。

**不做什么**
- 不做玩家账号(那是 M2 会员管理,后台账号与玩家是两回事)
- 不定义各业务模块具体有哪些节点(各模块在自己的 README 第 6 段声明,本模块只定模型与规则)
- 不做审批流 —— 开号、改角色即时生效,事后靠操作日志复核
- 不做登录认证流程本身(登录页、找回密码归玩家端与基础设施)

**铁律**
- **权限判定一律在服务端**。权限树同时被用来渲染菜单与按钮,
  但界面隐藏只是体验,不构成防护 —— 每个节点都要在服务端独立判定
- **数据范围与功能权限是两个维度**,缺一不可:
  能做什么由**角色**决定,能看谁的数据由**账号绑定的推广商**决定

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 后台账号 | 运营人员用来登录后台的账号,**不是玩家** | 后台账号 |
| 角色 | 一组被勾选的权限节点。账号通过绑定角色获得功能权限 | 角色 |
| 权限节点 | 权限树上的一个可勾选项,四层结构见 `6.2-角色管理/权限模型.md` | 权限节点 |
| 系统角色 | 系统预置的超级管理员角色,鉴权时视同拥有全部权限 | 角色.系统角色 |
| 推广商范围 | 账号能看到哪些推广商的数据。**挂在账号上,不在角色上** | 账号-推广商关联 |
| 运营商范围 | 账号可操作哪些运营商的数据。**挂在账号上,不在角色上** | 账号-运营商关联 |
| 操作日志 | 全站后台操作的留痕,按操作者、操作类型、模块、描述与变更前后数据记录 | 操作日志 |
| 到期时间 | 账号的有效期,过期后不能登录 | 后台账号.到期时间 |

## 7. 决策清单

| # | 规则主题 | 涉及范围 | 执行结论 |
|---|---|---|---|
| D18 | 「角色类型」与「账号类型」的语义 | 6.1 · 6.2 字段清单 | 不设角色类型与账号类型。角色以全局唯一的角色标识区分,不据标识授予权限;系统角色是唯一的特殊角色。 |
| D19 | 权限树里「提交审查」对应什么动作 | M5 的 5.1 | 提交审查不作为独立业务动作开放,权限目录不设该节点。提现使用5.8自动转人工及5.1审核入口,不增加第二条重复提交路径。 |
| D20 | 界面已有、权限树缺失的操作节点如何补齐 | M5 的 5.1 · 5.2 · 5.3 | **执行规则**。权限目录由系统预置,页面已接入真实查询或配置、操作在界面有入口且服务端有处理时才收录;M5 的节点差异见 M5 第 6 段,补节点的动作在本模块 |
| D21 | 财务类账号是否强制开启二次验证 | 6.1-A6 | 拥有财务资金变更权限的账号必须绑定并启用二次验证后才能执行资金操作,不得关闭或绕过;其他账号默认关闭。财务角色授权即时生效,未绑定时仅允许完成绑定,不执行资金操作。 |
| D22 | 操作日志是否受推广商范围过滤 | 6.3-R1 | 日志查询与导出都按账号推广商范围过滤,平台级日志仅全平台管理账号可查;跨推广商审计通过明确授予全部对应范围执行,不设置隐式绕过。 |
