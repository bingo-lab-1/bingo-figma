# M6 · 账号管理

## 1. 定位与边界

**做什么**:后台账号、角色与权限的管理,以及全站操作日志。
**本模块是全平台权限模型的唯一定义方** —— 其余模块只声明自己有哪些权限节点,不重复描述模型。

**不做什么**
- 不做玩家账号(那是 M2 用户管理,后台账号与玩家是两回事)
- 不定义各业务模块具体有哪些节点(各模块在自己的 README 第 6 段声明,本模块只定模型与规则)
- 不做审批流 —— 开号、改角色即时生效,事后靠操作日志复核
- 不做登录认证流程本身(登录页、找回密码归玩家端与基础设施)

**铁律**
- **权限判定一律在服务端**。权限树同时被用来渲染菜单与按钮,
  但界面隐藏只是体验,不构成防护 —— 每个节点都要在服务端独立判定
- **数据范围与功能权限是两个维度**,缺一不可:
  能做什么由**角色**决定,能看谁的数据由**账号绑定的推广商**决定

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 后台账号 | 运营人员用来登录后台的账号,**不是玩家** | 后台账号 |
| 角色 | 一组被勾选的权限节点。账号通过绑定角色获得功能权限 | 角色 |
| 权限节点 | 权限树上的一个可勾选项,四层结构见 `6.2-角色列表/权限模型.md` | 权限节点 |
| 推广商范围 | 账号能看到哪些推广商的数据。**挂在账号上,不在角色上** | 账号-推广商关联 |
| 操作日志 | 全站后台操作的留痕,按操作者、路径、请求参数与接口描述记录 | 操作日志 |
| 到期时间 | 账号的有效期,过期后不能登录 | 后台账号.到期时间 |

## 3. 依赖关系

**上游依赖(我引用)**
- 渠道代理:推广商列表(**本仓库范围外**),账号绑定数据范围时选它

**下游被依赖(谁引用我)** ← 改权限模型前先看这行
- **全部业务模块**。M2 用户管理、M5 财务管理已在各自 README 第 6 段声明权限节点;
  数据中心、玩法中心、运营管理、渠道管理、系统设置同理(**均在本仓库范围外**)
- 各模块页面的「可见范围过滤」依赖账号的推广商绑定

> **权限模型是全平台被依赖最广的一处。** 改四层树的层级、改角色与账号的绑定方式,
> 影响每一个模块的每一个页面,改动前必须逐个模块确认。
