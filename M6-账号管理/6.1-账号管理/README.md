# 6.1 · 账号管理

## 1. 背景与目标

**目标**:开通、停用和回收后台账号,并明确每个人能看哪些推广商的数据。

**谁在用**

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 管理员 | 新人入职开号、离职停号、调岗换角色 | 账号靠口头交接,离职的人还能登进来 |
| 风控 | 核对谁能看到哪些推广商的数据 | 说不清数据边界,跨推广商泄露查不出 |
| 主管 | 给下属设到期时间与登录来源限制 | 外包与临时账号长期有效,没人记得回收 |

**业务价值**:后台账号是所有操作的源头。开号快、停号准、边界清,
出事时才能一眼看出是谁做的、他本来该不该有这个权限。

**不做什么**
- 不定义角色里有哪些权限(那是角色列表页,权限模型见该页的辅助文件)
- 不管玩家账号(那是用户管理模块,后台账号与玩家是两回事)
- 不做登录流程本身(登录页、找回密码归基础设施)
- 不做审批流 —— 开号与改号即时生效,事后靠操作日志复核

**适用范围**

| 维度 | 取值 |
|---|---|
| 终端 | 桌面后台,最小宽度 1440 |
| 响应式 | 否 |
| 界面语言 | 简体中文 |
| 时区 | 运营时区,页面顶部标注 |
| 货币 | 不涉及金额 |

## 6. 需求清单

> 本页权限节点见 `../README.md` 第 6 段;判定规则见 `../6.2-角色列表/权限模型.md` 第 5 段。

|---|---|---|---|---|
| 6.1-R1 | 账号列表与筛选 | 进入页面 · 点查询 · 翻页 | 四项筛选可组合;敏感字段脱敏;分页与总数准确 | `permission:account` |
| 6.1-R2 | 新增账号 | 点新增账号并提交 | 账号唯一;角色单选、推广商多选均必填;密码不回显 | `permission:account:create` |
| 6.1-R3 | 编辑账号 | 点某行编辑并提交 | 改角色或推广商**即时生效**;密码留空表示不改 | `permission:account:edit` |

## 7. 需求详述

### 6.1-R2

**触发条件**:点击新增账号,填写弹窗并确认。

**可输入数据**:见第 5 段弹窗字段。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 必填校验、密码强度提示、推广商多选、二次验证开关联动 |
| 服务端 | 权限判定、账号唯一性、角色与推广商有效性、密码加密存储、留痕 |

**处理逻辑**

1. 判权限;无权限不展示入口,服务端二次判定
2. 校验账号全局唯一、角色存在、所选推广商都存在且启用
3. **不得授予超出自身的范围**:操作人只能把**自己已有的推广商**授予他人 ——
   否则任何能开号的人都可以给自己开一个能看全部推广商的小号
4. 密码加密存储,任何接口都不回显明文
5. 保存后账号立即可用
6. 写操作日志,记录操作人、被建账号、角色与推广商范围

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无新增权限 | 提示无权限 |
| 账号已存在 | 该账号名已被占用 |
| 必填项未填 | 定位到具体字段并提示 |
| 未选推广商 | 请至少选择一个推广商 |
| 所选推广商超出自身范围 | 拒绝并说明只能授予自己已有的推广商 |
| 密码不满足强度 | 按 A3 提示具体要求 |
| 开启二次验证但未填谷歌配置 | 请补齐谷歌地址与密钥 |

**测试案例**

- 正向:建一个绑「财务专员」角色、推广商仅 A 的账号 → 该账号只能看到推广商 A 的数据,
  且只能做该角色勾中的操作
- 正向:密码字段在任何列表与详情中都不回显
- 逆向:账号重名 → 拒绝;推广商一个不选 → 拒绝
- 逆向:操作人只有推广商 A,却给新账号勾上 A 与 B → 拒绝
- 逆向:开启二次验证但谷歌密钥留空 → 拒绝

### 6.1-R4

**触发条件**:点击某行的状态开关。

**可输入数据**:目标状态(启用 / 停用)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 二次确认,停用时提示该账号将立即无法登录 |
| 服务端 | 权限判定、状态变更、**在线会话失效**、留痕 |

**处理逻辑**

1. 判权限
2. 停用:立即禁止登录,并使该账号**已登录的会话同时失效** ——
   只挡登录不挡在线会话,等于停用要等到对方主动退出才生效
3. 启用:恢复登录能力,不重置密码与二次验证配置
4. **不允许停用自己** —— 会把自己锁在外面且无人可恢复
5. 写操作日志

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无状态切换权限 | 提示无权限 |
| 停用自己 | 不能停用当前登录的账号 |
| 重复提交 | 只生效一次 |

**测试案例**

- 正向:停用一个在线账号 → 该账号当前会话立即失效,再次登录被拒
- 正向:重新启用 → 可正常登录,二次验证配置保持不变
- 逆向:停用自己 → 拒绝
- 逆向:连点两次 → 只生效一次

### 6.1-R6

**触发条件**:点击查看验证码 · 点击重置验证码。

**可输入数据**:目标账号(单条)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 二次确认;查看结果不落地、不允许复制到剪贴板之外的地方 |
| 服务端 | 权限判定、返回或重置验证码、**强制留痕** |

**处理逻辑**

1. 判权限;查看与重置**各自独立授权**,不合并
2. **查看**:返回该账号当前的二次验证信息。这个动作等于获得了以该账号身份登录的能力,
   因此必须逐次写操作日志,记录操作人、被查账号与时间
3. **重置**:作废旧的二次验证配置并生成新的,原持有人需重新绑定
4. 两个动作都进操作日志的重点关注项,按操作人与频次汇总

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无查看权限 | 提示无权限,按钮不可见 |
| 无重置权限 | 同上,与查看分别判定 |
| 目标账号未开启二次验证 | 提示该账号未开启,无可查看或重置的内容 |

**测试案例**

- 正向:查看某账号验证码 → 操作日志立即出现一条记录,含操作人与被查账号
- 正向:重置后原配置失效,原持有人需重新绑定
- 逆向:只有查看权限的账号点重置 → 拒绝
- 逆向:对未开启二次验证的账号点查看 → 提示无内容,不报错

## 8. 数据流向与系统串接

**数据流向**:管理员在弹窗中填写账号信息并选定角色与推广商 →
服务端校验唯一性与授权范围后保存 → 该账号登录后,
功能权限按其角色判定、数据范围按其推广商判定 → 所有操作留痕进操作日志。

**系统串接**:**无外部系统**。推广商列表来自渠道代理侧(**本仓库范围外**),
本页只引用其标识与启停状态;二次验证使用标准的时间型一次性密码,不依赖第三方服务。

## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权开号 | 无新增权限的账号提交 | 拒绝并提示;服务端二次判定 |
| E2 | 授予超出自身的范围 | 操作人把自己没有的推广商授予他人 | 拒绝,只能授予自己已有的推广商 |
| E3 | 停用不生效 | 停用了账号但对方仍在线 | 停用时同步使已登录会话失效,不等对方退出 |
| E4 | 把自己锁死 | 停用或删除当前登录的账号 | 拒绝 |
| E5 | 删除后失去追溯 | 删除账号后其历史操作无从查证 | 操作日志**保留**,不随账号删除而清除 |
| E6 | 账号过期未回收 | 到期时间已过但仍能操作 | 过期即不能登录,已登录会话同样失效 |
| E7 | 密码或密钥泄露 | 接口回显了密码或谷歌密钥明文 | 一律不回显,列表与详情均脱敏 |
| E8 | 批量删除误操作 | 批量删除勾中了不该删的账号 | 二次确认并列出被删账号清单,逐个可见 |

## 10. 状态清单

| 状态 | 表现 |
|---|---|
| 错误 | 弹窗内字段级提示,弹窗不关闭,已填内容保留 |
| 已停用 | 列表中仍可见并明确标注,不从列表消失 |
| 已过期 | 特有态:到期时间已过的账号需可被筛出并明确标注,与手动停用区分开 |
| 未开启二次验证 | 特有态:查看与重置验证码的按钮置灰并说明原因,不是隐藏 |

## 11. 涉及表与职责

**数据归属**

- 拥有(owner=M6):后台账号 · 账号推广商关联
- 只读:角色(owner=M6,由 6.2 写入)· 推广商(owner=渠道代理,**本仓库范围外**)

**前后端职责**

| 事项 | 归属 |
|---|---|
| 权限判定 | **服务端** |
| 账号唯一性、授权范围不得超出自身 | **服务端** |
| 密码加密存储与不回显 | **服务端** |
| 停用时使在线会话失效 | **服务端** |
| 谷歌密钥脱敏 | **服务端** |
| 表单交互与即时格式提示 | 界面 |
| 二次确认与影响面提示 | 界面 + 服务端双重校验 |
