# 权限模型 · 四层权限树与授权规则

> 本文是 `6.2-角色列表` 的组成部分,不是独立页面(没有自己的菜单项)。
> 页面级的列表、筛选、增删改见同目录 `README.md`;账号侧的绑定见 `../6.1-账号管理/README.md`。

## 1. 定位

**全平台「谁能做什么、谁能看谁的数据」的唯一出处。** 各业务模块在自己的模块 README
第 6 段声明「我有哪些节点」,但节点的**结构、层级规则、授权方式、数据范围**只在这里定义一次。

之所以放在角色列表页下:权限树就是在这一页被配置的 ——
与 `资金模型.md` 放在用户列表页下同一个道理,全平台语义归属它被定义与消费的那一页。

**不做什么**
- 不列举各模块具体有哪些节点(那会变成第二份清单,必然与各模块分叉)
- 不规定权限如何存储与下发 —— 本文只写必须达成的结果
- 不定义登录认证本身(账号怎么登进来是另一件事)

**适用范围**:全平台所有模块、所有后台账号。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 权限节点 | 权限树上一个可勾选项。四层结构见第 3 段 |
| 角色 | 一组被勾中的权限节点 |
| 账号 | 运营人员的登录身份。**绑定一个角色 + 一组推广商** |
| 推广商范围 | 账号能看到哪些推广商的数据。**挂在账号上,不在角色上** |
| 页面节点 | 第三层节点,决定能否打开某个页面 |
| 操作节点 | 第四层节点,决定能否执行页面内的某个动作 |

## 3. 四层权限树

树的层级与后台菜单完全一致,见 `截图/弹窗-新增角色-权限树.png`:

```
第一层  模块      财务管理
第二层  分组      └ 提现管理           (可有可无)
第三层  页面        └ 提现订单
第四层  操作          └ 批量审批 · 审核 · 提交审查   (可有可无)
```

**分组层可有可无。** 冻结资金解锁配置直接挂在财务管理下,没有中间分组;
提现订单则挂在提现管理分组下。文档描述节点路径时按实际层级写,不强行补齐四层。

**操作层可有可无。** 人工充值、人工充值操作记录、操作日志都是叶子页面,没有操作子节点;
充值商品配置则有新增、编辑、删除、状态切换四个。
两棵子树展开后的实例见 `截图/弹窗-新增角色-权限树-财务管理展开.png` 与
`截图/弹窗-新增角色-权限树-账号管理展开.png`。

**父节点是子节点的前提。** 勾中任一操作节点必须同时持有其页面节点,
否则出现「能审核但打不开页面」的空权限。界面勾子节点时应自动补齐父节点,
但**服务端必须独立校验一次** —— 界面行为不构成防护。

## 4. 授权模型

功能权限与数据范围是**两个维度**,分别挂在角色和账号上,缺一不可。

| 维度 | 挂在哪 | 取值 | 说明 |
|---|---|---|---|
| 功能权限 | **角色** | 一组权限节点 | 一个账号**只能绑一个角色**(单选) |
| 数据范围 | **账号** | 推广商,**多选必填** | 决定能看到哪些推广商的数据 |
| 来源限制 | 账号 | IP白名单,选填 | 多个地址用英文逗号隔开 |
| 二次验证 | 账号 | 谷歌验证码开关 | 新建账号时**默认关闭** |
| 有效期 | 账号 | 到期时间 | 过期不能登录 |

账号侧的配置界面见 `../6.1-账号管理/截图/弹窗-新增账号.png`。

**角色单选意味着**:没有多角色并集,权限来源唯一、不存在叠加歧义;
代价是临时授予某个操作只能换整个角色,不能在原角色上追加。

**数据范围必须与功能权限一起判定。** 拿到「充值订单查询」页面节点只说明能打开这一页,
返回哪些行由账号绑定的推广商决定。**列表、汇总、导出一律先按范围过滤再返回** ——
汇总数字尤其容易漏,过滤前算出来的总额会泄露范围外的经营数据。

## 5. 判定规则

1. **一律在服务端判定。** 权限树同时被用来渲染菜单与按钮,但界面隐藏只是体验;
   每个节点都要在服务端独立判定,不能只在页面层拦一次
2. **父子完整性**:持有操作节点必须同时持有其页面节点
3. **未知节点拒绝**:请求中出现权限树上不存在的节点标识,拒绝而不是静默忽略
4. **即时生效**:角色改动对该角色下所有账号立即生效,不要求重新登录
5. **异步任务继承发起人身份**:导出等异步动作在队列里执行时,
   仍按**发起人**的角色与推广商范围判定,不得以系统身份绕过

## 7. 已知边界

以下是**当前模型的事实**,不是待改进项 —— 记下来是为了让消费方知道边界在哪,
不要在文档里假设不存在的能力。

| 边界 | 现状 |
|---|---|
| 额度 | 权限是二值的,只管能不能做,**不管能做多大**。金额与次数上限由各业务页面自己的参数控制,不随角色变 |
| 字段级 | 最细到操作节点,**没有字段级权限**。脱敏与否由各页面自行规定,无法按角色区分 |
| 互斥 | 树是加法模型,**无法表达「这两个节点不能同时勾」** |
| 行级范围 | 数据范围只到推广商一层,**没有更细的行级约束** |
