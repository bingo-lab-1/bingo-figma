# 6.3 · 操作日志

<a id="1-背景与目标"></a>

## 1. 用途

让后台干预操作都能被查到是谁、什么时候、做了什么。

### 使用者

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 风控 | 追查异常操作,还原一笔资金调整的来龙去脉 | 出了问题只能猜,查不到人也说不清经过 |
| 财务 | 对账不平时反查当天的人工干预 | 只能逐个页面翻记录,漏一个就查不出源头 |
| 管理员 | 核对权限改动与账号变更 | 谁给谁提了权限没有痕迹 |

这是整个后台统一的「事后说得清」的凭据。
各业务页面要求的「留痕」都落在这里,不各自建一套记录表。

### 本次范围
- 不提供任何修改能力 —— 纯只读,页面不能改写或删除日志
- 不做告警与实时监控(那是运维侧的事,本页只负责可查)
- 不替代各业务页面自己的业务流水(如账变流水、人工调整记录),两者互补而非重复
- 本版不提供:时间范围筛选;请求路径、请求参数、返回参数、IP地址、请求方法、耗时、代理头与请求状态;变更前后数据展示;导出;保留期与归档

### 适用范围

| 维度 | 取值 |
|---|---|
| 终端 | 桌面后台,最小宽度 1440 |
| 响应式 | 否 |
| 界面语言 | 简体中文 |
| 时区 | 时间按浏览器本地时区展示 |
| 货币 | 不涉及金额 |

<a id="4-关键参数与规则"></a>

## 2. 查询条件

`截图/列表-筛选面板与表头.png` 为旧后台界面留档,字段以本页为准。

**筛选字段**

| 字段 | 类型 | 可输入数据与校验 |
|---|---|---|
| 用户ID | text | 操作者账号标识,精确匹配 |
| 用户名 | text | 模糊匹配,不区分大小写;按操作者账号当前的用户名、姓名、邮箱查找 |
| 操作类型 | select | create / update / delete / query / tag_update / user_kick / password_update,单选;列表外的操作类型不能通过本筛选查询 |
| 模块 | text | 模块标识,精确匹配;当前写入值为 user / activity / finance / game / cms / system |

四项筛选可组合,均非必填。

### 查询参数

| 配置或参数 | 填写与执行规则 |
|---|---|
| 每页条数(A1) | 默认 20 条/页;界面可切换 20 / 50 / 100 |
| 默认查询窗(A2) | 不设时间窗,默认查全部日志 |
| 日志保留期(A3) | 不设保留期,日志不自动清理,也不提供归档 |
| 查询响应上限(A4) | 本版不设查询超时 |

<a id="5-字段清单"></a>

## 3. 结果字段

**表格列**

| 列 | 说明 | 默认显示 |
|---|---|---|
| ID | 记录标识 | 是 |
| 用户ID | 操作者账号标识 | 是 |
| 用户名 | 操作者账号当前的用户名,无用户名时取姓名、邮箱;查不到账号时为空 | 是 |
| 操作类型 | 写入时的原始值,如 risk_config_update、user_kick | 是 |
| 模块 | 写入时的模块标识 | 是 |
| 操作描述 | 业务动作说明或操作原因,无内容显示 -,最多展示两行 | 是 |
| 操作时间 | 按浏览器本地时区展示 | 是 |

服务端同时保存记录对象、变更前数据与变更后数据,本页不展示。

**日志不记录请求参数与返回参数。** 写入方只记录业务字段,不写密码明文,
如改密只记录是否设置过密码。日志本身不能成为泄露渠道。

## 4. 操作规则

### 日志列表与筛选(6.3-R1)

进入页面 · 点击查询 · 切换筛选 · 翻页。

输入信息：见“查询条件”中的筛选字段,全部可组合、均非必填。

1. 判权限;无权限直接拒绝,不返回任何数据
2. 日志查询与导出均按当前账号的推广商范围过滤。平台级日志仅全平台管理账号可查;跨推广商审计须明确授予全部对应范围,不提供隐式绕过(D22)。
3. 按筛选条件取数,按操作时间降序

### 变更前后比对(6.3-R2)

本版不提供。变更前后数据只保存不展示,列表没有展开入口。

### 异常与处理

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权查看 | 无权限账号直接访问本页地址 | 跳转无权限页,接口拒绝且不返回任何数据 |
| E2 | 日志成为泄露渠道 | 操作涉及密码等敏感内容 | 写入方只记录业务字段,不写明文 |
| E3 | 大跨度查询 | 日志量很大 | 本版无时间筛选,按分页取数 |
| E4 | 超出保留期 | 查询很早的日志 | 日志不自动清理,不存在过保留期的情况 |
| E5 | 日志写入失败 | 业务操作成功但日志没写上 | 视同异常并告警 —— 无痕迹的资金操作等于没有凭据 |
| E6 | 账号已不存在 | 操作者账号查不到 | 日志**保留**并显示用户ID,用户名为空 |

### 日志列表与筛选遇到异常时(6.3-R1)

| 错误状况 | 提示 |
|---|---|
| 无查看权限 | 无此操作权限,不展示列表 |
| 查询失败 | 列表区域提示错误并可重试 |
| 用户名查不到账号 | 返回空列表 |

### 页面状态

| 状态 | 表现 |
|---|---|
| 错误 | 列表区域内提示并可重试,不整页跳转;筛选条件保留 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 6.3-R1 | 日志列表与筛选：进入页面 · 点查询 · 翻页 | 四项筛选可组合;按时间倒序 |
| 6.3-R2 | 变更前后比对：查看列表 | 当前不提供:列表没有展开入口,不展示变更前后数据 |
| 6.3-R1 | 受限账号查询或导出其他推广商日志,或尝试查询平台级日志 | 仅返回授权范围内的日志;平台级日志仅全平台管理账号可查 |

### 日志列表与筛选(6.3-R1)

- 正向:按用户ID查询 → 只返回该账号的操作,按时间倒序
- 正向:按用户名输入部分姓名 → 返回匹配账号的操作
- 正向:风控参数保存后按模块 system 查询 → 出现该次保存,操作描述为修改原因
- 逆向:无权限账号进入 → 拒绝且不返回数据

## 6. 相关资料

### 入口与关联页面

- 菜单:系统管理 → 操作日志
- 跳入:本版无页面跳入,从菜单进入后按用户ID或模块筛选

### 权限

| 操作 | 权限或执行方 |
|---|---|
| 日志列表与筛选(6.3-R1) | `permission:log:view` |
| 变更前后比对(6.3-R2) | 本版不提供 |

> 本页权限节点见 `../README.md` 第 6 段;判定规则见 `../6.2-角色管理/权限模型.md` 第 5 段。

### 术语与共用口径

> 权限节点与角色的定义见 `../6.2-角色管理/权限模型.md`,本文不重复。

| 术语 | 定义 |
|---|---|
| 操作类型 | 这次操作的类型标识,由写入方给定,不是受控枚举 |
| 模块 | 这次操作所属业务域的标识 |
| 操作描述 | 这次操作的业务说明,涉及原因的操作记录操作原因 |
| 变更前数据 / 变更后数据 | 写入方记录的改动前后内容,服务端保存,本页不展示 |

### 依赖与数据流

**数据流向**:后台账号执行干预操作 → 服务端在处理该操作时写入一条日志
(操作者、操作类型、模块、描述、记录对象、变更前后)→ 本页按筛选条件读取并展示。
**本页只读,不产生任何写入。**

**系统串接**:**无外部系统**。日志由平台自身在处理请求时写入,不依赖第三方。
与各业务模块的关系是**被依赖**:它们要求的「留痕」统一落在这里,各自不建记录表。

### 数据归属与职责

**数据归属**

- 拥有(owner=M6):操作日志(本页**只读**,写入方是各业务操作本身)
- 只读:后台账号(owner=M6,由 6.1 写入)

**前后端职责**

| 事项 | 归属 |
|---|---|
| 权限判定 | **服务端** |
| 不记录敏感明文 | **服务端**,由写入方负责 |
| 日志写入的完整性 | **服务端**,写入失败须告警 |
| 用户名解析 | **服务端**,按操作者账号当前资料展示 |
| 筛选交互与分页 | 界面 |

### 日志列表与筛选的职责(6.3-R1)

| 归属 | 做什么 |
|---|---|
| 界面 | 筛选交互、分页、操作描述折叠展示 |
| 服务端 | 权限判定、筛选、排序分页 |
