# 权限模型 · 四层权限树与授权规则

> 本文是 `6.2-角色管理` 的组成部分,不是独立页面(没有自己的菜单项)。
> 页面级的列表、筛选、增删改见同目录 `README.md`;账号侧的绑定见 `../6.1-账号管理/README.md`。

## 1. 定位

**全平台「谁能做什么、谁能看谁的数据」的唯一出处。** 各业务模块在自己的模块 README
第 6 段声明「我有哪些节点」,但节点的**结构、层级规则、授权方式、数据范围**只在这里定义一次。

之所以放在角色列表页下:权限树就是在这一页被配置的 ——
与 `资金模型.md` 放在用户列表页下同一个道理,全平台语义归属它被定义与消费的那一页。

**不做什么**
- 不列举各模块具体有哪些节点(那会变成第二份清单,必然与各模块分叉)
- 不规定权限如何存储与下发 —— 本文只写必须达成的结果
- 不定义登录认证本身(账号怎么登进来是另一件事)

**适用范围**:全平台所有模块、所有后台账号。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 权限节点 | 权限树上一个可勾选项。四层结构见第 3 段 |
| 角色 | 一组被勾中的权限节点 |
| 账号 | 运营人员的登录身份。**绑定一个角色 + 一组推广商** |
| 系统角色 | 系统预置的超级管理员角色,鉴权时视同拥有全部权限 |
| 推广商范围 | 账号能看到哪些推广商的数据。**挂在账号上,不在角色上** |
| 运营商范围 | 账号可操作哪些运营商的数据。**挂在账号上,不在角色上**,见第 4 段 |
| 页面节点 | 第四层的查看类节点,决定能否打开某个页面 |
| 操作节点 | 第四层的动作类节点,决定能否执行页面内的某个动作 |

## 3. 四层权限树

树的层级与后台侧边栏菜单一致,节点按权限码前缀归到对应菜单;`截图/` 下的权限树图片为旧后台界面留档:

```
第一层  模块      财务管理
第二层  分组      └ 提现管理           (可有可无)
第三层  页面        └ 提现订单
第四层  节点          └ 查看提币申请 · 审核提币申请
```

**分组层可有可无。** 页面可以直接挂在模块下,也可以放在分组下。
文档描述节点路径时按实际菜单层级写,不强行补齐四层,不以不存在的页面补齐权限树。

**操作节点可有可无。** 投注明细、操作日志只有查看节点;
币种管理则有查看、新增、编辑、删除、设置默认五个节点。
页面节点与操作节点在弹窗里同层平铺,勾选模块、分组或页面等于全选其下全部节点。
未能归到菜单的节点放入「其他」分组。

**页面节点与操作节点相互独立。** 勾操作节点不会自动带上页面节点,只勾操作节点时账号看不到页面入口。

## 4. 授权模型

功能权限与数据范围是**两个维度**,分别挂在角色和账号上,缺一不可。

| 维度 | 挂在哪 | 取值 | 说明 |
|---|---|---|---|
| 功能权限 | **角色** | 一组权限节点 | 一个账号**只能绑一个角色**(单选) |
| 数据范围 | **账号** | 推广商,**多选必填** | 决定能看到哪些推广商的数据 |
| 运营商范围 | **账号** | 运营商,由系统管理员分配 | 见下 |
| 来源限制 | 账号 | IP白名单,选填 | 多个地址用英文逗号隔开 |
| 二次验证 | 账号 | 谷歌验证码开关 | 普通账号默认关闭;拥有财务资金权限时强制绑定启用 |
| 有效期 | 账号 | 到期时间 | 过期不能登录 |

账号侧的配置见 `../6.1-账号管理/README.md`。

**角色单选意味着**:没有多角色并集,权限来源唯一、不存在叠加歧义;
代价是临时授予某个操作只能换整个角色,不能在原角色上追加。

**数据范围必须与功能权限一起判定。** 拿到「充值订单查询」页面节点只说明能打开这一页,
返回哪些行由账号绑定的推广商决定。**列表、汇总、导出一律先按范围过滤再返回** ——
汇总数字尤其容易漏,过滤前算出来的总额会泄露范围外的经营数据。

- 充值商品与赠送、人工充值单、邀请宝箱、幸运转盘、拼多多活动、首充破产补助及修改会员推广渠道,按账号的运营商范围判定。
  范围由系统管理员分配,未分配运营商的非系统账号不能操作任何运营商;系统角色不受限
- 同期群分析除页面节点外,还要求持有整个平台数据范围节点

## 5. 判定规则

1. **一律在服务端判定。** 权限树同时被用来渲染菜单,但界面隐藏只是体验;
   每个节点都要在服务端独立判定,不能只在页面层拦一次
2. **页面入口**:菜单和页面路由按页面节点放行,无权限时跳转无权限页
3. **未知节点拒绝**:请求中出现权限目录里不存在的节点标识,拒绝而不是静默忽略
4. **即时生效**:角色改动对该角色下所有账号立即生效,不要求重新登录;实时推送在每次下发前重新判定
5. **按发起人判定**:导出按发起人当次请求的角色与推广商范围判定,不得以系统身份绕过;本版后台没有排队执行的异步导出
6. **授权不得超出自身**:非超级管理员只能授予自身持有的节点,
   只能管理和分配权限不超出自身的角色,不能管理系统角色
7. **系统角色短路**:系统角色鉴权时视同拥有全部节点,新增节点无需再勾选;其标识与权限不可改,不可删除

## 7. 已知边界

以下是**当前模型的事实**,不是待改进项 —— 记下来是为了让消费方知道边界在哪,
不要在文档里假设不存在的能力。

| 边界 | 现状 |
|---|---|
| 额度 | 权限是二值的,只管能不能做,**不管能做多大**。金额与次数上限由各业务页面自己的参数控制,不随角色变 |
| 字段级 | 最细到操作节点,**没有字段级权限**。脱敏与否由各页面自行规定,无法按角色区分 |
| 互斥 | 树是加法模型,**无法表达「这两个节点不能同时勾」** |
| 行级范围 | 数据范围只到推广商一层,**没有更细的行级约束** |

财务资金变更权限要求账号先绑定二次验证;未绑定时拒绝资金操作并引导绑定,启用后不允许关闭。其他账号默认关闭。查询及导出日志按账号推广商范围过滤,平台级日志仅全平台管理账号可查。
