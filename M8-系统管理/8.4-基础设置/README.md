# 8.4 · 基础设置

## 1. 用途

运营决定玩家是否必须先成功充值才能投注。当前运营商一份配置,每次新投注实时读取,切换不需要发版。

本页目前只有平台投注模式一项。模式只决定“充值资格”这一道校验,余额、风控、游戏及提现限制仍独立执行。两种模式对彩金和打码任务的语义见[资金模型·平台充值前投注资格](../../M2-会员管理/2.1-会员列表/资金模型.md#平台充值前投注资格),执行结论见 [M4-D73](../../M4-活动管理/README.md#7-决策清单)。

后台桌面端使用,界面简体中文,充值资格按原币净额判断,不做币种换算。

## 2. 配置项

页面顶部显示当前生效模式和版本号,版本从 v1 开始,每次保存加一。

| 配置项 | 含义和填写规则 |
|---|---|
| 投注模式 | 必选,二选一:充值投注限制(平台默认)、无限制投注 |
| 修改原因 | 必填,去除首尾空格后 1 至 500 字 |

| 模式 | 规则 |
|---|---|
| 充值投注限制 | 玩家至少一笔链上充值到账,扣除冲正后原币净额仍大于 0,才能通过充值资格校验。不限币种,没有额外最低金额;人工加款和活动彩金不算。全部归零后恢复限制 |
| 无限制投注 | 不要求先成功充值即可通过充值资格校验,其他投注检查不变 |

## 3. 操作规则

### 切换模式

运营选择新模式并填写修改原因后点击保存,系统弹窗展示目标模式、当前版本和原因,确认后提交。所选模式与当前模式相同时保存按钮不可用。

提交时校验版本号,与当前版本一致才写入。成功后版本加一,操作日志记录操作人、修改原因及修改前后的模式和版本。

### 生效范围

保存后下一笔新投注立即按新模式判断。已受理的投注继续结算,不回滚;不冻结或清除彩金,不重置打码任务。

充值投注限制下,未满足条件的玩家提交投注时被服务端拒绝。注册送好礼和签到奖励页面按当前模式向玩家展示投注条件。外部德州扑克服务的接入不在本页承诺范围,页面明确提示尚未验收。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 修改原因为空 | 提示“请填写修改原因”,不进入确认 |
| 修改原因超过 500 字或模式非法 | 服务端拒绝,配置不变 |
| 其他人已先保存 | 提示“配置已被修改，请刷新并重新确认”,配置不变 |
| 保存结果未知 | 提示“保存结果未知，请重新读取后确认”,运营重新读取后判断 |
| 保存成功但页面刷新失败 | 提示“已保存，但刷新失败；请重新读取当前配置。” |
| 配置读取失败 | 页面显示“配置不可用”,可重新读取,不能编辑 |
| 配置缺失、模式无效或充值事实无法确认 | 新投注一律拒绝,不按任何模式放行 |
| 账号只有查看权限 | 控件不可用,提示“当前账号仅有查看权限。” |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 8.4-R1 | 从充值投注限制切到无限制投注,填写原因并确认 | 显示版本加一;未充值玩家的新投注通过充值资格校验 |
| 8.4-R2 | 模式未变 | 保存按钮不可用 |
| 8.4-R2 | 修改原因为空时点击保存 | 提示“请填写修改原因”,不弹确认 |
| 8.4-R3 | 充值投注限制下,未充值玩家提交投注 | 投注被拒绝,余额不变 |
| 8.4-R3 | 充值投注限制下,玩家有一笔净额大于 0 的成功充值 | 通过充值资格校验,继续走其他投注检查 |
| 8.4-R3 | 玩家唯一一笔充值被全额退款 | 恢复限制,新投注被拒绝 |
| 8.4-R3 | 玩家只有人工加款 | 不算成功充值,新投注被拒绝 |
| 8.4-R4 | 切换模式时有投注已受理 | 已受理投注继续结算 |
| 8.4-R4 | 切换模式后查看玩家彩金和打码任务 | 彩金和打码任务不变 |
| 8.4-R5 | A、B 看到同一版本,A 先保存,B 再保存 | B 提示“配置已被修改，请刷新并重新确认”,配置为 A 的结果 |
| 8.4-R6 | 配置无法读取时玩家提交投注 | 投注被拒绝,不放行 |
| 8.4-R7 | 账号只有 `system:basic:view` | 可查看,控件不可用并提示仅有查看权限 |
| 8.4-R7 | 账号没有 `system:basic:view` | 菜单不显示,服务端拒绝读取 |
| 8.4-R8 | 保存成功后查看操作日志 | 能查到操作人、修改原因及修改前后的模式和版本 |
