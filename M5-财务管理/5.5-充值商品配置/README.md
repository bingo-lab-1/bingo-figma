# 5.5 · 充值商品与赠送

<a id="1-背景与目标"></a>

## 1. 用途

运营在同一入口维护充值商品、充值金额打码倍数、常规固定彩金和按次数递进的比例彩金。原“充值商品配置”与“账号首充”合并；每次比例可不同，命中比例奖励时不再发固定金额彩金。

| 使用者 | 目标 |
|---|---|
| 运营 | 配置商品、共享赠送方案、第 1～N 次比例及打码倍数 |
| 客服与财务 | 查询订单的阶段、奖励依据、实际彩金和打码任务 |
| 玩家端 | 使用同一规则展示条件、剩余次数、预计金额及打码要求 |

本页拥有充值赠送规则；钱包、账变与任务语义以[资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)为准。支付方式与模板编排归 5.6。

[4.15 首充破产补助](../../M4-活动管理/4.15-首充破产补助/README.md)的翻倍专用订单是本页商品赠送的明确例外：建单时锁定用途并排除本单固定与限次比例彩金，充值仍按 X 建任务；补助由玩家在活动内手动领取。活动资格、宝箱与领取参数归 4.15，本页不重复配置。

充值通用倍数适用于当前运营商全部真实充值，包括商品订单与 Crypto 入金。无商品关系的 Crypto 入金不会因此自动参加商品赠送。5.2 按商品人工生成订单沿用 X 和商品常规固定赠送，但不取得真实首充或限次比例资格；5.3 人工余额调整沿用逐笔人工倍数及豁免权限。

桌面后台最小宽度 1440，简体中文，时间按运营时区，金额按各自币种展示与结算，不隐式换币。

## 2. 配置项

页面顶部为“充值通用配置”，下方为“充值商品 / 赠送方案 / 赠送记录”内部标签页。现有 `截图/` 反映合并前界面，新版以本文为准。

### 充值通用配置

| 字段 | 规则 |
|---|---|
| 充值金额打码倍数 X | 运营商级唯一配置，默认明确保存为 1；必填正数，最多 2 位小数，普通配置不开放 0 倍 |
| 配置版本 | 保存生成版本，记录操作人、时间和前后值；并发编辑拒绝覆盖 |
| 适用范围 | 当前运营商全部真实充值及 5.2 按商品人工生成订单；仅影响新订单/新入金记录；5.3 人工余额调整另按原规则 |

X 不随商品、支付渠道、赠送类型或方案开关变化。商品订单创建时锁定 X 及版本；无商品 Crypto 首次持久化充值记录时锁定。补单、确认等待、重新核验与重试沿用快照。配置缺失不等于默认 1 倍，缺少有效倍数依据不能完成入账建码。

### 商品列表与编辑

| 字段 | 规则 |
|---|---|
| 商品模板、币种 | 必填，属于当前运营商可用范围 |
| 面值、售价、获得的真金数量 | 非负金额，默认 0；上架时面值和售价须大于 0；面值、实付、到账真金允许不同 |
| 常规固定赠送开关 | 默认关闭，替代“复充赠送彩金”；不按真实首充/复充身份另作排除 |
| 固定彩金金额 | 开启时必填且大于 0，使用商品币种 |
| 固定彩金打码倍数 | 开启时必填正数，最多 2 位小数；与充值 X 独立 |
| 限次赠送方案 | 可不绑定；选择一份具体方案，替代“不绑定/充值绑定”泛化类型 |
| 上下架、热门、排序 | 默认下架、非热门、排序 0；排序非负整数，越小越靠前 |
| 到账与打码预览 | 自动计算充值来源金额、所选赠送、各自打码量与合计；取消手填“彩金前端展示金额” |
| 赠送真金 | 本版不提供编辑，新商品关闭，既有值只读保留，旧订单依据不变 |

筛选：商品 ID、上架状态、模板、绑定方案。列表列：序号、ID、运营商、商品 ID、模板、币种、面值、售价、到账真金、常规赠送、方案、热门、排序、状态及操作。X 在顶部维护，不逐商品重复配置。

### 共享限次赠送方案

| 字段 | 规则 |
|---|---|
| 方案名称与 ID | 名称必填，ID 稳定；改版本不创建新方案身份 |
| 开关 | 默认关闭，配置完整后可启用；关闭保留配置和进度 |
| 重置周期 | 不重置 / 每日重置；每日按运营时区；有订单引用或奖励记录后不得修改周期，另一周期须显式新建方案 |
| 比例彩金打码倍数 Y | 方案统一正数，最多 2 位小数；第 1～N 次共用；固定彩金使用商品自身倍数 |
| 奖励次数 | 连续第 1～N 次，至少 1 次；“增加一次奖励”追加阶段，删除从末次开始 |
| 阶段金额档 | 每阶段至少一档“币种＋最低单笔充值金额＋赠送比例”；门槛非负，同阶段同币种门槛唯一 |
| 赠送比例 | 正数，最多 2 位小数；不套用 VIP 免费领取比例的 0～100% 上限；不提供固定与比例叠加选项 |
| 引用商品 | 编辑展示受影响商品；商品币种须在方案每一阶段均有配置 |

一个商品只绑定一份限次方案；同方案跨商品、模板、渠道和币种共享账号次数。复制商品/模板继续引用原方案，不隐式复制方案或次数。方案被引用、有在途订单或奖励记录时不可删除，可停用。

### 配置口径

| 参数 | 规则 |
|---|---|
| A1 精度 | 金额按币种精度，比例和倍数用十进制定点数计算 |
| A2 基数 | 比例按成功支付有效金额计算，排除赠送，不以面值或通道扣费后商户净收入代替；充值建码基数为实际到账充值来源金额 |
| A3 打码 | 充值任务＝到账充值金额×快照 X；彩金任务＝实际彩金×对应倍数；两笔独立，不把充值和彩金合计乘彩金倍数 |
| A4 排序 | 非负整数，默认 0，越小越靠前 |
| A5 启停 | 下架/停用阻止新订单使用，已生成订单按快照履约；重启不清零次数 |
| A6 互斥 | 普通商品充值满足下一阶段比例资格，只发比例；否则使用开启的常规固定赠送；常规关闭则不送。4.15 翻倍专用订单按建单时锁定用途排除两者，见下方专用订单规则 |
| A7 次数 | 第 N 次指本方案第 N 次成功比例奖励；未达门槛、失败、固定赠送均不推进 |
| A8 周期 | 运营商＋账号＋方案＋周期共享进度；不重置为持续周期，每日重置按运营日 |
| A9 版本 | 商品、候选赠送规则与 X 随订单保存快照；实际阶段在结算时确定并固化 |
| A10 发放 | 本页普通商品固定/比例赠送随真实充值自动发彩金并建任务，不另设手动领取；奖励与计数原子一致。4.15 补助彩金独立手动领取，不在充值入账时自动发放 |

## 3. 操作规则

### 新增编辑商品、方案及通用配置

1. 校验当前运营商、角色权限和数据范围，包含商品、方案、记录与引用关系。
2. 校验金额、币种、比例、倍数、连续阶段和引用；开启的赠送必须有倍数，关闭项保留配置但不执行。
3. 展示改动与影响范围，保存生成新版本并留痕；并发提交拒绝静默覆盖。
4. 只影响新订单或新 Crypto 记录，不改旧订单快照、已入账金额或已建任务。
5. 改比例、上限或启停不重置进度；新版本上限小于等于已用次数时，采用新版本的订单不再获得比例奖励。

### 结算与次数推进

下列次数与发奖步骤适用于普通商品充值；先检查订单不可变用途，4.15 翻倍专用订单按下一节处理，不进入固定/比例分支及阶段占用。

1. 读取有效支付事实与订单快照，按订单幂等键读取或创建本笔唯一赠送结果。人工加款、无真实支付的人工生成订单不获得方案资格；真实支付补单沿用原单。
2. 首次受理有效支付结算时固定运营日及计数周期，恢复不因跨日占用新周期。同运营商、账号、方案与周期串行确定下一阶段＝已成功比例奖励次数＋1。已确定的阶段与待处理依据先持久化；若本次资金事务失败，保留该阶段待恢复占用，同账号方案周期后续订单排队，不得把阶段重新分配。预占不计成功次数，恢复沿用原阶段。
3. 按订单快照，选择当前阶段、币种最高满足门槛的一档，不跳到后续阶段。命中比例分支便不再进入固定分支；资格不满足才评估固定赠送。
4. 比例彩金＝成功支付金额×比例，向下保留币种精度，再按实际彩金金额计算任务。赠送均记彩金来源，不增加真实充值金额或次数。精度后为 0 时记录原因，不发奖、不建彩金任务、不消耗次数，也不改发固定赠送。固定、无赠送或零额结果成功落定时释放临时阶段占用，不推进比例次数，后续订单继续处理。
5. 充值来源按实际到账金额×X 建任务；非零彩金按自身倍数另建任务。调用资金服务，原子提交充值入账、赠送结果、任务、流水及成功奖励次数，任一失败不留下“次数已用但奖励未到账”的终态。
6. 重复回调、补单和恢复返回原结果。去重键覆盖运营商＋充值订单＋充值赠送用途，不能因方案版本改变而重复发钱。
7. 已收款但结算失败须保存原依据、异常原因并告警，支持恢复；不丢弃收款事实，不静默改发固定彩金，不按当前配置重算。

普通商品充值的互斥只约束本页两类赠送；4.15 专用订单仅增加“本单两类商品赠送均排除”的用途例外，不扩大到 VIP、签到等其他活动。每日重置不清除彩金、任务和历史记录。退款/拒付沿用资金域受控流程，不自动重置次数或回收已入账彩金。

### 首充破产补助翻倍专用订单

1. 玩家在 4.15 主动选择翻倍后，由活动业务在受理充值前校验宝箱资格，提供同币种、单笔达标的商品选择与不可变活动依据。建单时绑定宝箱，锁定“首充补助翻倍”用途、选定领取模式、活动条件、商品与 X，并向玩家明确本单不发商品固定/比例彩金；不能事后把普通充值绑定为翻倍订单。
2. 该单两类商品赠送均不执行，也不预占或消耗共享比例次数；不得先发商品彩金再回收。此前首充已取得的商品赠送和已有打码任务保留。支付成功后仅入充值来源金额、按快照 X 建任务，并幂等提供真实支付结果供 4.15 确认翻倍条件。
3. 补助彩金仍由玩家在 4.15 手动领取，按活动锁定金额与倍数独立入账建码；活动记录与充值记录互相关联。普通充值和专用订单的用途不可因失败、补单、配置修改或重试被静默改写。
4. 关联订单建单时锁定支付有效期，以真实业务支付时间判断，不以回调到达时的订单显示状态判断。领取期限内合法建单、在锁定支付有效期内付款的，回调迟到或活动已关闭/截止仍按原快照履约；真实超期付款进入财务核查，不丢弃收款、不自动发奖或改成普通商品赠送。支付结果未知时保留宝箱占用；只有已确认未支付且不可继续支付的终态才可按 4.15 规则释放并重新选择。具体时间、状态和资格规则唯一维护于 4.15（M4-D90）。

### 玩家展示与记录查询

普通商品充值展示实付、到账充值金额、预计阶段、门槛、剩余次数、彩金及各自倍数。预览与结算使用同一规则，预览不占次数；并发结算可能推进阶段，最终以结算结果为准。支付后刷新进度，次数用完显示常规赠送。4.15 专用订单展示首充补助翻倍用途、本单排除商品彩金及补助另行手动领取的说明，不沿用普通订单的固定/比例赠送预览。

内部赠送记录支持用户、订单、商品、方案、周期、币种、固定/比例及状态筛选。详情保留快照版本、实际阶段、基数、门槛、比例/固定金额、实际彩金、X、彩金倍数、两类任务、账变引用及失败/零额原因。状态区分处理中、成功、无赠送、异常待恢复。财务首笔充值事实不得替换成比例第 1 次。

专用订单在商品赠送记录中记“无赠送—首充补助翻倍用途排除”，可关联宝箱、活动依据和充值订单；不生成虚假的比例阶段记录。补助领奖结果从 4.15 活动记录关联查询，不能据本页“无赠送”误判补助已取消。

### 下架、删除商品及新增模板

下架禁止新下单，旧单按快照完成。删除二次确认，有套餐引用或在途订单则拒绝；历史订单保留原配置依据。新模板在运营商内名称唯一。重复提交只生效一次，所有写入留痕。

## 4. 特殊情况

| 场景 | 处理 |
|---|---|
| X、固定彩金倍数或 Y 缺失、为 0 或负数 | 普通配置拒绝保存/启用；运行时阻止受影响入账并告警，不按 0/1 兜底；人工豁免按原权限 |
| 阶段跳号、缺币种档、重复门槛 | 定位字段，拒绝保存或绑定 |
| 最后一次被两笔订单竞争 | 按服务端串行结算顺序最多一笔占用，另一笔使用常规规则 |
| 未达当前阶段门槛 | 不消耗、不跳阶段，可使用常规固定赠送 |
| 比例分支执行失败 | 按原依据恢复，不回退固定分支；成功次数随事务回滚，但保留待恢复阶段占用，后续订单排队 |
| 商品/方案关闭后旧订单支付 | 旧单按快照履约，关闭仅影响新订单 |
| 4.15 专用订单的支付结果未知 | 保留用途和宝箱占用，不发商品彩金、不占比例次数，不静默转普通订单 |
| 4.15 合法关联订单回调迟到或真实超期付款 | 以真实业务支付时间对照建单时锁定的支付有效期；有效期内付款的迟到回调按原快照履约，补助仍手动领取；真实超期付款进入财务核查，不丢收款、不自动发奖 |
| X 从 1 改为 2 | 新订单/新 Crypto 记录按 2；旧记录按已锁定 1；不改历史任务 |
| Crypto 确认等待期间修改 X | 沿用首次持久化记录中的 X，链上确认及风控要求不变 |
| 改已用方案周期或删除有引用方案 | 拒绝并显示引用/记录，允许停用或显式新建 |
| 越权、跨运营商、并发编辑 | 服务端拒绝，不泄露他方数据或覆盖他人修改 |
| 加载、错误、保存中 | 后台更新保留已有列表，错误保留输入可恢复，保存中防重复提交 |

## 5. 验收场景

| 编号 | 场景 | 预期 |
|---|---|---|
| 5.5-R1 | 商品列表、筛选及预览 | 金额有币种、规则和状态可见，展示金额自动计算 |
| 5.5-R2 | 新增编辑商品 | 校验、权限、留痕、版本及并发正确，历史不回溯 |
| 5.5-R3 | 上下架 | 下架不可新下单，旧单履约 |
| 5.5-R4 | 删除 | 引用/在途拒绝，历史依据保留 |
| 5.5-R5 | 新增模板 | 运营商内重名拒绝，复制商品不重置次数 |
| 5.5-R6 | 通用 X 从 1 改为 2 | 新商品订单及新 Crypto 记录按 2，旧记录按 1，赠送开关不改变 X |
| 5.5-R7 | 第 1/2/3 次 30%/20%/10% | 逐次比例，严格不加固定赠送；用完回常规；多门槛取最高满足档 |
| 5.5-R8 | 支付、资金及任务 | 本金、赠送、任务、计数原子一致；回调/补单/恢复无重复 |
| 5.5-R9 | 跨商品/渠道/币种、并发及每日重置 | 共享次数，最后一次仅一笔占用，跨日恢复不重复，历史任务保留 |

### 入口与权限

菜单：财务管理 → 充值管理 → 充值商品与赠送。沿用商品路由 `/admin/finance/recharge/product/` 及目录编号；原账号首充 `/admin/activity/recharge/first-recharge/` 跳转至统一入口方案区，执行目标页权限，原入口停止独立写配置。

| 操作 | 权限 |
|---|---|
| 页面访问 | `finance:recharge:product`（沿用） |
| 商品新增/编辑/删除/上下架 | `finance:recharge:product:create` / `edit` / `delete` / `toggle`（沿用） |

| 方案维护及启停 | `finance:recharge:product:scheme-edit`（新增） |
| 赠送记录查询 | `finance:recharge:product:reward-record`（新增） |

### 数据归属与依赖

- 本页拥有商品/模板、通用 X、赠送方案及版本、阶段档位、次数进度和赠送依据记录。
- 充值赠送业务服务负责规则选择、互斥、阶段及快照，再向资金服务提交金额、币种、倍数与来源；钱包和账变服务不得反向读取活动配置。
- 4.15 在受理专用充值前提供已校验的宝箱用途与活动依据；充值赠送业务据快照排除本单商品彩金，支付结果回传活动业务。活动的手动领取独立提交补助发奖依据，账务不反查活动配置或重新判资格。
- 资金域唯一写入钱包、账变及任务。充值/彩金是同币种单一钱包的资金来源，不是两个钱包；每日重置不作废彩金或任务。
- 币种、支付事实、账号及权限引用各自来源；有效投注核销、提现限制及人工豁免沿用资金模型。
