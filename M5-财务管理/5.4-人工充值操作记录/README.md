# 5.4 · 人工充值操作记录

## 1. 背景与目标

**目标**:让每一笔人工加钱与扣钱都能被查到是谁、什么时候、为什么做的,事后复核不用去翻数据库。

**谁在用**

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 财务 | 日终复核当天的人工调整,发现异常频次 | 人工改动无从核对,月底对不平也查不出源头 |
| 风控 | 查某个玩家是不是被反复补钱 | 内部套利没有痕迹可查 |
| 客服主管 | 核对下属的补偿操作是否合规 | 只能靠口头确认,出事无法追责 |

**业务价值**:人工调整是绕过支付通道直接改余额的动作,**它的价值不在于能做,而在于做完能查**。
这一页就是那个「能查」。

**不做什么**
- 不提供任何修改能力 —— 本页只读,改动一律回到人工充值页操作
- 不重复定义金额与打码语义,一律引用人工充值页的对应需求
- 不做跨玩家的资金汇总统计(那是数据中心的事)

**适用范围**

| 维度 | 取值 |
|---|---|
| 终端 | 桌面后台,最小宽度 1440 |
| 响应式 | 否 |
| 界面语言 | 简体中文 |
| 时区 | 运营时区,页面顶部标注 |
| 货币 | 多币种共存,金额必须带币种标识 |

## 5. 字段清单

筛选与表格见 `截图/列表-筛选与表格.png` —— 该页只有两个筛选项,是全模块最薄的一页。

**筛选字段**

| 字段 | 类型 | 可输入数据与校验 |
|---|---|---|
| 用户ID | text | 数字,精确匹配 |
| 充值类型 | select | 见下方枚举 |
| 操作人 | text | 精确匹配。**实采界面暂无此项,建议新增** |
| 变动时间 | daterange | 起止时间。**实采界面暂无此项,建议新增** |

**表格列**

| 列 | 说明 | 默认显示 |
|---|---|---|
| 序号 | 当前页行号 | 是 |
| ID | 记录标识,可用于对账追溯 | 是 |
| 用户ID | 被调整的玩家,可点击进入玩家详情 | 是 |
| 充值类型 | 动的哪条轨、哪个方向 | 是 |
| 变动金额 | **可正可负**,带币种标识。正为加钱、负为扣款 | 是 |
| 操作人 | 执行这笔操作的后台账号 | 是 |
| 备注 | 操作原因,由 5.3 提交时必填 | 是 |
| 变动时间 | 记录生成时间,按运营时区展示 | 是 |

**充值类型枚举(L2)**:实采仅见到「真金」一个取值。按 5.3 的方向与两轨设计,
完整枚举至少应能区分**真金加钱 / 真金扣款 / 彩金加钱 / 彩金扣款**。
**枚举未取全**(界面下拉为自定义组件,本轮未能展开),见模块决策 D8。

**变动金额可为负是既定行为,不是脏数据。** 实采存在 `R$-0.63` 的记录,对应 5.3 的扣款方向。

## 7. 需求详述

### 5.4-R1

**触发条件**:进入页面 · 点击查询 · 切换筛选条件 · 翻页 · 打开带筛选条件的分享链接。

**可输入数据**:用户ID(数字)· 充值类型(枚举)· 操作人(文本)· 变动时间(起止)。
全部可组合,均非必填。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 筛选交互、分页、金额正负与币种的可读呈现 |
| 服务端 | 权限判定、可见范围过滤、筛选校验、排序与分页、超时保护 |

**处理逻辑**

1. 判权限;无权限直接拒绝,不返回任何数据
2. 按筛选条件取数,默认按变动时间降序
3. 金额一律带币种标识,负数显式带负号,不用颜色单独表意
4. 操作人缺失的历史记录显示为「未记录」,不显示空白

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无查看权限 | 提示无权限,不展示列表 |
| 查询超时(见 A3) | 中断并提示缩小时间范围,不返回半截数据 |
| 用户ID 非数字 | 请输入数字用户ID |
| 起止时间颠倒 | 结束时间不能早于开始时间 |

**测试案例**

- 正向:按用户ID 查询 → 只返回该玩家的记录,按时间倒序,金额带币种
- 正向:存在一笔扣款记录 → 金额显示为负,充值类型可区分方向
- 逆向:无权限账号进入 → 拒绝且不返回数据
- 逆向:查询超大时间跨度触发超时 → 中断并提示,不返回半截数据
- 逆向:历史记录操作人为空 → 显示「未记录」而不是空白

### 5.4-R2

**触发条件**:点击列表中的用户ID。

**可输入数据**:无。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 打开玩家详情,保留当前筛选与滚动位置 |
| 服务端 | 玩家详情的权限判定 |

**处理逻辑**

1. 校验是否具备玩家详情查看权限
2. 打开详情,关闭后回到原筛选条件与滚动位置

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无玩家详情权限 | 用户ID 不可点击,或点击后提示无权限 |
| 玩家已注销 | 提示该玩家已注销,记录仍可查看 |

**测试案例**

- 正向:点用户ID → 打开详情;关闭后筛选条件与滚动位置不丢
- 逆向:无详情权限 → 拒绝并提示,不泄露玩家信息

## 8. 数据流向与系统串接

**数据流向**:5.3 人工充值提交成功 → 服务端写入人工调整记录与账变流水 →
本页按筛选条件读取并展示 → 财务与风控据此复核。**本页只读,不产生任何写入。**

**系统串接**:**无外部系统**。数据全部来自平台内部的人工调整记录,不涉及第三方。

## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权查看 | 无权限账号直接访问本页地址 | 拒绝并提示无权限,不返回任何数据 |
| E2 | 历史脏数据 | 早期记录的操作人为空(实采存在) | 显示「未记录」,不显示空白,也不当成加载失败 |
| E3 | 大跨度查询 | 不设时间范围查询全量 | 按 A3 超时中断并提示缩小范围,不返回半截数据 |
| E4 | 负数被误读 | 扣款记录显示为负金额 | 明确标注方向与负号,并在列说明中写清这是扣款不是异常 |
| E5 | 记录与流水对不上 | 人工调整记录存在但账变流水缺失 | 由周期对账捕获并告警(见资金模型 R15),本页如实展示不做掩盖 |

## 10. 状态清单

| 状态 | 表现 |
|---|---|
