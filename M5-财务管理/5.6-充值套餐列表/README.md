# 5.6 · 充值套餐列表

## 1. 背景与目标

**目标**:控制玩家在每一种支付方式下看到哪些充值档位,让不同通道能上不同的价格组合。

**谁在用**

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 给不同支付方式配不同档位组合 | 所有通道只能共用一套档位,没法按通道做差异化定价 |
| 财务 | 核对高费率通道是否配了对应的档位 | 高费率通道上了低价档,每单都在亏手续费 |

**业务价值**:支付方式的费率、限额、到账速度各不相同,档位组合也应该不同。
这一页是「哪个通道卖什么」的唯一控制点。

**不做什么**
- 不配置商品本身的价格与赠送(那是 5.5 的事,本页只做绑定)
- 不配置支付方式的费率与限额(那是通道管理的事)
- 不做玩家端收银台的排版

**适用范围**

| 维度 | 取值 |
|---|---|
| 终端 | 桌面后台,最小宽度 1440 |
| 响应式 | 否 |
| 界面语言 | 简体中文 |
| 时区 | 运营时区,页面顶部标注 |
| 货币 | 多币种共存,金额必须带币种标识 |

## 7. 需求详述

### 5.6-R2

**触发条件**:点击创建套餐 · 点击某行编辑 · 在弹窗内提交。

**可输入数据**:套餐名称(必填)· 所属支付方式(必填,只列启用中的)· 商品模板(必填,须存在)·
类型 · 状态。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 必填校验、支付方式与模板的下拉只列有效项 |
| 服务端 | 权限判定、唯一性校验、引用有效性校验、保存与留痕 |

**处理逻辑**

1. 判权限;无权限不展示入口,服务端二次判定
2. 校验必填项;套餐名称在同一运营商下不得重名
3. 校验引用的商品模板存在且其下至少有一个已上架商品 ——
   绑了空模板等于玩家打开收银台看到空列表
4. 校验同一支付方式下**不存在第二个生效套餐**(见 A1);冲突则拒绝并指出冲突方
5. 保存后立即生效;**不回溯影响在途与历史订单**
6. 记录操作人、时间与改动前后值

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无配置权限 | 提示无权限 |
| 必填项未填 | 定位到具体字段并提示 |
| 套餐名称重复 | 该名称已存在,请换一个 |
| 引用的商品模板不存在或已删除 | 该商品模板不可用,请重新选择 |
| 模板下没有已上架商品 | 该模板下没有已上架商品,玩家将看到空列表 |
| 同一支付方式已有生效套餐 | 该支付方式已绑定套餐 X,请先停用它 |
| 并发编辑 | 提示已被他人修改,请刷新后重试,不静默覆盖 |

**测试案例**

- 正向:为某支付方式创建套餐并绑定一个含 3 个上架商品的模板 → 玩家在该支付方式下看到 3 个档位
- 正向:编辑套餐换绑另一个模板 → 新订单按新模板,**在途与历史订单不受影响**
- 逆向:为已有生效套餐的支付方式再建一个生效套餐 → 拒绝并指出冲突方
- 逆向:绑定空模板或已删除的模板 → 拒绝
- 逆向:套餐重名 → 拒绝;两人同时编辑 → 后者被提示刷新

### 5.6-R4

**触发条件**:点击某行删除并通过二次确认。

**可输入数据**:被删除的套餐(单条)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 二次确认,确认前显示该套餐当前是否启用 |
| 服务端 | 在途订单检查、删除与留痕 |

**处理逻辑**

1. 判权限
2. 检查是否存在通过该套餐产生的未终态订单;存在则拒绝
3. 删除并留痕;**历史订单保留当时的套餐与商品信息**,不因删除而丢失溯源
4. 若该套餐处于启用状态,须先停用再删除,避免玩家端瞬间无可用档位

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 无配置权限 | 提示无权限 |
| 存在在途订单 | 该套餐还有未完成订单,暂不可删除 |
| 套餐仍处于启用状态 | 请先停用该套餐再删除 |
| 重复提交删除 | 只生效一次 |

**测试案例**

- 正向:停用后删除一个无在途订单的套餐 → 删除成功,历史订单仍可溯源到当时的档位
- 逆向:直接删除启用中的套餐 → 拒绝,要求先停用
- 逆向:删除有在途订单的套餐 → 拒绝
- 逆向:连点两次删除 → 只生效一次

## 8. 数据流向与系统串接

**数据流向**:运营创建套餐并绑定支付方式与商品模板 → 服务端校验唯一性与引用有效性后保存 →
玩家端打开收银台时按当前支付方式取对应套餐 → 展示该模板下的已上架商品 →
玩家选档下单,后续由 5.2 充值订单承接。

**系统串接**:**与通道管理有接缝,无第三方直连**。支付方式由通道管理维护(见模块索引 5.11),
本页只引用其标识与启停状态。责任边界:支付方式是否可用由通道侧决定,
本页在支付方式被停用时不得继续对外提供该套餐。

## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权配置 | 无配置权限账号提交 | 拒绝并提示;服务端二次判定 |
| E2 | 重复绑定 | 同一支付方式被绑定两个生效套餐 | 拒绝并指出冲突方(见 A1) |
| E3 | 引用已删除的模板 | 模板被删除但套餐仍指向它 | 保存时拒绝;已存在的脏数据在玩家端按空列表处理并告警 |
| E4 | 停用后玩家端已打开收银台 | 玩家页面停留期间套餐被停用 | 下单时二次校验,已停用则拒绝并提示刷新,不按打开时的状态放行 |
| E5 | 支付方式被停用 | 通道侧停用了该支付方式 | 该套餐不再对外提供,列表中显式标注支付方式已停用 |
| E6 | 删除仍有在途订单的套餐 | 存在未终态订单 | 拒绝删除 |

## 10. 状态清单

| 状态 | 表现 |
|---|---|
| 错误 | 弹窗内字段级提示,弹窗不关闭,已填内容保留 |
| 支付方式已停用 | 特有态:套餐本身仍启用但支付方式已停用,列表须显式标注,避免误判为可用 |
| 已停用 | 列表中仍可见并标注,不从列表消失 |

**前后端职责**

| 事项 | 归属 |
|---|---|
| 权限判定 | **服务端**,按角色的权限节点判定 |
| 可见范围过滤 | **服务端**,按账号绑定的推广商过滤,列表、汇总与导出一律先过滤再返回(见 `../README.md` 第 6 段) |

| 下单时的套餐与支付方式二次校验 | **服务端** |
| 表单交互与即时提示 | 界面 |
| 二次确认与操作留痕 | 界面 + 服务端双重校验 |
