# 5.6 · 充值套餐列表

<a id="1-背景与目标"></a>

## 1. 用途

把支付方式与商品模板绑定成套餐,为按通道配置价格组合保存依据。

本版玩家端尚未按套餐取数:玩家看到的是所属运营商下全部已上架商品,套餐的绑定与启停不改变玩家端展示和下单。

### 使用者

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 给不同支付方式配置档位组合 | 没有记录哪个通道对应哪组档位的依据 |
| 财务 | 核对高费率通道是否配了对应的档位 | 高费率通道上了低价档,每单都在亏手续费 |

支付方式的费率、限额、到账速度各不相同,档位组合也应该不同。
这一页是「哪个通道绑定哪组档位」的唯一维护点。

### 本次范围
- 不配置商品价格、赠送方案或充值通用倍数（由 5.5 统一维护），本页只绑定支付方式与商品模板；切换套餐或渠道不重置同一赠送方案的账号次数
- 不配置支付方式的费率与限额(那是通道管理的事)
- 不做玩家端收银台的排版
- 不提供删除套餐,不再使用的套餐停用即可;支付方式没有后台维护入口,本页只能选择已存在且启用的支付方式

### 适用范围

| 维度 | 取值 |
|---|---|
| 终端 | Web 后台,桌面优先(设计基准 1440px) |
| 响应式 | 版面按窗口宽度自适应,不做移动端专门适配 |
| 界面语言 | 简体中文 |
| 时区 | 列表没有时间字段;页面副标题显示顶栏所选时区,默认为浏览器时区 |
| 货币 | 多币种共存,金额必须带币种标识 |

## 3. 操作规则

### 套餐停用后玩家端的生效延迟(A3)

玩家端不读取套餐,停用不影响玩家端展示。

一个支付方式只绑定一个生效套餐,一个套餐只引用一个商品模板,按A1与A2校验。

### 创建与编辑套餐(5.6-R2)

点击创建套餐 · 点击某行编辑 · 在弹窗内提交。

输入信息：套餐名称(必填)· 所属支付方式(必填,只列启用中的,选项带运营商名称)· 商品模板(必填,只列与支付方式同运营商且含已上架商品的模板,选项带已上架数量)·
类型 · 状态。

1. 服务端判权限,无权限时拒绝
2. 校验必填项;套餐名称在同一运营商下不得重名
3. 校验支付方式存在且启用,商品模板存在且其下至少有一个已上架商品,两者属于同一运营商
4. 校验同一支付方式下**不存在第二个生效套餐**(见 A1);冲突则拒绝并指出冲突方
5. 保存后立即写入;**不影响在途与历史订单**
6. 记录操作人、时间与改动前后值

启停没有独立开关,在编辑弹窗切换「套餐状态」并保存,校验与创建相同。

### 删除套餐(5.6-R4)

本版不提供删除入口,不再使用的套餐在编辑中停用。

## 4. 特殊情况

### 边界处理

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权配置 | 无配置权限账号提交 | 拒绝并提示;服务端二次判定 |
| E2 | 重复绑定 | 同一支付方式被绑定两个生效套餐 | 拒绝并指出冲突方(见 A1) |
| E3 | 模板下商品全部下架 | 编辑保存时模板已无上架商品 | 保存时拒绝;未编辑的套餐保持原绑定 |
| E4 | 玩家下单 | 玩家选择商品下单 | 下单只校验商品和运营商,不读取套餐,套餐停用不影响下单 |
| E5 | 支付方式被停用 | 通道侧停用了该支付方式 | 列表中显式标注支付方式已停用;该套餐再次编辑时须改绑启用中的支付方式,否则保存被拒绝 |
| E6 | 删除套餐 | 运营需要下线套餐 | 不提供删除,改为停用 |

### 创建与编辑套餐遇到异常时(5.6-R2)

| 错误状况 | 提示 |
|---|---|
| 无配置权限 | 提示无权限 |
| 必填项未填 | 定位到具体字段并提示 |
| 套餐名称重复 | 该名称已存在,请换一个 |
| 支付方式不存在或已停用 | 支付方式不存在或已停用 |
| 引用的商品模板不存在 | 该商品模板不可用,请重新选择 |
| 模板下没有已上架商品 | 该模板下没有已上架商品,玩家将看到空列表 |
| 支付方式与模板运营商不同 | 支付方式与商品模板不属于同一运营商 |
| 同一支付方式已有生效套餐 | 该支付方式已绑定套餐 X,请先停用它 |
| 并发编辑 | 套餐已被其他人修改,请刷新后重试,不静默覆盖 |

### 页面状态

| 状态 | 表现 |
|---|---|
| 错误 | 弹窗内字段级提示,弹窗不关闭,已填内容保留 |
| 支付方式已停用 | 特有态:套餐本身仍启用但支付方式已停用,列表显示红色标记,避免误判为可用 |
| 已停用 | 列表中仍可见并标注,不从列表消失 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 5.6-R1 | 套餐列表与筛选：进入页面 · 点查询 | 两项筛选可组合;状态可见 |
| 5.6-R2 | 创建与编辑套餐：点创建套餐 · 点编辑 | 必填校验生效;同一支付方式不得出现两个生效套餐;模板须存在、含已上架商品且与支付方式同运营商 |
| 5.6-R3 | 启用与停用：在编辑弹窗切换套餐状态并保存 | 列表状态更新并留痕;启用时校验同支付方式无其他生效套餐;玩家端展示和在途订单不受影响 |
| 5.6-R4 | 删除套餐：当前不提供 | 列表无删除操作;不再使用的套餐可停用,记录保留 |

### 创建与编辑套餐(5.6-R2)

- 正向:为某支付方式创建套餐并绑定一个含 3 个上架商品的模板 → 保存成功,列表显示绑定关系
- 正向:编辑套餐换绑另一个模板 → 保存成功并留痕,**在途与历史订单不受影响**
- 逆向:为已有生效套餐的支付方式再建一个生效套餐 → 拒绝并指出冲突方
- 逆向:绑定无上架商品的模板 → 拒绝
- 逆向:支付方式与模板属于不同运营商 → 拒绝
- 逆向:套餐重名 → 拒绝;两人同时编辑 → 后者被提示刷新

## 6. 相关资料

### 入口与关联页面

- 菜单:财务管理 → 充值管理 → 充值套餐列表
- 本页无页面跳转;商品模板下的商品在 5.5 充值商品与赠送维护

### 权限

| 操作 | 权限或执行方 |
|---|---|
| 套餐列表与筛选(5.6-R1) | `finance:combo` |
| 创建与编辑套餐(5.6-R2) | 创建 `finance:combo:create` · 编辑 `finance:combo:edit` |
| 启用与停用(5.6-R3) | `finance:combo:edit` |
| 删除套餐(5.6-R4) | 当前不提供,无对应权限 |

> **权限**:本页权限码对应角色配置里的权限树节点(模块 → 分组 → 页面 → 操作),
> 完整映射与「已有 / 需新增」见 `../README.md` 第 6 段。
> 勾中任一操作节点必须同时持有其页面节点,判定一律在服务端做。

### 术语与共用口径

> 套餐、商品模板的定义见 `../README.md` 第 2 段,此处不重复。

| 术语 | 定义 |
|---|---|
| 所属支付方式 | 该套餐生效于哪一种支付方式 |
| 类型 | 套餐的分类维度。候选为「默认」及已有套餐使用过的类型,不区分运营商 |

### 依赖与数据流

**数据流向**:运营创建套餐并绑定支付方式与商品模板 → 服务端校验唯一性与引用有效性后保存。
玩家端不读取套餐:商品按玩家所属运营商取已上架商品(5.5),下单不校验套餐与支付方式,后续由 5.2 充值订单承接。

**系统串接**:**与通道能力衔接,无第三方直连**。支付方式由通道能力维护,
本页只引用其标识与启停状态。责任边界:支付方式是否可用由通道侧决定,
本页在支付方式被停用时只做列表标注。

### 数据归属与职责

**数据归属**

- 拥有(owner=M5):充值套餐
- 只读:商品模板(owner=M5,由 5.5 写入)· 支付方式(owner=通道能力,本页引用其标识和启停状态)

**前后端职责**

| 事项 | 归属 |
|---|---|
| 权限判定 | **服务端**,按角色的权限节点判定 |
| 可见范围过滤 | **服务端**,按账号绑定的推广商过滤,列表、汇总与导出一律先过滤再返回(见 `../README.md` 第 6 段) |
| 唯一性、引用有效性、并发控制 | **服务端** |
| 表单交互与即时提示 | 界面 |
| 操作留痕 | **服务端** |

### 创建与编辑套餐的职责(5.6-R2)

| 归属 | 做什么 |
|---|---|
| 界面 | 必填校验、支付方式与模板的下拉只列有效项 |
| 服务端 | 权限判定、唯一性校验、引用有效性校验、保存与留痕 |
