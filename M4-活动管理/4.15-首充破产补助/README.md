# 4.15 · 首充破产补助

## 1. 活动介绍

符合活动人群的玩家完成首次真实充值后,游戏净亏损达到首充金额的设定比例,获得一个补助宝箱。玩家可以按配置直接领取基础彩金,或从宝箱入口再次充值后手动领取翻倍彩金。每个运营商内每个账号最多获得一个宝箱、成功领取一次。

活动帮助运营配置首充后的亏损补助,客服可以查明首充、亏损、宝箱、关联充值和最终发奖依据。“破产”指达到活动亏损门槛,不要求钱包余额为零。

### 范围

- 提供不翻倍、固定充值翻倍、随机充值翻倍三种模式,一次只能启用一种。基础奖金支持比例区间,上下限相等为固定比例。
- 用户标签控制参与人群,渠道定向通过标签表达。本活动独立于 M5 的限次充值赠送,不把“第1次比例奖励”视为真实首充。
- 普通领取与翻倍领取二选一;开箱、达到亏损条件或充值成功都不代替玩家手动领取宝箱彩金。
- 后台配置、活动内部记录与玩家领取规则一并交付。单钱包、账变、打码和提现约束复用资金模型。
- 不提供每日重置、反复补助、已领基础奖后充值补差或玩家取消已入账奖励的入口。

后台采用桌面运营页面,最低宽度1280px,界面为简体中文,玩家提示按运营语言展示。时间保存统一时间点,界面注明运营时区。参与币种由运营选择,每份参与记录的亏损、奖励和关联充值均使用原首充币种,不在本活动换币。

## 2. 运营配置

### 配置字段

| 编号 | 配置项 | 填写与执行规则 |
|---|---|---|
| A1 | 名称与开关 | 每运营商一套活动,名称1–40字符;新活动默认关闭,先保存草稿、发布再开启 |
| A2 | 参与人群 | 全部用户 / 指定用户标签,默认全部用户;指定时至少一个当前运营商启用标签,满足任意一个即符合;需组合条件时在标签规则内定义 |
| A3 | 参与币种 | 平台已开通的充值币种,至少选择一个,无默认;翻倍金额按每个所选币种分别配置 |
| A4 | 亏损观察期 | 不限 / 首充后N天,默认不限;限时N为正整数、必填,一天按连续24小时计算,不是自然日 |

| A8 | 不充值可领取基础奖 | 是/否,默认是;不翻倍模式必须为是;为否时必须有完整可用的翻倍充值配置 |
| A9 | 固定翻倍档位 | 每行币种、最低单笔充值金额、奖励总额倍数;金额>0且符合币种精度,倍数≥1、最多两位小数;同币种门槛不得重复,高金额档倍数不得降低 |
| A10 | 随机翻倍配置 | 每币种最低单笔充值金额>0;随机奖励倍数下限/上限满足1≤下限≤上限≤5,最多两位小数;按0.01倍步长等概率抽取一次 |
| A11 | 普通彩金打码倍数 | 允许普通领取时必填,正数、最多两位小数,无默认;不允许普通领取时不执行此项 |
| A12 | 翻倍彩金打码倍数 | 固定/随机翻倍时必填,正数、最多两位小数,无默认;应用于最终全部翻倍彩金 |

| A14 | 充值本金打码倍数X | 只读显示M5运营商通用值,不能在本活动覆写;关联充值订单锁定当时X |

金额与计算精度引用资金模型。比例、倍数及乘积超出平台资金可支持范围时拒绝发布,不得截断数值。固定与随机翻倍配置只校验并执行当前模式,切换后的隐藏字段不得残留限制。每个参与币种必须有该模式的完整充值条件,否则拒绝发布。

### 草稿、发布与启停

草稿可不完整,已填值必须合法。发布校验全部当前模式字段、参与币种和标签有效性,核对确认后生成配置版本;并发修改拒绝覆盖。普通无领取路径、倍数缺失或随机区间非法都不能发布。

活动首次发布不自动开启。首充成功时锁定当时已生效版本和参与依据;后续发布仅影响新参与。关闭停止新参与,已经进入观察、已经产生宝箱或已关联订单继续按原配置和期限履约。重新开启不清除历史参与与已领取结果。配置操作及启停记录操作人、时间和变更前后值。

### 玩家可见信息

开箱前后应展示基础彩金、能否普通领取、翻倍所需充值金额、翻倍后的总彩金和两类彩金各自的打码要求。选择充值前展示该单本金X及该笔充值不再获得商品固定/比例赠送的说明。随机倍数在付款前展示已锁定的实际值,不能只展示可能的最大值。

首次出现宝箱时提示一次,用户关闭后保留活动入口和未领取标记;同一会话不反复强制弹窗。开箱或刷新不改变奖励。金额展示使用真实可领值,未领取金额不计入钱包余额。

## 3. 参与和领奖规则

### A15 · 真实首充与人群认定

M5提供当前运营商内第一笔真实成功充值单。人工加款、无真实支付的人工生成订单、赠金和失败订单不构成首充;真实Crypto入金可以构成首充。并发首笔顺序由财务提供,不能以消息到达顺序各算一次。

记首充有效实付金额为P、成功时间为T0。P不包含商品或其他活动彩金,也不以商品面值、通道扣费后的商户净收入替代。P须大于0且币种在活动范围内。

首充成功时活动开启、人群符合、币种可用且基础奖金可产生至少一个最小币种单位,才建立一次参与记录。记录首充单、P、币种、T0、活动版本、标签条件及当时命中依据。指定标签按T0的有效规则和事实判断;数据迟到按原时点恢复,无法可靠判断时记录核查原因,不按后续标签状态随意补资格。

标签后来摘除、正常配置修改不撤销已取得的参与权;账户封禁、资金限制仍在实际操作时校验。首充时不符合的用户不因后来换标签、换币种、再次充值或活动重启而取得另一份首充机会。后续充值不提高P,不重开观察期,也不因第二次充值自动终止原观察。

### A16 · 亏损计算与宝箱触发

观察期开始包含T0;限时模式结束为T0＋N×24小时且不包含结束时刻。不限模式持续观察到首次达标。只统计T0以后受理,且在观察期内最终结算的同币种投注。

**游戏净亏损L＝max(累计最终结算投注金额－这些投注的累计总派彩金额,0)。** 充值与彩金出资的游戏输赢均计入。总派彩包含游戏实际返还的本金部分,不能只取净利润;不按游戏有效投注折算系数加权。未结算、取消、作废不计,退款或冲正使用修正后的事实。提现、人工扣款、赠金和充值均不当作游戏盈亏。

按可信结算业务时间及稳定顺序累计,首次L≥P×A5比例时触发一个宝箱。门槛计算保留高精度,不提前向下取整放宽条件。观察期结束仍未达标则结束参与,不在下一次充值重新开始。迟到结算按原业务时间恢复,不能把截止后的新投注算入,也不能只读当前余额替代历史触发依据。

正常后续赢钱不撤销已经合法形成的宝箱;原结算撤单、首充退款等事实修正另按特殊情况处理。生成或恢复同一个宝箱不增加参与次数。宝箱首次可展示时间独立记录,领取期限从该时间开始,刷新和技术重试不重置期限。

### A17 · 基础彩金和随机结果锁定

固定比例（上下限相等）:B＝P×比例/100,向下保留币种精度。

比例区间:先将P×下限/100与P×上限/100分别向下保留币种精度,下端不低于一个最小币种单位;在该金额区间内按最小单位等概率抽取B。固定结果不足一个最小单位或区间不能产生正金额时不建立参与,记录“首充金额不足以生成奖励”,不向用户展示零额宝箱。

B在首次形成宝箱时只生成一次并保存;同时保存比例区间、金额上下限、版本与依据。随机翻倍模式同步按A10抽取M,固定比例或随机基础奖均不能通过刷新、重开、取消未支付订单或领取重试重新抽取。

固定翻倍模式由关联订单金额命中档位得到M;随机翻倍模式使用宝箱已锁定M。最终翻倍彩金C＝B×M,向下保留币种精度。这里M是总额倍数,领取金额为C,不再额外发B。

### A18 · 普通领取

玩家在领取期限内点击普通领取,服务端校验资格归属、模式、账户限制、是否已有翻倍支付占用及原领取结果。允许不充值领取时,一次发放B彩金,同时建立B×普通彩金倍数的独立任务。

同一宝箱只能受理一条最终领取路径。普通领取成功后结束,后来充值不补差、不再领翻倍。打开宝箱、登录或后台恢复不能代替玩家首次领取。

### A19 · 选择翻倍与关联充值

1. 玩家在领取期限内选择翻倍,从活动入口选择当前币种的充值商品。关联充值必须为同币种单笔真实支付,不累计多笔凑门槛。
2. 固定模式按该订单应付金额取最高满足门槛的一档;随机模式须满足对应币种最低金额。下单前显示B、已选M、最终C、对应彩金倍数和充值X,并保存宝箱、配置版本、应付金额和条件。
3. 本单的赠送用途锁定为“首充破产补助翻倍”。排除该单M5商品固定彩金和限次比例彩金,不占用或消耗限次比例机会。原首充已发的奖励保留,不事后回收;其他订单及VIP、签到继续按自身规则执行。
4. 不能把普通充值完成后再追认为翻倍单。创建关联订单即占用宝箱,同一宝箱最多存在一笔待支付、支付中或支付结果未知的关联订单,期间普通领取和创建第二笔关联订单不可用。
5. 已确认未支付且不可继续支付的终态订单可解除占用;仍在领取期限内时可重新选普通/翻倍,随机结果不变。关闭页面、支付超时或网络错误不能直接视为未支付。
6. 支付成功须核验真实支付事实及金额币种与订单一致。本金按M5订单快照到账并建立充值金额×X的任务;活动保存翻倍条件已满足,不自动入宝箱彩金。金额不一致由财务核查,不偷偷降档、升档或改发商品赠送。
7. 创建关联订单时即锁定其支付有效期,以真实业务支付时间判断。领取期限内合法创建且在该订单支付有效期内实际付款的,即使成功通知在有效期后到达也按原规则履约;实际付款超出订单支付有效期的异常收款进入财务核查,不得静默吞款或自动发奖。
8. 一旦关联充值确认成功,保留一次手动领取C的权益,不再用原宝箱选择截止时间使其过期,不可改领基础奖。界面明确显示“充值成功,翻倍彩金待领取”;用户手动领取后才入彩金并建任务。

本活动免除的是该单商品赠送,不是充值本金打码。无商品绑定的自由Crypto入金不能事后作为翻倍订单;如使用Crypto支付商品,仍须在建单时已有可靠的商品、宝箱和支付订单关联。

### A20 · 领取、打码与异常恢复

普通奖B或翻倍奖C均计彩金来源,不增加真实充值金额和充值次数。彩金入账、独立打码任务及成功领取记录必须一致完成;未领取资格不建任务。相同宝箱的并发点击或不同请求编号也只能发一份奖。

领取请求被受理时锁定金额、倍数及路径。失败或结果未知查询并恢复原请求,不另建奖励、不重新抽取、不释放给另一领取路径重复处理。受理后跨截止时间仍完成原申请;只有未受理领奖、无合法在途订单且无已支付翻倍权益的限时资格,才在到期后结束。

充值X与普通/翻倍彩金倍数相互独立。首充、原赠金及后续充值的旧任务照常存在,亏损、钱包归零或补助不清除旧任务。已入账彩金不因活动关闭或长期不投注作废,提现继续按该币种全部任务及资金限制判定。

### 计算示例

示例P＝100 USDT,亏损门槛50%,基础比例固定20%,得到B＝20。玩家净亏损达到50时触发;普通彩金倍数3,充值50可取M＝2,翻倍彩金倍数5,充值X＝2。

| 路径 | 本次新增充值到账 | 本次彩金 | 本次新增充值任务 | 本次新增彩金任务 |
|---|---:|---:|---:|---:|
| 普通领取 | 0 | 20 | 0 | 60 |
| 充值50后手动领翻倍 | 50 | 40 | 100 | 200 |

两条路径只能完成一条;翻倍总奖为40而非60,该充值订单不再送商品固定/比例彩金。表中不包含此前尚未完成的任务,示例金额和比例不是默认配置。

## 4. 特殊情况

| 编号 | 情况 | 处理结果 |

| E1 | 不符合首充/标签/币种条件 | 不参与并记录依据,不能用后来的状态改认第二笔为首充 |
| E2 | 观察期限到达 | 未触发参与结束;业务时点在窗口内的迟到事实按原窗口恢复,不能读取现在的盈亏重判 |
| E3 | 有限领取期限到达 | 无已受理领奖、无合法在途订单且无已支付翻倍权益的宝箱结束;已受理请求和合法关联订单继续处理;已支付翻倍资格保留 |
| E4 | 选择普通与翻倍的并发请求 | 同一宝箱只占用一条路径,另一请求返回当前状态;不能两边发钱 |
| E5 | 支付失败、超时、迟到回调 | 明确未付款终态才能释放;未知结果保留占用;有效支付及补单沿用原快照,不重复本金或宝箱权益 |
| E6 | 活动发布或关闭 | 只改变新首充参与,原参与的规则、观察期、宝箱、订单及任务保持原依据 |
| E7 | 标签计算迟到或后来摘除 | 初始判断按T0恢复;参与后普通标签变化不撤权,实时账户资金限制仍执行 |
| E8 | 投注撤单修正使原触发无效 | 未受理领奖且无在途/已支付关联单的宝箱,回到观察中（窗口尚未结束）或结束（窗口已结束）,保留原随机结果及首次生成时间;再达标恢复同一宝箱不重抽、不延长原领取期限。有待支付、支付中或结果未知的关联单时,先转异常核查并保持占用,确认未支付且已不可支付后再按修正事实处理。已关联收款、已受理领奖或已入账转资金异常核查,不静默扣钱 |
| E9 | 原首充发生已确认退款/拒付 | 未触发参与,以及未受理领奖且无在途/已支付关联单的宝箱结束,不改认新首充;有在途关联单时先转异常核查并保持占用,确认未支付且已不可支付后才结束。已经收款的翻倍单或已受理/入账奖励走资金异常核查,不由活动直接回收彩金 |
| E10 | 本金或本次彩金倍数缺失 | 拦截对应入账并保留恢复依据,不得按0或当前新配置兜底;本金已到账而待领补助异常时不重做本金 |
| E11 | 币种停用或平台资金服务不可用 | 暂停不能执行的领取,显示原因;平台原因导致的暂停时间不计未受理宝箱领取期限,恢复后接续剩余时间;已有订单按资金规则处理 |
| E12 | 玩家封禁/资金限制 | 暂停新充值选择或领奖,保留依据,不代领;解除后仍在资格范围内可继续,个体限制不自动延长期限 |
| E13 | 资格金额过小或计算越界 | 不发零额宝箱、不截断越界金额,记录原因;不可改用固定商品赠金伪装补助成功 |
| E14 | 查询空、加载失败、无权限 | 无记录显示空状态,查询失败可重试且保留筛选;无查看权限不返回数据;保存/领取中阻止重复动作 |

异常核查展示涉及的充值或投注修正、宝箱/订单状态和已有资金结果。已收款或已入账事项由有权限的财务按原账变核查及受控修正流程处理,本活动记录页只读,不提供任意改奖、重置机会或直接扣款按钮。

## 6. 相关资料

### 入口与权限

功能归属：活动管理 → 活动配置 → 充值活动配置 → 首充破产补助。配置和活动记录在同一页面,玩家入口来自首次触发提示及活动入口。既有“账号首充”仍归M5/5.5,不复用其名称或每日次数。

| 操作 | 权限码 |
|---|---|
| 查看配置、版本及活动内部记录 | `activity:first-deposit-relief:view` |
| 保存配置草稿 | `activity:first-deposit-relief:edit` |
| 核对并发布版本 | `activity:first-deposit-relief:publish` |
| 开启/关闭新参与 | `activity:first-deposit-relief:switch` |

修改权限须同时具备查看权限。服务端验证账号角色、运营商及推广商数据范围,不能只依赖前端隐藏按钮。

### 活动内部记录

筛选包括用户ID、首充单号、关联充值单号、币种、活动版本、参与/触发/领取时间及业务状态。状态包括观察中、待选择、翻倍待支付、翻倍可领取、领取处理中、已领取、已结束和异常核查。

详情保留：首充P/T0和币种、标签命中依据、观察起止、亏损金额与原结算引用、触发时间、宝箱首次可展示时间与领取截止、基础比例/金额区间与B、随机M或档位、关联订单及互斥用途、领取路径、实际彩金及倍数、充值X、账变/任务引用、异常和恢复结果。截止字段在不限时显示“不限”,不得显示为0。记录只读,不能改随机结果、复活已结束机会或重发奖励。

### 共用规则与责任

- M4拥有活动版本、人群判定、参与/宝箱、随机结果、订单关联意图及领取依据;只读消费支付与游戏事实,不直接改余额。
- M5提供真实首充、关联支付、退款/拒付、入账与资金结果。[5.5充值商品与赠送](../../M5-财务管理/5.5-充值商品配置/README.md)维护X和普通商品赠送,[5.2充值订单](../../M5-财务管理/5.2-充值订单查询/README.md)保存受理时的专用用途与互斥快照。财务账务服务只消费快照,不反向查询活动配置重算。
- 玩法提供投注受理、最终结算、总派彩、取消及修正事实;M2提供账号、标签及历史命中依据,渠道复用标签条件。
- [资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)定义单钱包、独立任务、彩金不作废、有效投注核销和提现限制;本活动不另建资金语义。[权限模型](../../M6-账号管理/6.2-角色列表/权限模型.md)维护功能权限和账号数据范围。
- 与M5充值合并的实现衔接参考[KAN-248](https://bingobox.atlassian.net/browse/KAN-248);该票链接用于说明既有依赖,不代表本活动已纳入其交付。
