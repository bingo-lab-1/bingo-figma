# 活动简化评审

本文件评估现有九类活动是否简单、合理，给出具体改版建议及代价。它是设计评审，现行实施与验收依据仍是各活动 PRD；这里的建议不表示已修改线上行为，也不表示收益和成本保持不变。

评审依据是当前仓库正文、模块决策和用户对玩法的明确要求。没有实际使用率、领取率和成本数据，因此以下结论是设计判断，不声称某个简化方案已经证明能提高转化或降低总支出。

## 评审方法

每个活动经过三轮检查：先用一句话确定目标，再尝试删除配置与步骤，最后用用户行为和异常案例反驳简化方案。保留能解释目标、成本或用户权益的复杂度，删除缺少独立用途的组合。

检查以下六件事：

1. 用户能否说清为什么参加、需要做什么、能得到什么。
2. 每项运营配置是否真的提供独立决策；固定规则不做无效选择器。
3. 是否把开放人群、玩法条件和领奖条件混在一起。
4. 是否因为先领奖、等级变化或技术延迟，使同样达标的用户得到难以解释的不同结果。
5. 配置变化、关闭、漏领和再次参与是否产生大量特例。
6. 简化会失去什么能力，是否撤回用户明确提出的要求，是否改变成本。

发奖去重、资金结果查询、权限、原有权益、币种和打码准确性始终保留。文档变短不能作为删除这些要求的理由。

## 总体结论

| 活动 | 判断 | 推荐方向 |
|---|---|---|
| 注册送好礼 | 核心已经简洁 | 保留注册自动发固定奖励，减少重复的投注限制说明和后台操作 |
| 兑换码 | 随机拆预算和反复领取使其明显复杂 | 新码改为固定金额、每人每码一次，保留一码多人领取 |
| 红包雨 | 定时领取明确，奖励计算层数过多 | 保留场次、充值资格、VIP基础金额，删除多重加成 |
| 刮刮乐 | 取得卡后还有多重使用限制 | 控量前移到发卡，已取得的有效卡可直接刮 |
| VIP签到 | 超出按等级每日福利的核心目标 | 删除30日矩阵、补签和连续节点，保留按等级日奖及当天补差 |
| 常规七日签到 | 三个漏领选项实际上是三种玩法 | 最简替代方案为固定七个自然日、漏领跳过；明确列出与原要求的冲突 |
| 每日签到 | 核心已经较简洁 | 保留单档、达标推进、补领和连续奖，主要优化填写与说明 |
| VIP配置 | 等级基础、周期福利和复充促销耦合 | 分清职责，保留成长及保级机制，减少奖励的二次门槛 |
| 代理返佣 | 核心机制清楚，操作可以减少 | 保留直属、终身判档及每日增量，删除无效模式选项，统一领取全部 |

## 1. 注册送好礼

依据：[4.8 注册送好礼](4.8-注册送好礼/README.md)。

**目标：注册成功后，让新用户获得一笔清楚、可查询的固定奖励。**

注册自动发、每玩家一次、固定金额和统一倍数已经构成简单完整的玩法。当前篇幅较长，主要因为反复解释平台注册前后投注资格和资金处理，而非活动本身需要这么多玩法。

推荐保留名称、币种、奖励金额、打码倍数和活动开关。平台投注模式在本页只读展示，给用户直接解释“已到账是否可用于游戏”；详细判断在平台规则维护一份。发布预览自动展示奖金和所需流水，不再要求运营自行核算。

后台可以在首次发布确认中同时展示是否开启，合并一次操作；仍分别校验发布和启停权限。缺少启停权限的账号只能发布，不能借合并按钮获得额外权限。草稿与生效配置继续分开。

**反例检查：**删除充值限制会改变整个平台的投注政策，不能作为注册活动的简化；改为先充值再发奖，则不再是注册赠金。两项都不推荐。活动重新开启和重复注册通知也不能产生第二份奖励。

**代价与判断：**主要是交互及文档调整，不需要改变奖金机制。若希望活动承担“免费体验游戏”的目标，平台投注模式必须与这个目标一致；仅改变活动宣传不能解决到账后仍无法使用的问题。

## 2. 兑换码

依据：[4.1 兑换码管理](4.1-兑换码管理/README.md)、[新增兑换码](4.1-兑换码管理/新增兑换码.md)。

**目标：运营发出一个凭证，符合条件的用户输入后领取奖励。**

目前同时配置随机上下限、总预算、总次数和单人次数，并要求随机分配最终精确用完预算。最复杂的是拆预算，而非兑换动作。

推荐新码使用以下玩法：

- 每个码一个固定奖励金额、领取人数上限、有效期、人群和打码倍数。
- 每个用户对同一码领取一次；一个码仍可供多人领取。
- 最大支出由固定金额乘人数自动计算，批量生成再展示所有码的合计。
- 创建后冻结，停用阻止新兑换，历史和已受理奖励保持可查。

**反例检查：**每人每码一次不等于一个码只能使用一次，也不等于一批码只能领一次。多个不同码仍是独立奖励。固定奖励也不能取消原币、标准计价与汇率的区别。

**代价：**取消公共码随机发红包、同一用户重复兑换同一码的能力，改变现有 D37、D86 的设计。原配置可用“上下限相等、单人次数为1”先表达这种玩法，但正式删除其他能力后才能减少维护分支。旧码继续按原约定结束，不追改已经发出的奖励承诺。

**判断：**推荐简化，但它是玩法调整；若实际运营需要同一码反复发随机奖励，就应把随机预算视为该活动的核心能力，不能伪装成可无损删除的字段。

## 3. 红包雨

依据：[4.2 红包雨](4.2-红包雨/README.md)。

**目标：让当天已经充值的用户在指定时段回来领取随机奖励。**

当前奖金依次经过VIP区间、标签组优先级、充值加成和亏损加成，再取较大系数。人群既用于准入，又用于选择另一套奖金算法，运营很难直观看出最终结果。

推荐保留场次、当天成功充值资格、每场一次、每日总领取次数、VIP基础奖金区间及打码倍数。奖金直接从VIP对应区间产生，删除充值加成、亏损加成和标签专用加成表。

后台用增删时段行管理场次，场次数自动得出；不再因为修改一个“场次数”字段而清空整张时段表。

**反例检查：**每日总次数值得保留。例如开放八场但每天最多领两次，可以兼顾时间选择与成本控制；只保留每场一次会让用户最多领取八次。VIP分档也可以保留，它的差异直接可解释，不需要为少一张表取消会员权益。

**代价：**失去按充值、亏损及特殊人群进一步加奖的能力。原来基础奖2元加成70%得到3.4元，去掉加成后沿用2元并不能维持用户收益；应重新核对奖金配置，不能把算法减少等同于预算不变。

**判断：**适合大幅减少奖励计算层数。下一场生效、正在处理的奖励恢复等边界继续保留；没有必要同时改掉所有时间规则。

## 4. 刮刮乐

依据：[4.4 刮刮乐](4.4-刮刮乐/README.md)。

**目标：一笔达标充值获得一张卡，用户刮开获得随机结果。**

当前每日刮奖限次和有效期限制旧卡使用，持卡上限又限制后续发卡。某些合法配置会让用户获得多张卡，却没有足够的刮奖机会在过期前使用。

推荐方案：

- 一笔达标充值发一张卡，每人每天最多取得规定数量的新卡。
- 卡片有效期内随时可刮，取消每日刮奖次数和运营配置的未刮卡上限。
- 有限的每日发卡数量与有效期共同限制积累规模。
- 发卡时确定结果、金额、币种和打码倍数；重试不重新抽奖。
- 金额档按递增充值门槛配置，取达到的最高档，上界由下一档推导。
- 活动人群统一用于准入，取消档位中的标签交叉匹配和重叠顺序优先级。

**反例检查：**不能改成充值后直接到账，否则失去刮卡体验。中奖概率和奖金区间仍有独立用途，可以保留。达到当日发卡上限后，需要在用户充值前明确提示本日不再发卡；后续充值照常处理，不能误表示支付失败。

**代价：**每日发卡上限并非每日刮奖上限的改名，奖励产生速度和成本都会变化。取消档位人群会失去同金额对不同人群使用不同奖池的能力；取消刮奖限制会失去让用户分多日使用库存卡的回访手段。递增门槛会取消原区间的空档，最高档不再设置充值上限，因此部分原来不符合金额条件的充值会取得发卡资格，也会影响成本。

**判断：**推荐把限制前移，避免已经得到的有效卡因另一层次数限制无法使用。旧卡的结果、期限和权益需要独立保护，新发卡规则不能重抽旧卡。

## 5. VIP签到

依据：[4.10 签到奖励](4.10-签到奖励/README.md)。

**目标：VIP越高，每天的福利越高；当天充值达标可以取得更高的日奖。**

当前包含每个VIP等级的30日日历、逐日充值与免费比例覆盖、充值补签、补签额度、四个连续节点，以及多套版本锁定时点。大部分复杂度用于管理个人长周期，而用户最初描述的核心是按等级领取每日福利。

推荐方案：

- 每个VIP等级只设一个每日全额奖金。
- 全活动统一充值门槛、免费比例和打码倍数，不设日级覆盖。
- 每个业务日独立，不设个人30日周期，不需要单独报名。
- 首次合法领取时按当前VIP确定当天金额；已领取后升级不重算今天，次日首次领取再按新等级计算。
- 保留当天先免费、后充值达标自动补差，总额不超过该日锁定的全额。
- 删除补签及7、15、20、30日连续节点。漏领只影响当天，不影响下一天。

**反例检查：**删除补差虽然少一条发奖链路，却会使上午领免费、下午充值的人比晚领奖的人少拿。它解决的是领取顺序问题，值得保留。相反，补签和节点奖励引入了另一套连续行为目标，可以删除。

每日金额锁定也值得保留：当天领取后再升级不能不断补到更高档，否则一份日奖会变成多次等级追补。首次领取前升级仍按现稿使用当前等级，这与“任何升级都只能次日生效”有区别，最终规则应直接写清这一行为。

**代价：**失去30日编排、付费条件补漏签和连续节点激励，改变现有多条模块决策。三类签到互斥仍保留；新日制必须重新定义切换边界，不能继续依赖被删除的30日周期。迁移时停止旧制自动续轮，只完成现有旧周期并履行已取得奖励，之后再承接新日制。

**判断：**九类中最值得优先重做的活动之一。配置规模可从“VIP等级数×30天及覆盖字段”降为“每VIP一个金额＋活动共用参数”。

## 6. 常规七日签到

依据：[4.12 常规七日签到](4.12-常规七日签到/README.md)。

**目标：一笔达标充值换取七天回访福利，后续不需要再次充值或投注才能领取。**

单笔成功充值、不限首充、当天第1天、进行中再充值不重置、固定奖金，这些要求清楚，应保留。

三个漏领选项实际上定义了三个不同产品：中断模式是连续领取任务，跳过模式是固定日历福利，保留模式是不限总时长的分次领取。它们影响结束日期、再次参与和跨活动切换，维护代价无法通过隐藏配置解决。

如果重新选择最简玩法，我推荐：

- 激活日起固定七个自然日，第1天即可领取。
- 某天漏领只失去当天奖励，第二天继续下一日。
- 七天金额分别可设，打码倍数全活动统一。
- 本轮在第7天结束时关闭；即使当天已领末日奖，也不提前开启下一轮。
- 一轮结束后，需要之后发生的新达标充值才能再参与；进行中充值不预存为下一轮资格。
- 取消仅限制“正常结束”的重复参与开关，统一结束后的再次参与规则。

**反例检查：**若领完第7天就立刻结束，随后同日新充值激活，但又限制同日只能领一份，就会出现“充值当天第1天，却次日才领第1份”的特例。因此本建议固定在第7天日界结束，直接避免同日换轮。代价是第7天领完后的充值仍属于进行中充值，必须提前说明它不会启动下一轮。

现稿关闭正常重复参与后，中断用户仍可新充值重开，正常完成用户却不能再参加。这个开关不能解释为活动总参与次数上限，也不能用于承诺总成本上限。

**与用户原要求的冲突：**固定跳过会删除用户明确提出的中断和保留两种选择；统一倍数、重复规则和结束时刻也会改变当前配置。这里只给出替代方案，不能把它当作文档整理直接写回实施PRD。

若保留三种模式，就将它们作为三套明确玩法分别说明，承认对应的维护成本。尤其永久保留会使未结束的用户长期不能切换到其他签到，不能一边承诺永久保留，一边自动取消旧轮。

**判断：**适合重新作一次产品取舍。把三种模式藏进“高级设置”只能缩短表单，不能减少规则维护量。

## 7. 每日签到

依据：[4.14 每日签到](4.14-每日签到/README.md)。

**目标：每天充值与有效投注都达标，连续七天再获得额外奖励。**

现稿已经采用用户明确选择的单档、自动参与、统一门槛、七天日奖、一次连续奖和领取全部。继续减少核心规则，很容易删掉用户需要的功能。

推荐保留：当天双条件达标推进；漏点领取不打断；全天未达标才中断；下次达标重新开始；历史已达标奖在本轮截止前可补领；当日或次日开放；每轮锁定配置。

后台使用“一键填充七天金额，再逐日修改”。这只是填写工具，保存结果仍是七个明确金额，不增加默认值继承。直接展示本轮总奖金、奖励最早开放时间和截止例子。

**反例检查：**

- 第1天达标忘领，第2天继续达标，进度应到第2天。当日领取模式可领两份，次日领取模式只能先领第1天奖励。不能为了少做自动进度，改为点击领取才算签到。
- 次日领取时，第8天可以领取旧轮末奖，同时达标开启新轮。不能因为还有旧奖未领，就禁止本活动正常循环。
- 将额外奖并入第7天金额少一个字段，却隐藏了连续奖励的独立含义；保留额外奖，界面可以展示合计。

**代价与判断：**核心保持，只优化配置与说明。取消补领、次日领取或连续额外奖的收益不足以支持撤回用户明确要求。

## 8. VIP配置

依据：[4.6 VIP配置](4.6-VIP配置/README.md)。

**目标：持续贡献形成等级，等级带来可预期的权益。**

当前把等级成长、保级、周月福利、投注返现、领取时充值要求和出款限额放在一起。一个开关暂停等级和奖励，却不停止出款限制，还引入保级计时暂停与恢复。

推荐按职责整理，仍可以在同一页面维护：

- 等级成长和保级作为持续运行的基础规则；周期奖励单独启停，出款按等级权益执行。
- 保留充值与有效投注双门槛、完整个人保级月和降级后的重新升级规则。
- VIP周期奖励定位为等级权益，删除领取时再次充值及免费比例分支；复充激励由VIP签到等充值玩法承担。
- 领取窗口采用固定自然周期：昨日返现次日领取，上周奖在下一周领取，上月奖在下一个月领取，删除任意月日和小时段配置。
- 用户使用一个入口领取当前可领权益，后台仍区分奖励类别及原始依据。

**反例检查：**月底升级后只有一天保级，说明统一自然月并不一定更合理；完整个人保级月应保留。有降级就必须保留新的升级依据，否则历史累计值会让用户立即升回。出款额度占用和跨日释放也不能为缩短PRD而删除。

当前“先领免费后充值不补差”会让用户因早领取而少拿。将VIP周期奖定位为忠诚权益并删除这层领取选择，可以消除这个问题；直接照搬VIP签到的补差则会新增状态和成本。

**代价：**取消领取时充值门槛会减少直接促复充手段，延长领取机会也可能增加实际支出。重新核算奖金后才能把方案转换为实施配置，不能沿用原金额并承诺成本不变。关闭奖励也不再暂停等级成长，与现稿开关含义不同。

**判断：**需要分清目标后重构职责，但不应因为复杂就删除保级或双门槛。这些机制承担实际的长期权益控制。

## 9. 代理返佣

依据：[7.1 代理返佣](../M7-代理管理/7.1-代理返佣/README.md)、[7.3 代理关系](../M7-代理管理/7.3-代理列表/README.md)。

**目标：直属下级的真实贡献产生佣金，长期贡献提高后续返佣比例。**

“终身累计决定档位，当日新增用于发钱”本身容易解释，不需要为统一结构改成每天重新判档或固定单比例。

推荐：

- 固定仅直属，删除只有一个可用值、其他模式置灰的选择器。
- 保留充值佣金、投注佣金和终身阶梯，用户只需领取全部当前可领佣金。
- 领取入口展示两类组成，后台仍保留逐笔来源、金额与打码依据。
- 常规比例和范围调整从下一业务日生效；紧急关闭停止新佣金，原有可领佣金继续可领。
- 展示“次日结算完成后可领取”；开放时刻到但尚未结算时显示结算中，不能显示为零佣金。
- 明确业务发生时间、采用配置和技术重试时间，避免迟到处理重新选择人群或比例。

代理本人是开放范围的判断对象，下级贡献是计算来源，两者不能混用。现有独立渠道入口继续保留，不为复用强行撤掉已经提供的定向能力。

**反例检查：**自动到账可以少一次点击，但会撤掉手动领取的回访动作，并改变带打码佣金的钱包体验。先保留领取全部已能减少操作。按日重新判档则会改变长期激励，不能作为表单简化处理。

**代价：**删除单条领取后用户不能挑选领取顺序；次日生效会取消当天即时调比例能力。原有阶梯、退回处理和佣金不过期继续按其业务目的保留。

**判断：**主要做局部简化和时间口径修正，核心经济机制保持。

## 跨活动复查

三类签到分别承担等级日福利、一次充值后的回访、每天双条件连续行为。名称相近不构成合并依据。若采用本评审的VIP签到简化，日奖与签到周期可以明显分开；三类签到互斥的用户占用和切换时点仍须明确，不能由一个通用开关猜测。

公共能力应从最终选定的玩法提取。现在就做兼容全部现有选项的统一引擎，会把VIP签到、七日漏领模式和随机预算中最复杂的分支带给其他活动。

值得稳定共用的是：业务日和原始事实、开放范围判断、配置留痕、奖励与资金结果记录、幂等恢复、权限。资格取得时点、漏领、开奖、保级、阶梯判档和退款后权益属于各自玩法，先把规则讲清再复用。

## 改版边界与检验

本评审的建议分为两类，实施时分别处理：

- 填写工具、自动推导场次数、删除无效模式选择、减少重复说明，主要改善操作和维护。
- 删除随机性、漏领模式、补签节点、加成、人群分档或充值条件，以及改变发卡限次和领取窗口，均是业务改版。应逐项说明对用户、配置和成本的影响。

转换为正式PRD时，每篇至少用正常参加、漏领或未达标、再次参与、配置改变、关闭、重复请求和资金结果未知等场景验证。旧码、旧卡、旧轮和已取得奖励按各自承诺处理，不用新规则重算或直接取消。

当前个别正文与验收仍有旧说明冲突，例如刮刮乐的卡片边界。核对时以用户明确要求、现行执行结论及对应决策逐项追溯；文字冲突修正和本评审提出的新玩法要分别记录，不能混为同一项整理。
