# 4.17 · 拼多多活动

## 1. 活动介绍

玩家每轮首次旋转先获得目标彩金约95%的活动进度,之后通过每日免费机会和邀请新用户注册获得的机会继续旋转。剩余金额按后台配置的份数逐次补齐;本轮新邀请好友的充值人数、累计充值和累计有效投注同时达到加速条件后,下一次旋转直接补齐剩余金额。满额后由玩家手动领取整笔彩金。

每运营商配置一个目标奖励,每位玩家独立循环。每轮从实际首次旋转起计算连续有效时间,默认3×24小时。提前领取成功或到期未领取都会刷新下一轮;新轮等待玩家首次旋转才开始计时,不会在玩家离线期间不断空转轮次。

### 范围

- 单一目标金额,不提供多个奖档、逐档领奖、实物、字母收集或额外大奖池。九宫格/转盘用于呈现本次获得的金额,结果按本页规则确定。
- 每轮首抽按95%计算,其余金额分N份;注册赠1次与每天免费1次按同一每日额度处理,不叠加。邀请所得机会与每日免费机会都可以推进金额。
- 邀请机会可以跨轮保留,同一好友在本活动只贡献一次机会。加速只统计本轮新好友及其本轮事实,旧轮好友不能重复加速。
- 进度金额是待领取彩金,不是钱包资产。满额仍须在本轮截止前申请领取;满额但未申请也会过期。已经入账的彩金及任务不随轮次重置。
- 参与人群使用M2标签;开放渠道保留独立选择,复用M2的受控渠道选项和注册渠道事实。轮内邀请汇总与加速条件归本活动,不是单个玩家标签条件。
- 与邀请宝箱、代理返佣和普通充值赠送分别计算,不消耗其他活动资格,不改变好友充值本金的打码规则。

后台使用简体中文,最小宽度1280px。玩家页面按运营语言展示。活动时间显示运营时区及准确截止时刻;个人轮次按连续小时计算,每日免费机会按运营自然日计算。加速金额使用USD标准计价,彩金落活动选择的真实币种。

## 2. 运营配置

### 配置字段

| 编号 | 配置项 | 填写与执行规则 |
|---|---|---|
| A1 | 名称、活动开关、说明 | 名称1～40字符,必填;新配置默认关闭;说明最多2000字符。开关控制新轮启动,说明不改变服务端规则 |
| A2 | 参与用户标签 | 全部用户/指定标签,默认全部;指定时至少选择一个本运营商启用标签,任一命中即可。限制邀请人,不要求新注册好友充值或命中标签才能赠次 |
| A3 | 开放渠道 | 全部渠道/指定渠道,默认全部;指定时至少选择一个受控渠道,多选为任一命中。读取邀请人的注册渠道,与A2同时满足;不另建渠道字典 |
| A4 | 目标彩金A与币种 | 选择一个可发放活动彩金的真实币种,填写正金额,均必填无默认。金额须符合币种精度,至少为100个最小单位,并通过A6的拆分校验;目标是本轮最终总奖,不是在95%之外再加一笔 |
| A5 | 个人轮次有效天数D | 整数1～7,默认3;从本轮首抽起连续D×24小时,不使用全平台统一截止日 |
| A6 | 分配金额个数N | 整数1～10000,默认100;表示首抽后正常路径需要的旋转次数。剩余金额必须足够拆成N份正金额,不能靠零金额结果或超出币种精度的份额凑数 |
| A7 | 加速获得条件 | 必填三个正门槛:充值好友人数P为正整数;累计充值R与累计有效投注W为正USD金额,最多8位小数,无默认数值。三个条件使用AND,金额按合格好友合计,不是要求每人分别达到R/W |
| A8 | 彩金打码倍数Y | 正数,最多两位小数,必填无默认;领取目标A时建立A×Y的独立任务 |
| A9 | 同注册IP有效邀请人数上限K | 正整数,默认1;同运营商、同一邀请人在本活动内,同一注册IP累计最多K名好友可赠次并进入加速范围。跨轮不清零,不同邀请人分别计数;采用可信注册IP,不采用最近登录IP |
| A10 | 弹窗方式 | 关闭/注册后弹出/访问活动时弹出,默认关闭。弹窗关闭不影响手动活动入口,展示不自动旋转或领奖 |
| A11 | 首抽比例与机会规则展示 | 只读显示首抽95%、每日免费1次、每名合格新好友赠1次及机会有效期,本版不提供注册赠1～5次或免费合计99%的另一套参数 |

所有已填数字必须合法;金额、倍数和乘积须落在资金支持范围内,不静默截断输入。P/R/W为加速条件,不是正常抽满后再次收取的领取门槛。示例“3名充值好友、累计100 USD、有效投注1000 USD”不是默认配置。

### 保存、发布和初始化

草稿可不完整,非法已填值不能保存;发布须完整校验并展示变更。发布不自动开启,并发修改不得覆盖其他人的更新。保存、发布、启停均记录操作者、时间及变更。

| 变更 | 生效规则 |
|---|---|
| 目标A、币种、D、N、P/R/W、Y | 下一轮实际首次旋转时使用当时已发布版本并锁定;待首抽的新轮没有旧金额承诺,启动时展示实际新参数并由玩家点击确认旋转。进行中轮次不重算 |
| 用户标签与渠道 | 新轮首抽检查当时有效条件并保存依据;普通摘标、渠道变化或规则编辑不撤销已启动轮次。底层资料未知时不能用默认值启动 |
| 同IP上限K | 按新好友注册绑定业务时点的已发布规则判断,独立于轮次版本;已确认赠次和IP占位不追溯撤销。降低K后既有占位保留,停止超过新上限的后续赠次;提高K只用于之后新注册的好友 |
| 活动关闭 | 停止启动新轮;已有进行中轮次继续免费机会、邀请获次、加速和领取直至结束。关闭期间仅仍有进行中旧轮的邀请人可获新邀请机会。结束后等待重新开放,旧余额保留 |
| 名称、说明和弹窗方式 | 新发布后用于展示,不能改写旧轮金额、期限或资格说明 |

运营时区沿用本运营商业务时区,首次发布后本活动运行中不可直接切换,避免同一自然日重复送次。原表“初始化时间设置”落实为下一轮重新采用已发布规则,不提供清空所有玩家当前进度、重发免费次数或重置IP名额的按钮。

## 3. 参与和领奖规则

### A12 · 机会来源及使用

机会分为每日免费机会和邀请机会,均不可提现或转让,不是彩金。玩家能看到今天免费机会是否可用、下一次刷新时间和未用邀请机会。

| 来源 | 产生与有效期 |
|---|---|
| 注册赠送 | 注册成功当天提供1次免费机会,占用当天每日额度;不是注册1次再加当天1次。次日按普通每日规则刷新,未用注册机会不单独累积 |
| 每日免费 | 有参与资格的玩家每天最多使用1次,已有进行中轮次按该轮资格继续。每日额度不补发离线日、不叠加未用余额;已有账号也可按该规则进入活动 |
| 邀请注册 | A14认定一名新直属好友后增加1次邀请余额,不要求好友先充值;同一好友本活动只发一次。未用余额跨轮保留,到期刷新轮次不清除,不计为新轮的新好友 |

按运营时区00:00刷新每日额度,而非注册后每隔24小时。注册日和同日连续完成多个轮次仍共享当天1次。实际旋转优先使用当天免费机会,没有时才扣邀请余额;邀请机会按获赠顺序使用,每次消耗关联具体赠次来源。没有任何机会不能旋转,即使加速条件已达标也须等待每日机会或继续邀请。

异常恢复不另设可自由领取的赠次:确认原旋转未执行或按E6撤销时,原邀请机会退回原赠次来源;原每日机会仍在当日则释放原额度,已经过日则建立仅供原轮原请求恢复的一次机会。恢复机会优先使用,不增加今日免费额度,有效期随原轮顺延,原轮结束后失效且不跨轮;同一次旋转最多恢复一次可用机会,重复处理不累加。

活动开放时可登记本运营商合法邀请关系产生的邀请机会,邀请人是否能使用仍由首抽时的人群、渠道及账户资格决定。待首抽期间获赠的机会可用于首抽,但首抽前注册的好友不进入该轮加速。每次赠次保留好友、关系、注册时点、IP判断和次数来源,重复通知不重复增加。

### A13 · 个人轮次及首抽

每位玩家同时最多一个可操作轮次;异常旧轮恢复时对后继轮次的保留与暂停按A18执行。初次访问或上一轮结束后展示“待首抽”;查看页面、弹窗、获得次数均不启动计时,不提前展示95%为已获得金额。

玩家首次旋转时,服务端检查活动开放、参与标签与渠道、账户限制和可用机会,锁定A4～A8及业务时区,消耗1次机会,保存首抽结果。该次受理业务时间为T0,截止时间为T0＋D×24小时。配置锁定、次数消耗、首抽结果和轮次开始必须一致完成;失败不能只扣次数。

每轮都适用首抽95%,并非账号仅第一次享有。令U为目标A包含的最小币种单位数,首抽单位数B=floor(U×95/100),首抽进度为B个单位。“约95%”仅来自向下取整,本版不另外随机选择首抽百分比。首抽只是进度,不入钱包、不建任务。

同一首次旋转重复请求、刷新、跨设备操作都返回同一结果,不能再次消耗机会或生成另一个轮次。正常后续旋转和领取受理要求服务端时间早于截止时间,到达截止时刻即不再接受旧轮新操作;系统阻塞与已受理请求按A18/E5处理。

### A14 · 新好友、注册IP与邀请次数

M7提供同运营商合法直属关系和稳定关系标识,M2提供真实注册成功时间、注册IP及可用性。同一好友只归原直属邀请人,不能因轮次变化、重绑、改配置、重复消息而再次贡献机会;不计二级团队、自邀或人工补绑。

同一邀请人对同一注册IP的占位累计不超过K。按首次成功确认赠次的顺序占位,同批按稳定好友ID排序,并发不能超额;迟到记录不挤掉已确认好友。IP未知时显示核查中,不把空值当每人不同的IP;资料补齐后按原注册时点规则恢复。已明确因K满额而未获赠的历史好友不因后来提高K或重开轮次补发。

超过IP上限的好友可以正常注册和保留M7关系,但不贡献本活动机会、充值人数、充值金额或投注金额。该限制不是M8注册拦截,也不使用4.16邀请宝箱的设备名额。机会用完、关系解除或轮次结束均不自动释放IP占位与去重记录。

正常解除邀请关系不扣回已获机会。解除前合法发生的事实保留,解除时点后的新充值/投注不进入原邀请人的加速汇总;迟到消息使用原业务时点,不按通知到达时间转入新轮。

### A15 · 正常旋转分配剩余金额

首抽后剩余M=U－B个最小单位,分为N份。发布时要求B>0且M≥N;否则提示运营提高目标金额或减少份数。不能把原本配置100份静默变成50份。

每份先分配q=floor(M/N)个单位,前r=M mod N份各增加1个单位,其余份额不增加。每份为正、差额至多1个单位,合计恰好M。份额顺序在首抽时固定,玩家正常旋转每次依次消耗一份,不重新随机分配。实现可等价计算,不要求预建N条记录。

每日免费和邀请机会使用同一分配规则。N只计算首抽后的正常旋转,因此未经加速需1次首抽加N次后续旋转。第N次后续旋转必定达到目标;不要求邀请N人,也不再检查加速充值条件才能领取。每轮开始前展示目标、期限、N和正常路径说明,不能将95%的金额比例描述为已完成95%的邀请工作量。

正常旋转完成后记录次数来源、已完成份数、本次增加金额、前后进度及轮次。满额后停止旋转并保留未用邀请余额,不继续扣次或重复增奖。

### A16 · 本轮加速条件

本轮统计上界取实际结束时刻与有效截止时刻的较早者;尚未结束时采用有效截止时刻。本轮候选只包括注册绑定业务时点在[T0,本轮统计上界)内、通过A14且仍符合来源事实的直属新好友。提前领取成功后新注册的好友及新发生的充值投注不再计入旧轮。首抽前好友、上一轮好友和其他邀请人的好友均不计入,即使他们在本轮再次充值或投注。邀请次数余额跨轮使用不改变这些好友的归属。

| 指标 | 汇总范围 |
|---|---|
| 充值人数p | 本轮候选中至少有一笔真实充值成功且扣除退款后仍有正到账金额的不同好友数,同一好友多次充值只计1人 |
| 累计充值r | 所有本轮候选在本轮内、直属关系有效期间真实成功到账充值的净额,按每笔原始USD标准计价汇总;排除彩金、人工上分、无真实支付的人工商品单 |
| 累计有效投注w | 所有本轮候选在本轮内受理并最终结算、且事实发生时直属关系有效的有效投注,按既有游戏折算比例和原始USD标准计价汇总;排除取消、作废与冲正部分 |

各笔充值、投注不得早于该好友注册绑定。使用到账和最终结算等原始业务时间,不使用回调到达时间;统计截至本次评估业务时点。标准计价缺失或来源未齐备时标明未知,不猜测汇率或将异常当0。以上是本活动对真实事实的筛选,不修改M2现有“成功到账充值”的通用标签指标定义。

当p≥P、r≥R、w≥W同时成立,页面显示“再转一次即可补齐”。这不是额外一笔奖励,也不会自动增加次数或入账。玩家使用1次机会旋转时再核对完整依据,满足则本次增加A－当前进度,立即满额;不继续消耗剩余正常份额,不另发A之外的加速奖。

资料齐备后5分钟内更新展示,旋转时以服务端核对为准。该次旋转涉及的加速依据不完整时保留核查和次数占用,不默认走普通小额结果;恢复原请求后只产生一个结果。正常路径最后一份本就必定满额,可以独立按A15完成,不依赖未知加速指标。技术阻塞顺延按A18处理。

正常提现、后续游戏输赢不撤销已确认真实充值或有效投注。退款、投注冲正、原注册事实错误按E6/E7处理,不将普通标签变化当成原始事实失效。

### A17 · 满额、手动领取与资金

满额后显示本轮目标彩金、币种、Y、打码量和领取截止时刻。玩家须在截止前点击领取;没有受理过领取的轮次,即使满额也按时过期。页面需清楚提示“满额后仍需在倒计时结束前领取”,不把按钮称为直接提现。

服务端受理时检查奖励归属、轮次、满额结果、截止时间、账户/资金限制以及原资金结果,锁定唯一领奖申请。该轮金额固定为A,以本轮币种和Y一次入彩金,同时形成对应账变和A×Y独立任务。首抽及小额进度不另外入账,不把A与首抽金额相加。

领取处理中不得开启第二个领奖申请或下一轮。不同页面、不同请求编号、跨设备请求均按同一轮奖励防重;结果未知查询并恢复原申请。已在截止前受理的申请在截止后继续处理,明确未入账失败也恢复原申请,不要求用户重新取得资格。领取成功和账变/任务结果必须可核对,最多入账一次。

本活动奖励不增加充值金额、充值次数或首充事实。每笔彩金任务独立,不清理原任务;领取成功不意味着已满足全部提现条件。好友自己的充值仍按原充值及赠送规则处理;本活动不创建专用充值订单、不排除其他充值赠送或占用其次数。与4.16邀请宝箱和7.1代理返佣按各自规则叠加。

### A18 · 结束、下一轮和故障恢复

| 触发 | 当前轮与下一轮 |
|---|---|
| 领取成功 | 当前轮记已领取,自动创建下一轮待首抽;不赠送新免费次数。下一轮首次实际旋转重新检查资格、锁定最新规则并开始自己的D×24小时 |
| 到期仍未满额,或满额但未受理领取 | 当前轮记已过期,旧进度不能兑换或带入新轮;自动创建待首抽新轮,不自动旋转、不自动计时 |
| 截止前已受理领取,资金处理中或未知 | 保留当前轮原申请直到结果明确,不因倒计时到点重置或开新轮 |
| 活动关闭或新轮资格不满足 | 已结束轮次保留历史,下一轮展示等待开放/资格不足;邀请余额保留,不擅自启动或消耗机会 |

每日额度独立于轮次:同日重新开始仍不补次数,过了运营日界才刷新。邀请余额未用部分继续保留,但旧轮好友和统计不会复制到新轮。待首抽可以长期等待,不因经过几个3天就补造多个轮次。

系统自身或依赖故障确实阻塞该玩家旋转、查看已受理结果或领取时,记录受影响区间并暂停倒计时;恢复后截止时间顺延这些区间的并集时长。已受理且结果未知的旋转锁住原轮和机会,不能在恢复前判成正常到期并开新轮。暂停期间仍按事实时间保存注册、充值与投注,恢复后按顺延后的本轮窗口复核;每日额度不按暂停天数补发。

技术迟到通知按原时点补到原轮,不能搬到新轮重复统计。若迟到事实证明旧轮的旋转因系统资料不完整被错误处理,旧轮进入受控核查,暂停该玩家新轮操作,先完成原请求恢复并按实际阻塞时长修正期限;不自动补发整笔彩金或重扣次数。已经启动的新轮保留全部进度、次数记录和剩余时间,暂停期间延长其期限;旧轮恢复结束后继续同一新轮,不因旧轮补领成功再次创建或覆盖新轮。旧轮纠错仍按原事实归属处理,顺延不重复采纳已归入后继轮次的好友或事实。若旧轮没有受理过旋转/领取且不存在可证明的系统阻塞,单纯后来发现加速门槛曾达标不能代替当时的旋转与领取动作。

玩家离线、忘记操作、个人封禁/风险限制不顺延;限制解除时按实际剩余窗口继续或按已到期处理。普通关闭活动不构成旧轮故障,因为旧轮仍可按约履行。
