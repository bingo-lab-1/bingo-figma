# 4.14 · 每日签到

## 1. 活动介绍

每日签到鼓励用户每天充值和参与游戏。用户当天的累计成功充值和有效投注都达到要求,就能获得当天签到奖励。连续达标七天,还能获得一份额外奖励。

活动只有一个档位。用户不用报名,也不用先打开活动页面;达标就开始计算进度,奖励需要点击领取。运营可以设置七天各自的奖金,但这一轮每天的充值和投注门槛相同。

本次包含后台配置、页内活动记录查询、签到与领奖规则,不包含玩家端视觉设计。不做多档叠加、未达标补签、暂停进度、VIP变额、随机奖励或日奖补差。

后台使用简体中文,沿用现有桌面后台适配规范;玩家活动说明按运营语言填写。每天的起止按平台业务时区计算。门槛使用平台标准计价币种,奖金使用活动选择的奖励币种,展示金额时必须带币种。

## 2. 运营配置

| 配置项 | 含义和填写规则 |
|---|---|
| 活动名称 | 便于运营识别,名称长度见下方A16 |
| 奖励币种 | 选择已开通的币种,全部奖金使用同一币种 |
| 每日充值门槛 | 用户当天累计成功充值至少达到这个金额 |
| 每日有效投注门槛 | 用户当天累计有效投注至少达到这个金额 |
| 七天各自的奖金 | 每天一个固定金额;可先一键填成相同金额,再逐日调整 |
| 连续完成额外奖金 | 连续完成整轮时,除末日日奖外再发这笔奖励 |
| 奖励打码倍数 | 全活动统一,日奖和额外奖共用;到账后各笔奖金分别产生打码要求 |
| 领取时间 | 统一选择当日或次日开始领取 |
| 活动开关 | 决定是否接受新一轮签到,关闭后的旧轮处理见特殊情况 |
| 活动说明 | 必须与实际参与、领奖和过期规则一致 |

周期固定、自动循环,不再提供这两项的配置开关。页面同时显示当前配置版本、生效日期及当前开放的签到类型。

### A5 · 奖金、币种和打码

按本轮第1至第7天分别填写固定奖金。所有日奖及额外奖共用一个打码倍数,每笔奖金到账后产生的打码要求为“实际奖金×该倍数”。用户不用先完成这笔奖金的打码,才能领取它。

奖金和倍数均为正数。奖金精度随奖励币种,倍数最多两位小数。奖励不随充值币种或VIP等级变化。

### A16 · 保存和成本预览

活动名称为1至40个字符,活动默认关闭。金额和倍数没有默认业务值,必须由运营填写。可以保存不完整的草稿,但门槛、任何一天的奖金或额外奖缺失时都不能发布,需要指出具体缺项。发布前展示完整配置供核对,期间草稿被修改需要重新核对。

成本预览展示“七天日奖之和＋连续额外奖”。这是完成一轮的奖金合计,不是用户整个活动最多能拿到的金额;自动循环和中断后重启都可能再次产生奖金。

本版不增加独立人群、渠道筛选或手工修改签到进度。

## 3. 参与和领奖规则

### A1、A4 · 达标自动开始,只算一个档位

活动允许新参与、用户也符合平台及三类签到参与要求时,当天充值和有效投注都达标,自动记为本轮第1天。每轮固定连续7天。

用户不需要报名或访问活动页面。当天金额超过门槛,也只计一天,不会多得其他档位奖金。

### A2、A3 · 每天分别计算充值和投注

每天都要同时满足以下条件:

- 当天累计成功充值金额达到充值门槛。
- 当天累计有效投注金额达到有效投注门槛。

本轮每天使用同一组门槛。统计从平台业务时区当天00:00开始,到下一天00:00截止,包括当天首次达标前已经发生的有效充值和投注。

按真实成功充值统计,赠金和人工充值不计入。有效投注以玩法提供的有效金额为准,不直接使用原始下注额,也不使用用户还剩多少打码任务代替。

新活动及配置版本按业务日边界生效,不补算启用前的日期。用户当天被其他签到活动占用时,这一天也不能事后补成本活动的签到日。

### A8 · 达标推进,未达标中断

今天达标,本轮自动往后推进一天。当天还没达标时只显示充值、投注分别还差多少,不能在早上就判断这一轮中断。

到当天结束时,确认全天仍未达标,本轮才中断。之后再次达标,从新一轮第1天开始,不继承上一轮的天数。数据还没有查清时先核查,不能直接当成未达标。

**忘记领奖不会打断签到。** 进度看当天是否达标,不看有没有点击领取。

### A9 · 连续完成后获得额外奖励

连续达标第7天,同时取得第7天日奖和连续额外奖。额外奖每轮一次,金额由运营设置,打码倍数与日奖相同。

中断前后的天数不能拼在一起取得额外奖。日奖和额外奖各自记录是否领取,但适用同一轮的领取时间和截止规则。

### A6 · 什么时候能领,什么时候失效

运营选择当日领取时,当天达标后就开放该日奖励;选择次日领取时,该日奖励从下一业务日开始开放。

已经达标但忘记领取的奖励,可以在本轮领取截止前补领。补领当天不需要重新达标,也不会占用当天签到进度。

正常完成一轮时:

| 领取设置 | 本轮全部未领奖励的截止 |
|---|---|
| 当日领取 | 完成第7天的当天结束 |
| 次日领取 | 完成第7天的下一天结束 |

**中途中断**:确认全天未达标的当天结束时,本轮全部未领奖励一起失效,两种领取设置均如此。不能在当天结束后,追溯到昨天取消此前已经合法领取的奖励。

开放时刻可以领取,达到截止时刻就不能再提交新领取。过期奖励不带到新一轮,也不因为开启新一轮而延长时间。

### A7 · 点击“领取全部”

“领取全部”领取当前所有已开放、未领取、未过期的日奖及额外奖,可以包含之前忘领的奖励。系统逐笔核对资格,分别展示处理结果。

某笔失败,只重试未成功的部分;已经成功的不能再发。结果尚未查清的先显示处理中。去重时区分用户、轮次以及奖励日或额外奖,不能用“今天已经领过一次”挡住其他合法奖励。

领取只改变奖励状态,不会创建新一轮或增加签到天数。这个统一领取入口为本版交互方案。

### A10 · 活动开启期间自动循环

正常完成一轮后,从下一业务日起再次达标,自动开始新一轮。中断后也是下次达标自动重启,没有单独的循环开关。

次日领取时,用户可能正在领上一轮的末日奖励,同时开始新一轮签到。这两件事可以同时发生,旧奖励仍按原截止失效。同一天最多算一个签到日,不能既算旧轮最后一天,又算新轮第一天。

**例子**:小王第一天达标但忘领,第二天继续达标,进度仍然来到第2天;已开放的两天奖励可以一起领取。如果第二天全天未达标,第三天才再次达标,第三天就算新一轮第1天。

## 4. 特殊情况

### A11 · 运营修改配置

按“每轮开始时确定规则”处理。用户开始一轮后,这一轮门槛、奖金、倍数及领取时间保持不变。运营修改配置只影响之后开始的新轮。

保存草稿不影响线上,发布后从下一业务日生效。最多保留一个待生效版本;有用户开始参与后,奖励币种不可修改。

新轮可以使用新配置,不必等待旧轮奖励领完;旧轮待领奖励仍用旧金额、倍数和截止。

### A12 · 关闭活动或切换签到类型

三类签到互斥沿用[已定D83](../README.md#7-决策清单):同一运营商最多开放一种签到接受新轮,同一个用户不能同时进入另一类签到。

关闭或切换后,停止新参与、中断后的重启和正常循环。已经开始的任务轮继续执行到完成或中断,原有奖励按本轮截止处理。

只要该用户还有本活动正在进行的任务轮、未结束的领奖窗口,或已经合法提交但未处理完的领取,暂不释放给另一类签到。

### A13 · 充值或投注数据晚到

数据不完整时显示核查中,不自动把有争议的进度中断后再开一轮。本轮尚未截止时,核实原日期确实达标,可以恢复正确进度和奖励;不能同时发原轮后续奖和错误重启产生的首日奖。

本轮正式截止后,不重新开放玩家领取入口。用户在截止前已经提交领奖,后来确认当时符合要求,则继续完成这次申请。

平台技术问题造成的历史损失保留记录,交财务复核;本活动不自动增加补偿奖励。

### A14 · 充值退款或投注撤单

按原日期扣减充值或投注金额。新领奖申请需要重新检查原日资格。已经合法受理的奖励,不自动改金额或追回。

如果历史修正导致原轮和新轮奖励冲突,停止自动发放有争议的奖励,保留依据供复核,不能重复生成同日奖金。

### A15 · 账号限制或奖金到账较慢

平台禁止用户参与时,不开始新轮;禁止发奖时,不接受新的领奖申请。账号限制不会延长领取截止,解除后也不能补领已过期奖励。

账号被限制不代表过去的充值和投注变成零,原日达标仍要根据真实记录核查。已经合法受理的奖励如果还没到账,继续查询原申请的结果,超过截止也不丢弃申请或另发一笔。

### 页面需要说明的情况

| 情况 | 用户或运营需要看到什么 |
|---|---|
| 草稿缺项 | 缺少哪项配置,可保存但不可发布 |
| 尚未达标 | 充值和有效投注各自差额 |
| 其他签到占用 | 不能开始本活动的原因 |
| 中断 | 本轮已中断,下次达标从首日开始 |
| 达标但未开放 | 开放日期 |
| 历史奖励仍可领 | 原奖励日、所属轮次及截止,并计入领取全部 |
| 新轮进行且旧奖待领 | 清楚区分当前签到进度和旧轮待领奖励 |
| 过期 | 奖励已失效,不能误写成当天未达标 |
| 数据或资金未查清 | 区分“资格核查中”和“领奖已受理、到账处理中” |
| 活动已停止接受新轮 | 已有轮次继续执行,但不会再开始新一轮 |

空、加载、取数失败及无权限沿用公共要求,不规定页面布局。

## 5. 验收场景

下表按当前规则列出可执行的验收场景。

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 4.14-R1 | 统一填充奖金后修改某天金额,预览并发布 | 单轮合计正确,新配置只影响之后开始的轮次 |
| 4.14-R1 | 漏配末日日奖或额外奖,或填写非法金额 | 不可发布,指出缺项或错误字段 |
| 4.14-R1 | 无权限发布,或已有待生效版本仍尝试发布 | 拒绝对应操作;配置没有多档或独立循环选项 |
| 4.14-R2 | 用户未打开页面,当天双条件仍达标 | 自动开始或推进签到 |
| 4.14-R2 | 全天未达标,之后再次达标 | 从新轮首日开始;不能在当天尚未结束时提前判中断 |
| 4.14-R2 | 当天多笔事实重复通知,或金额远高于门槛 | 当天仍只计一个签到位置 |
| 4.14-R2 | 关闭活动,或切换时缺少一侧权限 | 关闭后旧轮继续且不能开新轮;权限不足的切换完整拒绝 |
| 4.14-R3 | 原日达标漏领,本轮截止前补领 | 能领已开放历史奖,不要求今天再次达标,不改变进度 |
| 4.14-R3 | 只达到充值或投注条件,次日才补足另一项 | 不产生昨日奖励,展示当天各自差额 |
| 4.14-R3 | 新轮已经开始,申请领取过期旧奖 | 拒绝,新轮不延长旧奖截止 |
| 4.14-R3 | 领取全部中部分成功,再次请求 | 成功部分不重复发,失败部分可重试,未知结果先核查 |
| 4.14-R3 | 正常完成后配置为次日领取 | 末日日奖与额外奖次日可领,并可开始新轮,分别计算期限 |
| 4.14-R3 | 前日达标,当天最终未达标 | 按中断当天结束截止,不追溯取消此前合法领取;见D84 |
| 4.14-R4 | 全部连续达标,期间从未点击领取 | 仍获得额外奖,与末日日奖独立记录且使用统一倍数 |
| 4.14-R4 | 试图把中断前后天数相加,或重复发送末日事实 | 不能拼接取得额外奖,同轮不重复产生额外奖 |
| 4.14-R5 | 截止前合法提交,截止后才确认到账 | 继续原申请,保留原任务日及轮次,不另发一笔 |
| 4.14-R5 | 数据晚到、退款或投注撤单使历史资格发生变化 | 按原日核查;不重复生成错误新轮奖励,争议奖励留待复核 |
| 4.14-R5 | 已过期后新增领奖,或被限制发奖后等待解除 | 不重开窗口、不延长截止;已有合法申请继续核查 |
| 4.14-R6 | 在本页打开活动记录,核查日奖及额外奖 | 能查用户、轮次、原任务日、领取期限、达标依据、奖励与资金结果;不出现档位筛选或跨档汇总;无查看权限或超出账号数据范围的查询被拒绝 |

## 6. 相关资料

**入口**:活动管理 → 活动配置 → 每日签到。后台编辑、保存、预览发布及启停;玩家端按上述规则展示进度与领取结果。

**权限**:以下权限由服务端检查,不能只靠界面隐藏按钮。

| 操作 | 权限码 |
|---|---|
| 查看配置与活动记录 | `activity:daily-check-in:view` |
| 编辑草稿 | `activity:daily-check-in:edit` |
| 发布配置 | `activity:daily-check-in:publish` |
| 启停活动 | `activity:daily-check-in:switch` |

**记录查询**:本页内提供“活动记录”区,与活动配置一起交付并验收。必须能查询用户、轮次、本轮第几天、原任务日、开放日、实际领取日、截止、日奖或额外奖、门槛与实际达标金额、本轮规则、奖金币种和金额、倍数、状态原因及对应资金结果。没有档位筛选或跨档汇总。记录区只读查询,服务端按查看权限、运营商及账号数据范围隔离结果。

**责任与共用规则**:

- M4负责活动配置、轮次、原日资格、领奖依据及失效原因;保存每轮采用的规则,供页内活动记录查询。
- M2提供账号与风险信息,M5提供充值及资金结果,玩法提供有效投注和撤单事实(本仓库范围外),M6提供权限。活动不自行定义这些事实。
- 财务负责奖金入账和逐笔打码。结果未知先查原请求,历史奖励不能按当前配置猜算;财务和玩法须提供按原业务日期查询的历史事实,缺失时按数据恢复规则处理。
- 本活动不直接调用外部支付机构。共用说明见[资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)、[标准计价](../../M2-用户管理/2.1-用户列表/标准计价.md)和[公共能力与复用边界](../公共能力与复用边界.md)。
- [VIP签到](../4.10-签到奖励/README.md)与[常规七日签到](../4.12-常规七日签到/README.md)是不同活动,只复用公共能力,分别维护领奖规则。
