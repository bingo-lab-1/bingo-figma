# M4 · 活动管理

## 1. 定位与边界

**做什么**:运营给玩家发奖的各种活动,在后台的配置和查记录都归这个模块。活动很多种
(兑换码、红包雨、签到、转盘、充值返现……),这里统一放。**首版只做兑换码(4.1)**,
其他活动先在索引表登记,要做时再逐个开。

**为什么放进本仓库**:活动发的奖要加钱、要打码、有领取门槛,这些都和"钱"的规则挂钩,
所以文档得和 `资金模型.md`、`标准计价.md` 放一起改,拆开就会对不上 —— 和财务(M5)、
代理(M7)进本仓库是一个道理。运营原来不在范围内,现在**按活动一个个收进来,不一次全收**。

**不做什么**

- **不做玩家端那些页面** —— 这里只是后台,玩家看到的另外做
- **不做把码 / 奖发出去的通道** —— 私信、邮件、活动位归别处,这里只产出奖励规则和码
- **不做加钱和打码本身** —— 归资金那边,活动这边只触发,不自己改余额
- **不做兑换码以外的活动** —— 红包雨、签到等首版不做,只登记

**铁律**

- **资金域不得反向依赖活动域**(00-公共约定 依赖铁律):奖励入账与冲回一律通过财务账变完成,
  账变带来源标识,本模块不直接改钱包余额
- **核销记录是审计数据**:发放依据入账后不可改,谁在何时领了多少逐笔留痕

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 兑换码 | 运营做出来发给玩家的一串码,玩家输进去就能领奖;详见 4.1 | redeem_code |
| 兑换码规则 | 一批码共用的设置(奖励多少、能领几次、门槛、打码倍数) | 兑换码规则 |
| 随机奖励 | 在最小和最大之间随机出来的一次奖励金额 | — |
| 领取门槛 | 领之前要满足的条件(充过钱、绑了手机等);都做成用户标签,不单独设字段(D39) | — |
| 核销 | 玩家领成功一次,记一条记录并触发加钱 | redeem_code_log |
| 打码倍数 | 领到的钱要玩够几倍流水才能提,细节见 `资金模型.md` | coding_multiple |

## 3. 依赖关系

**上游依赖(我引用)**

- 财务(M5 与 `资金模型.md`):钱包与账变、打码任务、玩家充值汇总、标准计价换算 ——
  奖励的入账、门槛判定与打码全部依赖
- M2 用户管理:用户标签(2.5)—— **领取门槛与定向的唯一实现方式**,充值 / 手机 / 指定人群
  等条件都做成标签,领取时按标签当前命中集判断;另用玩家档案与封禁状态
- 发放通道(私信 / 邮件 / 活动位,owner 各异,**本仓库范围外**):把码送达玩家,本模块只产出码
- M6 账号管理:权限模型与全站操作日志

**下游被依赖(谁引用我)** ← 改活动奖励或核销数据前先看这行

- 数据中心(**本仓库范围外**):读核销记录做活动效果统计
- 玩家端(**本仓库范围外**):读玩家已领记录

## 6. 权限点汇总

| 权限码 | 树节点路径 | 名称 | 页面 |
|---|---|---|---|
| `operation` | 活动管理 | 模块入口 | — |
| `activity:redeem-code:view` | 活动管理/兑换码管理/查看 | 页面访问、查询、详情与领取明细 | 4.1 |
| `activity:redeem-code:add` | 活动管理/兑换码管理/新增 | 新增并生成兑换码 | 4.1 |
| `activity:redeem-code:switch` | 活动管理/兑换码管理/启停 | 启用 / 停用 | 4.1 |
| `activity:redeem-code:delete` | 活动管理/兑换码管理/删除 | 删除(软删) | 4.1 |

> 查看兑换码详情(4.1-R2/R5)为只读,复用 `activity:redeem-code:view`,不单设权限。
> 获取入口设置首版不做(D38),暂不设对应权限。

线上原有"编辑兑换码"操作,本设计**取消**(创建后只读,D40),故不设编辑权限;
其余(新增 / 删除 / 启停)按本仓库命名约定重整为上表。
授权层现状见 M6 README —— 服务端权限判定口径以 M6 为准,本模块权限码先是文档约定。
