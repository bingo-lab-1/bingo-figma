# M4 · 活动管理

## 1. 定位与边界

**做什么**:运营给玩家发奖的各种活动,在后台的配置和查记录都归这个模块。活动很多种
(兑换码、红包雨、刮刮乐、签到、转盘、充值返现……),这里统一放。**首版做兑换码(4.1)、红包雨(4.2)、刮刮乐(4.4)与 VIP配置(4.6)**,
其他活动先在索引表登记,要做时再逐个开。

**另外还承载 VIP 等级体系**(2026-09-01,M2-D1):VIP 不是一个活动,是**跨活动的玩家分层** ——
红包雨按等级分金额档、VIP 奖励按等级发、签到按等级配奖,消费方几乎全在活动侧,
所以等级序列与升降级规则一并归本模块拥有和写入,不留在 M2。它在菜单上单列一层,
不与红包雨、刮刮乐并列在「活动配置」下 —— **并列会让人误以为它是又一个活动**。

**为什么放进本仓库**:活动发的奖要加钱、要打码、有领取门槛,这些都和"钱"的规则挂钩,
所以文档得和 `资金模型.md`、`标准计价.md` 放一起改,拆开就会对不上 —— 和财务(M5)、
代理(M7)进本仓库是一个道理。运营原来不在范围内,现在**按活动一个个收进来,不一次全收**。

**不做什么**

- **不做玩家端那些页面** —— 这里只是后台,玩家看到的另外做
- **不做把码 / 奖发出去的通道** —— 私信、邮件、活动位归别处,这里只产出奖励规则和码
- **不做加钱和打码本身** —— 归资金那边,活动这边只触发,不自己改余额
- **不做兑换码、红包雨、刮刮乐、VIP 以外的活动** —— 签到、转盘等首版不做,只登记。
  xlsx 里「签到奖励按 VIP 等级配奖」那一支**本轮明确不收** ——
  收了等于把签到活动整个拖进来,首版边界会被撑破

**铁律**

- **资金域不得在账务链路上依赖活动域**(00-公共约定 依赖铁律④第 1 款):奖励入账与冲回
  一律通过财务账变完成,账变带来源标识,本模块不直接改钱包余额。
  M5 只读展示 VIP 等级不违反此条 —— 限制的是钱怎么算,不是屏幕上显示什么
- **VIP 的判定输入不得包含用户标签**(依赖铁律④第 2 款):等级只由充值与有效投注等
  原始数据判定。**「等级判定输入」与「奖励领取门槛」是两件事,不得混称** ——
  后者可以用标签,前者不行;混称就会绕出 `VIP → 标签 → VIP` 的环
- **核销记录是审计数据**:发放依据入账后不可改,谁在何时领了多少逐笔留痕

## 3. 依赖关系

**上游依赖(我引用)**

- 财务(M5 与 `资金模型.md`):钱包与账变、打码任务、玩家充值汇总、标准计价换算 ——
  奖励的入账、门槛判定与打码全部依赖
- M2 用户管理:用户标签(2.5)—— **领取门槛与定向的唯一实现方式**,充值 / 手机 / 指定人群
  等条件都做成标签,领取时按标签当前命中集判断;另用玩家档案与封禁状态。
  **注意方向**:标签可以拿来当领取门槛,但**不得进入 VIP 等级的判定输入**(第 1 段铁律)
- 玩法(**本仓库范围外**):有效投注 —— VIP 等级的投注门槛与投注返现的计算基数,
  口径为「实际投注 × 游戏折算比例」,与提现流水、打码、代理返佣同口径
  (`../M7-代理管理/7.1-代理返佣/README.md` A12),**不是原始投注额**
- 发放通道(私信 / 邮件 / 活动位,owner 各异,**本仓库范围外**):把码送达玩家,本模块只产出码
- M6 账号管理:权限模型与全站操作日志

**下游被依赖(谁引用我)** ← 改活动奖励或核销数据前先看这行

- **M2 用户管理**:VIP 等级 —— 2.1 的列表展示与筛选、2.5 的属性条件(M2-D56)。
  **改等级序列前先看这里**:等级的增删会直接影响 2.5 里含 VIP 条件的标签
- **M5 财务管理**:VIP 等级 —— 5.2 订单列表展示、提现风控参考,**仅展示,不入账务判定**
- **本模块内**:4.2 红包雨按 VIP 等级分金额档,等级增删会触发 4.2-A6 的覆盖校验(4.2-E7)
- 数据中心(**本仓库范围外**):读核销记录做活动效果统计
- 玩家端(**本仓库范围外**):读玩家已领记录

**4.6 为什么是一页**:运营配 VIP 是一条连续动作 —— 先定基础设置,再拉等级序列,
再逐级填三张奖励表,拆成两页会让人在两个路由之间来回跳。**但编辑权限仍然分开**
(`vip-level:edit` / `vip-reward:edit`,见第 6 段):等级序列一改就动到 2.5 标签、
2.1 筛选与 4.2 金额档三个下游,奖励金额只动本模块,两者不该由同一个权限位放行。

线上另有「兑换码设置」`/settings`(玩家端获取入口配置),**首版不做**,以后需要再另开(D38)。
其余运营活动(签到、转盘、充值返现、充值码、洗码等)首版**均不收入**,
需要时逐页在本表登记后另开需求 —— 不一次性铺开。
**签到虽与 VIP 奖励共用等级分档,仍不在本轮收入范围**(第 1 段)。
