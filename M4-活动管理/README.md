## 1. 定位与边界

**做什么**:拥有运营活动的配置、参与资格、奖励依据及记录。本文档收录兑换码、红包雨、刮刮乐、VIP配置、注册送好礼、VIP签到(4.10)、常规七日签到(4.12)、每日签到(4.14)、首充破产补助(4.15)、邀请宝箱(4.16)、拼多多活动(4.17)、排行榜活动(4.18)和幸运转盘(4.19);代理返佣在 M7。每种活动的记录归入对应活动内部,不单独登记记录页面或设置记录侧栏入口。

原「账号首充 / 首充奖励」并入 M5 的[5.5 充值商品与赠送](../M5-财务管理/5.5-充值商品配置/README.md),正式定义为可按次数配置不同百分比的限次充值赠送。商品、共享赠送方案及赠送记录在财务入口统一维护,M4 不另建首充配置页面;本金打码通用配置也由 5.5 拥有,不纳入 VIP 或其他活动的配置。归属与自动结算边界见 D89。

**首充破产补助独立归入 4.15**:按账号真实第一笔成功充值形成一次参与依据,之后同币种游戏净亏损达标才产生宝箱;与 5.5 的「第 1 次成功比例奖励」分别判断。普通或充值翻倍奖励由玩家二选一手动领取,关联翻倍订单的充值赠送互斥见 D90 和 4.15 正文。

**邀请宝箱独立归入 4.16**:每名有效直属下级产生固定基础彩金,累计人数达到里程碑再产生额外彩金,均由上级手动领取。上级参与人群和下级达标条件复用标签,邀请关系与跨账号注册设备计数分别读取 M7 和 M2 原始事实;计奖、容量及奖励规则归活动拥有,不复用代理佣金判档。完整边界见 D91 和 4.16 正文。

**拼多多活动独立归入 4.17**:单目标彩金、个人限时轮次;每轮首抽先形成约95%的待领取进度,剩余金额按配置份数推进。每日免费次数及直属新用户注册邀请次数均可旋转;本轮新邀请好友的充值人数、真实充值金额和有效投注同时达标,下一次有次数的旋转补齐剩余进度。满额后手动领取才入账建码,成功领取或到期后可进入下一轮。参与标签、独立渠道及本活动注册IP计数的专属边界见D92,不套用4.16的逐好友发奖规则。

**排行榜活动独立归入4.18**:真实玩家日榜、周榜独立奖池,固定前50名,测试账号不参与,不设标签门槛。原始下注额统一按USD排名、按最终结算时间归期;基础彩金与投注比例形成奖池,以平台统一真实币种手动领奖并独立建码。空缺不补造参与者、不分奖、不滚存;本文真实玩家版本不含隐藏机器人占奖设计。与M2/2.7运营查询排行榜的统计区别及范围见D93和4.18正文。

**幸运转盘独立归入[4.19](4.19-幸运转盘/README.md)**:符合条件自动参与,不设报名按钮;基础与进阶双彩金奖池,每日免费券、真实充值阶梯赠券和进阶抽奖里程碑分别计奖,全部奖励手动领取。自定义金额、权重与概率披露、旧券履约和版本边界见正文及D94。

**另外还承载 VIP 等级体系**(2026-09-01,M2-D1):VIP 不是一个活动,是**跨活动的玩家分层** ——
红包雨按等级分金额档、VIP 奖励按等级发、签到按等级配奖,消费方几乎全在活动侧,
所以等级序列与升降级规则一并归本模块拥有和写入,不留在 M2。它在文档功能导航中单列一层,
不与红包雨、刮刮乐并列在「活动配置」下 —— **并列会让人误以为它是又一个活动**。

**为什么放进本仓库**:活动发的奖要加钱、要打码、有领取门槛,这些都和"钱"的规则挂钩,
所以文档得和 `资金模型.md`、`标准计价.md` 放一起改,拆开就会对不上 —— 和财务(M5)、
代理(M7)进本仓库是一个道理。运营原来不在范围内,现在**按活动一个个收进来,不一次全收**。

**不做什么**

- 本模块维护活动后台及玩法规则;[玩家端Account](../玩家端/Account/README.md)另行定义VIP、本人奖励摘要和操作入口,其他活动视觉稿由Figma维护
- **不做把码 / 奖发出去的通道** —— 私信、邮件、活动位归别处,这里只产出奖励规则和码
- **不做加钱和打码本身** —— 归资金那边,活动这边只触发,不自己改余额
- **三类签到独立定义**:VIP签到(4.10)、常规七日签到(4.12)和每日签到(4.14)各自维护规则及内部记录。其他活动线索见活动清单,不自动成为独立页面需求。

**铁律**

- **资金域不得在账务链路上依赖活动域**(00-公共约定 依赖铁律④第 1 款):奖励入账与冲回
  一律通过财务账变完成,账变带来源标识,本模块不直接改钱包余额。
  D65 新增一个受控例外:M5 可在出款申请受理前读取当前 VIP 等级与逐级每日出款上限,仅判断能否受理并写订单快照;
  已受理后的钱包、账变和放款金额不得因 VIP 或配置变化重算
- **VIP 的判定输入不得包含用户标签**(依赖铁律④第 2 款):等级只由充值与有效投注等
  原始数据判定。**「等级判定输入」与「奖励领取门槛」是两件事,不得混称** ——
  后者可以用标签,前者不行;混称就会绕出 `VIP → 标签 → VIP` 的环
- **核销记录是审计数据**:发放依据入账后不可改,谁在何时领了多少逐笔留痕

**4.12 常规七日签到**对应原表「7日返现」,领取记录在活动内部查询。固定奖励、单笔充值激活与漏领模式见 D81–D83。

## 3. 依赖关系

充值商品赠送由 5.5 定义资格、分次比例、固定与比例互斥及奖励依据,由充值赠送业务编排调用财务完成入账与独立打码任务;钱包和账务服务只接收金额、币种、倍数及来源,不得在账务链路上反向查询 M4 活动规则。真实充值的本金打码倍数 X 来自 5.5 运营商级通用配置,与彩金倍数分别锁定快照,不因合并管理入口混为同一倍数。

首充破产补助 4.15 读取 M5 真实首充及充值修正事实、玩法同币种已结算投注和派彩及其修正、M2 首充时的人群标签命中与账号状态。活动拥有参与、亏损观察、宝箱及普通/翻倍领取依据;关联充值订单在创建时固定补助用途,仅排除该单的5.5固定与比例赠送且不消耗比例次数。充值本金按5.5的X入账建码,宝箱彩金仍须手动领取,已付关联订单及已受理领奖按原依据继续履约。活动只提交已确定的奖励与来源,账务不反向计算活动资格。

邀请宝箱 4.16 读取 M7 直属邀请关系及绑定事实、M2 上下级标签规则快照和判定事实及注册设备事实。活动负责在下级注册绑定时接纳、锁定依据,并执行同账号一次、同设备跨账号名额、每上级奖励人数上限、有效人数和里程碑计奖;M2 不承担活动设备名额或发奖次数。事实纠错可修正当前有效人数C,已占计奖名额U及设备占位保留,恢复沿原记录处理,具体见4.16。财务只消费活动确定的金额、币种、打码倍数和来源,不反向查询邀请或标签;邀请奖励与代理返佣、充值商品赠送可按各自条件叠加。

拼多多活动 4.17 读取 M2 参与标签判定、受控渠道选项及注册渠道和注册IP事实,M7直属注册绑定事实,M5真实充值及修正、玩法有效投注及修正。M4拥有个人轮次、免费与邀请次数、同邀请人本活动累计IP容量、金额份数和加速汇总;加速是本轮奖励规则,不在M2另建一套标签指标。财务只消费领取时已确定的奖励币种、金额、倍数和来源;本金X、5.5赠送、4.16邀请宝箱及代理佣金分别按各自条件计算。受控渠道数据由M2提供,不在活动创建新渠道字典。

排行榜活动4.18读取M2账号归属、测试标记的业务时点依据及账户限制,玩法原始下注、最终结算、取消修正和期间事实齐备依据,资金域原投注USD标准金额及期末奖励币种汇率。M4拥有日/周归期、真实玩家排序、奖池预算和结算快照;手动领取时只向财务提交确定的金额、币种、Y和来源。USD排名使用原入账时汇率,期末汇率只用于奖池预算换算,两者不能互换。M2/2.7的查询不承担本活动计算或派奖。

幸运转盘4.19读取M2参与时的标签判定、账号事实及账户限制,M5真实充值、修正、原业务时点及原入账USD标准金额。渠道通过标签定向,不另建渠道字段。M4拥有参与版本、周期、券、中奖及里程碑奖励依据;手动领取时提交已确定的彩金与倍数,财务不反查奖池。本金X与5.5赠送保持原规则,具体叠加、归期和恢复见4.19。

注册送好礼依赖平台注册成功事实形成领取资格,玩家手动领取后才请求M5彩金入账及绑定打码任务;未领取不产生资金或打码义务。充值翻倍延后,本期不依赖关联充值或跨活动赠送互斥。
平台基础设置拥有投注模式,游戏/投注侧读取该模式与财务充值事实执行,4.8 只读展示。
4.8内部记录区与玩家端区分待领取资格、领取处理中和已领取结果;已领取不等于可投注或可提现,领取后暂不提供玩家取消奖励及任务的功能。
每日签到4.14读取M5成功充值及修正事实、玩法按原日归属的有效投注和撤单、M2账号资格及M6权限;活动内部记录区消费单档轮次、原任务日的日奖/额外奖资格、最早领取日和本轮截止、奖励与资金结果。

常规七日签到 4.12 消费财务成功充值及资金结果、M2 账号资格、M6 权限;活动内部记录区与玩家端只读消费本轮进度和发奖结果。

签到奖励 4.10 消费本模块等级及其历史、财务成功充值事实和资金发奖结果;活动内部记录区与玩家端只读消费签到状态。
签到侧的充值门槛用于金额与补签资格计算,不是人群标签筛选;这是 D80 已定的边界补充,不得推断所有活动可自建人群条件。
