# 4.16 · 邀请宝箱

## 1. 活动介绍

符合参与人群的玩家邀请好友注册,每名直属好友达到有效下级标签条件并通过活动去重后,邀请人获得一份固定彩金;累计有效好友达到里程碑人数,再获得该档额外彩金。两类奖励以宝箱展示,达标后即可手动领取,支持一键领取。

运营分别维护邀请人的参与标签和好友的有效标签,用基础奖励提供逐人反馈,用人数里程碑鼓励持续邀请。客服可以查明每名好友为何计入、对应奖励和实际资金结果。

### 范围

- 每运营商一套长期累计活动,每名下级只贡献一次基础奖励,每个里程碑只奖励一次;活动改版或重新开启不重置人数和已领记录。
- 只接纳活动开启期间新注册并绑定的直属下级。上下级绑定、邀请码和解除关系复用M7,不支持活动补绑、换绑或二级团队计数。
- 同时提供基础奖和里程碑额外奖;达到最高里程碑后,尚未达到个人奖励人数上限的邀请人仍可获得基础奖。
- 标签定义用户条件,活动维护关系采纳、注册设备计奖去重、人数与奖励。不给充值、投注门槛另设一套可写字段。
- 奖励金额固定,无随机开箱;不设置次日等待、每日领取次数、领取顺序、领取期限或自动入账。每个宝箱的彩金和打码要求在生成时明确展示。
- 奖励发给邀请人。好友的注册礼、充值赠送以及邀请人的代理返佣继续按各自规则执行,不因本活动达标而扣除其他奖励或消耗充值事实。

后台为简体中文桌面页面,最小宽度1280px;玩家提示按运营语言展示。时间按运营时区展示。标签金额指标复用平台USD标准计价,奖励使用活动配置的真实币种,标准计价统计值不能直接作为钱包余额入账。

## 2. 运营配置

### 配置字段

| 编号 | 配置项 | 填写与执行规则 |
|---|---|---|
| A1 | 活动名称、开关及说明 | 名称1～40字符、必填;新活动默认关闭。说明最多2000字符,用于解释规则,不能改变服务端条件 |
| A2 | 参与上级标签 | 全部用户/指定标签,默认全部用户;指定时至少选一个本运营商启用标签,任一命中即可。渠道、VIP等限制放在所选标签内部 |
| A3 | 有效下级标签 | 必选一个本运营商启用的组合标签,无默认。只读预览完整条件、AND/OR、统计时间范围及单位,修改条件进入标签管理;活动页面不重复输入充值或投注门槛 |
| A4 | 奖励币种 | 必选一个平台已开通且可发放活动彩金的真实币种,无默认;基础奖与所有里程碑使用同一币种 |
| A5 | 每名有效好友基础彩金B | 正金额、必填无默认,符合A4币种精度;每名计奖好友生成一份 |
| A6 | 彩金打码倍数Y | 正数、最多两位小数、必填无默认;基础奖和新发布的里程碑共用该值,不是充值本金X |
| A7 | 每位上级奖励人数上限N | 正整数、必填无默认;本活动最多占用N个基础计奖名额,不限模式不开放;不是每日上限 |
| A8 | 同注册设备有效人数上限K | 正整数,默认1;同运营商、本活动内跨全部上级累计占用,不按日或配置版本重置;用户ID另外固定去重一次 |
| A9 | 里程碑奖励表 | 至少一档;每行填写累计有效人数k和额外彩金G,k为正整数、唯一、严格递增且≤N;G为正金额且符合币种精度,无默认金额。G是在基础奖之外另加,不是累计奖励总额 |

金额和倍数按资金模型精度计算。非法数字、金额精度溢出或金额×倍数超出资金支持范围时拒绝保存/发布,不能截断成另一金额。示例“累计充值金额≥100 USD且累计有效投注≥300 USD”可在标签内用AND组合,是推荐示例而非系统默认条件。

### 草稿、发布与生效

草稿允许不完整,已填值须合法;发布校验当前字段、标签可用性、奖励币种及全部档位,展示变更内容后确认生效。并发修改拒绝覆盖,所有保存、发布及启停记录操作人、时间和变更依据。发布不自动开启。

| 变更 | 生效范围 |
|---|---|
| 名称和说明 | 新发布后展示,不改变既有计奖条件 |
| 上级标签、下级标签/其规则版本、基础B及Y | 用于生效后新接纳的下级;既有候选下级继续使用接纳时的标签规则、B和Y。不能直接用标签当前命中覆盖原依据 |
| 奖励币种 | 首次发布后不可直接修改,避免同一累计活动在币种间迁移奖励 |
| 人数上限N、设备上限K | 首次发布后只允许提高,不能降低;提高后重新检查已接纳但因名额不足未计奖的候选,不清除原名额和计数 |
| 已发布里程碑 | 身份、人数门槛、金额和该档Y固定,不能删除、降低、改名为新身份或重发;新增档位必须高于已发布最高人数门槛且不超过N |
| 新增里程碑 | 对已有和新邀请人均开放;已有有效人数满足时生成新增档奖励,其他人后续达标生成,不补发旧档 |
| 活动关闭 | 停止接纳新的注册绑定;已接纳下级仍可按原条件达标,已生成或之后合法形成的宝箱继续领取。重新开启不重置名额 |

标签管理中的规则修改不会直接发布本活动。后台显示所引用版本与当前标签版本差异,运营发布活动后才将新规则用于新接纳下级。所选标签停用或条件不可用时暂停新接纳并显示原因;已接纳下级依据有效快照继续处理,所需原始事实不可取得时进入核查。

发布预览展示新增档位会解锁的已有邀请人数与额外彩金总额、提高N/K可能重新纳入的候选数量,并区分已知金额与资料尚不完整的记录。不能把未知金额显示为0。相同条件的新邀请人最高奖励预览为N×B＋所有里程碑G之和;已有邀请人按历史基础B、已锁定奖励及当前增量分别展示,不能用最新B重算历史成本。

## 3. 参与和领奖规则

### A10 · 接纳新邀请

M7提供注册时形成的稳定直属关系标识、上级、下级、运营商及绑定业务时间T。T发生时活动开启、双方属于本运营商、关系合法且上级满足A2,才接纳该下级为候选。下级是否达标另按A11判断。活动开启前或关闭期间形成的关系不因后来开启而补入,不能从普通直属人数汇总直接推导活动人数。

同一关系的重复通知只建立一份候选。记录当时活动版本、上级标签判定、下级标签规则快照、B、Y、币种、注册设备事实及来源。上级后来正常摘标签只影响之后的新接纳,不撤销已接纳好友。封禁及资金限制另在实际认定/领奖时校验。

标签数据尚未完成计算或关系通知迟到时保留原T与原版本,通过M2保存的规则和事实恢复判断。不能用现在的标签或开关追认历史资格,也不能把数据未知当成永久不符合。无法复原时显示“资格核查中”及后台原因。

### A11 · 有效下级标签判定

下级满足接纳时锁定的A3规则,且直属关系在其达标业务时点仍有效,才可进入计奖认定。标签判定调用M2共用条件能力,保存规则版本、评估业务时点、指标值、来源及命中结果;不在活动另建充值/投注统计逻辑。

标签可使用现有开放条件及AND/OR组合。累计充值金额沿用M2“成功到账的充值之和,不含后台人工上分”的定义,有效投注沿用玩法定义并排除无效注单;跨币种使用各原始事实发生时已保存的标准计价记录。活动不额外增加真实支付证明过滤,也不将标签充值指标等同于首充或限次比例赠送的资格判定。不得把“下级ID数量”当成已达标好友数,不得把登录设备数量当成跨账号计奖去重。

事件推动判定,注册天数等已开放的时间型条件到达判定边界时也触发评估;正常数据齐备后5分钟内更新活动达标结果,每日复核漏处理记录。依赖超时、历史换算缺失或事实不完整时显示核查状态并可恢复,不猜测指标值。数据补齐后按原业务时点判断关系是否有效。活动不以处理延迟额外增加一天等待。

首次认定有效时保存证据。之后标签普通变化、阈值版本更新、正常提现或后续输赢不反复增减人数;原充值退款、投注冲正等事实纠错按E5处理。所需版本化判定和证据输出是本活动新增的M2消费能力,不是既有当前命中集合已具备历史回查能力。

### A12 · 去重、名额和人数

同一运营商内,同一个下级在本活动只归其原直属上级,只能有一份有效认定及基础奖。注册设备标识采用M2注册时保存的稳定标识,不随以后登录设备变化。设备不可用时暂不认定,不把空值当独立设备或把全部空值合并成一个设备。

每次认定同时校验并占用该注册设备的K名额度和上级的N名额度。跨上级并发仍不能突破K,同上级并发不能突破N。以活动首次成功完成认定并固定证据的顺序占位,同次处理按稳定下级标识排序;重复和迟到处理不挤掉已经确认的名额。

后台分别保留“已占计奖名额U”和“当前有效人数C”。正常情况下两者相等。每新认定一名,U和C各增加1并生成基础奖;U≤N。未领取、退出页面、活动关闭或事实纠错不会将已占名额自动让给另一个账号。发生认定纠错时C可以修正,U仍保留,细节见E5。

条件满足但N或K已满的候选保存首次达标证据,显示“达标未计奖”及原因,不增加C、不产生彩金。提高上限后按保存的认定检查顺序恢复,再次核对原达标证据、达标时点的关系、当前账户限制及可用额度,成功后仍使用该候选原B/Y;普通属性后来变化不覆盖原达标事实,事实纠错另处理。任何候选都不能因为切换上级、配置改版、重新开启或刷新而重新占一份名额。

只使用用户ID和注册设备进行本版计奖去重,不增加注册IP门槛。M8注册风控的放行与拒绝决定注册是否成功,本活动去重独立决定已经注册的账号是否计奖;两者不能互相替代。

### A13 · 基础奖和里程碑额外奖

每名首次认定有效的下级生成一份基础宝箱,金额取其接纳时B,打码倍数取同一依据Y。基础奖励不按好友充值比例计算,也不向下级本人再发一份。

认定使上级当前有效人数C达到或超过里程碑k时,生成该档额外宝箱,金额为G、倍数为该档发布时Y。一次处理跨过多个门槛时逐档生成,不只取最高档。相同上级与同一里程碑身份终生只产生一份奖励记录,增加配置版本不能产生第二份。

新增更高里程碑发布后,按已有C检查并生成新档奖励;活动关闭时也应处理已经满足新增档条件的已有邀请人。已解锁奖励保存金额、币种、Y、来源和依据,与基础奖各自独立。正常标签变化、关系后续解除和活动关闭不删除已合法形成的宝箱。

达到最高里程碑后仍继续对上限N以内的新有效好友发基础奖。没有自动新一轮、每日清零或达到最高档后循环奖励。

### A14 · 手动领取与一键领取

宝箱生成即开放手动领取,无领取过期。玩家可以任选一个可领宝箱,或一键领取当前全部可领奖励,不要求先领低档,也不设每日领取次数。打开活动页、查看宝箱或好友达标均不自动入账。

受理时校验邀请人身份、运营商、奖励归属、实时账户/资金限制和原资金结果。后台只读查看,不提供代领、任意改奖或重置机会。

一键领取在受理时固定本次奖励清单,展示数量、总彩金及各自打码要求;之后新解锁的奖励不自动加入该批。每个奖励仍独立入账、独立建立打码任务,不能将不同Y的奖励相加后乘当前倍数。

每份奖励的彩金入账、对应账变/任务与成功领取记录必须一致完成。不同页面、单领与一键领取、不同请求编号并发指向同一奖励时,最多成功一次。结果未知保留原申请,查询并恢复原记录;明确未入账失败允许重试原奖励,不另建一份。

一键领取允许各奖励分别完成,页面清楚展示“已领取金额、处理中数量、失败可重试数量”。部分成功不得显示为全部失败,再次领取只处理尚未成功且未被其他申请占用的奖励;原处理中记录继续恢复,不重复请求发钱。

### A15 · 彩金、打码和其他活动

基础奖及额外奖都记为彩金来源,不增加真实充值金额、充值次数或首充事实。奖励A实际入账时建立A×其锁定Y的独立任务;未领取不入账、不建任务,旧充值和彩金任务保持不变。

充值本金打码倍数X不在本活动配置,好友自己的充值仍遵守其充值订单的X。本活动不排除该订单商品赠送、不占用限次比例奖励次数,与7.1代理返佣按各自规则分别计算。通用本金X与限次比例赠送依赖[KAN-248充值配置合并需求](https://bingobox.atlassian.net/browse/KAN-248),本活动只增加邀请彩金及其独立任务,不重做充值配置。

已入账彩金及打码任务不因活动关闭、标签变化或长期未使用而失效。可投注、可提现仍按平台模式、该币种全部未完成任务及资金限制判定,领取成功不代表立即可以提现。

### 玩家展示与计算示例

玩家看到基础奖励金额、里程碑额外金额、奖励人数上限和已占名额、当前有效好友数、下一档差额、可领取彩金及打码要求。对已接纳的好友显示其适用条件与基础奖励;不同版本条件不能用当前宣传金额覆盖。

好友列表显示已注册/未达标/已计入/未计奖或核查中的状态及必要条件说明。只展示关系内必要的昵称或脱敏标识和达标状态,不向上级披露好友余额、精确充值投注流水、IP、设备标识或其他上级的去重占位信息。人数已满时明确本活动当前不再产生新的基础奖励,不能继续展示无上限承诺。

## 4. 特殊情况

| 编号 | 情况 | 处理结果 |
|---|---|---|
| E1 | 旧关系、活动关闭期间注册、上级不符合标签或无合法直属关系 | 不接纳并保留判定原因;后来开启、补充资料或更换当前标签不把第二次事件当新注册 |
| E2 | 标签/关系事件重复、迟到或事实不完整 | 同一关系和规则依据恢复;未知标记核查中,不补造来源、不按当前版本改判,不得重复计数 |
| E3 | 标签规则编辑、停用或正常摘除 | 新接纳按活动已发布的有效规则;停用影响新接纳,已接纳用原快照;已认定人数和奖励不因普通标签变化撤销 |
| E4 | M7正常解除关系 | 解除时点之后才达标的候选不计入;解除前确已达标的迟到事实按原时点恢复,已合法认定和宝箱保留;原关系不可重绑 |
| E5 | 退款、投注冲正或错误原始事实使认定依据失效 | 核查期间暂停受影响奖励及该上级新增认定/里程碑发放。确认失效后将该好友从C排除,U与设备名额保留;其未受理基础奖及因C不足的未受理里程碑暂停,保存原记录金额。该好友再次满足原条件且原直属关系在该次达标业务时点有效,才可恢复原认定/基础奖;解绑前达标的迟到证据可恢复,解绑后新达标不能恢复。C再次达标可恢复原里程碑,均不增加U或重发已领记录。已受理/已入账进入资金核查,不由活动静默扣款 |
| E6 | N/K名额用完或注册设备不可用 | 前者标明达标未计奖,后者标明资料核查;不当作成功有效人数。提高上限或资料恢复后检查原候选,不覆盖已确认顺序 |
| E7 | 一键领取部分失败或结果未知 | 成功项保留成功;未知沿原申请核查,明确未入账失败才允许恢复原奖励;不整批重发、不重建成功项任务 |
| E8 | 奖励币种停用、资金服务不可用或倍数缺失 | 暂停对应领取,保留资格及原因;不改币、不默认0/1倍,恢复后继续原奖励 |
| E9 | 邀请人或下级被封禁/资金限制 | 候选认定时核对涉及账号限制,有影响则暂停认定;领奖时核对邀请人限制。解除后按原记录继续;已经认定的下级事后封禁不直接扣邀请人的已入账资产,作弊认定按E5核查 |
| E10 | 修改N/K、追加里程碑、关闭后重开 | 上限只增、旧档身份固定;按保存候选和当前C处理新增可用范围,不重新奖励旧下级或旧档 |
| E11 | 新增里程碑补发与好友达标同时发生 | 同一上级同一档只有一份奖励,额度及任务只生成一次 |
| E12 | 页面空、查询失败、保存冲突或无权限 | 分别展示空态、可重试错误、保留输入的冲突提示;服务端拒绝越权及跨运营商数据,处理期间阻止重复动作 |

资格纠错、资金核查和恢复均保存来源、操作者或处理依据。活动记录页只读,不提供人工把另一个账号塞入已占名额、直接改计数或重复发奖的入口;财务核查按既有受控资金流程执行。

## 6. 相关资料

### 入口、权限和记录

功能归属：活动管理→活动配置→邀请宝箱。配置和活动记录同页,不新增独立侧栏记录菜单。玩家入口显示个人邀请码/邀请链接、活动规则、好友进度和宝箱,邀请码仍由M7生成。

| 操作 | 权限码 |
|---|---|
| 查看配置、版本及内部记录 | `activity:invite-chest:view` |
| 编辑配置草稿 | `activity:invite-chest:edit` |
| 预览变更并发布 | `activity:invite-chest:publish` |
| 开启/关闭新接纳 | `activity:invite-chest:switch` |

修改操作须同时具备查看权限。记录查询按账号的运营商及推广商数据范围执行,跳转用户、代理或资金记录时再核对目标权限。

筛选包括上级ID、下级ID、关系标识、注册/绑定/接纳/认定/领取时间、规则版本、候选状态、奖励类型、里程碑及领取状态。候选状态区分未达标、核查中、达标未计奖、已计入、关系结束、认定修正;奖励状态区分可领取、领取处理中、已领取、暂停核查、失败可恢复。

详情保留上级资格、下级标签版本及指标依据、注册设备来源和去重结果、N/K名额占用、C/U变化、基础B/Y、里程碑身份/G/Y、发奖依据、单领/一键清单、账变/打码任务及异常恢复引用。后台可解释计数和奖励,不能编辑这些历史事实。

### 共用规则与责任

- M4拥有接纳、计奖去重及名额、有效认定、人数、基础奖/里程碑、领取依据和查询,决策索引为M4-D91。
- [M2标签](../../M2-用户管理/2.5-用户标签/README.md)及[条件模型](../../M2-用户管理/2.5-用户标签/条件模型.md)拥有用户条件、规则版本/快照和共用评估能力;M2还提供注册设备和账号限制。版本化消费须新增支持,不将活动人数作为这些标签的反向条件,避免循环依赖。
- [M7邀请关系](../../M7-代理管理/7.3-代理列表/README.md)提供关系标识、绑定和解除事实;[代理返佣](../../M7-代理管理/7.1-代理返佣/README.md)保持自己的计算及领取规则,其既有页面范围不因本活动扩大。

- [资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)、[标准计价](../../M2-用户管理/2.1-用户列表/标准计价.md)和[权限模型](../../M6-账号管理/6.2-角色列表/权限模型.md)分别维护资金/打码、指标计价与授权,本活动不另建钱包语义。
- [M8注册风控](../../M8-系统设置/8.1-风控参数/README.md)的注册拦截与查询窗口不决定本活动的累计设备计奖额度。
