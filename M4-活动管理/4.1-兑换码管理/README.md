# 4.1 · 兑换码管理

## 1. 背景与目标

**目标**:让运营自己发"兑换码"给玩家。玩家输入这串码,就能领到一笔小钱。
运营能定好:发多少个、每个能领到多少、谁能领,以及领到的钱要先玩一玩才能取走。
这一页就管兑换码:做码、看谁领了、随时开关和删。

**谁在用**

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 做码、发码、看谁领了、随时关掉 | 发个福利都要等程序员,慢 |
| 玩家 | 输入码领奖(在玩家端) | 没有简单的领奖方式,拉人难 |
| 财务 / 风控 | 看一共发了多少、有没有被薅 | 钱被小号领走也查不出来 |

**业务价值**:活动当天就能开,不用等发版;谁领了多少都有记录,花了多少钱看得清;
领到的钱要先玩够量才能提,少被人白拿。

**不做什么**

- **不做玩家端那个领奖页面** —— 这里只是后台,玩家看到的页面另外做
- **不做获取入口设置** —— 玩家端"去哪拿码"的引导文字和社群入口(Telegram / WhatsApp)首版不做,以后需要再另开
- **不做把码发出去的动作** —— 私信、邮件、活动位归别的地方,这里只负责把码做出来
- **不做加钱和打码本身** —— 这里只是触发,真正加钱、记打码由资金那边管
- **不做别的码类活动** —— 充值码、洗码等各是各的,不并进来

**适用范围**

| 维度 | 取值 |
|---|---|
| 终端 | 电脑后台,按 1440px 宽设计 |
| 响应式 | 最小支持 1280px;不做手机版 |
| 界面语言 | 后台用简体中文(线上还有葡语,按运营语言显示) |
| 时区 | 有效期、领取时间都按运营所在时区显示(GMT−3) |
| 货币 | 奖励按玩家的币种,默认巴西雷亚尔(R$);跨币种统计见 A9 |

## 4. 关键参数与假设

<!-- 所有阈值只在这里写一遍;数字本身在配置或写死,这里只说有哪些、什么意思、在哪填。 -->

| 编号 | 参数 | 取值 | 依据 | 在哪配 |
|---|---|---|---|---|
| A1 | 奖励类型 | **固定为彩金**(bonus,不是真金;领到要打够码才能提,见 A3 与 `资金模型.md`);系统写死,不作为表单字段 | 已定(2026-08-24) | 写死 |
| A2 | 奖励金额 | 填一个最小值和最大值。填一样 = 固定金额;填不一样 = 在两者之间随机 | 已验证(线上例:1 ~ 1.5) | 新增表单 |
| A3 | 打码倍数 | 领到的钱要玩够"金额 × 倍数"的流水才能提;能填的范围待定 | 语义已验证;**范围是假设**(线上例:15000) | 新增表单 |
| A4 | 有效期 | 到这个时间就作废,不能再领;按运营时区算 | 已验证 | 新增表单 |
| A5 | 生成数量与领取模式 | 一次做 `count` 个**各不相同的码**;每个码能被领几次,由**总上限** `reward_limit` 和**每人上限** `user_reward_limit` 决定;想"一码只用一次"就把每人上限设 1、总上限设成码数 | **已定(D37,2026-08-23)** | 新增表单 |
| A6 | 领取门槛 | "谁能领"的所有条件(充过多少钱、绑没绑手机等)**统一做成用户标签**,不在本页设独立字段(D39) | 已定(D39);依赖 2.5 | 用户标签(2.5) |
| A7 | 定向(选标签) | 选一个或多个用户标签,命中的人才能领;不选 = 人人可领;**多标签取并集**(要"同时满足"就在 2.5 做成一个标签) | 已定(D39);并集口径同 M7-A10 | 新增表单 |
| A8 | 随机金额规则 | 在区间里怎么随机(是否均匀)、保留几位、怎么进位 | **未验证假设** | 写死 |
| A9 | 金额与统计币种 | 发的钱按玩家币种;跨币种算成本时按标准计价 USD,对齐 `标准计价.md` | 已定(见 M2-D24) | 写死 |

> A5 领取模式已定(D37):一次做 N 个不同的码,每个码能领几次看上限。
> A6/A7 领取门槛与定向已定(D39):全部用用户标签实现,只选标签。累计充值金额 / 次数已是
> 2.5 基础指标;**"是否绑定手机"是否为 2.5 指标待确认,缺则需 2.5 补**。
> A1 已定:奖励固定为彩金,系统写死,表单不出选项。
> A3 范围、A8 分布还没定 —— 定之前按线上实测值理解,先不写死到界面。

## 7. 需求详述

### 4.1-R1 · 做兑换码

**触发条件**:有权限的运营点「新增」,在弹窗里填好规则,提交。

**可输入数据**:完整字段见 `新增兑换码.md`。主要有:奖励金额(A2)、打码倍数(A3)、
有效期(A4)、做几个和领取上限(A5)、**定向标签(A6/A7,门槛和定向都用标签)**、备注。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 填表和当场检查(最小别大于最大、上限要正整数、有效期要在以后);标签从 2.5 拉 |
| 服务端 | 再检查一遍;一次做出 `count` 个**不重复的码**;存下规则和码;判断权限 |

**处理逻辑**

1. 检查填的值:最小 ≤ 最大;数量和上限都是正整数;有效期在当前时间之后。
2. 检查定向:开了定向就得至少选一个标签,标签只能选启用中的(2.5)。
3. 生成 `count` 个不重复的码(去掉容易看错的字符),存进去;撞了就重试。
4. 默认启用;记下谁建的、什么时候建的;刷新列表。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 最小金额大于最大金额 | 最小奖励金额不能大于最大奖励金额 |
| 数量或上限不是正整数 | 请填大于 0 的整数 |
| 有效期在当前之前 | 有效期要晚于现在 |
| 开了定向却没选标签 | 请至少选一个标签,或者关掉定向 |
| 没有权限 | 没有操作权限(服务端也会拦,不靠藏按钮) |

**测试案例**

- 正向:填 1~1.5 元、打码 15000、做 100 个、总上限 100、每人 1 次 → 做出 100 个不同的码,启用,列表能看到。
- 逆向:最小 2、最大 1 → 界面和服务端都拦下,提示金额不对。
- 逆向:没权限的账号提交 → 服务端拦下,一个码都不做。

### 4.1-R3 · 开关兑换码

**触发条件**:有权限的运营在列表里切换状态,并二次确认。

**可输入数据**:目标状态(开 / 关);没别的。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 状态开关和确认弹窗;切完马上显示 |
| 服务端 | 判断权限;改状态;关了之后就不让再领 |

**处理逻辑**

1. 检查权限和要切成的状态。
2. 改状态;一关就领不了,已发的钱不收回。
3. 记下谁操作的、什么时候;没过期也没领完就能再打开。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 想打开一个已过期 / 已删的码 | 该码已过期或已删除,无法启用 |
| 没有权限 | 没有操作权限 |

**测试案例**

- 正向:关掉一个启用中的码 → 玩家端马上领不了,列表显示停用。
- 逆向:同时一开一关同一个码 → 以最后一次为准,状态不乱。

### 4.1-R5 · 看领取记录

**触发条件**:运营在列表里点「领取记录」。

**可输入数据**:翻页;可按玩家或时间筛选(见 `领取用户明细.md`)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 弹窗分页显示谁领的、领了多少、什么时候 |
| 服务端 | 判断权限;只给看自己该看的;敏感信息打码 |

**处理逻辑**

1. 检查权限和能看的范围(按运营方 / 代理分)。
2. 查这个码的领取记录,分页返回玩家、昵称、金额、时间。
3. 没人领就显示空。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 没有权限 | 没有操作权限 |
| 想看别人家的数据 | 服务端按归属过滤,不给越权数据 |

**测试案例**

- 正向:打开一个有 3 条领取的码 → 弹窗显示 3 条,信息齐全。
- 逆向:越权账号想查别家的记录 → 服务端拦下或返回空,不泄露。

## 8. 数据流向与系统串接

**数据流向**:运营填表做码 → 服务端检查后**做出一批不重复的码存起来** →
(玩家去领时)检查门槛和定向、定金额、记一条领取、通知加钱和记打码 →
后台列表和领取记录再读出来显示。

**系统串接**:

- 钱包和账变、打码(归财务):加钱和打码都走财务那边,带上"来源"标记;
  这里只触发,不自己改余额。
- 用户标签(归 M2,2.5):领取门槛和定向全靠它——领取时看所选标签命中了谁。
- 玩家充值等数据(归财务):由 2.5 拿去算标签命中,本页不直接读。
- **除了平台自己的钱包 / 标签 / 充值数据,没有别的外部系统。** 发码的通道(私信 / 邮件 /
  活动位)不在本仓库,它们只拿走这里做好的码,不参与做码和领取。

## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权 | 没权限的账号去做码 / 删 / 开关 / 看记录 | 服务端拦下;不靠藏按钮;记录不泄露 |
| E2 | 抢超了 | 快领完时很多人同时领同一个码 | 服务端加锁,领到的总数不超过总上限 |
| E3 | 重复领 | 同一个人对同一个码点了好几次 | 只算一次,不超过每人上限,不重复加钱 |
| E4 | 过期 / 关了还领 | 码已过期或已关还想领 | 拦下并提示;不记账、不加钱 |
| E5 | 乱填 | 最小>最大、上限填 0 或负、倍数乱填、有效期填过去 | 保存时服务端拦下,指出哪儿填错了 |
