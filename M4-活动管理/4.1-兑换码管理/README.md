# 4.1 · 兑换码管理

## 1. 用途

运营在这里生成兑换码,设置每个码能发多少钱、允许领多少次、哪些用户可以领。玩家输入兑换码后领取彩金,奖金按配置产生打码要求。

后台可以查询兑换码、查看配置和领取记录、启用、停用或删除兑换码。创建后的奖励规则不能修改;需要调整时,停用旧码并新建。

本需求包含玩家兑换时的资格检查、领取结果及财务处理要求,不包含玩家领奖页的视觉设计、社群入口设置,也不负责私信、邮件等发码动作。充值码等其他码类活动不合并到这里。

后台使用简体中文,其他语言按运营语言展示;以1440px为参考、最小支持1280px,不做移动后台。有效期及领取时间按操作员浏览器时区显示。奖金币种与成本统计规则见A9。

一码多领、标签条件及创建后不可编辑沿用[模块D37至D41](../README.md#7-决策清单)。单码预算、随机分配和异常恢复按本文及D86执行。

## 2. 查询条件

| 条件 | 含义和填写规则 |
|---|---|
| 兑换码 | 去掉输入前后空格、转为大写后按包含匹配,最多8个字符 |
| ID | 同一次生成的批次ID,精确匹配 |
| 状态 | 全部、启用、停用、已过期、已领完 |
| 创建时间 | 可选日期范围,不设默认范围,按操作员浏览器时区取整天 |

进入页面自动查询,修改条件后点击“查询”应用,“清空筛选”恢复不限条件。默认每页50条。服务端按运营方和账号可查看范围过滤,不能通过换查询条件看到其他运营方的数据。

## 3. 结果字段

列表一行是一个具体兑换码,不是一批码。

| 字段 | 含义 |
|---|---|
| ID | 所属批次ID,同一次生成的码相同,可复制 |
| 兑换码 | 玩家输入的那串码,可复制,点击打开详情 |
| 状态 | 启用、停用、已过期、已领完;同时满足时已过期优先,其次已领完 |
| 币种 | 创建时选定的奖励币种 |
| 奖励总额 | 这个码配置的总预算,不是整批预算 |
| 已领金额 | 已经实际领走的累计金额,与配置预算分开显示 |
| 领取次数 | 这个码成功领取了几次 / 最多可以领几次 |
| 领取人数 | 成功领取过的去重用户数 |
| 用户范围 | 领取对象;用户标签模式显示所选标签,最多直接显示两个,其余用“+N”折叠,点击查看全部标签。没有所选标签的码显示“所有用户”,指定用户模式的具体用户在详情查看 |
| 过期时间 | 超过这个时间就不能再领取 |
| 创建时间 | 生成时间 |
| 操作 | 详情;启用或停用,仅状态为启用、停用的码可操作;删除 |

金额必须标明币种,不同币种不能直接相加。跨币种汇总使用标准计价,实际奖金仍保留原币金额。

详情同时提供只读配置和该码的领取明细,奖励类型固定为彩金,单次金额区间、打码倍数、单人上限、领取对象、剩余金额及备注在详情查看。完整新增字段见[新增兑换码](新增兑换码.md),明细字段见[领取用户明细](领取用户明细.md)。

## 4. 操作规则

### A1、A5 · 一次生成多个码,每个码独立使用

奖励固定为彩金,不提供奖励类型选项。一次可以生成多个互不相同的码,新码默认启用,也可选择以停用状态创建。每个码各自拥有奖励总金额、总领取次数和单人领取次数,相互不占用。

例如一次生成10个码,每码预算100 BRL、总领取上限5次,表示每个码各有100 BRL预算和5次名额,整批名义预算为1000 BRL。这是单币种说明示例,不是默认配置。若想让每个码只能领一次,将每码总上限和单人上限都设为1,不是把总上限设为生成码数。

新生成的码为4位大写字母数字,排除0、O、1、I、L,单批最多1000个。生成时不得重复使用历史码值,遇到重复只补足缺口;可用码值不足时拒绝并提示减少生成数量。历史8位码仍可按其状态领取,直至过期、领完或停用。这些格式规则沿用原稿。

创建成功后保存操作者与时间,列表显示本次生成的各个码。没有新增权限时不得生成任何码。

### A2、A8 · 每次金额随机,总预算不能超发

每个码配置奖励币种、奖励总金额、单次最小金额和最大金额。生成数量为1至1000的整数,总领取上限为1至1000000的整数,单人上限为正整数且不超过总领取上限。三项金额都必须大于0,法币最多2位小数、加密货币最多8位小数,最大金额不小于最小金额。

预算必须满足:

**总领取上限×最小金额 ≤ 奖励总金额 ≤ 总领取上限×最大金额。**

每次按币种最小单位随机分配,小金额更常见、大金额概率更低。分配时必须保证剩余金额仍能在剩余次数内按合法区间发完,既不能提前发空,也不能把超出单次上限的余款留到最后。

以奖励币种最小单位计算:剩余预算B、剩余次数n、单次上下限m/M,本次合法区间为L=max(m,B−(n−1)×M)、U=min(M,B−(n−1)×m)。取0至1之间的随机数r,本次金额为L+⌊r³×(U−L+1)⌋且不超过U,越靠近下限的金额越常见。最后一次领取精确发完余款。

### A3 · 奖金到账后的打码要求

每次领取后产生的打码量为“实际奖金×打码倍数”,倍数为0时不产生打码要求。彩金与提现条件沿用资金模型。

打码倍数为0至100000、最多8位小数,必填;新增表单预填1。

### A4 · 有效期和启停

创建时有效期必须晚于当前时间。到期后不能继续领取,但仍可查看该码及记录。

有权限的运营可以在列表启用或停用,点击后立即生效。停用立即阻止新领取,已发出的彩金不收回。未过期、未领完、未删除的码可以重新启用;重新启用不重置已领次数和预算。

启停操作保留操作者及时间。提交时核对该码在列表读取后是否已变化,已变化就拒绝并提示刷新,不能仅根据界面显示判断是否可领。

### A6、A7 · 谁可以领

领取对象仅支持“用户标签”或“指定用户”二选一，所选内容必填；不提供“所有用户”模式。充值等组合资格仍在标签内定义，不增加独立充值或手机号条件字段。

用户标签模式：至少选择一个启用且计算完成的标签，领取时命中任意一个所选标签即可。要同时满足多个条件，在一个标签内组合。

指定用户模式：只接受一个用户 ID，不接受昵称、账号、手机号或多个 ID。保存时服务端校验用户存在且位于当前运营方及操作员允许的数据范围；领取时服务端核对当前登录用户 ID，其他用户即使命中标签也不能领。切换模式只保存、执行当前模式的条件，清除另一模式的残留值。

领取对象创建后只读；需要修改时停用原码并新建。指定用户不自动更改总金额、总领取次数、单人次数或有效期；停用、过期、领完、幂等及并发资金约束继续执行。KAN-241 为开发版规则变更，不提供旧“全体用户”兑换码兼容策略。

本版不提供手机绑定标签条件,兑换码资格不依赖该条件。

### 玩家提交兑换码

依次核对码是否存在(已删除按不存在处理)、是否到期、是否领完、是否停用,再检查当前模式的领取对象资格（标签或指定用户 ID）、本人的领取次数及汇率。标签模式下所选标签全部停用时拒绝,部分停用时只按仍启用的标签判断。全部符合后,才分配本次彩金。

同一领取申请反复提交不能重复扣次数或发钱,返回首次领取结果;申请标识被其他用户或其他码使用时拒绝。如果每人上限允许多次,用户后续新的合法申请仍可再次领取。多人同时领取也不能超过该码总次数、单人次数或预算。

连续5次提交格式错误或不存在的码,该账号冷却30分钟;成功兑换后清空失败次数。距上一次失败满30分钟后失败计数清零;冷却期间不接受兑换、不累计新失败。资格不符、停用、过期、次数用尽及资金失败不计为错误码。

### A9 · 奖金与统计币种

每个码创建时选择一个已启用的奖励币种,总预算及单次金额区间都按该币种填写,创建后不可改变。实际奖励按该币种发放到玩家对应钱包,不跟随玩家当前选定的钱包币种;玩家没有该币种钱包时自动创建。

每次领取保存实际入账币种、金额及折算USD使用的汇率、来源、时间和USD金额,USD只用于统计,后续汇率变化不改已发奖金。非USD奖励币种要求汇率在2分钟内更新;汇率缺失或过旧、钱包不可用或折算USD后为0时拒绝领取,不占预算和次数。

### 查看、删除与异常处理

- 已创建的配置只读。详情包含配置和领取明细,不提供编辑权限或编辑入口;要改规则就停用后新建。
- 删除需权限和确认。删除后从列表隐藏,不能再领取或启用,详情也不再可打开;历史领取记录保留,本版不提供已删除码的查询入口。
- 已过期、停用或领完时,显示不可领原因。尚无人领取时显示空记录。
- 输入非法金额、过去的有效期或无效标签,服务端拒绝并指出字段,不能只靠界面校验。
- 预算与次数扣减、奖金入账、打码要求及领取记录在同一事务提交,任一步失败全部回滚,不占预算和次数,玩家可重新提交;不存在处理中状态,不会显示领取成功却缺少对应资金结果。并发冲突时系统自动重试,仍冲突时提示玩家重试,不得重复发钱。
- 列表或详情取数失败时允许重试,不影响其他可用操作。敏感信息由服务端脱敏。

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 4.1-R1 | 有权限生成一批兑换码 | 数量正确且码值不同,每码独立预算和次数,默认启用 |
| 4.1-R1 | 最小金额大于最大金额,或预算无法按次数合法拆完 | 拒绝生成,指出错误字段 |
| 4.1-R1 | 数量非法、有效期已过、限定人群却未选标签,或无权限 | 拒绝生成,不产生部分错误结果 |
| 4.1-R1 | 发码遇到历史已用码值 | 不复用旧值,补足本批数量 |
| 4.1-R1 | 末次领取或多人并发领取 | 金额在合法区间,末次发完余款,不超预算和次数 |
| 4.1-R1 | 玩家当前钱包币种与码的奖励币种不同 | 按码的奖励币种入账,保存USD折算依据;预算按奖励币种扣减 |
| 4.1-R1 | 同一申请重复提交,或本人有剩余次数后新申请 | 重试不重复发奖;新的合法申请不被误判为已领过一次即永久拒绝 |
| 4.1-R1 | 连续提交格式错误或不存在的码 | 达到规定次数后冷却;成功兑换清空失败次数 |
| 4.1-R1 | 汇率缺失或换算后奖励为0 | 拒绝受理,预算和总次数、单人次数均不减少 |
| 4.1-R1 | 冷却30分钟结束后再次输入一个错误码 | 失败计数从1开始,不立即再次进入冷却 |
| 4.1-R2 | 打开详情 | 配置与明细均可查,配置不可编辑 |
| 4.1-R2 | 试图修改已创建码的金额或领取规则 | 拒绝,启停是独立操作 |
| 4.1-R3 | 停用兑换码后用户提交新领取 | 不可领取,已发彩金不收回 |
| 4.1-R3 | 对已过期、领完或删除的码尝试启用 | 拒绝;正常重启也不重置预算和次数 |
| 4.1-R4 | 确认删除兑换码 | 列表不再显示,不能继续兑换,详情不可打开;历史领取记录保留,当前不提供已删除码的查询入口 |
| 4.1-R4 | 无权限删除 | 拒绝,原码和记录保持不变 |
| 4.1-R5 | 查看某码领取记录并按玩家、时间翻页查询 | 仅返回该码且在本人可查看范围内的数据,金额带币种 |
| 4.1-R5 | 无领取记录或尝试越权查看 | 前者显示空,后者拒绝或过滤,不泄露数据 |
| 4.1-R6 | 按码、批次ID、状态、创建时间筛选 | 分页返回匹配结果,兑换码按包含匹配,未选创建时间时不限范围 |
| 4.1-R6 | 码在查看期间到期或领完 | 查询结果反映新状态,不能凭旧显示继续兑换 |
