# 4.1 · 兑换码管理

## 1. 用途

运营在这里生成兑换码,设置每个码能发多少钱、允许领多少次、哪些用户可以领。玩家输入兑换码后领取彩金,奖金按配置产生打码要求。

后台可以查询兑换码、查看配置和领取记录、启用、停用或删除兑换码。创建后的奖励规则不能修改;需要调整时,停用旧码并新建。

本需求包含玩家兑换时的资格检查、领取结果及财务处理要求,不包含玩家领奖页的视觉设计、社群入口设置,也不负责私信、邮件等发码动作。充值码等其他码类活动不合并到这里。

后台使用简体中文,其他语言按运营语言展示;以1440px为参考、最小支持1280px,不做移动后台。有效期及领取时间按运营所在时区GMT−3显示。奖金币种与成本统计规则见A9。

一码多领、标签条件及创建后不可编辑沿用[模块D37至D41](../README.md#7-决策清单)。单码预算、随机分配和异常恢复按本文及D86执行。

## 2. 查询条件

| 条件 | 含义和填写规则 |
|---|---|
| 兑换码 | 去掉输入前后空格、转为大写后精确匹配 |
| 状态 | 全部、启用、停用、已过期、已领完 |
| 创建时间 | 默认近30天,按运营时区 |
| 包含已删除 | 默认不选;选中后同时返回已删除码,详情与历史仅可查看 |

进入页面或修改条件后分页查询。服务端按运营方和账号可查看范围过滤,不能通过换查询条件看到其他运营方的数据。

## 3. 结果字段

列表一行是一个具体兑换码,不是一批码。

| 字段 | 含义 |
|---|---|
| 兑换码 | 玩家输入的那串码 |
| 类型 | 固定为彩金 |
| 奖励区间 | 单次领取的最小、最大奖金 |
| 奖励总金额 | 这个码配置的总预算,不是整批预算 |
| 打码倍数 | 每次实际奖金对应的打码倍数 |
| 领取人数 | 成功领取过的去重用户数 |
| 已领次数 / 总上限 | 这个码成功领取了几次,最多可以领几次 |
| 单人上限 | 同一用户对这个码最多可以领几次 |
| 有效期 | 超过这个时间就不能再领取 |
| 状态 | 是否可领,或因停用、到期、领完而不可领 |
| 领取总金额 | 已经实际领走的累计金额,与配置预算分开显示 |
| 创建时间 | 生成时间,带时区 |
| 操作 | 查看详情、启停、删除 |

金额必须标明币种,不同币种不能直接相加。跨币种汇总使用标准计价,实际奖金仍保留原币金额。

详情同时提供只读配置和该码的领取明细。完整新增字段见[新增兑换码](新增兑换码.md),明细字段见[领取用户明细](领取用户明细.md)。

## 4. 操作规则

### A1、A5 · 一次生成多个码,每个码独立使用

奖励固定为彩金,不提供奖励类型选项。一次可以生成多个互不相同的码,新码默认启用。每个码各自拥有奖励总金额、总领取次数和单人领取次数,相互不占用。

例如一次生成10个码,每码预算100 BRL、总领取上限5次,表示每个码各有100 BRL预算和5次名额,整批名义预算为1000 BRL。这是单币种说明示例,不是默认配置。若想让每个码只能领一次,将每码总上限和单人上限都设为1,不是把总上限设为生成码数。

新生成的码为4位大写字母数字,排除0、O、1、I、L,单批最多1000个。生成时不得重复使用历史码值,遇到重复只补足缺口。历史8位码仍可按其状态领取,直至过期、领完或停用。这些格式规则沿用原稿。

创建成功后保存操作者与时间,列表显示本次生成的各个码。没有新增权限时不得生成任何码。

### A2、A8 · 每次金额随机,总预算不能超发

每个码配置奖励总金额、单次最小金额和最大金额。生成数量、总领取上限、单人上限都为正整数;最小金额不小于0,最大金额不小于最小金额。

预算必须满足:

**总领取上限×最小金额 ≤ 奖励总金额 ≤ 总领取上限×最大金额。**

每次按币种最小单位随机分配,小金额更常见、大金额概率更低。分配时必须保证剩余金额仍能在剩余次数内按合法区间发完,既不能提前发空,也不能把超出单次上限的余款留到最后。

以标准币最小单位计算:剩余预算B、剩余次数n、单次上下限m/M,本次合法区间为L=max(m,B−(n−1)×M)、U=min(M,B−(n−1)×m)。区间内整数金额x的权重为U−x+1,按权重随机抽取;只有一个金额时直接取该值。最后一次领取精确发完标准币余款。

### A3 · 奖金到账后的打码要求

每次领取后产生的打码量为“实际奖金×打码倍数”。彩金与提现条件沿用资金模型。

打码倍数为0至100000、最多8位小数,运营必填,不预填默认值。

### A4 · 有效期和启停

创建时有效期必须晚于当前时间。到期后不能继续领取,但仍可查看该码及记录。

有权限的运营可以切换开关,确认后生效。停用立即阻止新领取,已发出的彩金不收回。未过期、未领完、未删除的码可以重新启用;重新启用不重置已领次数和预算。

启停操作保留操作者及时间。并发修改以最后生效的状态为准,不能仅根据界面显示判断是否可领。

### A6、A7 · 谁可以领

充值、指定人群等资格条件都在用户标签中定义,这里不增加独立的充值或手机号条件字段。

不限定人群时,所有符合其他领取规则的用户都可领。开启限定人群后必须至少选择一个启用中的标签;领取时满足任意一个所选标签即可。要同时满足多个条件,在用户标签中组合为一个标签。

“已绑定手机”由2.5用户标签的当前属性提供,取当前有效绑定事实,不要求在本活动内绑定。

### 玩家提交兑换码

先核对码是否存在、是否启用、是否到期或领完,再检查本人的领取次数及标签资格。全部符合后,才分配本次彩金并提交资金处理。

同一领取申请反复提交不能重复扣次数或发钱;如果每人上限允许多次,用户后续新的合法申请仍可再次领取。多人同时领取也不能超过该码总次数、单人次数或预算。

连续5次提交格式错误或不存在的码,该账号冷却30分钟;成功兑换后清空失败次数。冷却结束后失败计数清零;冷却期间不接受兑换、不累计新失败。资格不符、停用、过期、次数用尽及资金失败不计为错误码。

### A9 · 奖金与统计币种

每码总预算及单次金额区间使用平台标准计价币种USD,创建后不可改变。实际奖励按玩家当前选定钱包币种发放,未选择时使用BRL。每次领取要保存实际入账币种、金额及当时用于统计的汇率依据,后续汇率变化不改已发奖金。

受理领取时先分配标准币奖金、占用同额预算和次数,再按受理时汇率换算为玩家钱包币种,按该币种精度向下舍入并锁定。预算扣减始终使用分配的标准币金额;舍入差单独记录,不重新分配。缺少汇率、钱包币种不可用或换算后为0时拒绝受理,不占预算和次数。

### 查看、删除与异常处理

- 已创建的配置只读。详情包含配置和领取明细,不提供编辑权限或编辑入口;要改规则就停用后新建。
- 删除需权限和确认。删除后从普通列表隐藏,不能再领取或启用;历史领取记录保留。列表增加“包含已删除”查询条件,默认不选;选中后可按码检索只读详情及领取历史。
- 已过期、停用或领完时,显示不可领原因。尚无人领取时显示空记录。
- 输入非法金额、过去的有效期或无效标签,服务端拒绝并指出字段,不能只靠界面校验。
- 领取记录、奖金到账、打码要求及次数预算应保持一致,不能显示领取成功却缺少对应资金结果。受理时占用预算与次数;结果未知保持占用并查询原申请,明确失败且确认未入账后释放占用。成功后转为已使用。有效期或关闭不取消已受理申请,恢复时仍使用原金额、币种及倍数;不得重复发钱。
- 列表或详情取数失败时允许重试,不影响其他可用操作。敏感信息由服务端脱敏。

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 4.1-R1 | 有权限生成一批兑换码 | 数量正确且码值不同,每码独立预算和次数,默认启用 |
| 4.1-R1 | 最小金额大于最大金额,或预算无法按次数合法拆完 | 拒绝生成,指出错误字段 |
| 4.1-R1 | 数量非法、有效期已过、限定人群却未选标签,或无权限 | 拒绝生成,不产生部分错误结果 |
| 4.1-R1 | 发码遇到历史已用码值 | 不复用旧值,补足本批数量 |
| 4.1-R1 | 末次领取或多人并发领取 | 金额在合法区间,末次发完余款,不超预算和次数;按标准币预算分配并按受理汇率换算 |
| 4.1-R1 | 同一申请重复提交,或本人有剩余次数后新申请 | 重试不重复发奖;新的合法申请不被误判为已领过一次即永久拒绝 |
| 4.1-R1 | 连续提交格式错误或不存在的码 | 达到规定次数后冷却;成功兑换清空失败次数 |
| 4.1-R1 | 汇率缺失或换算后奖励为0 | 拒绝受理,预算和总次数、单人次数均不减少 |
| 4.1-R1 | 冷却30分钟结束后再次输入一个错误码 | 失败计数从1开始,不立即再次进入冷却 |
| 4.1-R2 | 打开详情 | 配置与明细均可查,配置不可编辑 |
| 4.1-R2 | 试图修改已创建码的金额或领取规则 | 拒绝,启停是独立操作 |
| 4.1-R3 | 停用兑换码后用户提交新领取 | 不可领取,已发彩金不收回 |
| 4.1-R3 | 对已过期、领完或删除的码尝试启用 | 拒绝;正常重启也不重置预算和次数 |
| 4.1-R4 | 确认删除兑换码 | 普通列表不再显示,不能继续兑换,历史记录保留;通过“包含已删除”查询历史 |
| 4.1-R4 | 无权限删除 | 拒绝,原码和记录保持不变 |
| 4.1-R5 | 查看某码领取记录并按玩家、时间翻页查询 | 仅返回该码且在本人可查看范围内的数据,金额带币种 |
| 4.1-R5 | 无领取记录或尝试越权查看 | 前者显示空,后者拒绝或过滤,不泄露数据 |
| 4.1-R6 | 按码、状态、创建时间筛选 | 分页返回匹配结果,创建时间默认范围正确 |
| 4.1-R6 | 码在查看期间到期或领完 | 查询结果反映新状态,不能凭旧显示继续兑换 |

## 6. 相关资料

**入口**:活动管理 → 兑换码管理。新增生成码,详情查看只读配置与明细,每行可执行启停、删除。玩家端视觉设计和发码通道不由本页承载。

| 操作 | 权限码 |
|---|---|
| 查询、详情、领取明细 | `activity:redeem-code:view` |
| 新增 | `activity:redeem-code:add` |
| 启停 | `activity:redeem-code:switch` |
| 删除 | `activity:redeem-code:delete` |

M4负责兑换码规则、具体码、资格判断和领取记录。M2提供用户标签,活动通过标签判断资格,不直接读取玩家充值来另算条件。M5负责奖金入账、账变和打码,提供统计所需汇率依据;活动不自行修改钱包。没有本活动直接调用的外部支付机构,发码通道只使用这里生成的码。
