# 4.10 · 签到奖励

<a id="1-背景与目标"></a>

## 1. 活动介绍

让玩家清楚知道每天可领多少、充值后能增加多少、漏签后如何恢复,在成本可核算的前提下提升持续回访。

### 使用者

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 设置各等级每日奖励、补签条件和连续奖励 | 配置复杂,难以核算一轮最多发多少钱 |
| 玩家 | 每日领取奖励,充值达标补足当天奖励或补漏签日期 | 先免费领取后吃亏,或漏一天就不愿再参与 |
| 客服 / 财务 | 查清奖励金额、补签依据和发放结果 | 无法解释少发、重复发或连续进度变化 |

提供可理解的回访激励,体现等级权益;有限补签恢复参与机会,不是购买签到或扣除充值余额。
效果观察区分真实到访与补签,比较参与前后或相近人群的回访、实际奖励成本与异常率;不把补签直接算作历史到访。

### 本次范围

- 不合并原表另一张「每日签到」充值投注档位活动,不做充值翻倍或七日循环降奖。
- 不重新建设等级、钱包、打码、提现或平台投注模式;不设活动专属冻结余额。
- 不做玩家端视觉设计;本稿定义后台配置及其对玩家业务的约束。
- 首版不做受众、独立渠道、未充值可领天数、随机宝箱、手工改进度或任意日期补签。
- 不以设备或 IP 相同单独认定作弊,复用平台风险判断;不新增自动扣款、自动扣回历史奖励规则。

### 适用范围

| 维度 | 取值 |
|---|---|
| 终端 | 桌面运营后台;玩家业务不按终端区分 |
| 响应式 | 最小宽度 1280px,不做手机版后台 |
| 界面语言 | 后台简体中文,玩家说明按运营语言展示 |
| 时区 | 统一使用平台业务时区并标注;不按设备时区或领取后的滚动时长切日 |
| 货币 | 充值条件用平台标准计价币种;奖励用活动币种,金额始终带币种 |

> 2026-09-09 补充跨签到切换边界:见模块 D83 和本页 A1/A10。已有日奖、补差、补签规则不变;新参与及新轮建立均校验运营商当前签到选择与用户其他签到进行中资格。

### 配置与草稿(4.10-R1)

进入配置页、复制等级、批量编辑、保存草稿。

允许保存不完整草稿;有值字段必须合法。复制与批量填写只影响选中目标;保存遇到其他人更新拒绝覆盖并保留输入。等级变动后提示补齐,不复制别级为默认奖励。

### 预览与发布(4.10-R2)

核对并发布。

输入信息：完整草稿及预览版本。

校验 A1–A15 和等级覆盖;预览全额、免费、差额、补签及节点的区别;确认后按 A9 生效。已有待生效版本时拒绝再次发布,先等待生效,首版不提供静默替换。

## 3. 参与和领奖规则

### 配置与周期(A1)

每运营商一套;首次主动参与建立个人周期,当日为第 1 天,共 30 个计数日;自然日推进,结束后次日自动开始下一轮,但仅在仍被选为允许新轮的签到活动时成立(模块 D83);已切换到其他签到时本轮结束即停止续轮,不靠重进页面重置。新老用户均可首次参与。

配置或来源：周期固定。

### 充值与免费(A3)

当日累计成功充值达到门槛发全额;否则按免费比例发。门槛为非负标准币金额,0 表示直接全额;免费比例为 0–99 的整数,0 表示不提供免费部分。首版不设未充值可领天数。

配置或来源：活动默认值,逐日可覆盖。

### 当天补差(A4)

已成功领取免费日奖,当日充值达标自动补差,总额不超过首次受理时锁定全额。仅成功日奖可触发,无需再点击;未主动签到不得因充值自动发日奖。不补历史日或补签日的差额。

配置或来源：固定；D75;不同于 VIP D61。

### 充值补签资格(A5)

充值达标赠资格,不扣余额;补签门槛为正标准币金额。每日最多获得并使用 1 次,达到更高充值金额不增加次数;每轮可成功补签上限配置为 1–3,默认值 3。金额无默认值,发布前须填。

配置或来源：门槛与每轮上限可配。

### 补签对象与奖励(A6)

当前周期内最近 7 个已结束且非停用豁免的业务日期的漏签格,优先最早者;不跨周期、不补未来;周期最后一日漏签不另设宽限期,页面提前展示该日为本轮最后领取日。资格当日有效,无漏签可补不顺延。按历史快照免费部分发奖,即使当日充值达标也不发过去的全额。免费金额为 0 时允许无日奖补签,必须明示仅恢复进度。

配置或来源：范围固定。

### 连续节点(A7)

节点固定为 7、15、20、30 天,全 VIP 共用各节点固定奖励;正金额,不另设充值门槛,自动额外发放。当前周期任一连续段达到节点即取得资格,每节点每周期仅一次;跨周期不承接连续长度。

配置或来源：节点金额可配。

### 版本(A9)

草稿不影响线上;发布后下一个业务日生效,首次发布也遵循该规则。日奖规则按各业务日生效版本,首次领取后锁定;节点金额及其打码倍数、币种和每轮补签上限在周期建立时锁定。补签门槛取补签当日版本,当日不变。首次有玩家参与后禁止换奖励币种,不提供结束旧周期强制换币入口。

配置或来源：发布操作。

### 充值事实(A11)

财务成功到账时刻归日,只计真实成功充值,赠金不算;不计人工充值。用入账时标准币金额累计,不按当前汇率重算。同一笔充值可同时满足日奖补差、补签及其他既有活动,不消耗充值额、不新增互斥。

配置或来源：财务提供事实。

奖励金额和充值门槛为必填运营配置,缺失即禁止发布。

**执行顺序**:先判平台风险限制及活动是否允许新受理,再按财务最新事实(包含已确认退款)判断资格,最后锁定奖励受理。解除风险后恢复未受理差额时仍须执行 A14,不能仅凭解除前曾达标就发奖。已受理奖励不追溯重算。A10 的紧急豁免仅用于平台级活动中断,不适用于个体账号封禁。

### 启停与周期(4.10-R3)

首次主动参与、业务日变化、启停。

输入信息：参与意愿或目标开关状态;用户不能指定周期起日。

按 A1 建立唯一进行中周期,首次参与不等于签到;未领日奖留下漏签格。按 A10 豁免停用日期,不自动发免费奖、不赠补签次数。周期结束封存,新周期重新累计补签额度与节点资格;旧周期已受理奖励继续结算。

### 正常签到(4.10-R4)

玩家主动领取当日日奖。

输入信息：领取动作,不得接受玩家自报等级、金额或充值统计。

校验活动、日期和领取次数,按 A2/A3 取奖励并锁定快照。免费取整为零时不可正常签到,提示达标后领取。受理后显示处理中,确认到账及打码结果才标记完成,再执行 R7。升级不产生第二次日奖。

### 当天补差额(4.10-R5)

当日成功充值、原日充值事实或原日奖发放结果补齐。

输入信息：可信充值及发奖结果。

按 A4/A11/A12 找到同业务日成功免费日奖,以原快照门槛判定。差额=锁定全额减已发免费额,每格最多一笔差额;不修改格状态、不增加连续长度。充值先达标而免费日奖后到账时也须重新判断,不能漏发。

### 充值补签(4.10-R6)

玩家申请补签。

输入信息：确认服务端提供的目标日期与预计金额。

按 A5/A6 校验当日充值、日额度、周期额度、可补范围及最早目标;已成功次数与处理中占用之和共同计入上限。同一充值可满足正常奖励条件,不得按金额整除发多次资格。受理后占用次数并锁定目标;正金额确认到账后完成补签,零金额按 A6 明示确认后仅完成格。随后执行 R7。

### 连续奖励(4.10-R7)

正常签到或补签格完成。

输入信息：周期内已完成格与节点发奖历史。

按 A7 判断当前周期所有连续段,补签可连接前后段,不只检查今天向前的长度。一次跨过多个节点分别发放未领节点;同周期另一段再次达到同节点也不重发。金额按 A9 周期快照,不随 VIP 改变。

### 发奖恢复与可追溯(4.10-R8)

任何奖励的受理、结果确认、重试及审计查询。

输入信息：原发奖依据与资金结果。

日奖、差额、补签奖、连续奖分别记录业务日期、周期、目标格或节点、原等级、配置版本、充值判定依据、金额币种、打码倍数、状态和资金编号。结果未知先查原结果;确认未到账才恢复原动作,不重新取配置。统计区分正常签到、补签、差额和节点,零金额补签不伪造资金流水。

## 4. 特殊情况

### 停用(A10)

三类签到切换是独立操作(模块 D83):停止本活动新轮但旧轮照常履约,不适用本条完整停用日豁免;旧轮完成后不自动续轮。普通停用仍按以下规则执行: 正常启停均从下一个业务日生效,提交停用当日照常参与。完整停用日统一豁免、不占周期天数、不计漏签,补签回看窗口也排除这些日期;恢复后继续原周期。已受理发奖及原日应得补差继续履约。首版不提供活动页即时停用;紧急风险由平台管控阻止新受理,已受理资金结果继续核查,受影响业务日对未完成且无在途签到的用户按系统故障豁免,已完成或在途者保留原格。

配置或来源：活动开关。

### 跨日与延迟(A12)

签到受理日期由服务端确定;日界前已受理而后到账仍归原日。充值通知或换算延迟按真实到账日追认应得日奖差额;不因通知到达次日挪用为次日充值。技术原因阻止已提交补签者保留原请求恢复,未提交的过期补签资格不自动转为历史签到。

### 退款与拒付(A14)

已确认退款或拒付按原充值到账日减去对应标准币金额,部分退款按原换算比例扣减,不得低于零。未受理的日奖、补差、补签资格以重算值判定;已失效补签资格不能使用。已受理奖励不自动追回、不改已完成格和节点,留退款关联供财务风控复核;后续新充值仅按其真实到账日产生资格。

配置或来源：财务事实与活动判定。

### 技术失败与快照(A15)

服务端记录合法签到/补签请求的业务日期、目标及依据;依赖事实未知时保留处理中,补齐后按原日期恢复,明确不合格才拒绝。历史等级或配置缺失须从可审计历史恢复,不可用当前值代替;系统故障导致整日无法受理且无成功或在途格时按 A10 豁免。周期封存不阻断已受理格恢复及由其达标的原周期节点发放。

| E5 | 临近日界 | 请求与到账分属两日 | A12 归属,不把通知日当充值日 |
| E6 | 最后一日漏签 | 次日进入新周期 | 不允许跨周期补签;提前展示截止日期 |

| E14 | 时区修改 | 周期运行中更改平台时区 | 保留原日期映射;首版禁止运行中切换活动业务时区 |
| E15 | 退款先于补签 | 曾获资格但补签前充值已退款 | 按原日扣减后重判,不足则拒绝;不扣玩家余额购买资格 |
| E16 | 退款晚于受理 | 补签奖已受理后发生拒付 | 原奖继续查结果,不自动删格或扣奖;保留拒付关联供财务风控复核 |
| E17 | 风险解除 | 原日差额曾达标但因风险未受理 | 按原日最新充值净额重判后恢复,不使用解除日充值填补原日门槛 |
| E18 | 历史周期恢复 | 周期末受理的日奖在新周期才成功 | 完成原周期格及应得原周期节点,不占新周期日奖或节点次数 |
| E19 | 在途补签占额 | 本轮成功次数加处理中次数已到上限 | 拒绝新的补签,不能仅按成功次数判断剩余额度 |
| E20 | 节点版本变化 | 周期中途发布新节点金额和倍数 | 原周期节点仍使用周期开始时金额及倍数;新周期使用其开始时版本 |

### 配置与草稿遇到异常时(4.10-R1)

越权拒绝;取不到等级或币种时不允许发布。

### 预览与发布遇到异常时(4.10-R2)

预览后草稿变化要求重新核对;活动币种变更不自动换算旧金额。

### 启停与周期遇到异常时(4.10-R3)

重进页面、更名、发布或开关活动均不能创建同日第二个周期;平台时区变更不得追溯重切已生成日期,首版运行期间禁止切换活动业务时区。

### 正常签到遇到异常时(4.10-R4)

充值统计未知不能当作零引导领取免费;请求跨日按 A12 处理。

### 当天补差额遇到异常时(4.10-R5)

差额处理中不重新创建奖励;次日的新充值不满足原日门槛。风险解除或退款事实变化后按 A13/A14 重判尚未受理的差额,不得绕过退款扣减。

### 充值补签遇到异常时(4.10-R6)

结果未知继续占用;确认未入账且动作终止才释放,恢复原请求不得绕过上限。历史快照缺失不得用当前 VIP 代替。跨日的原已受理请求按原日期结算。

### 连续奖励遇到异常时(4.10-R7)

节点发奖失败不撤销日奖或补签结果,只恢复该节点奖励。

### 发奖恢复与可追溯遇到异常时(4.10-R8)

退款/拒付按 A14 重新判定未受理资格,保留已受理记录和资金结果,不自行扣钱包、删签到历史或撤销已得节点。

### 页面状态

| 状态 | 表现 |
|---|---|
| 草稿 / 待生效 / 生效 | 显示版本和明确日期,保存不等于上线 |
| 配置不完整 | 定位缺失等级、日期及字段,禁用发布 |
| 停用 / 待恢复 | 提示个人周期顺延规则,不显示奖励被追回 |
| 日奖处理中 / 免费已领待补差 / 全额已领 | 分别说明到账状态与剩余资格 |
| 漏签可补 / 不可补 / 补签处理中 | 显示目标日、奖励、充值差额及限制原因 |
| 节点达标处理中 | 签到已完成,仅该笔额外奖励尚未到账 |
| 充值或模式未知 | 显示事实暂不可用,不能伪装未充值或无限制投注 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 4.10-R1 | 配置与草稿：进入、编辑、保存 | 覆盖等级与周期,批量编辑不改变线上 |

| 4.10-R5 | 当天补差额：成功充值、原日事实补齐 | 只补当日已签日奖差额,不重复签到 |
| 4.10-R6 | 充值补签：玩家申请补签 | 原日快照、次数限制、不扣充值余额 |
| 4.10-R7 | 连续奖励：签到或补签完成 | 重算连续段,达标节点逐笔一次发放 |
| 4.10-R8 | 发奖恢复与可追溯：资金结果返回、重试、记录消费 | 四类奖励可独立对账,结果未知不重复发奖 |

### 配置与草稿(4.10-R1)

正向,复制后仅目标草稿改变;逆向,只读账号保存被拒绝。

### 预览与发布(4.10-R2)

正向,新版本只影响生效日起日奖;逆向,免费比例非法或在用等级缺行不能发布。

### 启停与周期(4.10-R3)

正向,停用后恢复保留原进度;逆向,周期最后一日漏签不能在新周期补回。

### 正常签到(4.10-R4)

正向,免费领取完成当日格;逆向,两设备同时点击仅一笔日奖。

### 当天补差额(4.10-R5)

正向,先免费后达标总额等于锁定全额;逆向,重复充值通知或随后升级不增加差额。

### 充值补签(4.10-R6)

正向,补齐中间漏签格恢复连续段;逆向,同时提交多个日期只受理符合顺序且额度内的请求。

### 连续奖励(4.10-R7)

正向,补签连接两段后发放新达标节点;逆向,另一连续段重复达标不重复发奖。

### 发奖恢复与可追溯(4.10-R8)

正向,延迟结果恢复后可对账;逆向,重复结果不重复加钱或推进进度。

### 依赖与数据流

**数据流向**:运营草稿经服务端校验发布;玩家行为与财务充值事实进入活动判定;活动传递固定奖励依据给资金,资金结果回到活动进度与记录消费方。

| 交接 | 正向 | 逆向 / 失败 |
|---|---|---|
| M4 等级 → 签到 | 当前等级用于正常签到,历史等级用于漏签快照 | 等级未知或奖励缺档不受理资金发奖,按 A15 保留请求恢复,不得降档发奖 |
| M5 财务 → 签到 | 提供成功时刻与标准币金额,判日奖、补差和补签 | 失败充值不计;事实未知显示处理中,延迟按 A12 恢复 |
| 签到 → 资金 | 固定金额及来源申请入账和打码 | 结果未知查原发奖,不提交新奖励 |
| 资金 → 签到 | 确认后完成对应格或奖励状态 | 节点失败只恢复节点,不重发每日奖励 |
| 平台设置 → 投注侧 | 按统一模式判断充值前投注资格 | 模式未知不能默认放行;不影响已受理赠金依据 |
| 签到 → 玩家端 / 记录页 | 显示可领、处理中、补签依据及真实到账 | 已到账不等于可投注或可提现 |

**系统串接**:无直接第三方发奖系统;玩家端与玩法在本仓库范围外,需消费上述状态和投注规则。等级历史快照、财务事实和幂等发奖均为必须实现并验收的交付要求,不宣称现已具备。4.11 记录页未完成前不能宣称活动可上线。

### 预览与发布的职责(4.10-R2)

界面展示影响范围与规则摘要;服务端判权限、校验并记录操作人及差异。

### 启停与周期的职责(4.10-R3)

服务端拥有周期日、豁免日和历史记录;界面显示明确时间及顺延原因。

### 正常签到的职责(4.10-R4)

界面说明当前可领、全额条件及打码;服务端校验平台资格和真实财务事实。

### 当天补差额的职责(4.10-R5)

服务端自动判断并触发差额,资金负责实际到账和打码。

### 充值补签的职责(4.10-R6)

界面解释不扣充值余额、可补日期和额度;服务端按历史快照校验和计数。

服务端计算连续段,产生独立节点奖励;界面显示达标依据及到账状态。

### 发奖恢复与可追溯的职责(4.10-R8)

M4 保留业务记录,资金持有账变与打码结果;记录页只读消费。
