# 公共能力与复用边界

本文件负责定位已有规则及识别复用边界,不复制参数值、不新增统一技术架构或表结构。具体规则仍由引用的源文档拥有;“可复用”指需求语义与验收维度可复用,不代表后端能力已经开发完成。

## 先区分五件事

| 业务层次 | 回答的问题 | 示例 | 归属 |
|---|---|---|---|
| 事实 | 实际发生了什么 | 某笔充值到账、某日有效投注、直属下级关系 | 财务、玩法、M2/M7等原始事实拥有方 |
| 活动资格 | 这次能否参与或领取 | 单笔达标激活、当日充值和投注都达标、持有有效卡 | 各活动 |
| 奖励计算 | 发多少、按哪份规则 | 固定金额、比例奖金、随机结果、VIP档位 | 各活动 |
| 受理与结算 | 哪份奖励被领取、资金结果如何 | 锁定依据、领取处理中、入账成功、独立打码 | 活动拥有资格和奖励依据;财务拥有入账与打码结果 |
| 记录与复盘 | 如何查明原因和效果 | 来源充值、周期、档位、已领/失效、资金引用 | 活动记录页及其事实拥有方 |

同一笔充值可被多个活动读取,不等于只能给一个活动“消耗”;是否叠加由各活动规则决定。三类签到之间的新参与互斥不扩大为所有活动互斥。

## 已有规则唯一出处

| 内容 | 唯一出处 | 活动侧应该做什么 |
|---|---|---|
| 钱包、彩金来源、奖励入账后的打码义务和提现 | [资金模型](../M2-用户管理/2.1-用户列表/资金模型.md)及 M5 | 给出奖励金额、币种、倍数和来源依据,不直接改余额;领取成功不等于可投注或可提现 |
| 跨币种统计与入账时汇率依据 | [标准计价](../M2-用户管理/2.1-用户列表/标准计价.md) | 门槛按源文档确定的标准计价事实判断,奖励落真实币种;不把标准币派生值当可入账资产 |
| 标签、渠道属性、指标及业务时间范围 | [条件模型](../M2-用户管理/2.5-用户标签/条件模型.md) | 复用人群定向;不要另做渠道字典、余额统计或标签规则引擎 |
| 真实充值和订单状态 | [M5财务管理](../M5-财务管理/README.md)及资金模型 | 使用成功到账事实,并明确活动统计窗口、人工充值是否计入及退款政策 |
| 有效投注与盈亏 | 玩法原始事实、资金模型及条件模型的统计口径 | 不把充值量、原始投注、有效投注、净盈亏互换;活动侧说明需要哪个口径及哪段时间 |
| VIP等级及历史 | [4.6 VIP配置](4.6-VIP配置/README.md) | 只读等级,按具体活动规定的时点选档;不复制等级成长规则 |
| 代理关系和绑定 | [7.3代理列表](../M7-代理管理/7.3-代理列表/README.md) | 邀请活动读取关系,独立定义“有效下级”,不把用户关系搬到 M4 |
| 权限与操作日志 | [M6权限模型](../M6-账号管理/6.2-角色列表/权限模型.md) | 各活动声明权限点,跨活动切换同时检查两侧权限;服务端强制执行 |

## 可共用的需求形态

| 能力 | 当前参考 | 后续消费者 | 复用时必须保留的差别 |
|---|---|---|---|
| 充值事件与门槛 | 4.12-A1/A3/A9、4.4-A3/A10/A11/A25 | 首充奖励、额外充值奖励、复充类活动 | 单笔、当日累计、首充第几笔是不同事实;当前标签不能替代原充值发生时的顺序 |
| 周期和奖励进度 | 4.10-A1、4.12-A2/A5/A6、4.14-A1/A4/A8 | 各签到及神秘彩金 | 每日签到采用单档个人轮次,达标推进、未达标中断、下次达标重启;不能与只充值一次的活动共用推进规则 |
| 统计期与领取窗口 | 4.6-A6–A8、7.1-A4 | 每日签到、次日宝箱、日/周补偿金 | 统计日与领取日分别记录;领昨日奖励不能误用今日数据 |
| 固定奖励和独立打码 | 4.12-A4、资金模型 | 每日签到及各类任务固定奖 | 每日/活动统一倍数各有口径,不能全仓统一一个字段粒度 |
| 随机奖励及次数资格 | 4.1-A2/A8、4.4-A3/A10/A11/A25、4.2金额规则 | 金蛋、转盘、随机宝箱 | 兑换码每码独立预算并保留余款,跨币种扣预算待D86;刮刮乐发卡和刮奖分别计数;转盘还含实物、字母,不是同一分布 |
| 奖励依据与资金结果恢复 | 4.10-A8/A9/A15、4.12-A8/A11 | 所有新增发奖需求 | 复用可追溯和不重复发钱的要求;锁定时点、补发资格及终止规则逐活动指定 |
| 三类签到互斥 | [模块D83](README.md#7-决策清单)、4.12-A10 | VIP签到、七日签到、每日签到 | 只控制新轮;切换后旧轮履约,与活动普通停用不同 |
| 活动记录的公共查询信息 | 模块数据归属、现有兑换码领取明细、4.10/4.12记录要求 | 各活动记录页 | 可复用参与人、依据、规则版本、奖励与资金结果展示;周期、卡、节点或下级明细仍独立,不强行合成一个记录页 |

## 不应强行统一的规则

| 看似相同 | 当前差异 | 文档处理 |
|---|---|---|
| 选多个标签 | 兑换码、红包雨取并集;VIP奖励领取要求同时满足(不用于等级判定);刮刮乐按4.4-A6取任意命中 | 引用各页的 AND/OR,禁止设置一个跨活动默认值 |
| 免费后充值 | 4.10 当天允许补差;4.6 VIP周/月/投注返现领过免费部分不补差 | 不抽象成一条通用“充值补全奖励”规则;4.6未领金额时点另见D88 |
| 配置生效 | 兑换码创建即冻结;红包雨规则下一场;4.10/4.12按发布业务日及各自快照 | 共用版本和审计的需求,不统一生效时刻 |
| 停用 | 4.12只停止新激活;4.10普通停用会豁免日期,跨签到切换另按D83 | 必须写明新资格、旧轮、待领取和在途资金分别如何处理 |
| 过期 | 卡片/领取资格可以到期;4.12保留模式没有整轮到期;已入账彩金及打码遵循资金模型 | 不将资格过期实现成钱包扣款或打码义务过期 |
| 有效客户 | 代理关系是原始事实;邀请宝箱、多代理宝箱需要不同充值/投注/去重门槛 | 共用关系查询,不沿用佣金的判档或默认认定“有效” |
| 补算或退款 | 4.12明确恢复技术迟到资格并按净额处理退款;刮刮乐新版明确异常充值/退款/封禁未纳入本期 | 不把七日签到的异常政策反向覆盖其他已定活动 |

## 三类签到对照

| 维度 | VIP签到（4.10） | 常规七日签到（4.12） | 每日签到（4.14正文） |
|---|---|---|---|
| 参与 | 主动参与,新老用户均可 | 单笔充值达标激活 | 单档达标自动参与,无需报名 |
| 日奖依据 | 领取时等级及当日日奖;免费比例/充值全额 | 激活快照中的固定奖励 | 当日充值与投注同时达标,金额可配 |
| 周期 | 当前PRD为个人30个计数日 | 七份奖励,保留模式可延长 | 固定个人周期,达标推进,断后重启及自动循环,见4.14-A1/A8/A10 |
| 后续充值 | 可触发当天补差及补签资格 | 不重置、不另开轮,不增加日奖 | 当日双条件达标推进,中断后再达标从新轮首日开始 |
| 额外奖励 | 当前PRD的连续节点及补签规则 | 无连续额外奖、无补签 | 本轮连续完成时额外奖励一次,统一打码,见4.14-A5/A9 |
| 领取日期 | 按现有PRD日奖和补差口径 | 当天领取,后续每天一份 | 当日/次日为最早领取日,历史达标奖保留至本轮截止;中断边界见D84 |
| 漏领奖励 | 按4.10日奖、补签和补差规则 | 保留模式停在未领份额 | 漏领不影响达标推进,可一次补领多份,本轮领取截止后失效 |

这张表是引用导航,不能用来推翻具体页的已定规则。运营对VIP升级次日奖更高的表述,不自动改成“已受理奖励跟随等级重算”。

## 新活动起草时的共用核对项

以下是文档写作检查,不是面向运营增加一套万能活动表单。每个新活动在“运营配置”和“参与和领奖规则”中明确自己的取值,已有活动无需被迫回填新字段。

1. 事实与条件:依赖谁、单笔或累计、业务日期、币种、是否包含人工充值;条件有未知状态时如何处理。
2. 资格与进度:激活时点、进行中再次充值、同活动/跨活动并行、漏领和循环、资格到期。
3. 奖励与领取:固定/比例/随机、中奖结果锁定时点、领取窗口、奖励打码倍数、重复请求依据。
4. 变更与异常:草稿/发布、旧参与者权益、停用、退款、平台故障和个体风险限制的区别。
5. 查询与验收:参与依据、规则版本、奖励结果、资金引用、失败/处理中/失效原因及活动特有维度;配置页和记录页分别登记。

## 本次发现的文档一致性问题

刮刮乐卡片修订已合入4.4正文,原A/R编号继续用于引用。复用时按现行的充值发卡、刮开结算和分别计数规则理解;卡片边界及Jira来源差异见模块D85,不从Git历史恢复已失效规则。

标准计价原文的“不作资金判定依据”指余额、打码及提现等原币资金判断;活动用标准币做充值门槛筛选不产生标准币资产。这里定位两者区别,不修改底层资金规则。
