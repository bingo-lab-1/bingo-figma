# 4.19 · 幸运转盘

运营阅读入口：[页面设计与运营评审](页面设计与运营评审.md)说明转盘怎么呈现、玩家怎么操作及后台怎么配置；[配置示例与成本测算](配置示例与成本测算.md)提供可复算样例。下文定义正式业务规则及验收，不表示功能已经开发上线。

## 1. 活动介绍

玩家参加本期活动后，每天可领取基础券体验转盘；本期真实充值累计达到阶梯，获得进阶券。两种券分别进入各自奖池，每次抽奖产生一份正金额彩金；本期进阶抽奖达到里程碑，再增加一份确定金额的彩金。玩家手动领取后才入账并建立独立打码任务。

基础券提供可实际领取的体验奖励，充值阶梯明确新增机会，里程碑提供随机结果以外的确定权益。提高充值意愿是设计目标，效果通过实际参与、充值及奖励成本验证；示例金额不代表已验证的转化效果。

### 范围与玩家体验

- 每运营商维护一个幸运转盘活动身份，包含基础池和进阶池；可保存、复制配置草稿并按期发布主题版本。基础赠券可关闭，进阶池与充值阶梯必须配置。
- 奖品使用同一真实奖励币种的彩金。首版不提供实物、字母收集、现金购券、券交换、再来一次或奖券作为奖品；不按投注量、亏损、充值笔数追加机会。
- 同一版本、同一奖池所有券采用相同概率。充值提高可得券数，不改变单券中奖概率；不按个人盈亏、VIP、渠道或资金压力暗改结果。
- 玩家依次看到“本期规则与参加”“两种券及奖池”“充值阶梯”“进阶里程碑”“待领彩金与记录”。配置值、进度和结果由服务端提供，布局由 Figma 表达。
- 充值前展示下一档所差的有效金额、新增及累计券数、进阶奖项概率、券期限、领取后的打码义务，以及商品赠送是否另行获得。达到末档后明确显示本期充值赠券已达上限。
- 免费中奖和已经获得的彩金均不以再次充值为领奖条件。平台既有账户限制、投注及提现规则继续执行；领取前说明彩金任务会影响相应币种钱包的提现。

后台使用简体中文，最小宽度 1280px；玩家文案随运营语言展示。采用运营商业务时区，周期截止展示准确日期、时间和时区。充值门槛使用原入账 USD 标准金额，奖励使用选定真实币种；两者分别标注，不把 USD 统计值当作资产。

### 转盘与操作设计

玩家端采用一个活动页、一个转盘区域切换基础／进阶奖池，每个有效奖项对应一个等角度格子。格子大小不代表概率，盘面附近常驻概率入口及说明，金额清晰可读。奖项按配置顺序展示；顺序仅随版本发布，不改变权重。具体信息、按钮状态、中奖流程和后台预览按[页面设计与运营评审](页面设计与运营评审.md)执行，视觉稿由Figma维护。

本期参加、当前用券和历史领奖分别判断资格。新期未参加、标签不符或停止接纳时，历史券及待领奖入口仍保留；选旧批次后，其奖池、币种、概率、截止和节点同时切换，旧期不再提供充值达档引导。免费奖可领取，充值只增加进阶机会，已到最高档明确提示本期不再赠券。

### 奖池、充值与里程碑

| 编号 | 配置项 | 填写与执行规则 |
|---|---|---|
| A9 | 两池奖项 | 各 6～16 个有效奖项，必填；可重复金额，每项有稳定标识、名称（1～30字）、金额和权重。金额大于0且不超过1000000奖励币种单位，符合币种最小单位；基础券关闭时可不配置基础池。表格顺序即盘面顺序，可在草稿调整，随版本发布且不影响权重 |
| A10 | 权重与概率 | 权重为 1～1000000 的整数；概率只读计算为该项权重／本池总权重。删除或停用项不进入新版本转盘，不能以零概率大奖占展示位。概率展示至少4位百分比小数，极小值标“低于0.0001%”并可查看精确权重比 |
| A11 | 彩金打码倍数 | 基础池、进阶池、里程碑各配置一个 Y，必填，1～10、最多2位小数；未启用的部分不用填。范围是本活动的产品选择，充值本金 X 仍由5.5维护 |
| A12 | 累计充值阶梯 | 1～10档；每档“累计门槛USD＋本档追加进阶券”。门槛为正数、最多8位小数、严格递增；追加券为1～100的整数，各档合计最多1000券。无自动默认奖励，不配置“每笔首充”或重复循环档 |
| A13 | 固定里程碑 | 可关闭或配置1～5档；“累计成功进阶抽奖数＋本档额外彩金”。抽数为严格递增的正整数且不超过A12累计最大券数；每档金额为正、最高1000000奖励币种单位，且符合币种最小单位与精度，不以发奖时舍入补救非法配置。每档每期一次，跨档奖励叠加，不是最高档替代前档 |
| A14 | 预算管理 | 选择“预计费用预警”或“最大承诺硬上限”，必填无默认；预算额为正数，单位与奖励币种一致。预警比例为1～100整数，默认80；两种方式均显示最大可能承诺，具体计算见A23 |

基础券和进阶券的名字可修改，类型身份不可互换。后台同时展示两个奖池的最低／最高彩金、单券期望金额及打码倍数；进阶池最低金额不得低于基础池最低金额，单券期望必须严格高于基础池，避免把同等奖池标为升级权益。各项概率合计来自精确计算，显示舍入不改变实际结果。

充值阶梯同时预览“本档追加”和“到本档累计”。里程碑预览单独列示确定彩金，不混入中奖概率，不宣传为某次必中大奖。奖池、阶梯、里程碑和预算可加载模板，模板只填草稿，发布前仍须完整核验。[配置示例与成本测算](配置示例与成本测算.md)提供一套可复算的周活动样例。

### 保存、发布和启停

草稿可不完整，已填非法值拒绝保存；发布要求所有启用部分完整、可兑现，展示与上一版本的差异、预计成本及最高责任。保存、发布、接纳开关、导出均按独立权限检查并记录操作人、时间及前后值；发布不自动开启。

后台按时间与人群、奖励与基础券、奖池、充值阶梯、固定节点、预算顺序填写，并提供玩家视角预览。预览使用当前草稿，标明模拟数据；覆盖未参加、免费体验、跨档、末档及旧券场景，不产生真实参与、券、充值或资金记录。字段要求及成本计算仍以A1～A14、A23为准。

首次发布用于尚未接纳任何人的当前周期；一旦本期已有参加记录，金额、概率、阶梯、人群、免费次数、倍数、币种、宽限与预算模式等业务修改统一从下个完整周期生效。本期已经展示并接纳的规则不改。当前名额和硬预算只允许增加；减少只能预约下一期。名称、图片和说明也随业务版本发布，不能即时替换旧券对应的奖项含义。

停止接纳或到达计划结束时间，只阻止新的本期参与；已参加者本期免费领取、真实充值赠券、抽奖及领奖继续按原版履约。恢复接纳使用本期原版本，不新建周期、不补历史免费券。新一期尚未参加者须重新核验并明确点击参加，单纯浏览、登录或充值不自动占名额。

## 3. 参与和领奖规则

### A15 · 参加与锁定本期规则

玩家登录后先看到本期规则、奖池概率及剩余接纳状态。点击“参加本期”，服务端检查时间、开关、标签、账户限制、人数和预算容量；成功后保存本期版本、人群依据、参与时间及本期完整权益。参加动作不扣款、不生成本金或彩金任务。

本期参加一次，跨设备和重复请求返回同一记录；复制草稿、重新发布和关闭重开不能创建第二份资格。普通摘标或标签规则修改不撤销本期资格，新一期重新检查；平台级账户限制仍实时执行。资格信息未知时显示核验失败，不把缺失结果当作符合。

标签依据记录本次读取时间、命中集及其可追溯的规则版本。刚满足VIP、渠道等条件但M2命中集尚未更新时，按当前未命中处理，提示资格更新后可重新检查；不承诺参加动作触发实时重算。选定标签停用后不再作为新参与的命中依据，已有本期权益按原记录保留。

本期进度从参加成功的服务端业务时刻开始，只统计该时刻及之后、周期结束之前的有效充值。参加前充值不追补；玩家未参加时，活动内充值入口先完成参加与名额确认，再进入普通充值页面。用户从其他入口充值且未参加，也不补算，页面须事先说明。

进入充值前同时说明“按真实充值成功时间归期，参与资格不跨期”。旧期发起、新期才成功的充值不能计回旧期；只有新期已参加且参加时点不晚于该笔业务成功时点，才计入新期。未满足时明确显示该笔未计入的原因，不长期显示处理中，不自动参加或要求再次充值修复。

### A16 · 每日领取基础券

参加后在当前运营日点击领取，按本期A6一次发足当天券数；当天重复领取只返回已领记录。注册日不额外叠加一份，连续登录不另乘系数。未领取额度不会结转，已经领取的券保留至本期券截止，跨日后可使用。

基础券仅进入基础池，不参与进阶里程碑。每份券保存所属期、版本、来源日及截止时刻；关闭活动后，已有本期参与者仍能领取本期剩余运营日的额度。异常恢复只修复已受理的领取，不把离线未领取日补成新权益。

### A17 · 充值累计与阶梯赠券

读取M5真实成功充值及修正，包含有真实支付依据的商品订单、符合财务确认标准的Crypto入金和真实补单；排除人工余额调整、无真实支付人工单、彩金、内部转账和未成功款项。5.5固定／比例赠送与本活动分别计算，转盘不消耗其奖励次数；4.15翻倍专用订单只排除既有5.5赠送，不额外排除转盘。

采用财务提供的原入账USD标准金额及原业务成功时间。不同币种共同累计，保留8位小数，部分退款等修正沿用原标准金额依据，不使用当前汇率。缺少汇率或归期事实时显示该笔“活动计数处理中”，充值本金照常处理；补齐后按原时点恢复，不能要求玩家重新充值。

设本期有效累计充值为S，阶梯门槛为T1…Tk，本档追加券为q1…qk。达到S的累计应得券数为所有 `Ti≤S` 的 qi 之和。每个阶梯只存在一份赠券记录，以已确认发放状态补齐，不能将重复支付通知再加一遍。

一笔跨过多档时一次补齐所有新增档；拆成多笔但累计相同时获得相同总券数。超过最高档不继续循环赠券，提现不重置累计进度。赠券只增加机会，不扣充值本金，也不改变本金X或新增本金打码任务。退款、迟到及补单按第4节处理。

### A18 · 券版本、归期和截止

券按基础／进阶、所属周期和版本分别记账，不能转让、兑换现金或换池。同类券默认选截止最早的周期批次；玩家可以选择其他批次，抽奖前明确展示实际要使用的版本、奖池和截止，旧券不拿新奖池做宣传。选定批次后，按券截止时间、阶梯门槛从低到高、稳定券序号依次消耗；基础券以来源日期代替阶梯门槛。来源在受理时锁定，玩家不能选择同批次中某张高档券来改变退款归因。

过期前未受理的抽奖不能开始；过期只结束券的使用权，不删除抽奖结果、待领彩金、钱包或打码任务。周期结束后用旧进阶券，仍推进旧周期里程碑，不计入新一期。故障延长只改变受影响券的截止，不把其本金累计期一起延长。

原业务时间符合本期的真实充值，即使回调、补单或标准金额到齐时已跨期，仍补发原期原版券。仅对首次确认发出的迟到券：若发出时原截止已过或剩余不足A7天，截止延长至实际可见时刻＋A7×24小时；重复通知不反复延长。已经发出后因退款等原因冻结的券按E6恢复，不重新套首次补发期限。对应里程碑仍可由这些券完成，历史周期入口保留。

### A19 · 每次抽奖与结果

一次操作消耗一张指定类型的有效券，产生一个确定奖项。服务端统一完成券占用、按该版本权重随机选项、唯一结果及进阶抽数推进；不能出现最终只扣券而没有结果。券无需额外支付，不提供自动连转或一键消耗全部券。

每次独立按 `p_i=w_i/Σw` 分配结果，不因前次结果、累计充值、里程碑、可用预算或实际奖品支出改变概率。同额多个奖项可以分别显示，金额总体概率为这些项概率之和。转盘格子大小和动画不表示等概率；规则入口列出实际概率。

结果以服务端已保存记录为准，动画只呈现结果。重复点击、跨设备并发与超时重试返回原结果；未知状态先查询，不能再扣券或重抽。确认未受理的请求不扣券；已受理但记录不完整的请求恢复原处理，不能通过重新开一局弥补。中奖彩金形成独立待领资格，不自动入账。

已确认结果后动画约2～3秒，可跳过；减少动态效果时直接呈现结果。动画前不预示奖项，不以停在大奖后滑走制造另一结果。结果层区分正常奖与同时达成的节点奖，显示待领取、金额、倍数及所需打码；允许稍后领取，有券时逐次手动再抽。关闭弹层、刷新和跳过都不丢奖、不重抽、不自动领取。

### A20 · 固定里程碑

只计算同一期成功保存结果、且其来源阶梯仍有有效充值依据的进阶券抽奖，基础券、动画次数、请求重试和领奖次数不计。节点达到时形成该节点唯一的额外彩金资格，金额和倍数使用本期快照，独立于当次抽中的奖项。退款纠错可能降低有效抽数，原始开奖次数和结果不删除；失去抽数支持的节点依E5核查，恢复达标仍使用原节点身份。

例如完成3次额外得1 USD、完成8次再得3 USD，完成8次累计节点奖为4 USD；第3及第8次抽奖仍按原概率另得正常奖。节点达到后即使玩家尚未领取此前奖项，也不阻止后续节点产生；超过末节点不循环，不因关闭重开重领。

### A21 · 领取、入账与记录

玩家可逐份或一键领取可领彩金。领取前展示实际币种、金额及每份倍数和所需打码；一键领取逐份提交并显示各份成功／处理中／失败状态，不把不同倍数合并套用一个值。已成功部分不能随整批重试再发。

奖励列表按真实币种分组，每组提供领取可领奖励操作；待核查、资金处理中和已经成功的奖励不纳入新的批量领取。不同币种金额不直接求和，未领、待核查和已到账各自标明。

待核查及已取消资格保留原记录和原因，不计当前可领取金额。单份资金处理中只阻止该份重复领取，不影响其他有效券抽奖或其他合法奖励领取；开奖未决与资金未决分别处理，不把一个奖励的等待扩大成整页停用。

彩金及节点奖由M4提供确定金额、币种、倍数、奖励来源，M5以原奖励唯一依据入账，同时建立相应独立任务；资金成功前不能显示已到账。未领资格不是余额，不建立任务，不影响原有钱包；领取后沿用[资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)的单币种钱包、独立打码和提现规则。

重复领取返回原结果；资金状态未知保留处理中并查询原申请，确认未入账失败才允许恢复同一奖励。开奖、领取和资金完成分开统计；派奖失败不退券重抽。中奖及已达标节点资格不因活动结束、未充值、普通摘标或改版被收回；用于获券的充值事实被撤销时，受影响资格按E5暂停核查，不能绕过核查领取。

### A22 · 版本、暂停及恢复

已接纳用户本期全部阶梯与里程碑保持原承诺，不能只冻结已发券、随后缩小未达标阶梯。旧版本继续运行至原券和奖励处理完毕；下一期更低预算或更少奖项不回溯旧期。

普通接纳开关不能暂停旧权益。平台故障、币种停用等导致无法使用券时，记录受影响对象及实际阻塞时段，恢复后将受影响券截止按实际阻塞时长顺延；已经到期的无关券不复活。平台账户限制期间按原限制处理，无运营手工重置进度、赠券、改中奖结果或清除资金任务的入口。

### A23 · 成本预览与预算控制

每池显示单券期望 `E=Σ(p_i×a_i)` 及最高奖 `M=max(a_i)`。某档累计有n张进阶券，若全部使用，其进阶预期成本为 `n×E进阶＋所有抽数门槛≤n的节点奖之和`；基础券单列。不得用打码倍数给彩金成本打折，也不能把预期费用宣称为实际支出上限。

每期接纳用户时，先计算该用户剩余可领取基础券总数b（包含当天、只含本期）、本期最大进阶券数q，以及全部节点奖合计G。最大可能承诺为 `L=b×M基础＋q×M进阶＋G`，基础券关闭时首项为0。这是最大责任，不是预计会发出的金额；未达到的充值档也包含在已承诺的可获得范围中。

| 模式 | 接纳与超额处理 |
|---|---|
| 预计费用预警 | 按最多券数与单券期望累计本期参与者的预期费用，并计入全部可能节点奖；达到预警线及预算额分别告警，实际费用可超过该数。名额仍限制新参与人数，不能因此限制已参加者赠券或中奖 |
| 最大承诺硬上限 | 每接纳一人，按L预占其完整本期权益；本期“已实际发放＋尚未履约预占”加新L不得超过B，否则在参加、充值前拒绝新的本期接纳。硬上限是该预算币种的金额，不以USD换算估值替代 |

抽奖锁定结果后，把该券最高奖占用改为实际待领金额，多余占用释放；付款只是预占转为已发放，不恢复为可重复花费的预算。未来免费日及未达标阶梯的承诺不能提前释放；退款造成的冻结或取消，在本期累计尚未结束或财务事实尚未齐备时仍保留可能恢复的额度。期末确认事实齐备后才能释放不可能再取得的额度，未知充值继续保留。到期未用券可释放对应占用及已经不可能达成的节点额度。

迟到事实、故障恢复及纠错必须先补原承诺；若此前事实齐备判断错误、额度已经释放，显示恢复负债和超额，暂停新接纳直到覆盖，不能拒付或重抽旧权益。跨周期报表同时展示本期新增承诺与历史未履约余额；每期预算重置不把旧责任清零。

后台必须并列显示：规则期望成本、最大责任、已承诺未使用、已中奖待领取、资金处理中、实际发放、释放占用和恢复负债。基础／进阶／节点奖励分列。页面提供至各条来源记录的追溯，不提供“按预算自动调概率”。

## 4. 特殊情况

| 编号 | 情况 | 处理 |
|---|---|---|
| E1 | 未参加、无名额、标签未知或不符合 | 不记活动充值进度、不扣款、不发券；参加前说明原因，普通财务充值仍按自身规则办理 |
| E2 | 首次领取、最后名额或同一张券被并发请求 | 各业务唯一依据只成功一次；失败方看到已有领取／参与／抽奖状态 |
| E3 | 本金已到账但USD标准金额暂缺 | 不影响本金；活动进度显示处理中，原时点补齐后补原期券，不用当前汇率 |
| E4 | 重复回调、跨期补单、乱序充值 | 原订单及原业务时点去重，按所属期重算尚未发放档；旧期补券保持原奖池、节点和规定的使用时间 |
| E5 | 退款、拒付或充值事实纠错 | 按原金额依据重算进度，来源阶梯失去门槛的未用券冻结；该档已用券的未领中奖资格，以及有效抽数已不足的未领节点资格，同时转为待核查、禁止领取。确认充值事实无效后，未用券作废、受影响且确认未入账的资格取消并留存原结果；已入账由资金域受控处理。正在入账或结果未知的奖励先核对原资金申请，不能当成未付取消或发第二份；活动不自行扣本金、不改中奖结果 |
| E6 | E5后同一期再次充值达到原档／原事实被纠正恢复 | 只恢复同一档原未用券身份、原已用券的中奖资格及再次满足有效抽数的原节点资格，沿用原金额与倍数。已消费券计入该档已授予量，不补第二张券或再增加抽数；已付资格不重发。新的充值必须本身属于原累计期，跨期新充值不能恢复旧档；原业务时间符合的事实纠错可以跨期恢复。已有券不刷新截止，系统误冻结按E8补时间，正常退款不顺延 |
| E7 | 抽奖或领奖超时、网络断开 | 先查原请求与资金依据；未知不重试成新抽奖。中奖已确定但发钱失败，恢复该奖，券和里程碑不重算 |
| E8 | 平台故障、币种停用影响用券 | 明示暂停原因，保留结果及余额；核定实际阻塞时间后给受影响券顺延，按原版本恢复，避免用继续充值解决系统问题 |
| E9 | 封禁等账户限制 | 按平台禁止的操作拒绝参与、抽奖或领奖，记录仍可追溯；既有权益不自动删除，解除限制后按有效性恢复，不绕过财务限制 |
| E10 | 已达到末档、旧券跨期使用 | 末档后不新增循环赠券；旧券抽数及节点归旧期，领取旧奖不增加新期充值或抽数 |
| E11 | 改币种、概率、人群、倍数、赠券数或暂停接纳 | 业务配置从下一完整期生效；已参加者本期阶梯继续，旧券旧奖沿原金额、币种和倍数兑现 |
| E12 | 预算不足或大奖短时集中出现 | 拒绝新的本期接纳或告警，按所选模式执行；已接纳者全部权益继续，不删除大奖、缩小金额或暗改概率 |
| E13 | 开奖后到期、关闭或跨期才领取 | 中奖和节点资格保留，无需额外充值；已入账本金、彩金及任务均不因活动周期结束被清除 |
| E14 | 缺概率、零金额、非法阶梯、不可达节点 | 拒绝发布，定位字段；不以运行时默认值或无奖项兜底 |
| E15 | 越权、跨运营商或超推广商范围 | 服务端拒绝，列表、详情、统计和导出保持同一数据范围，不泄露他方参与或充值记录 |
| E16 | 旧期发起充值、新期才真实成功 | 按真实成功时点检查新期是否已参加；符合则计新期，否则该笔不计活动。本金按原资金规则处理，返回页说明归期与不计原因，不回记旧期、不自动占新期资格 |

| 4.19-R32 | 资料刚达标但标签命中集未更新，或所选标签停用后再申请参加 | 使用当前生效命中集，不即时重算、不以未知当符合；停用标签不提供新资格；已有本期参与保留 |
| 4.19-R33 | 周日参加并发起充值，周一才成功；新期分别未参加／成功前已参加 | 未参加则本笔不计活动并说明原因；成功前已参加则计新期；两种情况都不计旧期，不影响本金，也不靠再次充值补救 |
| 4.19-R34 | 不传主题图、上传超限或伪装格式文件、上传失败及展示时缺图 | 无图可发布；非法文件被拒绝且原图保留；默认样式保证金额、概率入口及操作可见，图片不改变开奖 |
| 4.19-R35 | 新旧同类型券并存、默认进入及用尽所选批次；旧期基础券已用完 | 默认展示最早截止有效批次再允许抽奖；用尽后切其他批次须先确认并显示对应奖池；旧期不显示每日领券，当前充值进度与旧期抽奖进度各自注明 |
| 4.19-R36 | 某奖励资金处理中、另有有效券及可领奖；部分中奖资格待核查或已取消 | 未决奖励不重复领取，其他合法操作可继续；待核查及已取消不计可领金额且不进入批量领取，原记录与原因可查 |

### 入口、权限和内部记录

需求入口为“活动管理 → 幸运转盘”，配置与参与／赠券／抽奖／奖励记录在同一活动内部；不增加独立记录侧栏。本页定义入口归属，不声明现有网站已实现。

| 操作 | 权限 |
|---|---|
| 访问页面、读取配置 | `activity:lucky-wheel:view` |
| 编辑及复制草稿 | `activity:lucky-wheel:edit` |
| 发布及预约版本 | `activity:lucky-wheel:publish` |
| 开启或停止新参与 | `activity:lucky-wheel:switch` |
| 查看参与、券、抽奖、节点、资金和成本记录 | `activity:lucky-wheel:record` |
| 导出上述记录 | `activity:lucky-wheel:export`，同时持有record |

全部操作要求view和账号数据范围；查看用户、充值单及钱包详情继续检查对应原页面权限。抽奖结果不可由后台编辑，不提供手工赠券、强制中奖或清除打码入口。

内部查询支持周期、用户、渠道（读取用户事实）、版本、券类型、赠券来源、充值订单、奖项、资金状态及时间范围。记录保留参加时人群依据、原业务日期及USD金额、每档发放/冻结/恢复、券截止与顺延、实际权重版本、抽数及节点、彩金金额和倍数、资金/任务引用、去重与失败原因、预算预占和释放。

统计区分触达、成功参加、基础券领取、进阶券取得、抽奖、形成奖励资格和实际领取。充值相关指标以参加后的真实有效事实计算，并显示分档人数、同一用户前后期变化、退款、奖励面值成本及5.5已知叠加赠送；不能把相关性直接表述成活动带来的新增充值。使用不同版本对照时保留人群和日期口径，不能改同一已参与者的概率试验。
