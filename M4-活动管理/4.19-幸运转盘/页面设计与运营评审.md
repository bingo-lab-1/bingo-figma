# 幸运转盘页面设计与运营评审

本文件说明[幸运转盘正文](README.md)如何落到玩家操作和运营配置。运营可先读本页理解玩法，再看[配置示例与成本测算](配置示例与成本测算.md)判断奖励力度和承受范围，完整边界及验收以正文为准。本页给出本版采用的交互方案；颜色、尺寸、图片与最终排版由Figma表达，不把某种视觉风格当成提高充值的保证。

## 推荐采用的方案

采用“一个活动页、一个转盘展示区域、基础与进阶两个奖池切换”的形式。基础池用每日免费券提供体验，进阶池用真实充值累计赠券提供更高的单券奖励价值；使用进阶券还会推进固定彩金节点。用户先看清自己能拿到什么，再自行决定是否充值。

本版采用以下设计选择：

| 设计选择 | 玩家理解的含义 | 运营可调整的内容 |
|---|---|---|
| 两个奖池共用一个转盘区域 | 当前正在抽哪一池、消耗哪种券始终明确 | 两池名称、奖项、金额、权重；可关闭基础券 |
| 每个有效奖项对应一个格子 | 盘面看到的每个奖项都真实可中 | 每池6～16项；样例使用6项，便于读清金额 |
| 每次抽奖都有正金额彩金 | 免费券也可以形成可领取的奖励 | 金额分布及彩金打码倍数；没有“谢谢参与”占位 |
| 充值累计达到阶梯追加券 | 拆成多笔与一次充足获得相同机会 | 周期内1～10个门槛、每档追加券数 |
| 进阶抽奖达到节点额外得固定彩金 | 除随机结果外，还有可以事先算清的权益 | 关闭节点或配置1～5个节点 |
| 符合条件自动参与 | 无须报名；进入本期活动或真实充值时自动核验，充值触发接纳的本笔计入 | 全部用户或指定标签、接纳时间、名额和预算 |

“每次有彩金”不等于可无条件提现。参加、充值和领取前均能查看对应打码要求；免费奖和已中奖奖励不要求再次充值才能领取。首版不加入集字、实物、连续登录加成或多种任务中心，保持“领券—抽奖—领奖”的路径清晰。

## 玩家页需要让用户看清什么

采用移动端优先的信息层级，桌面端保留相同操作和含义。页面进入后，优先让用户看见当前周期、当前奖池、可用券和本次操作；完整规则可展开，但不能把重要限制只藏在长说明中。

| 内容 | 必须展示的信息与操作 |
|---|---|
| 活动信息 | 名称、当前周期起止及业务时区；“规则与概率”“我的券与奖励”始终可进入；明示“符合条件自动参与，真实充值按成功时间计入所属期”，不要求先打开活动页或报名 |
| 本期资格 | 登录后实际进入本期页面即自动核验，显示核验中、已自动参与或不可参与原因，无参加按钮；成功后展示有效充值。标签不符、接纳关闭、名额或预算已满分别给出可理解的原因，不显示内部标签名、预算余额或风控细节 |
| 奖池切换 | 显示“基础券 n 张”“进阶券 n 张”，数量为所选周期批次当前可用量；切换时同时更新盘面、概率、币种、倍数和期限。被冻结或过期的券在“我的券”单列 |
| 当前转盘 | 当前池名、所属周期、奖励币种、每格金额、固定指针和明确的抽奖按钮；紧邻展示“一次使用1张××券”和“格子大小不代表概率，查看奖项概率” |
| 每日基础券 | 仅当前期已参加者显示今日可领取数量、领取按钮或“今日已领取”；无充值前置。基础赠券关闭的当前版本隐藏此项，不影响旧版本基础券入口。旧期只展示剩余券，不再提供每日领取 |
| 充值阶梯 | 本期已计入金额USD、下一档门槛、还差金额、本档追加及到档累计券数，支持查看全部阶梯；充值计数处理中另行提示，不把未知金额计为0 |
| 固定节点 | 所选周期已完成的有效进阶抽数、下一节点所差抽数、该节点额外彩金和全部节点；节点显示未达标、可领、处理中、已领、待核查或已取消。退款导致有效抽数下降时说明原因，保留原达标记录，不用宝箱动画代替金额 |
| 我的券与奖励 | 按所属期查看券、抽奖记录和待领奖；奖励金额按真实币种分别汇总，不能把USD与其他币种直接相加。已经入账与尚未领取明确区分，待核查或已取消项保留记录，不计入当前可领取金额，不纳入一键领取 |

首次进入展示本期参与概况；抽奖区有有效进阶券时选进阶池，否则有有效基础券或当前基础池时选基础池，其余选进阶池。选定类型默认使用最早截止的有效批次，可能是旧期，此时必须显著标明所属期；没有该类型有效券时才展示本期奖池说明。当前无已发布奖池且没有历史券时展示暂无可用奖池，奖励记录仍可进入。

用户可主动选择其他批次；其后本次停留不因领券或收到充值通知而自动换池、换批次。所选批次用尽时，提示可切换至下一批次，由用户确认后才展示并使用另一版本；不沿着上一版盘面直接抽下一版。进入历史券入口时直接展示选定旧批次，抽奖前呈现该批次的全部信息。充值概况始终标为本期，转盘和节点标为所选期，不能把两者的进度混作同一期。

当前周期尚无资格、标签不符或接纳关闭，都不能挡住旧券与旧奖励。直接进入历史权益不会自动占新期名额；选择旧周期时，奖池、币种、概率、券截止和节点进度一并切到原版，充值进度仅供查看，不出现“再充值完成旧期阶梯”。实际进入本期页面后自动核验并展示本期资格及充值入口。

## 转盘本身怎样设计

### 格子、金额和概率

盘面为一圈6～16个等角度格子，每个格子绑定本版本一个稳定奖项。采用等角度是为了金额可读，实际开奖采用后台权重，盘面附近持续说明“格子大小不代表中奖概率”。不以扇区面积暗示各奖概率相同，也不根据玩家身份移动大奖位置。

每格首先读到金额，币种在盘面附近明确标注；名称和图片作为辅助。长名称可缩略并在奖项列表显示完整内容，金额和币种不能省成含义不明的图标。16格在小屏上仍须有清晰的完整奖项列表，不要求玩家靠放大盘面识别奖励。相同金额可以出现多格，概率明细同时给出各奖项及同金额合计概率。

奖项按后台表格顺序呈现，运营可在草稿中调整顺序，随版本发布；顺序不参与概率计算。最高奖可加“最高彩金”标识，并同处展示其实际概率；不用“即将中大奖”“差一点就中”或虚构中奖滚动条。主题只更换名称和图像，不遮挡规则、概率、券数量或领奖义务。

概率入口在参加前、充值前及有券抽奖时均可打开。详情列出金额、单项概率、同金额合计概率、所选版本及倍数；小概率精度和精确权重比按正文A10。进阶池同时明确“充值增加券数，不改变每张券的概率”。

### 点击、旋转与中奖

1. 点击“使用1张××券抽奖”后，按钮进入处理中并禁止重复提交。处理中的池与批次不可切换；允许用户离开页面，回来后先恢复原处理状态。
2. 服务端尚未确认结果时，只显示处理中，不提前展示某个金额。已确认结果后播放约2～3秒的加速、匀速、减速动画，最终指向对应奖项中心；不先停在大奖再滑走，不模拟改奖。
3. 提供“跳过动画”；开启系统减少动态效果时直接展示结果。跳过、切后台、刷新和重新进入都不重开抽奖，不改变扣券及结果。声音默认关闭，关闭声音不影响结果提示。
4. 结果展示“本次获得××币种彩金，待领取”，列出该奖倍数及领取后的所需打码；如同时达到节点，正常奖和节点奖分两项显示。此时钱包未入账，不显示“已到账”。
5. 提供“领取彩金”和“稍后领取”；剩余有券时可在结果确认后手动“再抽一次”，每次仍只用1张。无券时提供返回活动页，充值引导放回阶梯区，不把充值按钮放成领取必经步骤。“我的奖励”按币种分组领取，只提交可领项；待核查、资金处理中及已到账项单独展示。

抽奖超时显示“结果确认中，请稍后查看”，沿原请求恢复。服务端确认结果后，即使动画未播放也进入历史记录；客户端不能通过动画结束事件增加券数、节点抽数或奖励。

### 主按钮按状态表达真实动作

| 状态 | 当前操作 | 同时保留的说明或入口 |
|---|---|---|
| 未登录 | 登录查看资格 | 可见公开规则；登录后实际进入本期活动即自动核验，不增加报名步骤；仅全站登录不占名额 |
| 本期资格正在核验 | 资格核验中 | 自动处理，无参加按钮；未知不当成符合，旧券旧奖独立可用 |
| 本期自动接纳成功 | 按可用券或今日免费额度显示抽奖／领券操作 | 参与不扣款、不自动发基础券或抽奖，不产生资金任务 |
| 有当前所选池有效券 | 使用1张基础／进阶券抽奖 | 当前批次、剩余券数、截止、概率和倍数 |
| 当前期基础池无券，已参加且今日可领 | 领取今日基础券 | 领取后才进入可抽状态，不自动消耗新券 |
| 当前期基础池无券且今日已领 | 今日基础券已领取 | 本期尚有下一业务日时提示领取时刻，期末提示下期自动重新核验资格；可主动切换进阶池 |
| 历史期基础券已用完 | 本期基础券已用完 | 旧期不显示今日领取或明日领取，可返回当前期查看 |
| 进阶池无券且还有未达档 | 暂无进阶券 | 阶梯区显示“查看充值方式”；只引导当前已参加周期 |
| 已到最高充值档且券用完 | 本期进阶券已用完 | 明示继续充值不再增加本期券，保留待领彩金和下期时间 |
| 本期不符合或不再接纳 | 显示本期不可参加原因 | 不引导为取得本期资格而充值，旧权益按原规则处理 |
| 开奖状态未确定 | 结果确认中 | 锁定原抽奖并查询原结果，不重新扣券或更换抽奖上下文 |
| 某份奖励资金状态未确定 | 该份奖励领取处理中 | 只阻止该奖励重复领取并查询原资金结果；其他有效券可抽，其他可领奖励仍可领取 |
| 平台限制、系统故障或券冻结 | 显示当前不可执行的原因 | 可追溯原记录；解除、恢复及期限按正文E5～E9处理 |

新期状态只控制新期操作。旧券是否能抽、旧奖是否能领仍分别按自身状态和实时账户限制判断，不能把某个状态行变成全页禁用。

## 充值引导如何表达价值

充值区按“已经取得的权益—下一档新增权益—完整阶梯”解释。主文案使用可核实的金额和券数，不使用保证收益、虚假库存或与真实截止无关的倒计时。周期截止与券截止分别标注，倒计时如使用只能基于真实截止，刷新页面不重置。

以样例当前已计入20 USD为例：

> 本期已累计20 USD标准金额，已获得1张进阶券。再计入30 USD达到50 USD档，追加2张，累计可得3张。使用本期3张进阶券完成3次有效抽奖，另得1 USD彩金。每张进阶券可抽0.20～50 USD，概率见奖池；领取彩金后按3倍建立打码任务。

这里的“再计入30 USD”是活动统计差额，不承诺任何支付币种恰好充值30单位就达档，也不承诺支付页面一定存在相同金额商品。充值入口沿用现有商品与支付能力，可展示下一档目标，但不新建固定付款金额或自动凑单。跨币种时说明实际计数依据原入账USD标准金额；能提供换算预估时标明仅供参考。

玩家从活动进入充值时，系统在付款前自动确认本期资格和容量，不要求点击参加。核验失败留在活动页说明原因，不以尚未取得的券权益催促支付。用户从普通充值等其他入口直接成功充值，也会触发自动核验，通过时连同本笔计入活动；未打开活动页不是排除理由，活动核验失败不影响正常本金到账。

入口说明按真实充值成功时间归期，参与资格不跨期。支付成功返回后，分别展示“本金到账”及“活动资格核查中／计数处理中／已追加n张券／本笔未计入活动及原因”。未知与明确不符合分开，未收到确定结果时不建议重充，不自动抽奖或自动领取彩金。

例如周日发起充值、周一才真实成功，不能记回上周；本周已有资格则累计，没有资格则自动核验，通过即计本笔，确认不符合则说明原因，无须重新报名。资金成功时间在旧期、仅活动处理迟到的订单，沿原时点资格和容量依据恢复原期；原已拒绝的充值不因后来条件放宽重新计入，缺历史依据显示核查中。迟到恢复不补发历史未领取的免费券。

到达最高档后收起该活动的促充动作，显示已经获得的总券、可用券、节点进度和待领奖。固定节点按实际抽数解释，不能把“累计充值50 USD可得3券”写成“充值立即再送1 USD节点奖”。

## 后台如何让运营配得清楚

“活动管理 → 幸运转盘”内使用配置、版本、记录和统计入口，复用现有后台控件与权限。配置按下面顺序分组，每步都可以保存合法但不完整的草稿；完成所有必填项后才可发布。首版不把每种展示细节都做成运营开关。

| 配置顺序 | 运营填写 | 页面即时反馈 |
|---|---|---|
| 1. 时间与人群 | 名称、主题、接纳时间、日／周周期、人数上限、全部用户或标签 | 周期的准确起止；明确“多个标签满足任意一个”。标签使用本运营商启用项，展示名称和选择数量；不另填一组渠道条件 |
| 2. 奖励与基础体验 | 奖励币种、每天基础券数、券宽限、各类彩金倍数 | 基础券为0时隐藏当前基础池必填；预览券实际截止及领奖说明；旧版资料保持可查 |
| 3. 两个奖池 | 每项名称、金额、权重、图片和排列顺序 | 只读概率及总和、最低／最高奖、单券期望；基础和进阶对照显示，不允许零概率占位项 |
| 4. 充值阶梯 | 递增USD门槛及本档追加券 | 自动算到档累计券数，显示各档期望成本、对应节点、最高责任；不能把累计值当追加值再次相加 |
| 5. 固定节点 | 关闭，或抽数门槛及本档额外彩金 | 累计节点金额、可达性和与阶梯的对应关系；节点不混入转盘概率 |
| 6. 预算与发布 | 预算模式、金额、预警比例 | 单人完整承诺、人数上限对应规模、当前承诺及历史负债；列出版本差异、生效期和所有阻止发布的字段 |

选择标签时提供到M2标签的只读详情或有权限的编辑入口。要限定“渠道A且VIP3～5”，在M2用这两个属性条件建立AND标签，再在此选择该标签；选择两个现成标签表示OR，不等于AND。活动不新增独立排除标签、按人调整概率或自由公式编辑器；更复杂的条件仍按M2已支持的条件模型处理。

自动参与判断读取M2当前已生效的命中集，不即时重算；资料刚更新尚未命中的玩家，可在资格更新后再次访问或由新的有效事件触发核验，不需要靠充值重试。后台保存判断时间和可追溯依据，普通摘标不撤销本期已承诺权益。主题及奖项图片均可不填，格式、体积与失败处理按正文A1；缺图使用默认样式，始终保留可读金额和真实操作。

实际打开本期活动也会在自动接纳成功时占用名额并按所选模式记录成本，硬上限模式须预占完整权益预算，运营预览须说明这一点；不能只为充值用户预占，也不因用户关闭页面就释放承诺。仅全站登录、页面预加载、后台预览及直接查看旧权益不占新期容量。

发布前用当前草稿预览玩家看到的两池、概率、阶梯、节点、参加说明和领奖说明。预览明确标注“配置预览”，模拟的用户进度与开奖金额不是线上记录，不调用真实参与、充值、赠券或资金入账。首次发布仍需单独开启接纳；已有参与者时，业务改动显示“下个完整周期生效”，旧版可以只读查看。

预览至少覆盖：自动资格核验、直接充值后取得本期资格、仅领免费券、到第一充值档、跨多档、到最高档、无券有待领奖、持有旧周期券。运营调整权重或最高奖时同步看到期望成本与最大承诺；预算不足时提示调整名额、金额或所选预算方式，不自动降低已发布概率。

## 运营评审应重点看哪些选择

以下均有本版明确方案，运营反馈用于调整下一版需求或配置，不构成上线后临时变更已参加者承诺的入口。

| 评审重点 | 本版方案 | 判断时需要的业务资料 |
|---|---|---|
| 用户是否看得懂 | 基础免费体验＋充值累计进阶＋固定抽数节点，共用一个转盘区域 | 目标用户语言、现有活动页和充值流程 |
| 人群是否合适 | 全部或标签OR；渠道与VIP组合放在M2标签 | 目标渠道、用户阶段、VIP范围及可接纳规模 |
| 阶梯是否合适 | 自然周为默认周期；20／50／100／200／500 USD仅为样例 | 真实充值金额分布、商品面额、常见支付币种；避免照搬USD样例成为所有站点默认 |
| 奖励是否可感知 | 样例基础单券期望0.074 USD、进阶0.91 USD；节点另计 | 当地币种显示、常见客单价、奖励领取情况与实际费用 |
| 是否愿意承担成本 | 示例到500 USD档，进阶奖励期望28.38 USD；周首参加完整最大承诺947 USD | 活动预算、参与规模、5.5商品赠送及其他叠加奖励；预警与硬上限不可混称 |
| 后台是否足够灵活 | 人群、主题、两池权重、追加券、固定节点、倍数、名额和预算均可配 | 哪些参数由日常运营维护，谁有发布和开启权限 |
| 玩家是否理解领奖 | 抽中形成待领资格，手动领取才入彩金并建立任务；已中奖无领取期限 | 玩家对彩金与提现条件的理解、客服解释成本 |

这套设计希望通过真实免费体验、可算清的新增机会和固定节点提高参与及充值意愿。实际效果按正文统计口径验证，不把设计判断写成确定的转化承诺。运营反馈时可以直接指出需要改变的目标人群、阶梯、奖励力度或操作步骤，再同步修改正文、示例和验收。
