# 4.6 · VIP配置

## 1. 活动介绍

运营在这里设置VIP等级、升级和保级条件、各级奖励以及每日出款上限。用户充值和投注达到要求后自动升级,并按所在等级享受权益。

用户同时达到充值和投注门槛才能升级。升入新等级后,获得一个完整日历月来完成保级要求。周奖励、月奖励和投注返现需要在规定时间内手动领取;本月充值是否达标,决定领取全额还是免费部分。

用户标签只限制奖励领取,不影响升降级。关闭VIP活动后,暂停升降级和奖励发放,每日出款上限继续执行。

本页不提供单用户手工调级、升级一次性奖励或多套VIP方案。停用等级中的用户可以按迁移规则批量转移。[VIP签到](../4.10-签到奖励/README.md)是独立活动,使用本页的等级信息。

本页说明后台配置、页内奖励记录查询和业务行为,不设计玩家等级页、进度条或出款页面。后台为桌面端,参考1440px、最小支持1280px,不做移动后台;后台简体中文,活动名及等级名按运营语言。日期按平台业务时区计算,展示时间注明运营时区GMT−3。

升级、保级、本月充值门槛和出款限额使用平台标准计价币种;奖金使用活动选择的奖励币种。两种金额不能直接当作同一币种比较或入账。

## 2. 运营配置

### 基础设置(A1至A8、A16)

| 配置项 | 含义和填写规则 |
|---|---|
| 活动开关(A1) | 关闭后停止VIP升降级判定及奖励发放,已发不追回;出款限额仍执行 |
| 活动名称(A2) | 必填,1至40字符 |
| 奖励参与标签(A3) | 可不选;选多个时必须全部满足,即AND关系 |
| 渠道人群(A4) | 不单独配置渠道;先在用户标签中定义渠道条件,再选择该标签 |
| 统一打码倍数(A5) | 正数,一位小数,三类奖励及全部等级共用,每笔奖金独立产生打码要求 |
| 投注返现领取时间(A6) | 每天一个时段,默认00:00至24:00,领取上一自然日返现 |
| 周奖励领取时间(A7) | 每周选择一天及一个时段,默认周一00:00至24:00,对应上一个完整自然周 |
| 月奖励领取时间(A8) | 每月选择1至31号及一个时段,默认1号00:00至24:00,对应上一个完整自然月 |
| 奖励币种(A16) | 从平台已开通币种选择,必填;整个活动统一,不逐级或逐类配置,改动时弹出币种与金额核对提示,运营确认后保存 |

每个时段开始必须早于结束,使用24小时制。渠道标签内部选择多个渠道时可满足任意一个,但本页多个标签之间仍要求全部满足。

### 每个等级的设置(A9至A13)

| 字段 | 含义和填写规则 |
|---|---|
| 等级序号(A9) | 系统按历史最大序号加一产生正整数,不可手填、永不复用;归档后不补空号 |
| 等级名称(A9) | 只用于显示,不影响排序;去首尾空格、忽略大小写后不可重名,长度1至20字符 |
| 累计充值门槛(A10) | 达到该级所需累计充值,非负数 |
| 累计有效投注门槛(A10) | 达到该级所需累计有效投注,非负数;必须与充值同时达标 |
| 保级流水(A11) | 每个个人保级周期需要完成的有效投注,非负数,不要求逐级增加 |
| 未完成降级(A12) | 选择一个存在、启用且序号更低的等级;留空表示保级不足也不降级 |
| 等级启用状态(A13) | 新增默认停用,填齐后可启用;停用不再允许新用户升入 |
| 每日出款次数和金额 | 两项均必填,具体含义见A22至A24 |

高等级的充值、投注门槛均不能低于前一个启用等级。至少保留一个启用等级。等级名例如“Gold”和“ gold ”视为重名。

等级可以停用、迁移用户和归档,不做物理删除。迁移操作及停用用户权益见“停用、迁移和归档”。

### 每级的三类奖励(A14)

| 奖励 | 基础奖金怎么计算 |
|---|---|
| 周奖励 | 该级固定金额,非负数 |
| 月奖励 | 该级固定金额,非负数 |
| 投注返现(A18) | 上一自然日有效投注×该级返现比例;比例允许0至100% |

每一类分别设置“领取全额所需本月累计充值”和“未达标时的免费百分比”。充值门槛为非负标准币金额,免费比例为0至99的整数,不能填100。

某级某类奖励整张表留空,表示不提供这一类奖励。新增等级时三类都为空;不要把这种空白当成漏填。已经开始填写但缺少必要金额或规则时,必须指出缺项。

### 保存及配置提示

加载时可查看基础设置、等级及各级奖励。保存前整份检查金额、等级关系、时间、启用标签、币种及权限,不能部分生效。错误应定位到字段;修改可重试。

一般配置保存后立即生效,不设置统一延迟。但已发奖励、已受理出款不被新配置重算;已开放领取的奖励继续使用本期锁定的基础奖金、币种和打码倍数。

等级变动后提醒运营检查红包雨档位,本页不因红包雨未补档而拒绝保存。等级停用显示待迁移人数,归档等级不出现在日常候选中但历史可查。免费比例为0时说明“充值未达标不可领”;出款上限任一为0时,提示“该等级不可出款”并要求保存前确认。不规定这些提示的页面位置。

## 3. 参与和领奖规则

### 升级和保级(A10、A11、A17)

每次充值到账或投注结算后,根据累计充值和累计有效投注判断是否升级;发生过降级或迁移的用户按下文重新升级规则使用新增金额。两项都达到才升级,可以一次跨多级,只进入符合条件的启用等级,跳过停用等级。**不读取用户标签来决定等级。**

有效投注由玩法提供,口径为实际投注乘以游戏折算比例。保级看的是个人周期内的有效投注,不是充值额或原始下注额。

升入新等级的时刻就是保级周期起点,长度为一个完整日历月。例如9月12日15:00升级,到10月12日15:00检查保级。下一月没有相同日期时取该月最后一天,时刻不变;后续周期以上一次结算时刻继续计算。

周期结束时:

- 完成保级流水,保留等级,紧接着开始下一个完整日历月。
- 未完成且设置了降级目标,降到该级,从降级时刻开始目标等级的完整保级月。
- 未设置降级目标,保持等级并开始下一周期。
- 目标已停用或归档,本次不降级,告警请运营补配。

周期内再次升级,旧周期结束,从新的升级时刻重新获得完整保级月。升降级及保级结算都保存前后等级、周期起止、判定金额及原因。

### 奖励在规定时间内手动领取(A6至A8、A19、A21)

投注返现领上一自然日,周奖励领上一个完整自然周,月奖励领上一个完整自然月。它们的统计期与个人保级月不同。

用户需在所选领取时段内点击领取。超过窗口不补发,也不积累到下一期。同一期同一类奖励每人只能领一次。

月奖励配置的日期在当月不存在时,按当月最后一天开窗。例如配置31号而当月只有30天,就在30号开放;这不是延到下个月。领取时段包含开始时刻,不包含结束时刻;自然周从周一00:00开始。

### 全额和免费部分(A3、A15、A18)

领取时检查活动开启、账号未封禁、全部参与标签都满足,再读取本期已锁定的基础奖金。周、月为固定金额,返现以昨天有效投注计算。

三类奖励判断全额资格时,统一使用**领取所在自然月1日00:00至点击领取时**的累计成功充值,不是奖励统计期的充值,也不是个人保级周期的充值。

- 本月充值达到该类门槛:领取基础奖金的100%。
- 未达到门槛,包括完全没充值:领取“基础奖金×免费百分比”。
- 免费比例为0:未达标时不可领取。

**领过免费部分,本期就不能再领或补差。** 后来充值达标也不补足。这与VIP签到的当日补差是不同规则。

例如:周奖金50 BRL、充值门槛100 USD(标准计价)、免费比例20%。本月充值只有80 USD时领10 BRL;达到100 USD后首次领取则领50 BRL。如果已领10 BRL,之后达标不再补40 BRL。

免费金额按奖金币种最小单位及钱包舍入规则处理。结果为0不创建账变或打码任务;不占用本期领取名额,窗口内充值达标后仍可领取。

### 领取时确定哪些奖励信息(A20)

已领取的奖金金额、等级、币种和打码倍数固定,之后升级、降级或改配置都不改变这笔结果。

每期领取窗口开放时,按用户当时等级和已生效配置锁定基础奖金、奖励币种、打码倍数、充值门槛及免费比例。窗口内升降级或修改配置不重算这份奖励;全额资格仍按实际领取时的本月充值判断。统计期结束后注册的用户不领取该期奖励;统计期内注册的用户可领周月固定奖,返现仅统计注册后的实际有效投注。

### 暂停、降级和数据恢复

关闭活动时保存每人的保级剩余时长,恢复开启后按暂停时长顺延周期终点;关闭期间不累计保级流水,不补发关闭期间未开放的奖励。恢复时可按真实累计充值和投注判定升级,但仍执行以下降级后的重新升级规则。

保级降级或运营迁移时,记录该时刻累计充值和累计有效投注作为新起点。重新升到更高等级需要两项新增金额分别达到“目标等级门槛减本次降级或迁移后起始等级门槛”,差额小于0按0处理,且两项都必须有新增。后续再次升级仍沿用本次降级起点,直到又一次降级或迁移才重设,不能靠原有累计值立即升回。

有效投注数据缺失时保留原周期和应结算时刻,数据恢复后按时间顺序补做,下一周期从原应结算时刻开始。已经锁定或发放的奖励不因补做结算被追回。

投注返现逐笔使用投注结算时保存的汇率换算到奖励币种后汇总,按钱包币种精度舍入。缺少对应历史汇率时不以当前汇率替代,按本页金额缺失规则记录并停止该次奖励判定。

### 每日出款限额(A22、A23、A24)

每级设置当日最高次数及最高金额。次数为不小于0的整数;金额为不小于0、最多两位小数的标准计价金额。两项必填,没有“不限”选项,任一项为0就表示该级当天不可出款。

申请提交到服务端时,按用户当时VIP及最新限额检查。金额使用手续费前申请总额,按申请时汇率换算为标准币并保存,不是预计到账净额。两项都不能超:

- 当天已成功及仍占用的次数＋本次1笔,不超过次数上限。
- 当天已成功及仍占用的金额＋本笔标准币金额,不超过金额上限。

受理后立即占用次数和金额。待审核、审核中、放款中都继续占用;成功后计为已使用。审核拒绝、取消或明确失败,须在资金解除占用或归位后才释放。回执超时、结果未知时不释放。

所有额度始终归申请受理的业务日。昨天受理、今天成功,不再占今天额度;昨天的申请今天失败,只修正昨天的记录,不会增加今天额度。

升级、降级、迁移或修改限额不撤销原申请,不追回成功出款。下一笔按最新规则,但今天原有的成功和占用仍全部计入。若新上限已低于使用额,剩余展示为0。

例如当天已用1次、20 USD,升级后的上限为3次、100 USD,剩余为2次、80 USD。不能因为升级重新得到完整额度。并发申请也必须共同受限,不能每笔各自看旧额度而一起通过。

VIP活动关闭时以上限制照常执行。等级配置缺失或换算失败时拒绝受理,不按无限额或0金额放行。M4提供等级与限额,M5负责订单、占用和释放。

## 4. 特殊情况

### 停用、迁移和归档(A13)

停用、迁移和归档按以下顺序执行:

1. 停用等级时提示现有用户数,不再允许新用户升入。原用户迁移前保留等级、该级VIP奖励及出款限额。
2. 只能将停用等级用户批量迁往存在、启用且更低的等级。执行前预览来源、目标、人数及影响,再确认。
3. 不补发、不追回历史奖励,不撤销已受理出款。迁移逐人记录原等级、目标等级、操作人、时间和原因。
4. 从迁移时刻开始目标等级完整保级月,新出款按目标限额,当天已用额度不清零。
5. 等级没有用户后才能归档。序号、名称及历史引用永久保留,不复用序号。

### 领取和出款遇到异常时

| 编号 | 情况 | 如何处理 |
|---|---|---|
| E1 | 无权限修改、启停或迁移 | 服务端拒绝;权限按操作区分 |
| E2 | 同人同期同类重复点击 | 不重复发奖、打码或占领取名额 |
| E3 | 领取窗口已关闭 | 按服务端时间拒绝,不使用玩家设备时间;开始时刻可领,结束时刻不可领 |
| E4 | 达标未领期间升降级 | 已领奖励不变;未领奖励使用本期窗口开放时锁定的等级 |
| E5 | 领取前标签发生变化 | 按领取时命中情况检查全部标签,不回溯已领 |
| E6 | 停用等级仍有用户 | 保留原等级权益、迁移后再归档 |
| E7 | 降级目标被停用或归档 | 本次不降级,告警补配 |
| E8 | 月奖励日期不存在 | 按当月最后一天开放 |
| E9 | 在月初领取昨日返现 | 基数仍是上一自然日有效投注,全额门槛看领取所在月充值 |
| E10 | 关闭VIP活动 | 立即停升降级及新奖励发放,已发不追回,出款限额继续 |
| E11 | 窗口内修改奖励配置 | 已发及本期锁定的奖励不变,新配置用于后续窗口 |
| E12 | 改等级影响红包雨档位 | 本页提醒补档,覆盖校验由红包雨配置负责 |
| E13 | 有效投注数据失败或未就绪 | 不按0代替、不直接判降级;按原周期封存判定任务,数据恢复后依次补做结算 |
| E14 | 先领免费部分后充值达标 | 同期不补差、不再领 |
| E15 | 多笔出款并发 | 总次数和总金额都不得超过上限 |
| E16 | 已受理出款后等级或配置变化 | 原单不撤销,下一笔按最新规则且继续计入本日既有额度 |
| E17 | 出款拒绝、取消或失败 | 资金归位后释放原申请日额度,结果未知继续占用 |
| E18 | 非标准币出款 | 按申请时汇率确定标准币金额,换算失败不受理、不占额度 |
| E19 | 用户无合法等级或出款配置缺失 | 拒绝并告警,不能放开限额 |

奖励入账明确失败时不算成功领取,但原合法申请仍保留该期名额,只能恢复同一笔申请,不另开新领取。资金结果未知时,不能再次发钱;持续查询原申请,明确失败则使用同一奖励依据重试;截止前受理的申请超过窗口仍须完成,不另开领取名额。

奖励判定所需的标准币金额缺失时,本次不发、事后不补发。已经提交入账但结果未知的奖励,按资金结果未知处理。

空、加载、错误及无权限沿用公共要求;停用用户数、归档历史、零免费比例、零出款限额需要明确说明,不规定折叠或布局样式。

| 4.6-R5 | 窗口内升级或修改奖励后领取 | 金额和倍数保持窗口开放时的值;仅本月充值影响全额资格 |
| 4.6-R5 | 免费金额舍入为0,之后充值达标 | 首次不占名额;窗口内达标后可领取全额 |
| 4.6-R4 | 暂停2天后恢复VIP | 原保级终点顺延2天,暂停期间投注不计保级 |
| 4.6-R4 | 保级降级后没有新充值或新投注 | 不因旧累计门槛立即升回 |

| 4.6-R5 | 已领免费部分再领、窗口外领取或并发重复 | 拒绝重复或过期申请,不补差 |
| 4.6-R5 | 已达标未领时改等级或奖金 | 基础奖金、币种和倍数使用窗口开放时的锁定值,本月充值按领取时判断全额资格 |
| 4.6-R6 | 活动关闭 | 停止升降级与奖励发放,配置可改,已发不追回,出款限额照常 |
| 4.6-R6 | 无权限开关 | 拒绝,原状态不变 |

## 6. 相关资料

**入口**:活动管理 → VIP配置。等级序列也供用户列表及标签引用;本页不增加单用户手工调级入口。

| 操作 | 权限码 |
|---|---|
| 修改基础设置 | `activity:vip:edit` |
| 等级新增、停用、迁移、归档及等级配置 | `activity:vip-level:edit` |
| 修改奖励 | `activity:vip-reward:edit` |
| 启停VIP活动 | `activity:vip:switch` |
| 查询奖励发放记录 | `activity:vip-reward-record:view` |

等级和奖励权限分别检查,不能凭奖励编辑权限修改等级或出款限额。配置及记录的查看权限沿用模块定义,不因本文未新增权限码而允许越权读取。

**记录和责任**:

- M4拥有等级配置、用户等级、升降级与保级记录、三类奖励配置和发放依据。本页内提供“奖励发放记录”区,与VIP配置一起交付并验收。
- 升降级记录需查清周期起止、原目标等级、累计充值、累计有效投注、本周期有效投注及原因。迁移另记录操作人与影响用户。
- 奖励记录必须查清用户、类型、所属奖励期、采用等级、基础奖金、本月充值、全额门槛、实际比例、奖金币种金额、打码倍数、发放时间、处理结果及触发的账变。记录区只读查询,服务端按查看权限、运营商及账号数据范围隔离结果。
- M5拥有订单和出款额度,订单保存申请日、当时等级、两项上限、标准币金额、判定前用量和结果。只在申请受理前读取VIP限额,不能因此改变账变或放款金额。
- M5提供充值与标准计价,M2提供标签与封禁,玩法提供有效投注(本仓库范围外)。渠道通过用户标签提供;VIP不直接查询渠道字典。没有本页直接调用的外部支付机构。
