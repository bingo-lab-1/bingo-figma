# 4.6 · VIP配置

## 1. 背景与目标

**目标**:让运营自己定"充多少加投多少能升级、掉下来降到哪一级、每一级每周每月能拿多少钱、
什么时候能来领",玩家看得到自己离下一级还差多远,拿得到与等级匹配的持续回馈。

**谁在用**

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 定等级门槛与保级要求、定三类奖励的金额与领取条件、圈定参与人群、开关活动 | 想调一档等级的奖励要找程序员改代码,调完还不敢确认改对没有 |
| 玩家 | 知道自己在第几级、离下一级差多少、每周每月能领多少 | 只看到一个等级数字,不知道它值多少钱,也不知道怎么往上走 |
| 财务 / 风控 | 看这套等级体系每月发出去多少钱、发给了哪些等级 | 长期发放的成本说不清楚,超支了也不知道调哪一格 |

**业务价值**:等级把"充值 + 下注"两件事绑在一起,只做一样升不上去;
周月两档持续回馈给玩家一个固定的回访理由,不像一次性活动打完就散;
保级流水让高等级的待遇需要持续活跃来维持,成本不会一路只涨;
每一级每一类奖励的金额、门槛、领取窗口都在同一张页面上,改一个数不用动代码。

**不做什么**

- **不做玩家端的等级页和进度条** —— 这里只是后台,玩家看到的另外做
- **不做加钱和打码本身** —— 这里只定规则和触发,真正加钱、记打码由资金那边管
- **不做人群怎么算** —— "注册几天、累计充了多少、几个设备登录"全部是用户标签的事,本页只选标签
- **不做发放记录页** —— 谁在什么时候领了多少在「VIP 奖励发放记录」里看,本页只放入口
- **不做签到奖励** —— 原始表里签到也按等级分档,但签到是另一个活动,本轮不收
- **不做升级奖励** —— 原始表有这一项,本轮的三类奖励里没有,见决策 D62
- **不做手工调级** —— 等级只由规则判定,后台不提供"把某个玩家直接设成 VIP5"的入口
- **不做多套模板** —— 一个运营商一套配置,不做 A/B 或多版本并存

**适用范围**

| 维度 | 取值 |
|---|---|
| 终端 | 电脑后台,按 1440px 宽设计 |
| 响应式 | 最小支持 1280px;不做手机版 |
| 界面语言 | 后台用简体中文;活动名称与等级名按运营语言填(线上为葡语) |
| 时区 | 所有领取窗口、保级结算的自然日与自然月一律按业务时区切;界面展示时间按运营所在时区(GMT−3)并标注 |
| 货币 | 两套口径,互不换算:**升级门槛与保级流水、领取所需最低充值按平台标准计价币种判定**,与用户标签里的金额同一把尺子;**奖励金额与入账按活动自己选的奖励币种**。一个运营商一套配置 |

## 3. 术语

> 通用词(打码倍数、领取门槛)见 `../README.md` 第 2 段;彩金、打码任务、有效投注
> 见 `../../M2-用户管理/2.1-用户列表/资金模型.md`;标签、命中、重算见
> `../../M2-用户管理/2.5-用户标签/README.md` 第 3 段,这里不重复讲。

| 术语 | 定义 |
|---|---|
| 等级序号 | 等级的身份与排序依据,正整数,**一经使用永不复用**(D58);删掉的号作废,序列因此可能不连续 |
| 等级名 | 展示用的名字,可以是「1」「2」也可以是「黄金」「白金」;**只用于显示,不参与任何判定与排序** |
| 升级门槛 | 一个等级的准入线,由充值金额与投注金额两项组成,**两项都达到才升**(D57) |
| 保级流水 | 维持当前等级每个自然月要完成的有效投注量;当月没做够就按「未完成降级」掉级 |
| 未完成降级 | 保级没达成时降到哪一级,**填等级序号**,不填"降几级" —— 序列可能不连续,"降一级"没有确定含义 |
| 周奖励 / 月奖励 | 按等级配的固定金额,每周 / 每月开一次领取窗口,玩家在窗口内手动领 |
| 投注返现奖励 | 按等级配的返现,以上一自然日的有效投注为基数,次日开窗口手动领 |
| 领取窗口 | 一段允许领取的时间;错过不补,不累积到下一期 |

## 7. 需求详述

### 4.6-R1

**触发条件**:页面加载时读出当前配置;运营改动任意字段后点右侧悬浮「保存」。

**可输入数据**:见第 5 段「基础设置」九项;数值类只收数字,时刻类只收 24 小时制。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 表单交互、即时格式提示、改奖励币种时弹二次确认、保存前把未填必填项标红 |
| 服务端 | 整份校验后才落库,部分通过不落;权限判定;标签与渠道选项按当前已启用的清单校验 |

**处理逻辑**

1. 加载:读出基础设置、等级序列与每级三张奖励表,一次性给全,不分段取。
2. 运营改动;界面只做格式提示,不做业务判定。
3. 点保存 → 服务端按 A1 ~ A21 整份校验(等级与奖励部分的校验见 R2 / R3)。
4. 全部通过才落库;落库后立即生效 —— 配置改动不设延迟,与 4.4-A13 同口径。
5. 刷新页面显示;开关与纯文案的改动同样立即生效。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 活动名称为空或超长 | 活动名称必填,长度 1 ~ 40 |
| 打码倍数 ≤ 0 | 打码倍数必须大于 0 |
| 领取窗口起止时刻颠倒 | 结束时刻不能早于开始时刻 |
| 奖励币种未选 | 请先选择奖励币种,奖励金额需要它才有意义 |
| 选中的标签已被停用或删除 | 标签「X」已不可用,请重新选择 |
| 没有权限 | 没有操作权限(服务端也会拦,不靠藏按钮) |

**测试案例**

- 正向:填齐九项、打码 3 倍、周窗口改成周五 10:00 ~ 22:00 → 保存成功,重进页面数据一致。
- 逆向:活动名称留空 + 打码倍数填 0 → 一次性列出两条错误,都定位到具体字段,不落库。

### 4.6-R2

**触发条件**:点「新增等级」「删除」「启用 / 停用」;改任一门槛或保级流水后点保存。

**可输入数据**:序号(正整数,系统给,不可手填)· 等级名(1 ~ 20 字符)· 充值金额与投注金额
(非负数)· 保级流水(非负数)· 未完成降级(下拉选已存在且启用的更低序号,可留空)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 行内编辑、新增行、删除前二次确认、「未完成降级」下拉只列合法的更低序号 |
| 服务端 | 序号分配与不复用保证、门槛单调性校验、删除前的非空检查、停用的连锁影响提示 |

**处理逻辑**

1. 新增:序号取历史最大值加一,**不填补空洞**(A9、D58);新增行默认停用,填完再启用。
2. 校验序号:唯一;已删除的号不得重新出现。
3. 校验门槛:序号越大,充值金额与投注金额**都不得低于**前一个启用等级 —— 否则会出现"升到高级反而门槛更低"。
4. 校验保级流水:非负数;不强制单调。
5. 校验未完成降级:填的序号必须存在、启用、且小于本级序号;留空表示不降级。
6. 删除:该等级上**还有玩家时拦下**,提示先处理(A13,D60 拍板前的暂定口径);为空才允许删,删后序号作废。
7. 停用:不拦,但提示该级当前有多少玩家 —— 他们会保持在这一级,只是新玩家升不进来。
8. 全部通过才落库;等级序列的任何改动都会影响 4.2 红包雨的金额档覆盖校验(4.2-A6),保存后给一条提示。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 高等级的门槛低于低等级 | 第 N 级的充值 / 投注门槛不能低于第 M 级 |
| 未完成降级填了不存在或已停用的序号 | 第 N 级的降级目标「X」不存在或已停用,请重选 |
| 未完成降级填了不小于本级的序号 | 降级目标必须低于当前等级 |
| 删除时该等级还有玩家 | 第 N 级还有 X 名玩家,请先处理后再删除 |
| 序号试图复用 | 序号 X 已作废,不能再次使用 |
| 一个等级都没有 | 至少要有一个启用的等级 |

**测试案例**

- 正向:建 5 级、门槛递增、保级流水递增、第 5 级降级目标填 3 → 保存成功;停用第 4 级后重进,第 4 级仍在表里且状态为停用。
- 逆向:删掉序号 3(该级有玩家) → 拦下并提示玩家数;把第 3 级的充值门槛改到低于第 2 级 → 拦下,不落库。

### 4.6-R3

**触发条件**:展开某个等级的奖励区;改动三张表的任一格;切换「不充值是否领取免费彩金」;点保存。

**可输入数据**:奖励金额(周 / 月为非负金额,返现为 0 ~ 100 的比例)· 领取所需最低充值金额
(非负金额)· 免费领取百分比(0 ~ 100 的整数)· 不充值是否领取免费彩金(是 / 否)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 切到「是」时立即把另两格置灰清空,切回「否」时解锁并恢复可填;三张表可折叠 |
| 服务端 | 按 A15 校验锁定态与数值的一致性;锁定时忽略传上来的这两个值,不落库 |

**处理逻辑**

1. 每个等级各有三张表:周奖励、月奖励、投注返现奖励,结构相同(A14)。
2. 「不充值是否领取免费彩金」= 是 → 该表的「最低充值金额」与「免费领取百分比」置灰锁定,该级该类奖励全额免费领(A15)。
3. = 否 → 两格可填;领取时要求当期充值达到「最低充值金额」才发,充不够不发。
4. 三张表允许留空 —— 留空表示该级不发这一类奖励,不是校验错误。
5. 新增等级时三张表默认全空、开关默认为「否」。
6. 全部通过才落库;已发出去的奖励不受影响(A20)。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 返现比例超出 0 ~ 100 | 返现比例必须在 0 到 100 之间 |
| 免费领取百分比超出 0 ~ 100 | 免费领取百分比必须在 0 到 100 之间 |
| 锁定态下仍传来了被锁字段的值 | 服务端忽略,不报错也不落库 |
| 填了奖励金额但没选奖励币种 | 请先在基础设置里选择奖励币种 |
| 金额为负 | 金额不能为负数 |

**测试案例**

- 正向:VIP3 的周奖励填 50、最低充值 100、不充值可领选「否」→ 保存成功;改选「是」后另两格立即置灰,保存后重进仍是锁定态。
- 逆向:返现比例填 150 → 拦下;在锁定态下用改包方式传一个最低充值金额 → 服务端忽略,落库后该字段仍为空。

### 4.6-R4

**触发条件**:玩家充值到账时、投注结算时(升级判定);每自然月结束时(降级判定)。无后台按钮。

**可输入数据**:无人工输入;判定的输入只有玩家的累计充值金额与累计有效投注,
以及当月有效投注 —— **不含任何用户标签**(00-公共约定 铁律④第 2 款)。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 无。等级变动的结果在 2.1 用户列表与详情弹窗里看 |
| 服务端 | 判定、写等级、记升降级流水;活动关闭时不判定 |

**处理逻辑**

1. 升级:每次充值到账或投注结算后,取该玩家的累计充值金额与累计有效投注,
   与**下一个启用等级**的两项门槛比对;**两项都达到才升**(A10、D57)。
2. 一次可跨多级:同时满足第 5 级门槛时直接升到 5,不逐级停留。
3. 停用的等级**不能升入**,判定时跳过它继续比对更高的启用等级。
4. 降级:每自然月结束后统一判定(A17),取该玩家当月有效投注与所在等级的保级流水比对;
   未达成则降到该级「未完成降级」填的序号(A12);该格留空则不降。
5. 降级目标若在此期间被删或停用,本次**不降级**并告警提示运营补配(与 4.2-A13 的处理同精神)。
6. 每次升降级写一条流水:时间、前后等级序号、触发原因(升级 / 保级未达成)、判定当时的两项值。
7. 活动开关关闭时(A1)不做任何判定,玩家等级停在原地。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 玩家当前等级已被删除 | 不判定,告警提示运营该玩家处于作废等级(D60 拍板前的兜底) |
| 降级目标已被删或停用 | 本次不降级,告警提示补配降级目标 |
| 有效投注取数失败 | 本次不判定、不按 0 顶替,下个周期重试;与 M2-D34「取数失败判否」同口径 |
| 判定过程中等级配置被改 | 按判定开始那一刻读到的配置走完,不中途换规则 |

**测试案例**

- 正向:玩家累计充值 500、累计有效投注 5000,第 3 级门槛为 300 / 3000、第 4 级为 1000 / 8000 → 升到 3 级,不到 4 级;写一条升级流水。
- 逆向:玩家累计充值 2000 但累计有效投注只有 100,第 2 级门槛为 500 / 1000 → **不升级**(AND 未满足);月末当月有效投注 0、所在等级保级流水 1000、降级目标填 1 → 降到 1 级并留痕。

### 4.6-R5

**触发条件**:玩家在对应的领取窗口内点领取(玩家端动作)。无后台按钮。

**可输入数据**:无人工输入;发放金额由玩家当时的等级与三张奖励表推出。

**功能范围**

| 归属 | 做什么 |
|---|---|
| 界面 | 无。发放结果在「VIP 奖励发放记录」里看 |
| 服务端 | 窗口校验、资格校验、金额计算、彩金入账、建打码任务、写发放记录 |

**处理逻辑**

1. 查窗口:当前时刻是否落在该类奖励的领取窗口内(A6 / A7 / A8),按业务时区判;不在窗口内拒绝。
2. 查资格:活动开着(A1);玩家命中全部选中标签(A3);注册渠道在开放渠道内(A4);未被封禁。
3. 查等级:取**领取那一刻**的等级(A20);等级已被删或停用则不发,告警。
4. 算金额:周 / 月奖励取该级配的固定金额;投注返现取上一自然日有效投注 × 该级返现比例(A18)。
5. 判门槛:该类奖励的「不充值可领」= 是 → 直接发全额;= 否 → 查该期充值是否达到「最低充值金额」,达到发全额,没达到不发(A15)。
6. 发放:以彩金入账,带「VIP 奖励」来源标识,按 A5 的倍数**独立建一条打码任务**(M2-D3);本模块不直接改余额。
7. 留痕:写一条发放记录 —— 玩家、奖励类型、发放当时的等级序号、金额与币种、打码倍数、触发的账变、时间。
8. 同一期同一类奖励**每人只能领一次**;并发点击只成功一次。

**错误处理**

| 错误状况 | 提示 |
|---|---|
| 不在领取窗口内 | 按服务端时间判定,拒绝;不以玩家端时间为准 |
| 本期已领过 | 拒绝,不重复发放、不重复建打码任务 |
| 该期充值未达到最低金额 | 不发放,玩家侧按"不可领取"呈现 |
| 玩家所在等级已被删或停用 | 不发放,告警提示运营 |
| 入账失败 | 不记发放、不占用本期名额,玩家可重试;与 4.2-E8 同口径 |
| 换算失败(标准币金额待补算) | 本次不发、事后不补发;与 4.4-A24、`标准计价.md` S7 同口径 |

**测试案例**

- 正向:VIP3 玩家在周一 10:00 领周奖励,该级配 50、最低充值 100、不充值可领为「否」,上周充了 300 → 发 50 彩金,按 3 倍建打码任务 150,写一条发放记录。
- 逆向:同一玩家同一分钟内连点三次 → 只成功一次,只加一次钱、只建一条打码任务;窗口关闭后再领 → 拒绝,不补发(A21)。

## 8. 数据流向与系统串接

**数据流向**:运营填三个区块 → 服务端整份校验后存成配置 → 玩家充值 / 投注触发升级判定、
月末触发降级判定 → 玩家在窗口内领取,服务端算金额、通知加钱记打码、写发放记录 →
本页读出配置显示,4.7 读出发放记录显示。

**系统串接**:

- 钱包和账变、打码任务(归财务):加彩金和记打码都走财务那边,带「VIP 奖励」来源标识;
  这里只触发,不自己改余额。资金域不在账务链路上反向依赖本活动。
- 有效投注(归玩法,**本仓库范围外**):升级门槛的投注项、保级流水、投注返现的基数都用它;
  口径为实际投注 × 游戏折算比例,与提现流水、打码、代理返佣同口径(A11)。
- 玩家充值汇总(归财务):升级门槛的充值项、各类奖励的「最低充值金额」判定都用它。
- 用户标签(归 M2,2.5):活动绑定的标签,领取时按当下命中集判断;
  **标签只用于领取门槛,不参与等级判定**(铁律④第 2 款)。
- 渠道(归代理渠道,**本仓库范围外**):开放渠道用它的字典。
- 标准计价换算(归财务):门槛与最低充值金额的判定用标准币金额。
- **除了平台自己的钱包 / 标签 / 充值投注数据与渠道字典,没有别的外部系统。**

## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权 | 没权限的账号改配置 / 切开关 | 服务端拦下,不靠藏按钮 |
| E2 | 同一人连点领取 | 同一玩家同一期并发点领取 | 只成功一次,只加一次钱、只建一条打码任务 |
| E3 | 窗口边界 | 玩家点击到达服务端时窗口刚关 | 按服务端时间判定,拒绝;不以玩家端时间为准 |
| E4 | 领取途中升降级 | 玩家在窗口内升级后再领 | 以点领取那一刻的等级为准(A20);已领的不回溯、不补差 |
| E5 | 领取途中标签变化 | 玩家在窗口内被打上或摘掉参与标签 | 以点领取那一刻的命中集为准,不回溯已领的 |
| E6 | 等级被删 / 停用后仍有玩家 | 运营删或停用了某级,该级还有玩家 | 删除被 R2 拦下;停用允许,该级玩家保持不动但不再有人升入;历史发放记录里的序号仍指向作废等级,靠序号不复用保证不指错(D58) |
| E7 | 降级目标缺失 | 「未完成降级」指向的等级被删或停用 | 本次不降级,告警提示补配(R4 第 5 步) |
| E8 | 月奖励窗口落在小月 | 配了 31 号,当月只有 30 天 | 顺延到该月最后一天开窗(A19) |
| E9 | 周期跨月的返现 | 返现窗口配在 00:00 ~ 01:00,跨了自然日 | 领的始终是上一自然日的有效投注,按业务时区切,不因窗口跨点而改基数 |
| E10 | 活动进行中关开关 | 运营在窗口内关掉活动 | 立刻停止判定与发放,已发的不收回(与 4.2-E5 同口径) |
| E11 | 改配置影响未领奖励 | 运营在窗口内改了某级的奖励金额 | 保存即生效,**尚未领取的按新值发** —— A20 的快照锁的是"已发放的",不是"未领取的" |
| E12 | 等级序列改动波及红包雨 | 新增或停用等级后 4.2 的金额档出现缺口 | 本页保存不拦,但给提示;真正的拦截在 4.2 保存时(4.2-A6) |
| E13 | 有效投注取数失败 | 玩法侧数据未就绪 | 不判定、不按 0 顶替,下个周期重试(M2-D34 同口径) |
