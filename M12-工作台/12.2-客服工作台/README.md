# 12.2 · 客服工作台

## 1. 用途

客服在这里查看通过客服 API 写入的文字或图片咨询并回复。玩家 main 目前只有静态 Support 渠道项，尚未接入聊天界面；后台和后端能力不能视为玩家入口已交付。每名玩家只有一条会话，玩家首次发消息时创建，后续消息都进入同一会话。

页面面向桌面端，界面为简体中文，消息内容按原文显示。列表和消息时间使用查看者浏览器时区；日期筛选按后台所选业务时区转换为整日范围。

支持文字、图片、筛选、加急、解决及重新打开会话、重点客户标签和自动回复设置。不提供客服分配、转接或人工编辑、删除已发送消息。多名客服可同时处理同一会话。

## 2. 查询与处理信息

| 信息 | 含义和规则 |
|---|---|
| 会话列表 | 玩家会话，按最后消息时间倒序，每次加载 50 条，可“加载更多会话”。页头“刷新会话”和列表上方“刷新”都重新读取会话。页头汇总未解决、未回复、加急和已解决数量；支持全部、未回复、加急、重点客户、已解决视图 |
| 玩家名称、UID | 玩家昵称和用户 ID |
| 未读数 | 玩家发来且客服方未读的消息数，大于 0 时显示“N 未读” |
| 最后消息、时间 | 会话最新一条消息的内容和时间，没有时显示“暂无消息” |
| 聊天记录 | 打开时显示最新 50 条，可“加载更早消息”每次再取 50 条。每条显示发送者名称、客服或玩家、时间。离开底部时可点“查看最新消息”回到最新 |
| 回复内容 | 文字去首尾空格后最多 2000 字符；文字或图片至少一项非空 |
| 图片 | 每条最多 3 张 PNG、JPEG、WebP，单张最多 5 MiB、边长最多 4096 px，支持静态图片单独发送；上传完成后才能提交 |
| 筛选 | UID 前缀或昵称包含关键词，最多 100 字符；最后消息时间范围，开始含、结束不含；筛选和选中会话保存在地址中 |
| 会话标记 | 未解决/已解决、未回复、加急，以及命中当前有效代际的已启用重点客户标签 |

没有选中会话时提示“选择左侧会话，查看消息并回复玩家。”。选中的会话记录在页面地址里，刷新后保持。

## 3. 处理规则

### 接收消息

玩家发送消息后，会话列表和当前会话实时更新。实时连接之外，页面每 30 秒、窗口重新获得焦点、网络恢复和连接重建时都补查一次，缺失的消息按序号补齐。页面不可见时暂停接收和补查，恢复可见后补查。

### 回复

持有回复权限的客服在当前会话输入文字或上传图片，点“发送回复”或按 Ctrl / ⌘ + Enter 发送。回复以当前后台账号名称发出，服务端的玩家未读数增加；main 尚未展示该未读数。

提交后消息先显示“发送中…”，收到服务端确认后进入聊天记录。每次发送带唯一消息编号，同一编号和相同文字、图片列表重复到达时返回原消息，不产生第二条。图片校验归属、上传状态和有效期，并和消息在同一事务内绑定。

### 已读

聊天记录中的消息进入可视区域后，系统把客服方已读进度推进到该消息，未读数按剩余的玩家消息重算。已读进度只前进不后退，全部客服共用，一名客服读过后其他客服也不再显示未读。

### 会话处理与自动回复

玩家新消息将会话设为未解决、未回复；人工客服回复清除未回复，自动回复不清除，也不替换客服列表中玩家问题的摘要。标记已读不代表已回复。

客服可以加急或取消加急，标记已解决时同时清除加急和未回复。已解决会话不能再加急；玩家再发消息会自动打开。手动重新打开时，最后一条非系统消息来自玩家才恢复未回复。处理动作记录操作日志。鼠标停在会话列表或已向下阅读时冻结排序，新动态先提示，点击后更新顺序。

客服设置为全局配置。自动回复默认关闭；接待语可留空、最长 500 字符；最多 50 条有序规则，每条 1～10 个非空关键词、每个最长 50 字符，回复 1～500 字符。关键词去首尾空格并不区分大小写去重。最多指定 20 个重点客户标签，须为有效启用标签。保存带原更新时间，发生并发修改时拒绝旧版本。

自动回复按规则顺序作不区分大小写的子串匹配，每条玩家消息只取第一条命中规则。无命中时，仅首次会话或距前一条消息至少 30 分钟才发送接待语；人工客服最近 30 分钟回复过时暂停所有自动回复。自动回复不代表人工已受理。

消息保留期固定 90 天。后台任务每天归档超期消息，玩家和工作台不再返回这些消息及其图片；重算未读并维持后续序号连续，不提供归档查看入口。图片访问地址有效 5 分钟，归档后停止签发新地址，之前已签发的地址可在有效期内继续使用。每账号每小时最多申请 30 次图片上传。

### 权限

只有 `support:chat:view` 的账号显示“仅查看”，输入框禁用并提示“当前账号没有回复权限”；两项权限都有时显示“可回复”。标记已读只需要查看权限。实时推送每次下发前重新校验后台账号和权限，账号被限制或权限被移除后停止推送。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 回复未收到确认 | 消息保留并显示“未确认送达”，可“重试原消息”。重试沿用原消息编号，已送达时不重复 |
| 刷新页面时有未确认回复 | 回复在当前浏览器会话内保留，恢复后显示“未确认送达”，可继续重试 |
| 回复超过 2000 字符或全是空格 | 输入框限制 2000 字符；没有图片时空内容不能发送，服务端同样拒绝 |
| 同一消息编号提交不同内容 | 服务端拒绝，不写入新消息 |
| 实时连接中断 | 显示“实时更新暂不可用，连接恢复后会自动补查。”，可“重新连接”；当前会话显示“实时消息连接暂不可用，恢复连接后会自动补查。”，可“补查消息” |
| 消息同步失败 | 提示“消息同步失败，请重试补查。发送失败的回复可单独重试。”，可“补查消息”，已加载的消息保留 |
| 更早消息加载失败 | 提示“历史消息加载失败，请重试加载更早消息。”，已加载的消息保留，可再次“加载更早消息” |
| 已读同步失败 | 提示“已读状态未同步。”，可“重试已读” |
| 会话列表加载失败 | 提示“会话加载失败，请重试。已加载的会话仍可查看。” |
| 地址里的会话不存在 | 消息同步失败，页面显示“玩家咨询”和“UID —”，不能成功回复 |
| 地址里的会话存在但不在已加载的列表中 | 消息正常加载，可以回复；加载到列表前页面显示“玩家咨询”和“UID —” |
| 暂无会话 | 列表显示“暂无玩家咨询” |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 12.2-R1 | 玩家首次发送消息 | 新会话出现在列表顶部，未读数 1，内容与玩家发送一致 |
| 12.2-R2 | 同一玩家再次发送消息 | 仍是同一会话，未读数增加，会话回到顶部 |
| 12.2-R3 | 客服打开会话，未读消息进入可视区域 | 未读数清零，其他客服的列表同步清零 |
| 12.2-R4 | 持有回复权限的客服发送文字 | 消息进入聊天记录，发送者为当前账号，服务端发布消息并更新玩家未读数；main 聊天展示尚未接入 |
| 12.2-R5 | 回复请求超时后点“重试原消息”，原请求实际已写入 | 聊天记录只有一条该消息，“未确认送达”消失 |
| 12.2-R6 | 只有 `support:chat:view` 的账号打开会话 | 显示“仅查看”，能看消息和标记已读，不能发送；直接提交回复时服务端拒绝 |
| 12.2-R7 | 无图片时回复全空格，或文字超过 2000 字符 | 不写入消息；有合规图片时允许空文字 |
| 12.2-R8 | 两名客服同时回复同一会话 | 两条消息都写入，序号连续不重复，两边显示顺序一致 |
| 12.2-R9 | 实时连接中断期间玩家发送消息，连接恢复 | 页面自动补查，消息按序号补齐 |
| 12.2-R10 | 没有 `support:chat:view` 的账号访问 | 菜单不显示，查询和实时推送被拒绝 |

| 12.2-R11 | 发送纯图片、混合文字图片，或第四张/超 5 MiB/非支持格式图片 | 合规消息正常送达；超限和错误归属被拒绝，重试不重复绑定 |
| 12.2-R12 | 玩家提问后已读、自动回复、人工回复 | 前两者保留未回复，人工回复清除未回复 |
| 12.2-R13 | 加急后解决，再由玩家发消息 | 解决清除加急和未回复；玩家消息自动重开并恢复未回复 |
| 12.2-R14 | 关键词命中多条、没有命中、人工刚回复 | 首条命中优先；无命中按 30 分钟接待语规则；人工活跃时不自动回复 |
| 12.2-R15 | 同时修改设置，或选择已停用重点标签 | 旧更新时间保存被拒绝；无效标签不能保存 |
| 12.2-R16 | 按关键词、时间和视图筛选 | 列表与数量使用相同筛选；已解决不进入未回复、加急、重点客户视图 |
| 12.2-R17 | 超过 90 天的消息被归档 | 双端不再展示，未读按剩余消息重算，仍可发送新消息 |
