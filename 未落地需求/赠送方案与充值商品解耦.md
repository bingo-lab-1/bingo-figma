# M5 · 赠送方案按运营商生效（与充值商品解耦）

## 1. 用途

现行规则见[5.5 充值商品与赠送](../M5-财务管理/5.5-充值商品与赠送/README.md)：比例赠送方案要逐个绑定到充值商品上才生效，门槛按币种分别配置，链上入金不参加。绑定和门槛是两道独立的筛选，配错时系统不提示。比如门槛写「满 20 USD」却没绑 20 USD 档，买这一档就不参加；方案启用了却没有商品绑定，就完全不起作用。

本文把比例赠送改为按运营商生效，决策见[M5 决策 D121–D123](../M5-财务管理/README.md#7-决策清单)。本期不改玩家端展示。

| 项目 | 规则 |
|---|---|
| 生效范围 | 运营商；同一运营商同一时间最多一个启用方案 |
| 参加的充值 | 该运营商的全部普通商品充值和链上入金；后台人工商品单和 4.15 首充破产补助专用订单不参加 |
| 门槛 | 只配 USD；充值金额按入账时刻的平台汇率换算成 USD 后判断 |
| 彩金 | 按充值币种发放：原币金额 × 赠送比例，按该币种的金额小数位向下舍入 |
| 计次 | 按方案区分；商品充值和链上入金共用同一方案的次数 |
| 固定赠送 | 仍在商品上配置，只用于商品充值 |

## 2. 配置项

| 配置项 | 含义和填写规则 |
|---|---|
| 方案名称 | 必填，1～100 个字符，运营商内唯一 |
| 启用状态 | 新方案保存后为停用。只能在方案卡片上启用或停用；启停不生成新版本，也不重新校验规则。同一运营商同时最多一个启用方案，启用另一个时按操作规则第 1 条一步切换 |
| 重置周期 | 不重置／每日重置，新方案默认不重置，每日按平台业务时区计。方案启用过一次后不得修改周期，要换周期就新建方案 |
| 比例彩金打码倍数 Y | 正数，最多 2 位小数；第 1～N 次共用 |
| 奖励次数 | 连续的第 1～N 次，至少 1 次 |
| 阶段门槛 | 每个阶段至少一档「最低金额（USD）＋ 赠送比例」。门槛非负，小数位不超过 USD 的金额小数位，同一阶段内门槛不重复。不再按币种分别配置 |
| 赠送比例 | 非负，整数部分最多 8 位，最多 2 位小数 |
| 充值商品 | 商品表单不再有比例方案选项；常规固定赠送保留，规则不变 |

## 3. 操作规则

### 启用与切换

1. 启用方案时，如果运营商已有启用中的方案，确认框列出将被停用的原方案，并写明「所有玩家在新方案下从第 1 次开始，原方案的次数保留」。确认后，在同一次操作里停用原方案、启用新方案；此后锁定的充值按新方案判断。
2. 停用唯一启用的方案后，新的商品充值只按商品的常规固定赠送处理，链上入金不发赠送。
3. 编辑启用中的方案会生成新版本，只影响此后锁定的充值，玩家次数延续。

### 锁定方案

4. 商品充值在建单时锁定当时启用的方案版本；链上入金在首次记录时锁定，与充值打码倍数 X 的锁定时点相同（D19）。锁定之后再切换、停用或编辑方案，都不影响这笔充值。
5. 建单或首次记录时运营商没有启用方案的，这笔充值不参加比例赠送。

### 判断与发放

6. 充值入账后按锁定的方案判断。阶段 ＝ 玩家在该方案、该周期内已获得比例彩金的次数 ＋ 1。周期按入账时刻的平台业务日期计：商品充值取受理付款的时刻，链上入金取到账时刻。
7. 把原币金额（商品充值为实付金额，链上入金为到账金额）按入账时刻的平台汇率换算成 USD。这里使用的汇率与该笔本金入账时的标准币换算是同一个快照。取当前阶段已满足的最高一档门槛，按该档比例计算彩金。
8. 商品充值满足比例门槛时只发比例彩金；不满足时发商品已开启的常规固定赠送；两者都没有就不发。链上入金没有固定赠送，不满足门槛就不发。
9. 比例彩金按 Y 建打码任务，本金仍按 X 建打码任务。只有发出大于 0 的比例彩金才计一次，不满足门槛不计次。
10. 同一玩家、同一方案、同一周期内的商品充值和链上入金，按入账先后逐笔判断，同一次不会被两笔充值重复占用。
11. 入账时汇率缺失的，本金照常入账，这笔的比例赠送暂缓；等入账时刻的汇率补齐后再判断发放，不按 1:1 估算。暂缓期间，同一玩家同一方案的后续充值排在这笔之后。

### 链上回滚

12. 已到账的链上入金被链上回滚时，除冲正本金外，同时冲正这笔比例彩金、取消对应的彩金打码任务；这笔占用过次数的，次数退回。彩金的冲正方式与本金冲正相同。

### 记录

13. 赠送记录能查到商品充值和链上入金两种来源，显示来源、锁定的方案版本、原币金额、USD 换算金额与汇率、阶段、比例、彩金和打码，以及「等待汇率」状态。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 两人同时启用不同方案 | 只有一个成功，另一个提示方案已更新，刷新后重试 |
| 切换方案时，有已建单未付款的商品订单，或确认中的链上入金 | 按各自锁定的原方案处理 |
| 门槛高于该运营商所有商品的价格 | 该阶段只能通过金额更高的链上入金达成；系统不拦截这种配置 |
| 汇率长时间缺失 | 比例赠送一直暂缓，赠送记录显示「等待汇率」；补齐后自动按入账时刻的汇率处理 |
| 链上入金回滚时，彩金已经被使用 | 按本金冲正的现有方式冲正彩金 |
| 后台人工商品单、4.15 首充破产补助专用订单 | 不参加比例赠送，不占次数 |
| 已领完旧方案全部次数的玩家，运营切换到新方案 | 在新方案下从第 1 次开始，这是切换方案的预期结果 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 解耦-R1 | 运营商已启用方案 A，再启用方案 B | A 自动停用；确认框说明玩家从第 1 次开始；两个启用请求同时提交时只有一个成功 |
| 解耦-R2 | 新建或编辑充值商品 | 表单没有比例方案选项；启用方案后，该运营商所有商品（包括新建的）的充值都按方案门槛判断 |
| 解耦-R3 | 配置方案门槛，再用 USDT 商品充值和链上入金 | 门槛只能填 USD；两种充值都按入账时刻的汇率换算，达标即发，彩金币种与充值币种一致 |
| 解耦-R4 | 同一玩家先买商品、再链上入金 | 分别计为第 1、2 次；不满足门槛不计次，商品充值改发固定赠送，链上入金不发 |
| 解耦-R5 | 切换方案前已建单或已检测到入金，切换后才入账 | 按原方案结算；切换后的新充值按新方案从第 1 次开始，原方案的次数保留 |
| 解耦-R6 | 入账时汇率缺失 | 本金立即到账；比例赠送在汇率补齐后补发；同一玩家后续的充值不会越过它 |
| 解耦-R7 | 链上入金到账并发放彩金后被回滚 | 彩金被冲正，彩金打码任务被取消，次数退回 |
| 解耦-R8 | 修改启用过的方案的重置周期 | 拒绝，提示新建方案 |
| 解耦-R9 | 运营商没有启用方案时充值 | 商品充值只发固定赠送，链上入金不发 |
| 解耦-R10 | 查询赠送记录 | 能查到链上入金的比例赠送，显示来源和 USD 换算金额 |
