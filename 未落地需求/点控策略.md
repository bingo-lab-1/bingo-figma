# M2 · 限时 RTP 点控策略与执行记录

## 1. 用途

按已有复合标签配置限时养杀任务。养使用运营配置的较高 RTP，杀使用较低 RTP；实际效果受游戏结算影响，不承诺净赢、净输或精确局数。任务达到金额目标或用完生效时长后停止干预。

本说明以 KAN-296 及 2026-11-02 产品确认为准，替代旧的“最多 N 局至少净赢 X”和快养／慢养。平台模块先交付，供应商实际执行默认关闭，完成能力联调后开放。

| 项目 | 规则 |
|---|---|
| 游戏 | 第三方 Slot；Originals 不产生任务进度 |
| 首期币种 | USD，使用现有钱包，不新增玩家端切币入口 |
| 人群 | 复用用户标签，不另建标签分类 |
| 最低余额 | 全局配置，读取现有标准 USD 账户余额，必要事实不完整时不接受新任务 |
| 统计日 | 沿用平台业务时区 BUSINESS_TIMEZONE |
| 净输赢 | 本任务所属游戏局实际返奖减实际投注；不包含充值、提现和奖励 |
| 供应商范围 | 单用户、单厂商设置 RTP，当前协议允许 30–99 的整数 |

## 2. 配置项

### 全局设置

| 字段 | 约束 |
|---|---|
| 执行开关 | 默认关闭；供应商未验证、厂商未配置大盘时不能开启 |
| 最低标准 USD 余额 | 大于或等于零 |
| 排队有效期 | 正整数秒，默认 3600 秒，可配置 |
| 最长暂停保留时间 | 正整数秒，默认 86400 秒，可配置；不消耗生效时长 |

### 点控规则与触发项

| 字段 | 约束 |
|---|---|
| 名称 | 必填 |
| 复合标签 | 关联一个已有启用标签 |
| 启用 | 新规则默认关闭；控制新任务准入 |
| 排序 | 列表上方优先；新增追加，编辑不改位置 |
| 触发项 | 上线、当日第1次充值、第2次充值、第3次及以上充值、盈利、亏损 |
| 养／杀 | 决定目标净赢或净亏方向 |
| 目标方式 | 固定金额、含两端随机金额区间、同币种当日成功充值金额百分比 |
| 目标金额 | 大于零；USD 最多两位小数；比例结果按 USD 精度向下舍入 |
| 盈亏门槛 | 盈利／亏损触发项填写当日同币种成功充值金额的正百分比 |
| 执行 RTP | 30–99 的整数 |
| 最长生效时长 | 正整数秒；不配置局数、快慢或保证达标 |
| 每用户每日上限 | 每个稳定触发项独立计数；正整数或不限 |

多个触发项独立接受事件，不构成“前一阶段结束自动进入下一阶段”的流程。每个触发项保留稳定编号，编辑配置不清空当天用量。

### 大盘 RTP

在“第三方游戏”菜单下提供“大盘 RTP”页签，按当前商户连接和厂商配置，取值 30–99 的整数。未配置时不猜测默认 RTP。展示配置版本、保存状态、同步状态、错误和最近确认时间，保存成功不等于供应商已生效。

修改大盘不改变进行中、排队或暂停任务的 RTP 快照，不因养杀方向相对大盘反转而取消任务。普通用户同步最新大盘；已有任务结束且无下一任务时，读取最新大盘值，通过单用户 set-rtp 恢复，不能写回任务开始时的旧值，也不能用全用户 reset-rtp 覆盖其他人的任务。

## 3. 操作规则

### 标签匹配与事件

接收新事件时，按点控界面排序取首个启用且标签命中的规则。普通上线、充值、结算事件仅检查自身对应的触发类型，同类按添加顺序选择；标签变化等状态重评按“上线 → 充值 → 盈亏”选择一个可执行项。首个标签规则没有可执行项时，本事件不继续匹配后面的规则。每个事件最多生成一个任务。充值序号绑定具体成功充值单，积压的两笔事件不会都被当成第二笔。

标签变化作为独立、可去重的评估事件，使用当前在线、同币种当日成功充值次数和已结算盈亏选择触发项，不重放旧充值事件。新增更高优先级标签不打断当前任务；新养排队，新杀遵守杀插队规则。

任务关联标签失效时，结束该标签的当前、排队和暂停任务，保留历史和已用次数；确认旧控制停止后立即按排序转入剩余标签规则，不等待再次上线或充值。例如首充标签失效但当日注册标签仍命中，转入当日注册规则。没有可执行规则或待执行任务时恢复大盘。标签重新命中可以由新的变化事件重新评估，旧任务不复活，仍受每日上限限制。

### 入队快照、排队与次数

入队时一次性固定目标金额、币种、执行 RTP、规则与标签依据、最长生效时长和过期依据。后续充值、配置编辑、大盘变化、重试或恢复不重新计算。

养按入队顺序执行；杀按入队顺序优先执行，杀可以暂停养，不打断或重置另一个杀。所有待执行杀结束后，先恢复被暂停的养，再执行其他养。恢复沿用原任务进度和剩余时长。

每日用量按“用户、稳定触发项、统计日”记录，不按币种另开额度。接受入队即预占一次；失败、过期、未达成、标签失效或切币不退回；同一事件、重试、暂停和恢复不重复预占。跨日不改变已有任务快照。

### 生效计时与进度

只有确认本任务 RTP 已生效的时间消耗生效额度。排队和确认暂停不消耗额度，离线不延长仍生效的任务。进入 Originals 后确认停止供应商干预再暂停，返回适用 Slot 后继续原任务；Originals 的输赢不纳入。

游戏局首次投注前固定任务归属。回调根据原归属更新，不按回调到达时的活动任务分配。养自身亏损计入净结果：目标养2、累计净亏3，剩余目标为5。杀期间结果不计入暂停的养。

### 结束、恢复与核对

达标或生效时间用完后停止干预，确认控制结束后再进入下一任务 RTP，或恢复最新大盘。超时未达标也结束，不追加时长或加大强度追目标。

目标养5、单局净赢20，记录实际20、超额15；不扣回、不自动杀15、不重复计入等待任务。杀超额同样按实际结果记录。

任务状态、RTP 生效状态和金额结果分别记录。接口成功只表示受理；生效、停止、恢复或回合归属不明确时保持核对中，阻止冲突任务。延迟结算、重复、取消和修正只更新原任务，不自动重启已结束任务。

## 4. 特殊情况

| 情况 | 处理 |
|---|---|
| 全局执行关闭 | 不接受新任务，已有控制仍须确认停止并恢复，不可直接停止调度器留下覆盖 |
| 关闭或编辑规则 | 只影响新准入；标签失效另按标签退出规则处理 |
| 标签被点控规则引用 | 阻止删除；历史快照不阻止删除 |
| 排队或暂停过期 | 不再激活，保留历史和已用次数 |
| 供应商停止超时 | 保持核对中并继续核对，不能显示已恢复 |
| 大盘94改98，旧养任务96 | 旧任务继续96，不重新判断方向；结束时恢复最新98 |
| 新用户或未进入过某厂商 | 联调确认该厂商设置资格后才开放，失败不可当作已同步 |
| 切币 | 首期无玩家端切币入口；币种隔离保留在模型中，旧控制确认停止后重置旧币种任务，历史与额度保留 |

## 5. 验收场景

| 编号 | 场景 | 预期 |
|---|---|---|
| 点控-R1 | 创建规则并选择标签 | 复用已有标签；无局数或快慢配置 |
| 点控-R2 | 养2、养5、养10入队 | 仅养2生效，其他保持 FIFO |
| 点控-R3 | 养2已净赢0.5，杀5到达 | 确认暂停后杀生效，杀结束恢复养2，剩余1.5 |
| 点控-R4 | 杀中再来养和杀 | 新杀不打断当前杀，等待杀优先于养 |
| 点控-R5 | 暂停、重试、充值、编辑配置 | 快照不变，不重复占每日次数 |
| 点控-R6 | 排队、暂停、离线 | 等待和确认暂停不计生效时间，离线仍生效则继续计时 |
| 点控-R7 | 达到时限但未达标 | 确认停止后记未达成，不追目标 |
| 点控-R8 | 目标5、净赢20 | 实际20、超额15，不自动杀或重复记账 |
| 点控-R9 | 目标2、净亏3 | 剩余目标5 |
| 点控-R10 | 充值、提现、奖励、Originals | 不增加任务净结果 |
| 点控-R11 | 迟到、重复、取消或修正 | 更新原任务，不重启已结束任务 |
| 点控-R12 | 同事件多次投递 | 一笔任务、一次每日预占 |
| 点控-R13 | 最高标签规则无可执行项 | 不向后匹配 |
| 点控-R14 | 首充标签消失，当日注册仍命中 | 原标签任务失效后立即评估当日注册，不等待新充值 |
| 点控-R15 | 高排序标签新增，原标签仍在 | 不打断原任务，新任务遵循养杀队列 |
| 点控-R16 | 标签反复进入退出 | 旧任务不复活，变化事件去重，每日额度仍有效 |
| 点控-R17 | 排队、暂停过期 | 不再下发其 RTP，显示原因 |
| 点控-R18 | 大盘修改 | 普通用户同步，已有任务快照不变，结束恢复最新大盘 |
| 点控-R19 | 控制或归属不明 | 核对中，不激活冲突任务 |
| 点控-R20 | 供应商未验证 | 配置可保存，实际执行不开启 |
| 点控-R21 | 无权限或版本过期 | 服务端拒绝操作，旧配置不变 |
| 点控-R22 | 来源不同的任务或厂商并发 | 单用户只有一个活动任务，各厂商单用户控制不相互覆盖 |
