# 7.4 · 广告回传

> 本文是已确定、尚未实现的需求。后台当前没有回传配置和回传记录，玩家端和服务端也不向广告平台上报任何事件。实现后并入[7.4 推广渠道](../../M7-代理管理/7.4-推广渠道/README.md)，并从[未落地需求索引](../README.md)移除。

## 1. 用途

投放方在广告平台投放时，要让广告平台知道哪些广告带来了注册和首充，才能按这些结果优化投放。运营在推广渠道上为每个渠道配置回传；玩家正式注册、账号第一笔充值入账时，系统把事件回传到该渠道配置的像素，运营可以查看每一次回传的结果。

本版只接入 Facebook，回传两类事件：

- 正式注册回传“完成注册”。
- 账号首充回传“购物”或“订阅”，每个渠道选其中一个。

复充、创建游客、安装到桌面都不回传。本版不提供其他广告平台、广告消耗导入、按广告计划的报表、手动重发和回传记录导出。

后台桌面端使用，界面简体中文。金额一律折成美元回传。记录时间按查看者浏览器时间显示。

## 2. 配置项

### 渠道的回传配置

新增和编辑渠道时填写，每个渠道一份。

| 配置项 | 含义和填写规则 |
|---|---|
| 广告回传 | 开或关，默认关。关闭时本渠道不加载像素、不回传，其余各项可以不填，已填内容保留 |
| 像素 ID | 广告平台分配给像素的数字编号。开启回传时必填，只接受数字 |
| 回传令牌 | 广告平台为该像素生成的服务端回传凭据。开启回传时必填。只在服务端使用，保存后页面只显示“已设置”，不显示内容；重新填写即覆盖，留空保存则保持原令牌 |
| 回传事件 | 首充时回传的事件：购物或订阅，默认购物。两者使用场景相同，按投放方在广告平台选用的转化事件选择 |
| 测试码 | 选填。填写后本渠道的全部回传都带测试码，用于在广告平台的测试事件页核对；联调结束后清空 |

### 渠道列表新增内容

| 列表内容 | 规则 |
|---|---|
| 回传状态 | 未开启、已开启、测试中。已开启且填了测试码时显示测试中 |
| 操作：回传记录 | 打开该渠道的回传记录 |

### 回传记录

按记录生成时间倒序，默认每页 20 条。记录保留 90 天。

| 内容 | 规则 |
|---|---|
| 筛选：事件 | 全部、完成注册、购物、订阅 |
| 筛选：状态 | 全部、等待回传、成功、重试中、已过期 |
| 筛选：UID | 精确匹配 |
| 筛选：时间 | 按记录生成时间，默认近 7 天 |
| 时间 | 记录生成时间，即注册成功或首充入账的时间 |
| UID | 产生事件的账号 |
| 事件 | 完成注册、购物或订阅 |
| 金额 | 首充回传的美元金额；完成注册不显示金额 |
| 广告点击信息 | 有或无。账号保存了广告点击标识时为有 |
| 测试 | 是或否。发送时带测试码为是 |
| 状态 | 等待回传：尚未发送。成功：广告平台已接收。重试中：上次发送失败，等待下次重试。已过期：事件发生满 7 天仍未成功，不再发送 |
| 说明 | 上次发送失败时广告平台返回的原因 |

## 3. 操作规则

### 保存回传配置

回传配置随渠道一起保存，保存后立即生效：之后发生的注册和首充按新配置回传，等待回传和重试中的记录也按发送时的最新配置发送。

关闭回传后不再生成新记录，尚未成功的记录停止发送；重新开启时，事件发生未满 7 天的记录继续发送。

### 记录广告点击

玩家打开带渠道参数的链接时，玩家端把链接中的广告点击标识和渠道一起保存，保存规则与渠道参数相同。注册或创建游客时一并提交，由服务端保存在账号上，之后不再修改。

链接里没有广告点击标识的账号照常回传，由广告平台自行判断归属。

### 加载像素与上报浏览

账号归属的渠道开启回传时，玩家端加载该渠道的像素并上报浏览；渠道未开启回传时，玩家端不加载任何广告脚本，也不向广告平台发送请求。像素 ID 是公开信息，可以下发到玩家端；回传令牌不下发。

### 注册回传

玩家完成正式注册时，回传一次“完成注册”，邮箱注册和手机注册都算。创建游客账号不回传；游客之后完成正式注册时，按正式注册回传。

### 首充回传

账号第一笔充值入账时，回传一次渠道所选的事件。金额为这笔充值的本金按[标准计价](../../M2-会员管理/2.1-会员列表/标准计价.md)折成的美元金额，不含赠送和活动奖励。

充值沿用财务的充值事实，三种来源都算：链上入金、法币充值订单、后台人工加款时勾选“计入充值”的本金。首充按账号计，每个账号只回传一次，之后的充值不回传。

### 回传去向

事件回传到账号注册时所属渠道的像素。后台之后把会员改绑到其他渠道，不改变该账号的回传去向。

测试账号的注册和充值不回传，也不生成记录。是否为测试账号，注册看注册时的标记，首充看入账时的标记。

### 发送与重试

回传与注册、充值入账分开执行：回传失败或广告平台不可用，不影响注册成功和充值入账。玩家关闭页面、浏览器拦截广告脚本，都不影响注册和首充的回传。

发送失败后自动重试，间隔逐次加长。事件发生满 7 天仍未成功的，记录标记为已过期，不再发送。同一个事件在广告平台只计一次，重试不会造成重复计数。

### 随事件发送的资料

每次回传发送：事件名称、发生时间、事件编号、首充的美元金额、账号保存的广告点击标识和浏览器标识、玩家访问时的 IP 地址和浏览器类型、页面地址，以及由 UID 经不可逆处理得到的账号标识。本版不发送邮箱、手机号和姓名。

隐私政策页须说明平台会把上述资料提供给广告平台，用于衡量广告效果。

### 查看回传记录

渠道行点“回传记录”打开该渠道的记录，可按事件、状态、UID 和时间筛选。记录只读，本版不提供手动重发和导出。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 开启回传但像素 ID 或回传令牌未填 | 不提交，提示补全 |
| 像素 ID 含非数字字符 | 不提交，提示只能填写数字 |
| 像素 ID 或回传令牌填错，广告平台拒绝 | 注册和充值入账不受影响；记录显示重试中和广告平台返回的原因；改正配置后，未过期的记录自动发送成功 |
| 广告平台暂时不可用 | 同上，自动重试 |
| 首充的币种暂时折不出美元金额 | 记录保持等待回传，取得标准计价后发送；满 7 天仍取不到则标记为已过期 |
| 同一账号两笔充值几乎同时入账 | 只回传业务时间较早的一笔 |
| 首充是勾选“计入充值”的人工加款 | 回传，金额为加款本金折成的美元金额 |
| 人工加款未勾选“计入充值” | 不算充值，不回传；之后第一笔计入充值的入账才是首充 |
| 首充入账后被冲正 | 已回传的事件不撤回；该账号之后的充值不再回传 |
| 游客账号充值 | 游客账号的第一笔充值按该账号回传一次；游客之后正式注册得到的新账号另算首充 |
| 开启回传前已注册或已首充的账号 | 不补报；已首充的账号之后的充值不回传，未首充的账号在开启后的首充照常回传 |
| 渠道被停用 | 停用只影响新会员注册；已归属账号的回传按回传开关执行 |
| 关闭回传时仍有未成功的记录 | 停止发送；重新开启且事件发生未满 7 天的继续发送 |
| 修改像素 ID、回传令牌或回传事件 | 之后发送的回传按新配置，包括等待回传和重试中的记录 |
| 账号在注册之后才被标为测试账号 | 标记之后入账的首充不回传 |
| 账号只有 `promotion:channel:view` | 可以看回传状态和回传记录，不能保存回传配置，服务端同样拒绝 |
| 渠道没有回传记录或筛选无结果 | 显示“暂无数据” |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 7.4-R19 | 编辑渠道，开启广告回传，填写像素 ID、回传令牌和测试码，回传事件选购物，保存 | 保存成功，列表回传状态显示测试中；再次打开编辑，回传令牌显示“已设置” |
| 7.4-R19 | 开启广告回传但不填像素 ID 或回传令牌，或像素 ID 含字母 | 不提交，分别提示补全或只能填写数字 |
| 7.4-R20 | 已设置回传令牌的渠道，回传令牌留空并保存其他修改 | 保存成功，原令牌不变，之后的回传照常成功 |
| 7.4-R21 | 渠道开启回传后，玩家用该渠道链接完成正式注册 | 广告平台测试事件页出现一次完成注册；回传记录新增一条完成注册，状态成功 |
| 7.4-R21 | 玩家打开该渠道链接，系统创建游客账号 | 不回传，不生成记录 |
| 7.4-R22 | 账号第一笔充值入账，分别用链上入金、法币充值订单、勾选“计入充值”的人工加款 | 各自回传一次渠道所选事件，金额为该笔本金折成的美元金额；回传记录状态成功 |
| 7.4-R22 | 同一账号第二笔充值入账 | 不回传，不生成记录 |
| 7.4-R23 | 把渠道的回传事件改为订阅，新账号完成首充 | 回传订阅，不回传购物 |
| 7.4-R24 | 测试账号在开启回传的渠道注册并充值 | 都不回传，不生成记录 |
| 7.4-R25 | 渠道未开启回传时玩家注册并完成首充，之后开启回传，该玩家再次充值 | 注册和首充不补报，再次充值也不回传 |
| 7.4-R26 | 把回传令牌改成错误的值，玩家注册并首充；7 天内改回正确的令牌 | 注册和充值照常成功；记录先显示重试中和原因，改正后变为成功 |
| 7.4-R26 | 回传一直失败，事件发生满 7 天 | 记录变为已过期，不再发送 |
| 7.4-R27 | 账号首充入账并回传后被冲正，该账号再次充值 | 已回传的事件不撤回，再次充值不回传 |
| 7.4-R28 | 运营把会员改绑到另一个渠道，该会员完成首充 | 事件回传到注册时所属渠道的像素 |
| 7.4-R29 | 玩家发起链上充值后关闭页面，充值随后入账 | 首充照常回传 |
| 7.4-R30 | 玩家用带渠道参数和广告点击标识的链接注册；另一玩家用不带广告点击标识的链接注册 | 前者的记录广告点击信息为有，后者为无，两者都回传成功 |
| 7.4-R31 | 渠道未开启回传时玩家打开页面；开启后再打开 | 未开启时页面不向广告平台发送任何请求；开启后广告平台测试事件页收到浏览 |
| 7.4-R32 | 清空测试码后玩家注册 | 回传不带测试码，记录的测试为否，列表回传状态显示已开启 |
| 7.4-R33 | 在回传记录按事件、状态、UID 和时间筛选 | 返回符合条件的记录；失败过的记录能看到原因 |
| 7.4-R34 | 只有 `promotion:channel:view` 的账号保存回传配置 | 服务端拒绝，原配置不变 |

## 6. 相关资料

- 入口与关联页面：一级菜单“推广渠道”，新增或编辑渠道时配置回传，渠道行“回传记录”查看结果。渠道与归属规则见[7.4 推广渠道](../../M7-代理管理/7.4-推广渠道/README.md)。
- 权限：查看回传状态和回传记录 `promotion:channel:view`；保存回传配置随新增渠道 `promotion:channel:create`、编辑渠道 `promotion:channel:edit`。
- 数据与责任：回传配置和回传记录归 M7。充值事实和美元折算归 M5，见[资金模型](../../M2-会员管理/2.1-会员列表/资金模型.md)和[标准计价](../../M2-会员管理/2.1-会员列表/标准计价.md)。注册事实和测试账号标记归 M2。广告点击标识由玩家端采集，随账号保存。
- 共用规则：回传范围和首充口径见 [M7 决策 D146、D147](../../M7-代理管理/README.md#7-决策清单)。安装到桌面不回传，见[安装到桌面](../安装到桌面/README.md)。
