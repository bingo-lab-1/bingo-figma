# 用户详情弹窗

> 本文是 `2.1-用户列表` 的组成部分,不是独立页面(没有自己的菜单项)。
> 页面级的筛选、列表、导出等需求见同目录 `README.md`。

## 1. 定位

运营点开一个玩家后,**在一个弹窗里看完这个人的全部情况**,不用在多个页面之间跳。

**谁在用**
| 角色 | 在这里做什么 |
|---|---|
| 客服 | 玩家说"钱没到账",查他的充值记录和资产变动 |
| 风控 | 看关联账户数量,判断是不是一个人开了多个号 |
| 运营 | 看首充漏斗,判断这个人值不值得投放资源 |
| 财务 | 核对三分账余额与充提差 |

**不做什么**
- 不改余额(人工上下分跳 M3.5)
- 不做跨玩家查询(那是各独立页面的事,见第 5 段)

## 2. 展开方式

**弹窗**,不是抽屉,不是新页面。列表停留在弹窗背后,关闭后回到原筛选结果与滚动位置。

| 入口 | 位置 |
|---|---|
| 用户ID | 表格「用户ID」单元格,蓝色可点文本 |
| 分享链接 | 打开即直接停在该玩家的详情上 |

> 用户ID 旁边有**复制按钮**,点它只复制 ID,**不打开弹窗**。
> 勾选框与「设为测试账号」按钮同样不触发弹窗,避免误点。

## 3. 常驻信息区(不随 tab 切换)

弹窗顶部固定展示,切到任何 tab 都能看到:

| 字段 | 可否修改 | 说明 |
|---|---|---|
| 用户ID | 否 | |
| VIP等级 | 否 | |
| 用户账号 | **可改** | 手机号 |
| 用户提现绑定手机 | **可改** | 与登录账号可能不同 |
| 绑定邮箱 | **可改** | |
| 账号状态 | 否 | 正常 / 封禁 |
| 用户标签 | 否 | 自动打标,见第 6 段 |
| **打码量** | **可新增** | 后台可给玩家追加打码要求,通常为一个固定值，如10，20等等 |
| **总 RTP** | 否 | 后面跟一个括号显示当日 RTP,用于识别异常赢率 |
| 备注 | **可改** | 运营自由填写 |

> 修改账号、手机、邮箱、备注,以及新增打码量,**都要留痕**(见 E-2)。

### 4.2 账户详情
内容待定，显示银行账户信息

### 4.3 风控数据
判断是不是同一个人开了多个号。

| 维度 | 当前用户数据 | 关联账户数量 |
|---|---|---|
| 登录设备 | 该玩家用过几个设备 | 同一设备下有几个账号 |
| 登录IP | 该玩家用过几个 IP | 同一 IP 下有几个账号 |
| 注册设备 | — | 同一设备注册了几个账号 |
| 注册IP | — | 同一 IP 注册了几个账号 |


### 4.4 订单数据
单注明细,可筛选(局号 / 游戏类型，游戏类型我们可能暂时没有，每个游戏需要有一个游戏类型，例如原创，老虎机等等)。

**汇总**:参与次数 · 流水金额 · 游戏盈亏
**列**:序号 · 局号 · 游戏类型 · 品牌 · 子游戏名称 · 接入厂商 · 类型 · 投注金额 · 派彩金额 · **赠送金额** · **取消金额** · 会员盈亏 · 订单状态 · 投注时间

### 4.5 提款记录
可筛选(提现订单号 / 时间 / 状态)。

**汇总**:成功提现次数 · **成功提现真金** · **成功提现彩金**
**列**:序号 · **锁定** · 订单号 · **提现真金金额** · **彩金金额** · 提现信息(姓名 / 内容 / **CPF**)· 首次提现 · 手续费 · 实际到账 · 付款通道 · 提现方式 · 订单状态 · 操作人员 · 备注 · 操作
**时间**:注册时间 · 申请时间 · 提交时间 · 完成时间

他这里的表格略微复杂，可以看截图

### 4.6 充值记录
可筛选(订单号 / 状态 / 通道单号 / 支付通道)。

**汇总**:成功充值次数 · 成功充值金额
**列**:序号 · 订单号 · **通道单号** · 支付金额 · **获得金额** · **赠送金额** · 订单状态 · 支付通道 · 是否首充 · 时间 · 操作

> 支付金额与获得金额分开——充值活动的赠送体现在「赠送金额」。

### 4.7 资产变动
所有余额变动的流水,可按**变动原因多选**筛选。

**汇总**:三个总额 + **失败金额**
**列**:序号 · ID · 变动时间 · **变动原因** · **变更方式** · 状态 · 变动前金额 · 变动金额 · 变动后金额

> **变动前/后金额都记**,便于对账。投注先扣款生成一条记录，返奖在生成一条记录，即单次下注生成两条记录

### 4.8 投注记录
**按游戏聚合**的统计,不是单注明细(单注在 4.4)。可筛选游戏类型 / 厂商 / 品牌。

**列**:序号 · 游戏类型 · 厂商 · 游戏品牌 · 游戏ID · 游戏名称 · 总注单量 · 总投注金额 · 返奖金额 · 用户输赢 · **占单量** · **投注金额占比** · **RTP**

> 用来看这个玩家主要玩什么、在哪款游戏上赢得异常。

### 4.9 资产走势
余额随时间变化的图表,可筛选游戏类型 / 品牌 / 厂商 / 时间。


## 5. 为什么要做成弹窗

通过ID展开用户的详情信息可能在多处复用，路由跳转的话容易让运营反复操作。



## 7. 关键参数与假设

| # | 参数 | 取值 | 性质 | 待验证点 |
|---|---|---|---|---|
| A-1 | 风控关联账户的判定时间窗 | 1 小时 | **可配置** | 以时间为中心前后各取该时长，例如同IP登录，可以根据登录时间，以及一个前后时间窗口查询同IP的数量 |


## 9. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E-1 | 越权查看 | 改链接里的玩家标识,或绕过界面直接取数 | **每次取数都要在服务端判权限**并拒绝;把入口藏起来不算防线 |
| E-2 | 修改未留痕 | 改账号/手机/邮箱/备注,或新增打码量 | **全部必须留痕**,记录操作人、改动前后值 |
| E-3 | 单个 tab 失败 | 某个 tab 加载失败或超时 | **只有该 tab 显示重试**,其余 tab 照常可用 |
| E-4 | 玩家不存在或已注销 | 打开一条旧的分享链接 | 弹窗内提示,不出现系统错误页 |
| E-5 | 并发状态变更 | 弹窗打开期间该玩家被他人封禁 | 提交修改时提示状态已变更,不静默覆盖 |
| E-6 | 敏感字段泄露 | 手机号、CPF、收款账号的展示 | **数据发出前就要脱敏**;查看完整值需独立权限且单独留痕 |
| E-7 | 冻结资金误解冻 | 在 4.2 点「解冻」 | 二次确认 + 原因必填 + 留痕;金额级解冻规则见 M3.6 |
