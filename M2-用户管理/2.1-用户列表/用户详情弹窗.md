# 用户详情弹窗

> 本文是 `2.1-用户列表` 的组成部分,不是独立页面(没有自己的菜单项)。
> 页面级的筛选、列表、导出等需求见同目录 `README.md`。
> **本文所有金额的语义由同目录 [`资金模型.md`](./资金模型.md) 定义** ——
> 每个币种只有一个余额,真金彩金是账本上的来源构成,打码量是任务剩余量合计。
> 下面各 tab 的字段清单按实采截图记录**长什么样**,含义一律以 `资金模型.md` 为准。

## 1. 定位

运营点开一个玩家后,**在一个弹窗里看完这个人的全部情况**,不用在多个页面之间跳。

**谁在用**
| 角色 | 在这里做什么 |
|---|---|
| 客服 | 玩家说"钱没到账",查他的充值记录和资产变动 |
| 风控 | 看关联账户数量,判断是不是一个人开了多个号 |
| 运营 | 看首充漏斗,判断这个人值不值得投放资源 |
| 财务 | 核对该币种余额、来源构成与充提差 |

**不做什么**
- 不改余额(人工上下分跳人工充值页,**本仓库范围外**)
- 不做跨玩家查询(那是各独立页面的事,见第 8 段)

## 2. 展开方式

**弹窗**,不是抽屉,不是新页面。列表停留在弹窗背后,关闭后回到原筛选结果与滚动位置。

| 入口 | 位置 |
|---|---|
| 用户ID | 表格「用户ID」单元格,蓝色可点文本 |
| 分享链接 | 打开即直接停在该玩家的详情上 |

> 用户ID 旁边有**复制按钮**,点它只复制 ID,**不打开弹窗**。
> 勾选框与「设为测试账号」按钮同样不触发弹窗,避免误点。

见 `截图/弹窗-tab1-用户详情-标签悬浮.png`。

| 字段 | 可否修改 | 说明 |
|---|---|---|
| 用户ID | 否 | |
| VIP等级 | 否 | |
| 用户账号 | **可改** | 手机号 |
| 用户提现绑定手机 | **可改** | 与登录账号可能不同 |
| 绑定邮箱 | **可改** | |
| 账号状态 | 否 | 正常 / 封禁 |
| 用户标签 | 否 | 自动打标,标签本身在 2.5 用户标签页维护 |
| **打码量** | **可新增** | 显示该币种全部 `active` 任务的剩余量合计。新增即**创建一条独立任务**(`资金模型.md` R8),需填倍数与原因、二次确认、留痕 —— **不是直接加到一个累计值上**。倍数**可填 0**(该笔不带打码义务),但需独立的豁免权限 |

## 4. 十个 Tab 的内容

### 4.1 用户详情
玩家的身份与来源。

#### 4.1.1 账户详情
| 字段 | 可否修改 | 说明 |
|---|---|---|
| CPF | **可改** | 巴西纳税人识别号,脱敏展示,见第 7 段 E-6 |
| 余额 | 否 | 该币种的**单一余额**;多币种玩家按币种分别呈现 |
| 真金 | 否 | **账本派生的来源构成**,不是独立余额。带「明细」入口 |
| 彩金 | 否 | 同上,来源为活动发放的部分。带「明细」入口 |
| 佣金 | 否 | 同上,来源为代理佣金的部分。带「明细」入口 |
| 待打码量 | 否 | 该币种全部 `active` 任务的剩余量合计;点开看逐条任务。**任务无期限**,不会自行归零 |
| 今日输赢/历史输赢 | 否 | 红色为盈，绿色为输|

> 实采截图里这里是「钱包总余额 / 真金余额 / 彩金余额 / 佣金余额」四个并列数字 ——
> 那是竞品的双余额模型。按 `资金模型.md`,只有第一个是余额,后三个是来源构成。
> **后台保留这三个构成**(客服查来源、风控看彩金占比、财务对账都要),但它们不可加减、
> 不可单独提现、不作任何判定依据;玩家端按 R14 只显示单一余额。

### 4.4 订单数据
单注明细,可筛选(局号 / 游戏类型，游戏类型我们可能暂时没有，每个游戏需要有一个游戏类型，例如原创，老虎机等等)。

**汇总**:参与次数 · 流水金额 · 游戏盈亏
**列**:序号 · 局号 · 游戏类型 · 品牌 · 子游戏名称 · 接入厂商 · 类型 · 投注金额 · 派彩金额 · **取消金额** · 会员盈亏 · 订单状态 · 投注时间

「类型」取值为 下注 / 返奖 —— **同一局号会出现两行**(下注一行、返奖一行),
返奖行的投注时间为空。列多需横向滚动,见
`截图/弹窗-tab4-订单数据-左半.png` 与 `截图/弹窗-tab4-订单数据-右半.png`。

**有意不做的列:`赠送金额`。** 截图里它夹在派彩金额与取消金额之间,**我们不做**。
已核实该列在来源系统的数据库里恒为 0,是一列没有语义的死字段;
照抄只会让人以为它有含义。看到截图有、文档没有,是**刻意的,不要补上**。

本页也**不单独展示出资拆分**。R16 的彩金/真金出资在 tab7 资产变动的「变动金额」
一格里已经成对可见,同一份数据不在两处展示(见 `00-公共约定/README.md`「消灭重复性信息」)。

### 4.5 提款记录
可筛选(提现订单号 / 时间 / 状态)。

**汇总**:成功提现次数 · 成功提现金额(**按币种**)
**列**:序号 · **锁定** · 订单号 · **提现金额** · 提现信息(姓名 / 内容 / **CPF**)· 首次提现 · 手续费 · 实际到账 · 付款通道 · 提现方式 · 订单状态 · 操作人员 · 备注 · 操作

> 实采是「提现真金金额 / 彩金金额」两列 —— 双余额模型的产物。
> 按 `资金模型.md` R10,提现按**币种钱包整体**判定资格,不按真金彩金分别放行,
> 因此这里改成单一提现金额 + 币种标识。被拦截的申请要能看出**还差多少打码量**。
**时间**:注册时间 · 申请时间 · 提交时间 · 完成时间(四列并列在「时间」表头组下)

本表是弹窗里最宽的一张,「提现信息」与「时间」都是**两级表头**,需横向滚动三屏才能看完:
`截图/弹窗-tab5-提款记录-左半.png`(锁定/订单号/金额)·
`截图/弹窗-tab5-提款记录-中段.png`(提现信息/首次提现/手续费)·
`截图/弹窗-tab5-提款记录-右半.png`(到账/付款通道/四个时间戳/提现方式)。

### 4.6 充值记录
可筛选(订单号 / 状态 / 通道单号 / 支付通道)。

**汇总**:成功充值次数 · 成功充值金额
**列**:序号 · 订单号 · **通道单号** · 支付金额 · **获得金额** · **赠送金额** · 订单状态 · 支付通道 · 是否首充 · 时间 · 操作

> 支付金额与获得金额分开——充值活动的赠送体现在「赠送金额」。
> **这里的 `赠送金额` 与 4.4 订单数据里那个同名列不是一回事**,4.4 那个恒为 0、已确认不做;
> 这里的是「本笔充值触发了多少彩金」,是**交叉引用**而不是余额:
> 按 R8 彩金独立入账、独立建任务,不与充值合并成一笔。
> 实采样本里这一列也全是 0(那三笔充值没触发活动),**含义待实盘确认**。
> 末列一格内上下堆两个时间戳(创建时间 / 支付时间)。见 `截图/弹窗-tab6-充值记录.png`。

### 4.7 资产变动
所有余额变动的流水,可按**变动原因多选** + 日期范围筛选。

**汇总**:三个总额 + **失败金额**
**列**:序号 · ID · 变动时间 · **变动原因** · **变更方式** · 状态 · 变动前金额 · 变动金额 · 变动后金额

**金额三列各自拆成四个分量**,同一格内上下堆叠:总额 · 真金 · 彩金 · **打码量**。
即一行要展示 12 个数值。这是全弹窗信息密度最高的一处,见 `截图/弹窗-tab7-资产变动.png`。

四个分量的含义按 `资金模型.md` 重新定义:**总额**是该币种余额;**真金/彩金**是账本上的
来源构成,不是两个独立余额;**打码量**是该币种全部 `active` 任务的剩余量合计,
不是钱包上的一个累计字段。闪兑产生的账变还要能看出**迁移了多少打码义务**(R12)。

**这四个分量不是旧模型的残留,是 R16 扣款顺序的展示形态。** 一笔混合注的「变动金额」
那一格正是出资拆分:彩金扣光、真金补差,例如 `彩金 −3 / 真金 −2`;该注的派彩按冻结的
出资比例回冲,同样在这里成对可见。实采截图里下注行显示 `真金 −0.4 / 彩金 0`,
正是当时彩金为 0 走纯真金的情形 —— 与彩金优先不矛盾。

客服解释「我明明有真金为什么扣的是彩金」,靠的就是这一格。

**变更方式**是一组标记(如「总额:」「打码量增加」),标明这笔变动动了哪些分量;
下注/返奖这类不影响打码量的记录,该标记为空。见 `截图/弹窗-tab7-资产变动-下注与返奖.png`。

**变动原因**为多选下拉,实采可见:下注 · 取消下注 · 返奖 · 充值 · 提现 · pdd 提现 ·
代理提现 · 后台人工充值金额 ……(列表更长,需滚动)。
按新模型还需补上**闪兑转出 / 闪兑转入 / 汇兑舍入**三类(`资金模型.md` R11、F7)。
运营也会看到活动类原因(充值砸金蛋、新每日签到、VIP升级奖励)。
见 `截图/弹窗-tab7-资产变动-变动原因下拉.png`。

> **变动前/后金额都记**,便于对账。投注先扣款生成一条记录,返奖再生成一条记录,
> 即单次下注生成两条记录。
> **枚举全集待补** —— 实采账号看不到完整列表,需拿到有数据的账号后二轮采集。

### 4.8 投注记录
**按游戏聚合**的统计,不是单注明细(单注在 4.4)。可筛选游戏类型 / 厂商 / 品牌。

**列**:序号 · 游戏类型 · 厂商 · 游戏品牌 · 游戏ID · 游戏名称 · 总注单量 · 总投注金额 · 返奖金额 · 用户输赢 · **占单量** · **投注金额占比** · **RTP**

> 用来看这个玩家主要玩什么、在哪款游戏上赢得异常。见 `截图/弹窗-tab8-投注记录.png`。

### 4.9 资产走势
余额随时间变化的**面积图**,可筛选游戏类型 / 品牌 / 厂商 / 时间。
横轴是投注时刻(精确到秒,不是按天聚合),图下带区间缩放条。
见 `截图/弹窗-tab9-资产走势.png`。

### 4.10 状态监控
**一行一玩家的宽表**,把这个玩家的获客与首充事实拉平成一行,用于投放归因核对。
带「列设置」与「刷新」,需横向滚动。见 `截图/弹窗-tab10-状态监控.png`。

**基础信息**(表头组):用户ID · 注册时间 · 注册日期 · **渠道(运营商ID)** ·
**广告计划(代理ID)** · 设备ID · 首充时间 · 首充日期 · 首充金额 · 注册…(后续列被截断)

> 注册时间与注册日期、首充时间与首充日期**同时存在**(前者到秒,后者到天),
> 说明这张表是给按天对账用的。
> **截断的后续列待补** —— 需拿到有数据的账号后二轮采集。

## 5. 为什么要做成弹窗

通过ID展开用户的详情信息可能在多处复用，路由跳转的话容易让运营反复操作。

## 6. 关键参数与假设

| # | 参数 | 取值 | 性质 | 待验证点 |
|---|---|---|---|---|
| A-1 | 风控关联账户的判定时间窗 | 1 小时 | **可配置** | 以时间为中心前后各取该时长，例如同IP登录，可以根据登录时间，以及一个前后时间窗口查询同IP的数量 |

## 7. 异常与边界

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E-1 | 越权查看 | 改链接里的玩家标识,或绕过界面直接取数 | **每次取数都要在服务端判权限**并拒绝;把入口藏起来不算防线 |
| E-2 | 修改未留痕 | 改账号/手机/邮箱/备注,或新增打码量 | **全部必须留痕**,记录操作人、改动前后值 |
| E-3 | 单个 tab 失败 | 某个 tab 加载失败或超时 | **只有该 tab 显示重试**,其余 tab 照常可用 |
| E-4 | 玩家不存在或已注销 | 打开一条旧的分享链接 | 弹窗内提示,不出现系统错误页 |
| E-5 | 并发状态变更 | 弹窗打开期间该玩家被他人封禁 | 提交修改时提示状态已变更,不静默覆盖 |
| E-6 | 敏感字段泄露 | 手机号、CPF、收款账号的展示 | **数据发出前就要脱敏**;查看完整值需独立权限且单独留痕 |
| E-7 | 冻结资金误解冻 | 在 4.1.2 存取款点「解冻」 | 二次确认 + 原因必填 + 留痕;金额级解冻规则归财务的冻结解冻页(**本仓库范围外**) |
