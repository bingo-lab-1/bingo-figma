# 2.7 · 玩家排行榜

## 1. 用途

运营通过本页找出所选期间充值多、投注多或净赢金额高的玩家，并结合玩家的当前余额、渠道、标签和账号状态查看具体情况。

本文按现有后台页面归档，面向桌面端，使用简体中文；入口为“会员管理 → 玩家排行榜”。每行是一名符合所选榜单条件的玩家，后台管理账号不参与排名。封禁玩家和测试玩家不因身份被自动排除。

页面有“总充值金额”“总投注金额”“总输赢”三种榜单。金额统一按 USD 标准计价展示，两位小数、千分位分隔；页面当前没有币种选择或金额单位列。日期使用后台当前选择的时区。

## 2. 查询条件

首次进入默认查看今天的“总充值金额”榜，账号为空，标签和 VIP 等级不设限制；渠道默认不限定，从带渠道的入口进入时沿用该渠道。修改条件后点击“查询”才应用，多个条件须同时满足。

| 条件 | 含义和填写规则 |
|---|---|
| 会员账号 | 输入完整账号或其中一段，区分大小写，按包含关系匹配；输入中的首尾空格保留。留空不限定账号 |
| 渠道 | 单选，选择“全部渠道”或一个具体渠道；按玩家当前所属渠道筛选 |
| 标签 | 单选，选择“全部标签”或一个具体标签；按玩家当前标签筛选 |
| VIP等级 | 单选，选择“全部等级”或一个具体等级；按玩家当前 VIP 等级筛选 |
| 日期 | 分别选择开始和结束日期，默认均为今天；包含开始日零点至结束日结束的完整期间。只填一端时只限制该端，两端都清空时不限制统计时间 |

日期依据业务发生时间，而非注册时间。充值、提现、赠送、佣金和投注按相应资金入账或扣款时间统计；总输赢按投注结算时间统计。

例如，开始和结束日期均选择 9 月 8 日，就统计所选时区 9 月 8 日零点至 9 月 9 日零点之前发生的对应业务。9 月 7 日下注、9 月 8 日结算的投注，投注金额计入 9 月 7 日，总输赢计入 9 月 8 日。

结束日期早于开始日期时，服务拒绝查询并返回日期范围错误。同日查询是有效范围。页面对查询失败的现有表现见第4部分。页面没有按余额、封禁状态、在线状态或输赢正负进行筛选的独立条件。

## 3. 结果字段

列表共 19 列，包含操作列。金额、充值次数、提现笔数和投注笔数按所选期间统计；用户资料、用户余额和邀请人数取当前值。

表头沿用网站名称。“当日充值金额”等列在选择多日后展示多日合计，“总投注金额”等列也受日期限制；不能仅凭“当日”或“总”判断统计范围。

| 字段 | 含义 |
|---|---|
| 会员账号 | 当前玩家账号 |
| 用户ID | 玩家唯一标识 |
| 用户余额 | 当前钱包本金余额与赠金余额合计，按各币种当前汇率折成 USD 后加总；现有汇总不计入缺少汇率的钱包，不是所选期间结束时的余额 |
| 渠道 | 玩家当前所属渠道 |
| 封禁状态 | 玩家当前状态，显示“正常”或“已封禁” |
| 邀请人数 | 玩家当前直接邀请人数，不受日期条件限制 |
| 用户标签 | 玩家当前拥有的标签；没有标签时显示“-” |
| 当日充值金额 | 所选期间充值入账的 USD 标准金额合计，包含按充值入账的人工加款 |
| 当日提现金额 | 所选期间提现扣款的 USD 标准金额合计，按正数展示；不等同于最终成功的提款订单金额 |
| 当日赠送金额 | 所选期间“彩金发放”入账的 USD 标准金额合计；VIP奖励、普通人工加款、佣金和游戏派彩不计入此列 |
| 当日佣金 | 所选期间佣金入账的 USD 标准金额合计 |
| 当日充值次数 | 所选期间计入充值统计的记录数 |
| 总提现笔数 | 所选期间计入提现统计的记录数 |
| 总投注金额 | 所选期间投注扣款的 USD 标准金额合计，按正数展示；不等同于有效投注或完成打码量 |
| 总投注笔数 | 所选期间计入投注统计的记录数 |
| 总输赢 | 所选期间已结算投注的净输赢合计；正数表示玩家赢，负数表示玩家输，零表示合计持平 |
| 在线状态 | 玩家当前状态，显示“在线”或“离线” |
| 最近在线时间 | 玩家最近在线时间，按查看者浏览器本地时区显示到秒 |
| 操作 | “详情”，打开该玩家的会员详情弹窗 |

充值、提现、赠送、佣金和投注金额使用账变已经完成的 USD 折算结果，未完成折算的相应记录不计入这些金额及次数。充值次数、提现笔数、投注笔数按纳入统计的资金记录计数，不按业务订单去重。

提现扣款的退款不从“当日提现金额”中扣回；投注取消返还也不从“总投注金额”中扣回。查最终提款结果使用提款记录，查有效投注与打码使用对应资金规则。

一笔结算完整且折算齐全的投注，其净输赢是派彩标准金额减去投注标准金额；本页按结算期间汇总该净额。因此，不能直接用本页同一期间的总投注金额反推总输赢。折算缺失等现有实现限制见[网站核对记录](../../.artifacts/ban-ranking-prd-2026-09-10/README.md)。

当前余额按当前汇率展示，历史业务金额使用各笔业务保存的标准金额，两者的换算时点不同。余额仅供查看，不用于判断活动资格、扣款或可提现金额。

## 4. 操作规则

### 榜单切换与排序

| 榜单 | 入榜条件 | 排序依据 |
|---|---|---|
| 总充值金额 | 所选期间至少有一笔计入统计的充值入账 | 期间充值金额从高到低 |
| 总投注金额 | 所选期间至少有一笔计入统计的投注扣款 | 期间投注金额从高到低 |
| 总输赢 | 所选期间至少有一笔已结算投注 | 期间净输赢从高到低，净额为零或负数也可入榜 |

切换榜单会立即查询，保留已应用的筛选条件和每页条数，回到第 1 页。每个榜单分别确定入榜玩家，不是给同一份全体玩家名单换个排序。

金额相同的玩家按用户 ID 升序排列，列表不单列名次。列头不提供改变排序方向的操作。“总输赢”按带正负号的净额排列，不按输赢绝对值排列。

### 查询、重置与分页

首次进入自动加载。点击“查询”应用已填写的条件，保留当前榜单和每页条数，回到第 1 页。

“重置筛选条件”清空账号、标签和 VIP 等级，把日期恢复为今天，并回到第 1 页；保留当前榜单、每页条数及当前渠道。要跨渠道查询，需明确选择“全部渠道”后查询。

“收起筛选”只隐藏输入区，不清空条件或改变结果；展开后可继续编辑。

默认每页 20 条，可选 50 条或 100 条。切换每页条数回到第 1 页，保留榜单和筛选条件。页码、上一页、下一页沿用当前条件；底部展示本页起止条数与入榜玩家总数。

### 查看详情

点击某行“详情”，打开对应玩家的共用会员详情弹窗，默认进入“账号概览”。关闭后返回原榜单，保留筛选、分页及排序。

会员详情的资料及业务操作在[用户详情文档](../2.1-用户列表/用户详情弹窗.md)维护。排行榜本身不提供修改统计金额、批量处理或导出操作。

### 无结果与加载失败

没有符合当前榜单及筛选条件的玩家时，显示“暂无数据”和“调整筛选条件后再试。”无结果不表示所有玩家都没有业务，其他榜单或日期可有结果。

加载时显示占位。服务返回查询错误时，页面弹出对应的错误说明；网络错误提示“Network error”。

现场已确认：日期范围无效时，服务拒绝查询并弹出提示，但列表仍保留上一次成功的结果，没有出现“重试”按钮。保留的数据不是新条件的查询结果，需要修正条件后重新查询。这个错误处理缺陷及复现步骤见[网站核对记录](../../.artifacts/ban-ranking-prd-2026-09-10/README.md)，不将保留旧结果定义为正常查询规则。

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 2.7-R1 | 从菜单首次进入 | 默认今天、总充值金额榜、第 1 页、每页 20 条；自动查询符合入榜条件的玩家 |
| 2.7-R2 | 组合填写账号、渠道、标签和 VIP 等级后查询 | 结果同时满足全部条件；资料条件按玩家当前值判断 |
| 2.7-R3 | 日期选择同一天，再改为连续多天 | 分别统计所选时区完整自然日或整个期间；“当日”“总”表头不改变日期约束 |
| 2.7-R3 | 清空一端日期、清空两端日期，或设置结束早于开始 | 分别取消对应时间边界、取消全部时间限制；错误日期范围显示错误提示 |
| 2.7-R4 | 同一期间切换三个榜单 | 充值榜要求有充值入账，投注榜要求有投注扣款，输赢榜要求有已结算投注；人数可不同 |
| 2.7-R5 | 查看净赢、持平、净亏玩家的输赢榜 | 净额从高到低排列；持平和净亏玩家符合入榜条件时仍展示；同金额按用户 ID 升序 |
| 2.7-R6 | 对照充值、提现和投注资金记录 | 按已完成标准折算的相应记录统计金额及次数；次数不按订单去重，提现退款和投注取消返还不从扣款统计中扣回 |
| 2.7-R7 | 查看跨日下注、次日结算的投注 | 投注金额按扣款日计入，总输赢按结算日计入；不以注册日或统一时间字段代替 |
| 2.7-R8 | 切换历史日期后查看玩家资料 | 金额与次数随期间变化；余额、渠道、标签、账号状态及邀请人数仍是当前值 |
| 2.7-R9 | 切换每页条数、翻页，再查询或切榜单 | 每页条数支持 20、50、100；查询和切榜单回第 1 页，保留选定条数 |
| 2.7-R10 | 选择具体渠道和其他条件后重置 | 日期回今天，账号、标签、VIP 等级清空；渠道、榜单及每页条数保留 |
| 2.7-R11 | 点击某行详情后关闭 | 打开同一玩家的会员详情，默认账号概览；关闭后榜单查询条件和分页保持 |
| 2.7-R12 | 查询无匹配条件，或输入结束早于开始的日期 | 无匹配时显示空结果；非法日期由服务拒绝并提示，修正后可重新查询。失败后仍保留旧结果属于已记录缺陷，不能作为新查询结果验收 |
