# 条件模型 · 基础指标、时间范围与组合规则

> 本文是 `2.5-用户标签` 的组成部分,不是独立页面(没有自己的菜单项)。
> **本文只讲规则模型**:标签由什么构成、一条条件怎么判定。页面级的字段、需求、权限、
> 重算调度与异常处理见同目录 `README.md`,本文直接引用那边的参数编号(A1–A14)。
> 本次改造(2026-08-17)推翻旧口径的来龙去脉记在 `../README.md` 第 7 段决策清单
> (D31 修订、D33、D34、D35、D56 与 M4-D63),本文不重复。

## 1. 为什么改造

当前用户标签存在大量固定条件,例如「今日充值金额」「累计充值金额」「今日投注金额」
「累计投注金额」。很多条件本质上只是基础指标、时间范围和比较方式不同。

如果每种业务场景都作为独立条件开发,条件数量会持续增加,并产生大量重复逻辑。
因此本次将标签统一改造为三层(D33):

**基础指标 → 条件 → 标签**

基础指标是系统提供的最小数据单元;条件由基础指标进行比较产生;标签由一个或多个条件组成。

## 2. 条件结构

条件可使用统计指标或玩家当前资料。以下分类用于说明取值和比较语义,不要求界面强制分区。
数值指标条件为:

**左值 比较符 右值**

- 左值:「基础指标 + 时间范围」
- 比较符:`= ≠ > ≥ < ≤`
- 右值:常量,或另一个「基础指标 + 时间范围」
- 任何情况下都不允许标签作为左值或右值,标签之间不得相互引用(D31)

| 条件示例 | 类型 |
|---|---|
| 累计充值金额 ≥ 1000 USD | 基础指标与常量比较 |
| 今日充值金额 > 昨日充值金额 | 同指标不同时间范围比较 |
| 累计充值金额 > 累计提现金额 | 不同基础指标比较 |
| 最近7天投注次数 > 最近7天充值次数 | 不同基础指标比较 |

## 3. 基础指标

基础指标是构成条件的最小数据单元,**时间范围和比较方式不属于基础指标**。
例如「今日充值金额」不单独作为指标,而拆分为:**充值金额 + 今日**。

本版保留以下已开放指标及时间范围。金额类沿用现有标准计价 USD 口径(A9),
打码倍数的单位为倍;下表均为数值类,六个比较符全部可用。

| 分类 | 基础指标 | 类型 | 单位 | 统计口径 | 支持时间范围 |
|---|---|---|---|---|---|
| 充值 | 充值金额 | 金额 | USD | 成功到账的充值之和,不含后台人工上分 | 今日 / 昨日 / 最近N天 / 累计 |
| 充值 | 充值次数 | 次数 | 次 | 成功到账的充值笔数 | 今日 / 昨日 / 最近N天 / 累计 |
| 提现 | 提现金额 | 金额 | USD | 成功放款的提现之和,不含审核中与失败 | 今日 / 昨日 / 最近N天 / 累计 |
| 提现 | 提现次数 | 次数 | 次 | 成功放款的提现笔数 | 今日 / 昨日 / 最近N天 / 累计 |
| 投注 | 投注金额 | 金额 | USD | 有效投注金额之和,口径见 `../2.1-用户列表/资金模型.md` | 今日 / 昨日 / 最近N天 / 累计 |
| 投注 | 投注次数 | 次数 | 次 | Bet 笔数 | 今日 / 昨日 / 最近N天 / 累计 |
| 盈亏 | 净盈亏 | 金额 | USD | 保留正负号的净盈亏,语义见第 7 段 | 今日 / 昨日 / 最近N天 / 累计 |
| 账户 | 账户余额 | 金额 | USD | 当前本金与彩金账面总余额,不扣除资金占用;沿用现有指标取数与资金口径 | 当前 |
| 投注 | 待完成流水 | 金额 | USD | 当前有效打码任务的剩余金额,沿用现有指标取数与资金口径 | 当前 |
| 登录 | 登录次数 | 次数 | 次 | 按登录成功事件去重计数;同一事件重试只计一次,刷新令牌和心跳不计登录 | 今日 / 昨日 / 最近N天 / 累计 |
| 登录 | 登录天数 | 天数 | 天 | 时间范围内发生过登录的自然日数 | 今日 / 昨日 / 最近N天 / 累计 |
| 登录 | 距上次登录小时数 | 时长 | 小时 | 当前时点距上次登录的小时数,沿用现有取数口径 | 当前 |
| 注册 | 注册天数 | 天数 | 天 | 当前日期与注册日期的日历天差 | 当前 |
| 风控 | 登录 IP 数量 | 数量 | 个 | 时间范围内登录使用的去重 IP 数,排除空值 | 今日 / 昨日 / 最近N天 / 累计 |
| 风控 | 登录设备数量 | 数量 | 个 | 时间范围内登录使用的去重设备数,仅覆盖设备码字段上线后的记录 | 今日 / 昨日 / 最近N天 / 累计 |
| 代理 | 下级 ID 数量 | 数量 | 个 | 按首次绑定时间统计的直属下级 ID 数量 | 今日 / 昨日 / 最近N天 / 累计 |
| 投注 | 打码倍数 | 比率 | 倍 | 沿用现有指标的有效投注总额与产生打码义务的余额变动总额之比 | 今日 / 昨日 / 最近N天 / 累计 |

VIP等级、渠道来源及是否测试用户使用玩家当前资料。本版不提供手机绑定条件。

**属性条件**(D56):按下表提供区间、集合或布尔判断,与「基础指标 + 时间范围」共同组成条件。
属性是玩家当前时点的受控值,**没有时间范围**(等同恒为「当前」),不参与按日切片。
属性条件与指标条件在同一张条件表内混排,标签级 AND / OR 组合方式不变。

| 属性 | 类型 | owner | 取值 | 说明 |
|---|---|---|---|---|
| VIP等级 | 有序等级区间 | **M4** | 系统配置的有效 VIP 等级 | 使用“起始等级”和“结束等级”两个下拉框,不允许自由数字输入;区间包含两端,允许起止相同;例如 VIP 3～VIP 5 表示 3 ≤ VIP ≤ 5 |
| 渠道来源 | 枚举(无序、多选值) | **代理渠道**(仓库范围外) | 当前已启用的注册渠道 | 只读渠道字典与玩家当前注册渠道;使用「属于 / 不属于」;「属于」要求任一所选渠道命中,「不属于」要求全部所选渠道均未命中,整行结果再参与标签级 AND / OR |
| 是否测试用户 | 布尔 | **M2** | 是 / 否 | 读取当前测试用户标记,沿用等于和不等于判断 |

**VIP 校验**:试算与保存均由服务端校验起止等级确实存在于有效等级配置中,且起始等级不高于结束等级。
不能仅依赖下拉框限制;不存在的等级(例如 `999999`)或倒置区间均拒绝。

**渠道校验**:「不属于 A / B」表示既不属于 A 也不属于 B。
试算与保存均校验所选每个渠道存在且可用;兼容的旧单值请求与新多选数组请求执行相同校验,
任一无效渠道都拒绝,不能通过旧格式绕过。

> **依赖方向约束**(`../../00-公共约定/README.md` 第二部分 ④ 第 2 款):
> VIP 等级由充值与有效投注等原始数据判定,**其判定输入不得包含用户标签**,
> 依赖链因此单向:`原始数据 → VIP 等级 → 用户标签 → 活动门槛`。
> 用 VIP 条件组成的标签**可以**被 M4 活动当作领取门槛引用 —— 不成环,因为 VIP 不回读标签。
> 反过来,**任何把标签写进 VIP 升降级判定的设计都会成环,一律不许**。

> **重算时序**:VIP 等级变动后,含 VIP 条件的标签要到下一次重算才更新命中集(A4 重算窗口),
> 不做即时重算。读取当前命中集的活动按「领取那一刻的命中集」判断(4.2-A16 / E9),因此玩家刚升级、
> 标签还没重算到时按未命中处理 —— 这是已知代价,与其他指标类条件同一口径。
> 4.16 邀请宝箱的规则快照评估是新增消费方式,见第 11 段;不据此改变上述消费者的行为。
账户余额保留现有整体余额指标,本次不新增真金余额、彩金余额的独立条件或新的金额换算算法。
**首版不含**:活动参与次数(暂不接数据源)· 首充金额、最近一笔充值金额、最近一笔返奖金额、
独立的累计邀请人数指标(现有“下级 ID 数量”继续保留)。

## 4. 时间范围

时间范围与基础指标分离,第一阶段支持五种:

| 时间范围 | 定义 |
|---|---|
| 当前 | 当前时点数据,例如账户余额 |
| 今日 | 业务时区当日 00:00 至当前 |
| 昨日 | 业务时区上一自然日 00:00–23:59:59 |
| 最近N天 | **包含当天**在内的最近 N 个自然日,N 由运营逐条填写,取值边界见 A7 |
| 累计 | 玩家注册时间至当前 |

系统需新增**业务时区**设置(A13):所有涉及自然日的标签计算统一使用它,
避免服务器时区、运营时区、玩家所在地时区不同导致同一玩家算出不同结果。

不同指标可配置不同的可用时间范围(见第 3 段清单),前端按所选指标自动展示可选项。

## 5. 指标比较规则

指标比较沿用当前系统支持的范围与基础校验(A12)。**是否具有业务意义由运营配置时判断**,
不再额外要求逐项、有方向的业务可比白名单,也不再规定未列举的其余指标右值只能是常量。

保留当前类型/单位分组、值域以及同一指标同一时间范围的校验,本次不新增或移除已有比较保护。
不同业务名称本身不是拒绝理由;例如系统当前支持的“提现次数 = 投注次数”可继续配置,
是否适合业务人群由运营自行确认。

**可配置示例**:

- 累计充值金额 > 累计提现金额
- 今日充值金额 > 昨日充值金额
- 最近7天投注次数 > 最近7天充值次数

**现有基础校验仍拒绝的示例**:

- 充值金额 > 登录次数
- 投注金额 > 注册天数
- 账户余额 > 登录IP数量

**左右时间范围不必一致。** 左右两个指标各配自己的时间范围,系统不因时间范围不同而禁止比较,
是否有业务意义由运营判断;同一指标也可以用不同时间范围互比:

- 今日充值金额 > 昨日充值金额
- 最近7天投注金额 > 最近30天充值金额
- 当前账户余额 > 最近7天提现金额

**同一指标 + 同一时间范围**的现有限制继续保留:左右完全相同,条件恒成立或恒不成立,禁止。
最近 N 天须同时比较 N 值;同一指标的最近 7 天与最近 30 天不属于完全相同范围。

## 6. 右值

右值支持两种类型:

- **常量**:`[充值金额] [累计] [≥] [常量] [1000] USD`
- **基础指标**:`[充值金额] [累计] [>] [基础指标] [提现金额] [累计]`

选择基础指标作为右值时,沿用当前系统支持的指标与基础校验,不另加逐项业务白名单。
字段及表单联动规则见 `README.md` 的“配置项”。

## 7. 特殊数据处理

**净盈亏保留正负号。** 盈利 500 USD 记 +500,亏损 500 USD 记 −500。因此:

- 「净盈亏 ≥ 500」= 盈利至少 500 USD
- 「净盈亏 ≤ −500」= 亏损至少 500 USD

**无记录按 0,取数失败为 NULL(D34)。** 可求和、计数的指标,玩家在时间范围内没有任何记录时
统一按 0 参与判定。例如从未充值的玩家:

- 累计充值金额 = 0 → 成立
- 累计充值金额 < 100 → 成立

真正无法获取或未知的数据为 NULL,**NULL 不满足任何比较条件**(含 ≠),该条件判否 ——
待补算账变(A9)、汇总服务异常都属这一类。无记录与取数失败必须区分,不得混为一谈(README E4)。

金额继续使用现有统一口径(标准计价 USD,A9),本次改造不新增汇率计算逻辑。

## 8. 多条件组合

一个标签可包含多个条件(1 到 10 条,A1),组合方式为标签级单选(A14):

- **AND**:全部满足
- **OR**:任一满足

例如「高价值活跃用户」(AND):

- 累计充值金额 ≥ 1000 USD
- 最近7天投注金额 > 最近7天充值金额
- 最近7天登录天数 ≥ 3

第一阶段不支持 A AND (B OR C) 类多层嵌套。

## 9. 第一阶段不支持

- 标签引用标签,标签作为任何条件的左值或右值(D31,防依赖环)
- 活动参与次数指标
- 指标间加减乘除、百分比、增长率、自定义计算公式;右值带系数的比率条件列二期(D31)
- 多层 AND / OR 嵌套

标签由数值指标条件和玩家当前资料条件组成,不开放自定义公式。
现有“打码倍数”是系统提供的指标,不代表运营可自行编写指标间运算。

## 10. 核心原则

- **指标最小化**:不因时间范围或比较方式不同重复建指标
- **指标与时间分离**:「今日充值金额」是「充值金额 + 今日」,不是新指标
- **比较遵守基础校验**:保留现有类型/单位、值域及同指标同范围校验,业务意义由运营判断
- **禁止标签引用**:标签不能出现在任何条件的左右两侧
- **配置鲁棒性**:现有基础校验与 VIP、渠道的有效值校验在服务端执行,不能只依赖前端
- **优先组合**:新业务优先用已有指标组合实现,只有出现新的最小数据单元才新增指标

## 11. 邀请宝箱的版本化评估

[4.16 邀请宝箱](../../M4-活动管理/4.16-邀请宝箱/README.md)按 [2.5-R9](README.md#25-r9)新增版本化只读评估,
在下级注册绑定被接纳时保留上级当时的人群判断与下级条件规则快照,后续下级达标使用同一快照。
活动选择一个下级组合标签,充值与有效投注等条件只在标签维护;活动不另设同名门槛或指标引擎。

| 内容 | 执行口径 |
|---|---|
| 固定的规则 | 标签版本、条件与 AND / OR 组合、比较符、阈值、单位、时间范围及业务时区;规则编辑或正常停用不覆盖已接纳下级的快照 |
| 持续变化的数据 | 按每次评估的业务时点取值;“累计”为注册至该时点,“今日”等范围以保存的业务时区与该时点定位,“当前”指该评估时点的属性或指标,不能把后来值当成历史值 |
| 唯一计算能力 | 继续使用 M2 本文规定的指标、比较与组合语义;保存完整判定依据,不更新当前命中集,也不因活动冻结版本而恢复被停用标签的当前成员 |
| 未知与恢复 | 正常无记录求和/计数仍为 0;取数失败、待补算或无法重建历史依据时同时返回数据不完整及原因。4.16 保留核查状态,资料补齐按原业务时点与版本重评,不以当前标签未命中替代永久资格结论 |
| 能力范围 | 规则留存、时点依据保存及迟到恢复是 4.16 的新增需求;现有当前属性、5 分钟重算和进出流水不等于已经支持任意历史时点查询。不能重建的历史值如实返回未知 |
| 设备与有效人数 | “登录设备数量”统计单个账号使用多少设备;原始直属关系人数不等于活动有效计奖人数。注册设备跨账号占位由 M4 使用 M2 原始注册事实维护,不由标签维护 |

当前命中集继续按第 7 段及 R6 的 NULL 判否语义执行;版本化评估额外返回依据完整性,由 4.16 按其资格流程处理未知,
不改提现审核、其他活动或用户查询对当前标签的消费规则。活动不得反向修改玩家资料、标签或原始资金与投注事实。
