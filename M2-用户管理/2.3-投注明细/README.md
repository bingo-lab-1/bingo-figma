# 2.3 · 投注明细

## 1. 用途

运营和客服通过本页查清用户玩了什么游戏、投了多少、派彩多少，以及这笔投注的净输赢。点击局号可以查看对应的局详情。

本文按现有后台页面归档查询功能。页面面向桌面端，使用简体中文；入口为“会员管理 → 投注明细”。可以跨用户查询，也可以通过会员账号缩小范围。

投注时间和日期筛选使用查看者浏览器的本地时区。金额保留投注记录的原币，结合每行的币种阅读，不把不同币种的金额直接相加。本页只读，不修改投注、派彩或钱包余额。

## 2. 查询条件

不带筛选条件打开页面时，会员账号和日期为空，游戏、输赢结果、币种均不设限制。填写条件后点击“查询”才应用；多个条件同时填写时，结果须同时满足这些条件。

| 条件 | 含义和填写规则 |
|---|---|
| 会员账号 | 输入完整账号或其中一段；忽略首尾空格，不区分大小写，按包含关系匹配。留空不限定账号 |
| 游戏 | 单选，默认“全部游戏”；选择后只查询对应游戏 |
| 输赢结果 | 单选，默认“全部”；另外提供“仅赢”和“高倍赢(≥4x)”，具体口径见下文 |
| 币种 | 单选，默认“全部币种”；用于限定投注的原币。选项来自币种配置，本页不新增或修改币种 |
| 投注时间 | 分别选择开始日期和结束日期；开始日期包含当天零点，结束日期包含当天最后一刻。可以只填一端，未填的一端不设时间边界 |

游戏可选：Dice、Crash、Limbo、Plinko、Roulette、Mines、Baccarat、Blackjack。

日期选择框提供年月选择，以及“清除”“取消”“确定”。确定日期后仍需点击“查询”更新列表。页面没有局号、用户 ID、订单号或渠道的独立筛选框。

### “仅赢”与“输赢”列的区别

“仅赢”按玩法记录的派彩倍数大于 0 筛选；“高倍赢(≥4x)”按派彩倍数大于或等于 4 筛选。这两个条件都不使用列表“输赢”列的净额判断。

例如，一条 Plinko 记录投注 2、派彩 1.4，派彩倍数为 0.7。它会出现在“仅赢”结果中，但“输赢”列显示 -0.6，表示净亏损。“仅赢”因此不能理解为只看净盈利记录。

采集时发现，选择 USDC 会漏掉币种保存为 `usdc` 的记录；具体复现见[网站核对记录](../../.artifacts/bet-record-prd-2026-09-10/README.md)。这是现存查询缺陷，不作为币种筛选的业务规则。

## 3. 结果字段

每行表示一条投注记录，投注金额与派彩金额在同一行展示。投注扣款、返奖等资金流水另见[账变记录](../2.2-账变记录/README.md)。

| 字段 | 含义 |
|---|---|
| 序号 | 当前查询结果中的连续行号，翻页后接续编号；不是投注记录的业务编号 |
| 局号 | 页面用于识别这条投注的编号；点击可查看“局详情 / 公平性” |
| 用户ID | 投注所属用户的 ID |
| 会员账号 | 投注所属用户的账号；无值显示“-” |
| 游戏厂商 | 投注记录对应的厂商名称；没有可展示名称时显示“-” |
| 游戏 | 这条投注对应的游戏名称；无法识别的历史游戏保留原值 |
| 投注金额 | 这条记录的投注金额，使用本行币种 |
| 派彩金额 | 这条记录的派彩金额，使用本行币种；不直接等于用户盈利 |
| 输赢 | 派彩金额减去投注金额；正数为净盈利，负数为净亏损，零表示两者相等 |
| 币种 | 投注记录的原币代码，按记录值展示 |
| 投注时间 | 这条投注记录的时间，显示到秒 |

金额按千分位分隔，统一显示八位小数。页面显示精度不改变原始记账精度。投注金额不直接替代有效投注或已完成打码量，本页不计算打码核销。

列表不展示本金与彩金拆分、余额、标准币换算、取消金额、订单状态或汇总金额。

## 4. 操作规则

### 查询、重置与筛选区

首次进入自动加载列表。修改输入不会立即替换结果，点击“查询”后应用条件并回到第 1 页。

应用的筛选条件发生变化时，每页条数恢复为 20；条件保持相同时，点击“查询”保留已选择的每页条数。筛选条件和分页均未变化时，点击“查询”不强制重新取数。

“重置筛选条件”清空账号、游戏、输赢结果、币种和日期，并应用清空后的条件。“收起筛选”只隐藏输入区，不清空条件或改变列表；重新展开后可以继续编辑。

### 排序与分页

记录按投注时间从新到旧排列。页面不提供点击列头改变排序的操作。

默认每页 20 条，可切换为 50 条或 100 条。切换每页条数回到第 1 页，保留已应用的筛选条件。上一页、下一页和页码切换均沿用当前条件及每页条数。

底部显示当前起止条数和总记录数。第一页不能再向前翻，最后一页不能再向后翻；查询无结果时不显示分页栏。

### 查看局详情

点击某行局号，打开“局详情 / 公平性”，展示该行对应的信息。

| 字段 | 含义和展示规则 |
|---|---|
| 局号 | 与所点击行的局号一致，提供复制 |
| 用户ID | 与所点击行的用户 ID 一致，提供复制 |
| 游戏 | 所点击记录对应的游戏 |
| 投注金额、派彩金额 | 与所点击行一致，沿用该行币种 |
| nonce | 玩法记录保存的序号；没有记录时显示“-” |
| clientSeed | 客户端种子；现有服务对非空值返回 `[REDACTED]`，缺失时显示“数据缺失” |
| serverSeed | 服务端种子；现有服务对非空值返回 `[REDACTED]`，缺失时显示“数据缺失” |
| serverSeedHash | 服务端种子的哈希值，按记录值展示，提供复制 |

clientSeed 和 serverSeed 有展示值时提供复制，复制的是当前显示内容，包括 `[REDACTED]`；显示“数据缺失”时不提供这两个字段的复制按钮。复制不修改原记录，页面不显示复制成功或失败的提示。

弹窗只展示信息，不提供揭示明文种子、重新计算开奖结果或验证公平性的操作。关闭弹窗后保留原列表和查询条件。

### 无结果与加载失败

查询没有匹配记录时，显示“暂无投注记录”，保留筛选条件供修改。

请求过程中显示加载占位。请求失败时，显示“投注记录加载失败”、错误说明和“重试”，并清空列表结果。点击“重试”按当前已应用的条件和分页重新取数；失败提示不能解释为用户没有投注。

本页不提供编辑、删除、补单、重新结算、批量处理或导出操作。用户 ID 和会员账号是展示文本，不从本页跳转用户详情。

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 2.3-R1 | 不带筛选条件进入页面 | 自动加载第 1 页，每页 20 条；账号和日期为空，游戏、输赢结果及币种不设限制 |
| 2.3-R2 | 输入带首尾空格、大小写不同的账号片段，同时选择游戏后查询 | 忽略首尾空格和大小写，返回账号包含该片段且符合所选游戏的记录 |
| 2.3-R3 | 分别选择“仅赢”和“高倍赢(≥4x)” | 分别按派彩倍数大于 0、至少为 4 筛选；投注 2、派彩 1.4、倍数 0.7 的示例符合“仅赢”，输赢仍为 -0.6 |
| 2.3-R4 | 选择一种币种后查询 | 结果限定为该原币；币种大小写造成的漏查属于缺陷，复现依据见网站核对记录 |
| 2.3-R5 | 浏览器时区为 Asia/Hong_Kong，开始和结束都选择 2026-09-08 | 查询当地完整自然日，即 UTC 的 2026-09-07 16:00:00.000 至 2026-09-08 15:59:59.999 |
| 2.3-R5 | 日期只填写开始或结束一端 | 只按已填的一端限制投注时间 |
| 2.3-R6 | 从每页 20 条的第 1 页进入下一页，再切换为每页 50 条或 100 条 | 下一页从第 21 条起显示；切换条数回到第 1 页，条件保持，记录按投注时间降序排列 |
| 2.3-R7 | 查看投注金额和派彩金额不相等的记录 | 输赢等于派彩减投注；金额显示八位小数，并结合本行币种阅读 |
| 2.3-R8 | 点击局号，查看字段后关闭弹窗 | 打开对应记录的局详情；种子明文被遮罩，缺失字段按规则显示；关闭后列表和条件保持 |
| 2.3-R8 | 复制局号或有展示值的种子字段 | 复制当前显示文本，遮罩值不会变成明文种子；不修改记录，也不显示复制结果提示 |
| 2.3-R9 | 编辑条件但不查询，再收起、展开筛选区 | 原结果保持，已填写的条件保留；点击查询后才应用 |
| 2.3-R9 | 每页选为 50 条后应用不同条件，再重置 | 不同条件生效时回到第 1 页、每页 20 条；重置后清空全部条件 |
| 2.3-R10 | 查询不存在的账号，或查询请求失败后重试 | 无匹配时显示“暂无投注记录”；失败时显示独立错误说明和重试入口，重试沿用原条件与分页 |
| 2.3-R11 | 查看列表和局详情的可用操作 | 只支持查询、分页、详情查看和字段复制，不提供资金或投注修改、导出、公平性计算操作 |

## 6. 相关资料

- 入口：会员管理 → 投注明细。单个用户的订单视图见[用户详情的订单数据](../2.1-用户列表/用户详情弹窗.md#44-订单数据)，两个入口各自维护页面字段。
- 权限归属：沿用模块登记的 `user:bet:view`；功能权限与账号数据范围的公共约定见[权限模型](../../M6-账号管理/6.2-角色列表/权限模型.md)。
- 数据归属：投注记录由玩法能力提供，M2 负责只读展示；资金流水由 M5 财务拥有，查询入口见[账变记录](../2.2-账变记录/README.md)。
- 共用口径：本金、彩金、有效投注和打码义务引用[资金模型](../2.1-用户列表/资金模型.md)，本页不另建一套资金规则。
- 归档依据：[网站采集与核对记录](../../.artifacts/bet-record-prd-2026-09-10/README.md)，包含页面观察、实际查询、已确认的查询缺陷及核对范围。
