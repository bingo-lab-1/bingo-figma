# 2.2 · 账变记录

## 1. 用途

运营、客服和财务通过本页查清用户的钱为什么增加或减少、变化前后有多少余额，以及这笔变化关联哪张业务单据。打码量调整也在同一列表中查询，即使本次没有增加或扣除余额。

本文按现有后台页面归档查询功能。页面面向桌面端，使用简体中文；入口为“会员管理 → 账变记录”。本页只读展示资金账本，不执行充值、扣款、补账或修改原流水。

账变时间、汇率时点和日期筛选使用查看者浏览器的本地时区。原币金额与标准计价金额分别展示，不能把不同币种的原币金额直接相加。

## 2. 查询条件

直接打开页面时，所有条件为空，账变类型为“全部类型”，日期不预设为今天。填写条件后点击“查询”才应用；多个条件同时填写时，结果须同时满足这些条件。

| 条件 | 含义和填写规则 |
|---|---|
| 用户 ID | 按完整用户 ID 查询，精确匹配；留空不限定用户。这里不按昵称或手机号搜索 |
| 账变类型 | 单选，默认“全部类型”；选择后只查询对应类型的账变 |
| 币种 | 输入币种代码，输入字母自动转为大写，按代码精确匹配；留空不限定币种 |
| 关联单据 ID | 支持输入完整单据 ID 或其中一段，查询单据 ID 包含该内容的账变；留空不限定单据 |
| 日期 | 分别选择开始日期和结束日期；开始日期包含当天零点，结束日期包含当天最后一刻。可以只填一端，未填的一端不设日期边界 |

日期选择框提供年月选择，以及“清除”“取消”“确定”。确定日期后仍需点击“查询”更新列表。

账变类型可选：充值到账、彩金发放、投注扣款、投注返奖、投注退款、佣金入账、VIP奖励、平台转出、平台转入、提现扣款、提现退款、人工加款、人工扣款、打码量变动、入账冲正、出账冲正、充值拒付。

当前页面不提供独立的渠道筛选项。账号的数据访问范围归属平台权限规则，不通过本页增设或修改。

## 3. 结果字段

每行表示一条账变。同一张业务单据可以对应多行，例如一次投注的扣款与返奖分别记录。

| 字段 | 含义 |
|---|---|
| 序号 | 当前查询结果中的连续行号，翻页后接续编号；不是账变 ID |
| 用户 | 这条账变所属钱包的用户 ID |
| 账变时间 | 账变记录的时间，显示到秒 |
| 账变类型 | 以中文说明变化原因；无法识别的历史类型保留原值 |
| 币种 | 本笔账变所属钱包的原币代码 |
| 变动金额 | 分别显示本次变化的总额、本金、彩金和打码量；增加为正，减少为负 |
| 变动前余额 | 分别显示变化前的总额、本金、彩金及打码量 |
| 变动后余额 | 分别显示变化后的总额、本金、彩金及打码量 |
| 标准计费 / 汇率 | 页面沿用此列名，内容是标准计价金额及换算依据，具体见下文 |
| 关联单据 | 产生账变的业务单据 ID；无值显示“-” |
| 备注 | 账本记录的补充说明；无值显示“-” |

### 金额和打码量怎样看

金额按千分位分隔，统一显示八位小数。页面显示精度不改变账本中该币种的记账精度。

总额是本金与彩金的合计；本金、彩金表示资金来源构成，不是两个独立钱包。打码量单独表示流水要求，不计入总额。前余额、本次变动、后余额均读取这条账变对应的记录，不用用户当前余额代替历史金额。

打码量没有记录时显示“—”，有记录且为零时显示 `0.00000000`，两者含义不同。只调整打码量时，总额可以为零而打码量不为零。

例如，一笔打码量调整前为 510，本次减少 500，调整后为 10；这笔账变的总额为 0，不能解释为用户被扣除 500 元。

### 标准计价和汇率怎样看

“标准计费 / 汇率”列展示标准币金额，以及“精确”或“近似”标识。标准计价使用 USD，原币金额仍保留在前面的金额列中。

换算依据包括汇率等式、汇率采集时点和来源，例如 `1 USDC = 0.9999489498 USD`。存在多份换算记录时展示最新一份，并以 `v2`、`v3` 等标识记录数量；本页不展开历史换算明细。

| 情况 | 展示方式 |
|---|---|
| 没有换算记录，或最新记录正在补算 | 显示“待补算”，不将缺失的换算结果当作零金额 |
| 换算采用近似结果 | 显示标准币金额和“近似” |
| 换算采用精确结果 | 显示标准币金额和“精确” |
| 已有非待补算结果，但缺少汇率、时点或来源 | 相应位置显示“汇率待补”“时点待补”或“来源待补” |

标准计价用于查看和汇总，不改变原币余额、打码义务或提现资格。换算规则统一引用[标准计价](../2.1-用户列表/标准计价.md)。

## 4. 操作规则

### 查询与重置

首次进入自动加载列表。修改输入不会立即替换结果，点击“查询”后应用全部条件并回到第 1 页。

“重置筛选条件”清空用户、类型、币种、单据和日期，重新查询第 1 页；保留当前选择的每页条数。“收起筛选”只隐藏条件输入区，不清空条件，也不改变当前结果；再次展开可以继续编辑。

### 排序与分页

记录按账变时间从新到旧排列；时间相同时按账本序号从大到小排列。页面不提供点击列头改变排序的操作。

默认每页 20 条，可切换为 50 条或 100 条。切换条数回到第 1 页；上一页、下一页和页码切换均沿用当前已应用的查询条件。

底部显示当前起止条数和总记录数。第一页不能再向前翻，最后一页不能再向后翻；查询无结果时不显示分页栏。

### 无结果与加载失败

查询无匹配记录时，显示“暂无数据”和“调整筛选条件后再试。”，保留筛选条件供继续修改。

请求过程中显示加载占位。请求失败时，在列表上方显示“账变记录加载失败”、错误说明和“重试”；点击“重试”按当前已应用的条件和分页重新取数。失败提示不表示用户没有发生账变。

### 查询边界

本页没有编辑、删除、补账、批量处理或导出操作。用户 ID 和关联单据 ID 均为展示文本，不从本页直接跳转详情。原流水的生成、冲正及资金处理由资金账本负责；本页仅呈现其结果。

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 2.2-R1 | 不带筛选条件进入页面 | 自动查询第 1 页，默认每页 20 条，类型为全部，日期为空；记录按默认顺序展示 |
| 2.2-R2 | 同时填写用户 ID、币种和关联单据，点击查询 | 只返回同时符合条件的账变；输入小写币种时转换为大写 |
| 2.2-R2 | 输入关联单据 ID 的一段，点击查询 | 返回单据 ID 包含该内容的记录；不存在的内容返回空结果 |
| 2.2-R3 | 选择一种账变类型查询，再重置 | 类型查询只返回该类型；重置后清空条件并查询第 1 页 |
| 2.2-R4 | 浏览器时区为 Asia/Hong_Kong，开始和结束都选择 2026-09-08 | 查询该时区当天的完整自然日，即 UTC 的 2026-09-07 16:00:00.000 至 2026-09-08 15:59:59.999 |
| 2.2-R4 | 日期只填写开始或结束一端 | 仅按已填写的一端限制账变时间 |
| 2.2-R5 | 从每页 20 条的第 1 页进入下一页，再改为每页 50 条 | 下一页从第 21 条起显示；改为 50 条后回到第 1 页，当前查询条件保持 |
| 2.2-R6 | 查看普通资金账变和仅打码量变化的账变 | 前、变动、后三组数据分别展示；本金和彩金组成总额，打码量不计入余额；缺失打码数据显示“—” |
| 2.2-R7 | 查看有换算记录、近似换算及没有换算记录的账变 | 分别显示对应金额与依据、“近似”标识或“待补算”；原币金额保持可见 |
| 2.2-R8 | 保留已应用条件，收起并重新展开筛选 | 当前结果和条件不变，展开后可继续修改 |
| 2.2-R9 | 查询不存在的记录，或查询请求失败后重试 | 无结果显示空状态；失败显示独立错误说明和重试入口，重试仍使用原查询条件 |
| 2.2-R10 | 查看任意账变行及页面操作区 | 无资金修改、删除、导出操作；用户及单据字段不提供详情跳转 |
