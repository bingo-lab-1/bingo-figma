# M2 · 用户管理

## 1. 定位与边界

**做什么**:玩家账号的查询、干预、分层。**用户 的唯一写入方。**

**不做什么**
- 资金规则与记账归财务 M5;用户详情提供钱包修改余额和打码任务操作入口,具体操作在弹窗正文维护
- 不做后台账号管理(那是权限模块管理运营人员的账号,**本仓库范围外**)
- 不做风控规则引擎(只提供档案数据,规则判定另议)

**铁律**:封禁/解封/调级等干预操作**必须**留痕(操作日志,本仓库范围外)。
标签自 2.5 起改为规则判定,不再有人工打标动作 —— 留痕对象变成**规则的变更**,
自动打标与摘标另记进出流水(见 2.5)。

## 3. 依赖关系

只声明边界与读写方向,不在此重复定义它们的数据。标注「本仓库范围外」的才是范围外,
其余是仓库内的兄弟模块。

**上游依赖(我引用)**
- 代理渠道(**本仓库范围外**):渠道(注册渠道)、代理(上级代理)
- 财务(M5):钱包与账变记录提供余额及资金变化事实;弹窗的充值、提款记录是固定类型的账变查询。钱包修改余额与打码任务操作由资金能力处理。
  M2.2 是账变流水的唯一运营查询入口;M5 继续拥有数据,不再提供重复的「交易记录」页面
- 活动(M4):**VIP 等级**用于 2.1 的列表展示与筛选、2.5 的属性条件;单个会员的VIP修改入口在用户详情的账号概览。
  等级序列与升降级规则仍归 M4,用户详情不另设一套等级配置,见 `00-公共约定/README.md` 第二部分 ① 与 ④

**下游被依赖(谁引用我)** ← 改表前先看这行
- 财务(M5):用户(订单归属)、用户标签(提现风控与订单列表展示)
- 活动(M4):用户标签(活动领取门槛与定向,见 M4 的 D39 / D44 / D53)。[4.16 邀请宝箱](../M4-活动管理/4.16-邀请宝箱/README.md)另需 2.5-R9 的标签规则版本、按已保存规则评估及判定依据,并读取注册时点与注册设备事实;这是新增依赖,不等于现有当前命中集已能回查任意历史时点。
- [4.17 拼多多活动](../M4-活动管理/4.17-拼多多活动/README.md):每轮首抽时读取参与人的当前标签命中结果、注册渠道及账号限制,并保存本次判定依据;邀请赠次另读取新用户注册成功业务时点、稳定注册 IP 及其可用状态。渠道选项由渠道能力受控提供,M2 只提供玩家归属事实,不允许活动以自由输入值伪造渠道。普通摘标或渠道配置变化不撤销已开始轮次,下一轮重新判定;实际账号限制仍按活动旋转、领取等动作即时检查。
- 玩法(**本仓库范围外**):用户 用户标签(活动资格圈人)
- [4.18 排行榜活动](../M4-活动管理/4.18-排行榜活动/README.md):读取真实账号归属、下注及结算业务时点的测试标记依据和当前账户限制;不通过标签圈选参与人群。缺少对应时点事实须返回不可判定,不把当前标记冒充历史状态。M4拥有测试投注的排除依据、排名和获奖资格,M2不维护奖池或发奖次数。
- [4.19 幸运转盘](../M4-活动管理/4.19-幸运转盘/README.md):读取参与时的账号事实、标签命中结果及账户限制,指定标签任一命中,渠道通过标签定向。M4保存本次人群判定依据与活动版本,普通标签变化不改写旧券和旧奖;M2不维护充值赠券、奖池或里程碑进度,当前命中集不冒充历史判定。
- 代理渠道:用户(代理下级、佣金归属)
- 运营:用户标签(弹窗/推送定向)
- 数据中心:用户 登录记录(拉新/留存)

> **用户 和 用户标签 是全平台被引用最多的表**,改结构影响面最大 ——
> 影响面落在本仓库看不到的地方,改动前必须走到那几个下游确认。

## 4. 数据模型

**拥有的表**

| 表 | 说明 | 现状 |
|---|---|---|
| 用户 | 玩家主表 | 已有 |
| 实名认证 | 实名资料与审核结果 | 已有 |
| 标签 / 标签组成 | 具名人群规则及其条件行(「基础指标 + 时间范围 比较符 右值」),含标签级 AND/OR 组合方式 | 需改造 · 现有标签表无组成概念,见第 7 段 D23、D33 |
| 标签命中关系 | 当前命中某标签的玩家集合,由重算维护 | 需改造 · 现有关联表无打标时间与来源 |

| 登录记录 | 登录时间、IP 与平台 | 已有 |
| 注册IP记录 / 注册设备记录 | 注册 IP/设备 | 已有 |
| 身份信息(3 张) | 身份体系 | 需改造 · 与实名认证、用户标签重叠,见第 7 段 D2。其中的自动标识部分按 D23 迁入 2.5 规则标签后下线 |
| 提现账户 / 法币账户 / 加密账户 | 收款账户 | 已有 |
| 资金安全设置 / 资金汇总 | 资金安全/汇总 | 已有 |
| 封禁记录 | 封禁与解封流水及原因 | 新增 |
| 点控记录 | 对特定用户的赢率干预 | 新增 |

**引用数据**:钱包与账变记录归财务 M5,投注记录归玩法,渠道与代理关系归相应能力。用户详情提供的钱包、打码任务及单个会员VIP修改入口不改变这些事实的归属;VIP等级配置与成长规则仍归 M4。

**邀请宝箱的事实边界**:M2 提供注册设备原始标识及其可用状态,空值或取数失败不能当成每人不同的设备;M4 决定同设备能计奖几名下级并维护跨账号占位。该占位不等于标签“登录设备数量”、用户列表的设备查询或 M8 注册拦截,也不改变注册是否成功。M2 的版本化条件评估继续复用本模块唯一的指标口径和条件能力,活动不自行建立另一套充值、投注指标引擎。

**拼多多活动的事实边界**:注册 IP 是注册成功时保存的来源事实,不能被最新登录 IP 覆盖。注册业务时点、渠道或 IP 缺失、取数失败须显式返回不可判定及恢复依据,不能把空 IP 当成每人不同的 IP,也不能用通知接收时间替代注册时间。M4 拥有同一运营商、同一邀请人、本活动累计的同 IP 赠次名额、每好友全活动一次的赠次去重及跨轮机会余额;M2 不维护这些占位,它们与 4.16 的注册设备计奖、M8 注册拦截分别计算。首抽标签与渠道按 AND 判断并保存快照,所选限制需要的判定结果不可用时不启动轮次;选择全部人群或全部渠道不额外要求对应命中结果。这不要求 2.5 新增历史属性查询。4.17 的本轮好友集合与真实支付加速统计归 M4,分别读取财务和玩法来源事实,不改写 2.5 现有“充值金额”等指标定义。
