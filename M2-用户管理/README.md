# M2 · 用户管理

## 1. 定位与边界

**做什么**:玩家账号的查询、干预、分层。**用户 的唯一写入方。**

**不做什么**
- 不做资金操作(充值/提现/上下分归 M3,本模块只读展示)
- 不做后台账号管理(那是 M7 的 后台账号)
- 不做风控规则引擎(只提供档案数据,规则判定另议)

**铁律**:封禁/解封/调级/打标等干预操作**必须**留痕(`M7 OperationLog`)。

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 玩家 | C 端用户 | 用户 |
| 后台账号 | 运营人员账号,**不是玩家** | 后台账号(M7) |
| 标签 | 运营圈人分类,**非风控结论** | 用户标签 |
| 实名 | KYC 认证 | 实名认证 |
| 封禁 | 限制登录/出入金/投注 | 封禁记录 |
| 点控 | 赢率干预 | 点控记录 |

## 3. 依赖关系

**上游依赖(我引用)**
- `M5-代理渠道`:渠道(注册渠道)、代理(上级代理)
- `M3-财务管理`:钱包 账变记录(**只读**展示余额与账变)
- `00-公共约定`:客户端平台

**下游被依赖(谁引用我)** ← 改表前先看这行
- `M3-财务管理`:用户(订单归属)、用户标签(提现风控)
- `M4-玩法中心`:用户 用户标签 VIP等级(活动资格圈人)
- `M5-代理渠道`:用户(代理下级、佣金归属)
- `M6-运营管理`:用户标签(弹窗/推送定向)
- `M1-数据中心`:用户 登录记录(拉新/留存)

> **用户 和 用户标签 是全仓被引用最多的表**,改结构影响面最大。
