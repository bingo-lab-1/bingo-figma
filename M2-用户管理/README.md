# M2 · 用户管理

## 1. 定位与边界

**做什么**:玩家账号的查询、干预、分层。**用户 的唯一写入方。**

**不做什么**
- 不做资金操作(充值/提现/上下分归财务,**本仓库范围外**,本模块只读展示)
- 不做后台账号管理(那是权限模块管理运营人员的账号,**本仓库范围外**)
- 不做风控规则引擎(只提供档案数据,规则判定另议)

**铁律**:封禁/解封/调级等干预操作**必须**留痕(操作日志,本仓库范围外)。
标签自 2.5 起改为规则判定,不再有人工打标动作 —— 留痕对象变成**规则的变更**,
自动打标与摘标另记进出流水(见 2.5)。

## 3. 依赖关系

本模块是本仓库唯一在范围内的模块,以下依赖方**全部在本仓库范围外**,
只声明边界与读写方向,不在此重复定义它们的数据。

**上游依赖(我引用)**
- 代理渠道:渠道(注册渠道)、代理(上级代理)
- 财务(M5):钱包 账变记录(**只读**展示余额与账变)· 充值订单 提现订单(弹窗内的充提记录)。
  M2.2 是账变流水的唯一运营查询入口;M5 继续拥有数据,不再提供重复的「交易记录」页面

**下游被依赖(谁引用我)** ← 改表前先看这行
- 财务(M5):用户(订单归属)、用户标签 VIP等级(提现风控与订单列表展示)
- 玩法:用户 用户标签 VIP等级(活动资格圈人)
- 代理渠道:用户(代理下级、佣金归属)
- 运营:用户标签(弹窗/推送定向)
- 数据中心:用户 登录记录(拉新/留存)

> **用户 和 用户标签 是全平台被引用最多的表**,改结构影响面最大 ——
> 影响面落在本仓库看不到的地方,改动前必须走到那几个下游确认。
