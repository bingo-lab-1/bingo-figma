# M2 · 点控策略与执行记录

## 1. 用途

运营为一条点控规则选择一个已有复合标签，再添加多个触发项。每个触发项分别设置什么时候开始养、养多少，以及多少把内完成。

“养”指用户在本次点控期间至少净赢指定金额。净赢等于本次任务内游戏局的实际返奖减去实际投注，不包含任务开始前的亏损。例如，本次投注合计 100 USD、返奖合计 120 USD，净赢就是 20 USD。

| 项目 | 规则 |
|---|---|
| 适用游戏 | 第三方供应商提供的 Slot，不包含自研 Originals |
| 执行币种 | 使用用户当前默认选中的币种，运营不手动指定用户的执行币种 |
| 最低参与余额 | 全局统一配置，按系统现有的标准 USD 账户余额判断 |
| 养的金额 | 固定和随机目标按币种分别配置，使用执行币种对应的金额，不自动换汇 |
| 比例目标 | 所有触发项统一使用当前执行币种的当日累计成功充值金额作为基数 |
| 完成要求 | 最多执行 N 个有效付费局；净赢达标就停止后续控制，已有局结算查清后确认完成，可以提前结束 |
| 每日统计 | 沿用平台现有统计日口径，点控表单不增加业务时区设置 |
| 用户分层 | 直接选择用户标签模块已有复合标签，标签条件和启停仍在标签模块维护 |

## 2. 配置项

表单分为“全局设置、点控规则、触发项”三层。以下数字都是示例，不是默认值。

### 全局设置

| 字段 | 控件与示例 | 填写说明 |
|---|---|---|
| 最低参与余额 | 金额框：`1.00 USD` | 必填，允许零，不允许负数；所有点控规则共用同一个标准 USD 门槛 |

### 点控规则

| 字段 | 控件与示例 | 填写说明 |
|---|---|---|
| 规则名称 | 文本框：`首充用户养规则` | 必填，用于识别规则 |
| 规则启用 | 开关：`开启 / 关闭` | 控制整条规则是否接受新任务；新建规则默认关闭 |
| 用户复合标签 | 搜索下拉框：`请选择复合标签` | 必选，一个规则关联一个已有复合标签；只可选择启用中的标签 |
| 触发项列表 | 多张触发项卡片 | 至少添加一个触发项；点击“添加触发项”继续添加 |

分层名称、分层开关、标签条件编辑和匹配顺序都不出现在本表单中。新增规则追加到规则列表末尾，修改规则不改变原位置。

### 每个触发项

每张卡片都有“何时触发、养多少、多少局内完成”三个区域。“执行限制”是“何时触发”的子项。

| 区域 | 字段 | 控件与示例 | 填写说明 |
|---|---|---|---|
| 何时触发 | 触发事件 | 下拉框：`上线 / 当日第1次充值 / 当日第2次充值 / 当日第3次及以上充值 / 盈利 / 亏损` | 必选，每个触发项选择一个事件 |
| 何时触发 | 盈亏启动门槛 | 数值框：`50`，单位：`%` | 仅盈利、亏损事件显示；填写正数，基数固定为当前执行币种的当日累计成功充值金额 |
| 何时触发 · 执行限制 | 每用户每日执行上限 | 数值框：`1`，或选择`不限` | 当前触发项独立计数；选择次数限制时填写正整数 |
| 养多少 | 目标计算方式 | 下拉框：`固定金额 / 随机金额区间 / 比例` | 必选，只显示所选方式的目标输入项 |
| 养多少 | 固定净赢金额 | 按币种填写，例如：`USD：100.00`、`USDT：100.00000000` | 每个已配置金额都必须大于零；执行时自动取用户当前币种对应的金额 |
| 养多少 | 随机净赢金额区间 | 按币种填写，例如：`USD：80.00 至 100.00` | 每组区间两端都大于零，下限不能大于上限；执行时自动取对应币种的区间 |
| 养多少 | 目标比例 | 数值框：`20`，单位：`%` | 选择比例时必填，填写正数 |
| 养多少 | 比例计算基数 | 只读说明：`当前币种当日累计成功充值金额` | 选择比例时展示，运营不手动修改基数 |
| 多少局内完成 | 达成局数区间 | 两个整数框：`3` 至 `5`，单位：`局` | 必填；两端都为正整数，下限不能大于上限 |

固定和随机金额至少配置一个币种，按[共用金额精度](../00-公共约定/README.md#金额)填写。用户当前币种没有配置金额时，该触发项不启动任务；不会借用其他币种的数字。

盈亏启动门槛决定什么时候开始养，目标净赢决定开始后养多少。比例目标用同一个充值基数计算，但启动比例和目标比例各自填写、各自生效。

金额区间的两端相同，就使用这个金额。局数区间的两端相同，就使用这个局数。局数区间用于抽取计划局数，不表示用户必须至少玩到区间下限。

每张卡片提供“删除此触发项”按钮。规则表单提供“添加触发项”和“保存规则”按钮。

### 一条规则的填写示例

规则名称为“首充用户养规则”，选择已有的“首充用户”复合标签，添加以下触发项。金额示例使用 USD。

| 触发项 | 何时触发 | 执行限制 | 养多少 | 多少局内完成 |
|---|---|---|---|---|
| 触发项1 | 当日第1次充值 | 每用户每日1次 | 固定净赢100 USD | 3–5局 |
| 触发项2 | 当日净亏损达到当日充值的50% | 每用户每日2次 | 随机净赢80–100 USD | 4–6局 |
| 触发项3 | 上线 | 每用户每日1次 | 当前币种当日成功充值金额的20% | 3–5局 |

### 执行记录

以下内容由系统生成，运营只读查看。

| 内容 | 说明 |
|---|---|
| 用户、规则、复合标签、触发项 | 说明针对谁、为什么开始，保留任务开始时使用的配置 |
| 标准 USD 余额和最低余额门槛 | 保留开始任务时的参与资格判断依据 |
| 执行币种 | 记录本次任务实际使用的币种 |
| 目标净赢和计划局数 | 记录已经确定的 X 和 N；比例目标同时记录基数金额和比例 |
| 实际投注、实际返奖、实际净赢、已完成局数 | 记录本次进度和结果，金额带执行币种标识 |
| 任务状态、结束原因、开始时间、结束时间 | 说明是否完成以及为什么结束 |
| 供应商控制结果 | 记录控制是否生效、是否失败或是否正在核对，不代替游戏结算结果 |

任务状态包括“进行中、核对中、已完成、未达成、已重置、执行失败”。

## 3. 操作规则

### 保存与启停

运营先设置全局最低参与余额，再创建规则、选择复合标签，并逐个添加触发项。每个触发项的门槛、次数限制、目标和局数分别保存，不互相覆盖。

保存时检查必填项和数字范围。输入有误时指出具体字段，不保存错误配置。开启规则后可接受新任务，关闭后不接受新任务。

修改规则、删除触发项、关闭规则、标签变更或用户被摘除标签，都只影响后续新任务。已经开始的任务继续按开始时的规则执行，X、N和执行币种保持不变。

被当前点控规则引用的标签不能删除，需要先修改规则的标签关联；历史任务的标签快照不阻止删除。

### 最低余额与统计口径

最低参与余额只在开始新任务时判断。读取系统现有账户余额的标准 USD 值，不另设换算算法；余额大于或等于门槛才可参与。读取失败或标准计价数据不完整时，不开始任务。

标准 USD 只用于最低余额资格判断。养的目标、实际投注、返奖和净赢都按执行币种原币计算，不合并其他币种的资金。标签仍沿用用户标签模块自身的标准 USD 口径。

充值次数和充值金额使用当前执行币种的当日成功到账记录，不包含人工加款。盈亏启动门槛使用同币种当日已结算的适用 Slot 游戏局，净盈亏为实际返奖减实际投注，按最终结算时间归入统计日。

### 同时命中多个条件

按原策略设计，先按配置顺序取第一个启用且标签命中的规则，再在该规则内按“上线 → 充值 → 盈亏”的顺序选择一个可执行触发项。同类型有多个触发项时，按添加顺序取第一个满足门槛和执行限制的触发项。

选中的规则没有可执行触发项时，本次不执行，不继续匹配后面的规则。当前养任务未结束时，不叠加或替换新养任务；结束后按用户当时的条件重新判断。

### 开始任务与每日次数

用户正在适用的第三方 Slot 中，命中规则、满足触发条件，并通过最低余额和执行次数限制后，才开始任务。

任务开始时固定执行币种、目标 X 和计划局数 N。随机金额按该币种金额精度从包含两端的区间内取值，N从包含两端的整数区间中取值。固定金额直接使用填写值；比例金额按当前币种当日成功充值金额乘以比例计算。

比例基数在开始时固定，金额按执行币种精度舍去不足一个最小记账单位的部分。当日充值为零或计算后的目标为零时，不开始比例目标任务，也不通过盈亏比例门槛触发任务。

同一任务重试或恢复时继续使用原来的 X 和 N，不重新抽取。同一个上线或充值事件不重复建立任务。

成功开始一次任务，就占用一次该触发项的每日次数；任务失败、未达成或切换币种都不退回次数。同一任务重试不重复占用。次数按“用户、触发项、统计日”记录，不按币种另开额度。

跨统计日不重置正在执行的任务，X和N继续使用原值；新统计日的执行次数重新计算。

### 在多局内完成

开发将一次养拆成多个游戏局执行。任务只在“进行中”时纳入新开始的有效付费局，按游戏局开始顺序取最多 N 局；已经纳入的未结算局等待结果，不用后来的局替代。

一个完整付费局结算后计1局。同一局的多次扣款和返奖合并计算，局内免费旋转的返奖归所属付费局，不单独占局数。没有付费局归属的独立免费局不纳入本任务；取消局和重复记录不计。具体供应商记录怎样合并为一局由开发实现。

同币种下切换不同适用 Slot，继续同一个任务。进入 Originals 时暂停本任务的统计和控制，返回适用 Slot 后继续原进度。

实际净赢达到或超过 X 时停止后续控制。没有待结算局时，任务立即完成，可以少于 N 局；正常返奖超过目标时按实际金额记录。

已有局尚未结算时，任务进入“核对中”，不再控制或纳入新局，也不开始新任务。所有已纳入局结算后，净赢仍达到 X 才记为“已完成”；净赢不足但有效局数尚未用完N时，恢复“进行中”，只使用剩余局数。N局结算完仍未达到 X，就记为“未达成”，不自动增加局数。

例如，用户当日充值100 USD，亏损达到50 USD，满足50%的启动门槛。本次确定 X为92 USD、N为4，就从本次任务开始计算，在最多4局内净赢至少92 USD；之前亏损的50 USD不属于本次目标。

任务中的游戏局发生后续结算、取消或冲正时，更新原任务的实际记录。已经结束的任务不自动恢复执行；曾经完成的任务修正后净赢不足 X，结果改为“未达成”。

### 切换币种

用户成功切换币种后，停止旧任务的后续控制，清空用户当前点控进度，保留旧任务记录。确认供应商的旧控制已经停止、取消或全部生效且没有剩余控制后，旧任务记为“已重置”，原因为“切换币种”；新币种重新判断条件，符合后建立新任务，不继承旧目标和进度。切回原币种不恢复旧任务。

旧币种未结算局后续仍补入旧任务记录，不影响新任务。历史记录和当日已用次数保留。旧控制是否结束无法确认，或查明仍有剩余控制时，旧任务先记为“核对中”，保留切换币种原因，不新开任务、不发送新的控制请求。

### 供应商能力验收

供应商和执行币种通过本功能联调验收后才能开放点控。验收必须覆盖实际返奖金额、控制生效时机、游戏局归属以及停止或核对未生效控制的能力。

Call请求成功只表示供应商接收了请求。任务完成必须按实际投注和返奖判断；不能用接口成功代替净赢达成，也不通过直接调整钱包补齐目标。未通过能力验收的供应商或币种不启动任务。

所有任务结束前，都要确认供应商控制已经停止、取消或全部生效且没有剩余控制。仍有剩余控制或结果无法确认时，任务保持“核对中”，不开始新任务；查清后再按实际结果记为已完成、未达成、已重置或执行失败。

## 4. 特殊情况

| 情况 | 处理结果 |
|---|---|
| 用户未命中所选复合标签 | 不按该规则开始任务 |
| 标准 USD 余额低于全局门槛 | 不开始新任务；已经开始的任务按原规则继续 |
| 当前触发项每日次数已用完 | 跳过该项，在已经选中的规则内检查其他触发项 |
| 当前币种没有固定或区间金额配置 | 当前触发项不执行，记录“当前币种未配置目标金额” |
| 当日充值为零 | 不执行依赖充值比例的触发项；固定或随机金额的上线触发仍按其他条件判断 |
| 金额、比例或局数输入不合法 | 拒绝保存，指出字段，原配置不变 |
| 区间下限大于上限 | 拒绝保存，提示修改区间 |
| 用户进入 Originals | 暂停当前任务的控制和统计，保留进度 |
| 读取标签、余额或必要游戏事实失败 | 不按满足条件处理；记录异常，已有任务不重复建立 |
| 供应商明确未执行或明确执行失败 | 记录“执行失败”和原因；重试仍属于原任务，不重新抽取目标或占用次数 |
| 供应商结果不明确 | 任务进入“核对中”，先核对结果；不盲目重复下发控制，不新开任务 |
| 游戏局后续被取消或冲正 | 重算原任务局数与净赢，更新结果，不自动恢复已结束任务 |
| 任务达到目标 | 停止后续控制；没有待结算局时记为“已完成”，否则先核对已有局的最终结果 |
| N局结算完仍未达到目标 | 记录“未达成”，停止后续控制，不自动追加局数 |

## 5. 验收场景

编号用于追踪本功能要求，不占用新的后台页面编号。

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 点控-R1 | 查看两条规则的最低参与余额 | 共用同一个全局标准 USD 门槛，没有规则级最低余额字段 |
| 点控-R2 | 创建规则并选择复合标签 | 可选择已有启用标签；没有分层开关、标签条件编辑和匹配顺序 |
| 点控-R3 | 同一规则添加上线和充值两个触发项，分别设置限制和目标 | 两项独立保存；执行限制位于各自“何时触发”区域 |
| 点控-R4 | 切换固定金额、随机金额区间和比例 | 只显示对应输入项；比例基数固定显示当前币种当日成功充值金额 |
| 点控-R5 | 当日充值100 USD，亏损启动门槛50%，分别亏损49 USD和50 USD | 49 USD不满足该门槛，50 USD满足；另行填写的养目标不变 |
| 点控-R6 | 配置固定净赢100 USD、随机净赢80–100 USD | 固定方式使用100 USD；随机目标位于含两端的区间内 |
| 点控-R7 | 配置3–5局，恢复同一个已开始任务 | N为3、4或5；恢复时X和N不变 |
| 点控-R8 | 输入反向区间、零局数或负目标金额 | 拒绝保存，指出错误字段，原配置不变 |
| 点控-R9 | 余额不足，或当前触发项次数已用完 | 不通过该触发项开始任务 |
| 点控-R10 | 本任务投注100 USD、返奖120 USD | 实际净赢显示20 USD，不包含任务前输赢 |
| 点控-R11 | 在同币种两个适用Slot之间切换，再进入Originals后返回 | 两个Slot共用任务进度；Originals期间不增加进度，返回后继续 |
| 点控-R12 | 任务中切换币种，供应商旧控制已确认结束，再切回原币种 | 旧任务已重置，历史保留；新任务不继承旧目标和进度，旧任务不恢复 |
| 点控-R13 | 用户同时命中规则A、B，A在配置中靠前；A没有可执行触发项 | 只选择A，本次不执行，不继续尝试B |
| 点控-R14 | 所选规则的上线、充值和盈亏项同时满足；已有养任务时再次满足 | 无任务时按上线优先选一项；有任务时不叠加、不替换 |
| 点控-R15 | 只配置USD目标，用户选择未配置的其他币种 | 不借用USD数字启动任务，记录币种未配置原因 |
| 点控-R16 | 当前币种当日充值100，比例目标20%，随后又充值 | 开始时目标为20；已经开始的任务不因后续充值改变X |
| 点控-R17 | 一个付费局包含多次返奖和局内免费旋转，收到重复记录或取消 | 合并为一个局，重复不增加局数或金额；取消后修正记录 |
| 点控-R18 | X为92、N为4，第2局结算后净赢100，没有待结算局 | 提前完成，记录实际净赢100，不继续控制后面的局 |
| 点控-R19 | N局全部结算后实际净赢仍低于X | 记录未达成，不自动增加局数 |
| 点控-R20 | 任务开始后修改、关闭规则或改变标签命中 | 当前任务按原X、N继续；新任务按最新配置和标签判断 |
| 点控-R21 | 切换币种后旧局才结算，或旧任务发生冲正 | 结果补入旧任务，保持原币种；不影响新任务、不自动恢复旧任务 |
| 点控-R22 | 开始任务后失败、重试或切换币种 | 每日次数只占用一次，不退回，不按新币种另开额度 |
| 点控-R23 | 门槛1 USD，现有标准余额分别为0.99 USD和1.00 USD | 前者不能参与，后者通过最低余额判断，不新增换算算法 |
| 点控-R24 | Call接收成功，但游戏未结算或供应商结果不明确 | 不显示已完成；核对期间不重复下发，不开始新任务 |
| 点控-R25 | 供应商或币种未通过能力验收 | 不开放该供应商或币种的点控任务 |
| 点控-R26 | 净赢暂时达到X，但任务内仍有未结算局，最终结果又低于X | 先核对，不提前确认完成；N尚未用完就继续剩余局数，用完则记录未达成 |
| 点控-R27 | 切换币种时，旧控制结果未知或仍有剩余控制 | 旧任务进入核对中，保留重置原因；旧控制确认结束前不开始新任务 |
| 点控-R28 | 任务净赢已达标或N局已用完，但供应商仍有剩余控制 | 先停止或核对旧控制，不开始新任务；确认没有剩余控制后才记录最终结果 |
