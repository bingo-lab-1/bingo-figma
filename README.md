# Bingo 需求文档

本仓库描述后台功能和业务规则,供运营、设计、开发及测试共同使用。正文是当前实施与验收依据,修改业务规则时须同步相关页面和验收场景。

| 模块 | 内容 |

| [M2 用户管理](M2-用户管理/README.md) | 用户查询、详情、标签,以及资金模型和标准计价规则 |
| [M4 活动管理](M4-活动管理/README.md) | 兑换码、红包雨、刮刮乐、VIP配置、注册赠金及三类签到 |

模块索引区分有正文的页面和仅作导航的条目。导航条目本身不构成独立页面规格;活动正文规定的记录与查询能力仍须随活动交付。

## 跨模块规则

VIP由M4维护,升级同时要求累计充值和有效投注达标。用户标签只读取等级,不反向决定等级。三类签到同一运营商最多一种接受新轮,已有轮次继续按各自规则履约。

M4判断活动资格并记录奖励依据,M5负责入账、账变与打码。资金结果未知时核查原申请,不能通过重复申请再次发钱。提现明确失败且未付款后释放占用,超时保持占用。

人工充值超出权限上限时拒绝,不截断金额。财务资金操作要求二次验证,数据查询和导出均受账号推广商范围限制。注册超限拒绝注册,被拒绝的请求不计成功人数。

## 文档规范

规范见[公共约定](00-公共约定/README.md)。文档直接陈述执行规则,不展示任务状态。路由、负责人、优先级、排期和工作量由Jira维护;历史修改由Git记录。

所有页面采用六部分结构,按用途选择[活动模板](00-公共约定/页面模板.md)、[查询模板](00-公共约定/查询页面模板.md)、[配置模板](00-公共约定/配置页面模板.md)或[业务处理模板](00-公共约定/业务处理页面模板.md)。校验只接受这四类结构。保留页面路径和A、R、E、D编号,已有深层链接通过隐藏锚点保持可用。

规则与验收必须一致;配置项必须定义范围及缺项处理。截图和竞品记录仅提供参考事实,不覆盖正文规则。PRD写业务行为,界面布局由Figma表达。

## 本地校验

python3 00-公共约定/校验.py --strict
