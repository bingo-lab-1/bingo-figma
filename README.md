## 编写约定
1. **文档进 repo,跟代码同 PR 改。** 字段/规则变了不更新文档的 PR 视为未完成。
2. **字段分三层**:L1 实体字段(落库)· L2 枚举字典(独立版本化)· L3 派生指标(只读视图,须写明公式+时区+数据源)。三层混写是文档腐烂的头号原因。
3. **规则的数值放配置,不放文档。** 文档只记:有哪些规则、语义(条件→动作)、在哪配、谁能改。
4. **能自动生成的不手写**:ERD 用 `prisma-erd-generator`,API 契约用 `spectaql`,CI 校验 schema 与文档同步。
5. **完成的定义**:开发拿到能直接转成 schema diff + issue,不用回来问"字段什么意思/阈值多少"。
