# Bingo 需求文档

本仓库描述后台功能、业务规则及玩家端需求,供运营、设计、开发及测试共同使用。模块和玩家端正文描述系统当前行为,是实施与验收依据;修改业务规则时须同步相关页面和验收场景。尚未实现的需求放在[未落地需求](未落地需求/README.md)。

玩家端的字段、操作、页面关系和状态由本仓库定义;视觉稿、玩法服务实现和外部支付机构不在本仓库交付范围。活动文档定义玩法及权益,玩家端引用其个人结果和操作入口;具体界面由Figma表达,服务实现另由技术设计维护。

模块索引保留已有正文的页面;尚无正文的独立页面,仅在已核实侧边栏存在入口时登记。没有侧边栏入口的空登记当前不列为页面。

## 跨模块规则

VIP由M4维护,升级同时要求累计充值和有效投注达标。用户标签只读取等级,不反向决定等级。签到互斥规则见[M4决策D83](M4-活动管理/README.md#7-决策清单)。

M4判断活动资格并记录奖励依据,M5负责入账、账变与打码。资金结果未知时核查原申请,不能通过重复申请再次发钱。提现明确失败且未付款后释放占用,超时保持占用。

后台账号新建时默认是官方渠道下的测试账号,拥有玩家钱包,员工可以玩家身份充值、领取充值赠送和参加全部活动。测试标记只把账号数据排除在报表统计和代理佣金之外,不限制充值或活动;封禁和风控限制照常执行。见[M4决策D111](M4-活动管理/README.md#7-决策清单)。

玩家端只提供英文和简体中文两种语言,后台不配置语言。通知和网站内容的标题与描述,游戏平台、类型、子游戏和首页活动入口的名称,都按英文、中文两种填写,两种都必填,玩家按当前界面语言看到对应内容。见[M11决策D113](M11-内容管理/README.md#7-决策清单)。

人工充值超出权限上限时拒绝,不截断金额。财务资金操作要求二次验证,数据查询和导出均受账号推广商范围限制。注册超限拒绝注册,被拒绝的请求不计成功人数。

M9 在 Bingo 后台“报表管理”呈现,页面只读后台任务生成的分析结果;不修改用户、账务和邀请关系。充提金额沿用 M5 的成功事实和 USD 标准计价,同期群不另定钱包或汇率规则。

## 文档规范

规范见[公共约定](00-公共约定/README.md)。文档直接陈述执行规则,不展示任务状态。路由、负责人、优先级、排期和工作量由Jira维护;历史修改由Git记录。

功能需求页面采用六部分结构,按用途选择[活动模板](00-公共约定/页面模板.md)、[查询模板](00-公共约定/查询页面模板.md)、[配置模板](00-公共约定/配置页面模板.md)或[业务处理模板](00-公共约定/业务处理页面模板.md)。字段字典使用“分类与底色、字段定义”两部分，只维护字段定义及分类配色。校验分别检查这两类文档结构。玩家端使用独立目录和Account-R等需求编号,不占用后台菜单编号。保留A、R、E、D编号,已有章节的深层链接通过隐藏锚点保持可用;目录名称跟随后台实际菜单。玩家端范围决策D95见[玩家端索引](玩家端/README.md#7-决策清单)。

数据分析范围及口径决策 D96–D103 见[M9 决策清单](M9-数据分析/README.md#7-决策清单)。

点控策略决策D104见[M2决策清单](M2-会员管理/README.md#7-决策清单)，业务正文见[点控策略与执行记录](未落地需求/点控策略.md)。

规则与验收必须一致;配置项必须定义范围及缺项处理。截图和竞品记录仅提供参考事实,不覆盖正文规则。PRD写业务行为,界面布局由Figma表达。

## 本地校验

```bash
python3 00-公共约定/校验.py --strict
```

校验包含文档结构、规则完整性标记、需求编号、本地链接、合并冲突标记和流程图代码块。CI另外使用mermaid-cli检查流程图语法。

默认校验与CI流程图检查均排除根目录`.artifacts`历史草稿、审计报告及文档副本,共用[文档扫描范围](00-公共约定/doc_scope.py)。当前文档引用归档证据时,仍检查链接目标是否存在。历史内容保留当时状态,不为通过当前需求规范而改写。

需要审计包含历史资料的全部文档时,运行`python3 00-公共约定/校验.py --strict --include-artifacts`。此模式仍按现行通用规则报告历史措辞和失效链接,不代表这些内容属于当前需求;默认正式校验与归档审计分别记录结果。
