# D3 · 活动引擎参数模型 — 参考 aigobet 玩法中心

> 来源：aigobet 后台「玩法中心 > 活动配置」逐页采集，2026-07-25。
> 这是本次调研**单点价值最高**的产出：aigobet 的活动配置页 = 它真实活动引擎的可视化。
> 结论先行：**它的活动引擎是「分类固定 + 每类一页配置」，不是完全通用引擎**——
> 但每类配置页共享一套高度一致的参数骨架。你们应抄这套**参数骨架**，做成真正配置化的引擎，
> 避免重蹈「每加一个活动 = 加一个 action_type + 一张表 + 发一次版」的覆辙（aigobet 已到 159 个 action_type）。

## 通用参数骨架（4 个活动实测归纳）
所有活动配置页共享以下分区，字段随活动类型裁剪：

### ① 资格 / 圈人（Eligibility）
- 选择运营商（渠道）· 用户标签 · 模板 —— 活动可**按渠道/代理/标签差异化**
  （账号首充页副标题原文：「支持默认档位与按代理/标签的渠道差异化档位」）
- VIP等级区间（min/max）——见红包雨奖励矩阵

### ② 开关 / 命名 / 展示（Display）
- 活动开关（总开关）
- 活动完整名称(≤20) · 侧边栏简称(≤10)
- 说明开关 · 参与说明（富文本）
- 入口：前往 Banner配置 / 悬浮窗配置 / 侧边栏配置（活动与展示位解耦，交叉引用）
- 悬浮窗入口倒计时、显示倒计时

### ③ 时间 / 周期（Schedule）
- 重置类型：终身一次 / 每日重置（账号首充）
- 活动循环 · 冷却天数 · 活动周期 / 活动持续时间 · 活动天数 · 重置天数 · 重置时间

### ④ 奖励结构（Reward）— **随活动类型而变，这是差异核心**
| 活动 | 奖励结构 |
|---|---|
| 账号首充 | 档位表：`首充最低充值金额 → 返奖比例 → 打码倍数`（多档），另有 100+ 返还比例 |
| 红包雨 | 矩阵：`VIP等级(min/max) × 金额(min/max) × 今日充值≥系数% × 今日亏损≥系数%`（奖励同时看 VIP、充值、亏损） |
| 通行证 | 双轨里程碑：`任务条件 → 任务要求 → 免费奖励金额 / 付费奖励金额`；带**购买金额**(付费解锁) |
| 每日签到V2 | 日历表：`天 → 签到奖励 → 签到打码要求 → 当日存款要求 → 当日投注要求` |

### ⑤ 限制 / 打码（Limit & Wagering）
- 打码倍数（几乎所有活动都有 = 彩金流水解锁倍数）
- 玩家每日领取次数 · 每天次数（如红包雨每天次数）
- 强制最小充值开关 · 首充最高充值金额

### ⑥ 元信息
- 配置完成度进度条（如账号首充 56%）——引导运营配全

## 抽象成你们的通用活动引擎（建议 schema 五要素 + 两扩展）
```
Activity {
  code, type(充值/留存/召回/打码/裂变), enabled,
  display  { name, shortName, descOn, desc, banner, floatWindow, sidebar, countdown },
  schedule { cyclic, cooldownDays, periodDays, resetType, resetTime, durationDays },
  eligibility { operators[], userTags[], vipMin, vipMax, template },   # 圈人
  reward  { kind: TIER|MATRIX|CALENDAR|MILESTONE, rules: Json },       # 多态奖励，配置化
  wagering { multiplier },                                            # 打码
  limits  { dailyClaims, perDayCount, minRecharge, maxRecharge, forceMinRecharge },
  paid?   { buyAmount, paidTrack }                                    # 付费变体(通行证类)
}
```
- **关键决策**：`reward.kind` 用多态 + JSON 规则，就能用一张表覆盖 aigobet 那 40+ 个活动，
  不必一活动一表。你们现在 `activity.prisma` 是「一活动一 Config 表」，正在往 159 的坑里走。
- **成本核算**：每个活动的「领取记录」必须能 join 到发放金额，单独算 ROI（发放成本 vs 带来存款）。
