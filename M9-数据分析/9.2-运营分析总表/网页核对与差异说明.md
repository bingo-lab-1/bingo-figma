## 已识别差异及解释限制

这些记录不等于本次要求修复。复现时以实际网页标记原状，公式解释以独立来源标识，未来调整另行形成变更，不静默改写。

| 差异编号 | 关联指标 / 区域 | 现有证据与本次处理 |
|---|---|---|
| 9.2-X01 | 87 项完整性 | 源码旧注释仍写 74 列，其他指标旧数量也未更新。现场列元数据与实际定义均为 87；文档以实际清单为准，逐项保留同义列 |
| 9.2-X02 | 币种 | E08 现场金额只改符号；总表查询只传 from / to，不传 fx，表格只把币种交给 formatter。不能写“现有 BRL 已正确换算” |
| 9.2-X03 | M038、M040 | 元数据都为 dec，因此网页带货币符号；真实单位分别为倍、笔/人。字典同时写真实单位和页面格式 |
| 9.2-X04 | M068–M072 | 页面原提示称 Wild 为 D0…DN 共 N+1 天；E13 SQL 实际上限是 2/6/13/20/29，与 N 天一致。原提示原样保存在元数据；字典明确所查源码窗口，不用旧提示替代代码，也不声称线上所有历史值已重算 |
| 9.2-X05 | M048 | E13 的 user_first 同时独立取 MIN(confirm_date) 与 MIN(pay_amount)，后者不保证与首单同一行。例：先充 100，再充 20，之后充 5，源码首笔基础量会取 5；这是说明源码行为的假设样例，不是已核实的线上交易 |
| 9.2-X06 | M005、M017、M022、M025 | Aigobet 金额取 is_first_recharge 订单而未筛 parent_id=0，人数却筛根用户；Wild 金额取根用户首充当天全部充值。不能把两族“一级首充金额”视为同一人群同一金额范围 |
| 9.2-X07 | M018/M046、M016/M047、M030/M056 | 第一对两族同源；第二、三对只在 Wild 同源，Aigobet 用不同财务 / 渠道字段。全部独立编号，不因为 Wild 样本相等就删除列 |
| 9.2-X08 | M024、M064、M067–M087 | 当前无观察期成熟标记或未来格屏蔽；近期留存可为 0、长周期 LTV 可与短周期相同。文档说明只能表示当前已有事实，不能据此认定未来无回访或 N 日已完整 |
| 9.2-X09 | M067–M072 | 分子属于注册批次净充值，分母为该日期终身首充人数，可能包括更早注册用户。保留旧表公式，不把它描述成同一注册人群的标准人均 LTV；M024 则是首充批次的总充值人均，未减提现 |
| 9.2-X10 | M053–M055、M062 | Wild 返回固定 0 是上游未提供代理佣金的占位，不是实际佣金为 0 的证明；Aigobet 使用专属佣金 / 宝箱字段 |
| 9.2-X11 | M028、M044 | 原提示把 Aigobet 充值计数称为“笔数”，列名叫“人数”，实际映射渠道 recharge_num；M039 另有订单事实计数。M044 Aigobet 为（充值数+裂变数）/充值数，不能套 Wild 的裂变人数占比 |
| 9.2-X12 | 缺项与回退 | `_div` 实际把空分子按 0 处理，虽然函数注释称空操作数为 null；差值函数也多用空转 0，汇总会补 0。Wild M045、M073、M076 使用 truthy 回退，真实 0 同样触发回退；文档不承诺逐格缺失原因或严格空传播 |
| 9.2-X13 | M049 日均 | Aigobet 公式先 int(充值数) 再减 int(新首充数)，在日均基础量上也会截断。例 10.8−3.2 的公式输出 7，而非 7.6；这是来源表达式的例外，不修改现有实现 |
| 9.2-X14 | M051、M052、M059 | Wild 注释写 reason=5，但 SQL bonus_send 没有该过滤；不能把源码范围缩写成只含活动 reason=5。总彩金与付费 / 免费彩金分别存储及换算，显示尾差不能直接判为重复发放 |
| 9.2-X15 | M032 与 LTV 提现 | Wild 日提现主汇总筛 order_status=4；注册 LTV 提现另筛 order_result=1。保留两条查询真实条件，不宣称所有充提衍生列严格共用一套订单过滤 |
| 9.2-X16 | 日期、更新于 | 默认 / 快捷项使用浏览器今天，手动日期上限使用巴西今天；接口未传 from 时起点为结束前 30 日，双端包含共 31 日，前端默认最近 30 日不同。更新于来自共享 summary，以浏览器本地时间显示，不是总表专属同步完成时间 |
| 9.2-X17 | 推广商 / 渠道 | 原网页有控件，但总表请求不包含对应过滤；不能据控件存在宣称总表已按推广商 / 渠道筛选，更不能将筛选当权限边界 |
| 9.2-X18 | 汇总位置与热力 | 接口注释的 pinned 只表示汇总排在前面，现场汇总会正常滚出；表头固定。首充成本按低值更深红，保留当前配色方向 |
| 9.2-X19 | 主题 | E10 确认 html=dark 后背景仍为浅色。E19 的 .dark 与后置 :root 规则可解释该现象（源码推断）；不提供虚构的正常深色截图，不在本次悄悄修正 CSS |
