# 9.2 · 运营分析总表

## 1. 用途

运营通过本页按天查看一个平台的广告消耗、充提、获客质量、投注、彩金、佣金、LTV 与留存，并查看查询期间总汇总、全盘日均及月度汇总。日期代表发生业务或形成用户批次的自然日；“今日”类列名指该行日期，并非全部行都统计打开页面的今天。

页面承载在现有 Chartx 数据中台“投放数据中心 → 运营分析总表”，参考入口为[运营分析总表](https://dash.chartxcloud.com/marketing/platform-daily)。**本次只整理现有网页，不定义 Bingo 数据接入，不在 Bingo 后台另建副本。** 业务日按现有平台报表来源解释，页面顶栏显示 GMT-3；浏览器本地显示时间与业务日不可混同，现状细节见差异说明。

本页是**一列日期 / 汇总加 87 个指标的分组宽表**，不是同期群 D0–D60 矩阵，也不是总览页的图表集合。87 个指标全部纳入需求，不因当前屏幕只显示左侧列、某账号隐藏列或某平台暂时无数据而删减。图表表现为分组表头和部分数值列的热力底色；本页不新增折线图、饼图、柱状图、用户明细钻取、导出或数据修改入口。

**UI 按现有网页复刻。** 整体布局、表头分组、字段顺序、热力色块、冻结列、筛选控件及交互与参考页面一致。需求文档重点维护指标与业务规则，UI 直接以参考网页为准。

本文与[指标字典](指标字典.md)共同构成现有页面的复现与核对依据。原页面存在的公式差异、旧提示和显示问题见[网页核对与差异说明](网页核对与差异说明.md)。本文把“实际显示”“源码计算”和“名称通常含义”分开记录；本次不修正线上公式，不把疑似问题改写成已完成的修复，也不为其他平台新增口径。

### 2.2 联动及恢复

有效平台、完整日期区间变化后自动查询，不添加网页没有的“查询”按钮。日期仅选一个端点时不提交新条件。关闭日期弹层而未完成选择时保留原区间；开盘快捷项点击后立即应用并关闭。当前总表查询具有约 5 分钟前端缓存，不把刷新网页解释为上游数据采集。

开盘日期默认初始化在本页挂载周期只执行一次；已有明确 from 的链接或浏览器恢复区间被保留。同页切换盘口不会再次自动重置为新盘口开盘日至今，日期快捷项根据当前盘口更新。市场 / 产品约束盘口列表；共享推广商、渠道选择的失效清理由共享工具栏负责，不因此获得总表过滤能力。

“全部盘口”按原网页显示“跨盘口模式不支持”和选择具体盘口的提示，不将平台数据直接相加。没有当前平台时本页不渲染表格，不发无平台查询。非法日期或无权限平台直接拒绝，不静默回退到另一份数据。

列显隐按账号和本页面在浏览器本地记忆，独立于渠道明细页面；不提供跨设备同步承诺。当前 87 列下重新进入或刷新保留偏好；列集合未来变更时的旧偏好迁移不在本次现状整理中扩写。

### 3.2 行及汇总

| 编号 | 行类型 / 字段 | 规则 |
|---|---|---|
| 9.2-S01 | 日期 / 汇总 | 左侧冻结列，日行显示 YYYY-MM-DD；汇总行显示“总汇总”“全盘日均”“YYYY-MM 汇总”。不作为可点击日期钻取入口 |
| 9.2-S02 | 总汇总 | 查询区间内先合计各项基础金额和计数，再计算比例、成本、人均值；历史累计四列取区间最后一个有效日期的累计值 |
| 9.2-S03 | 全盘日均 | 基础金额、计数的区间合计除以实际有效日行数；先平均基础量再算比例，常规比例等价于合计分子除合计分母。历史四列均为“—”；人数、次数日均可为小数，Aigobet M049 在公式内截成整数是例外 |
| 9.2-S04 | 月度汇总 | 按查询区间与自然月的交集汇总，不补入筛选外日期。历史四列取该月在区间内最后一个有效日期的累计值；月标签 YYYY-MM 汇总，按月倒序 |
| 9.2-S05 | 每日行 | 一个平台一天一行，按日期倒序；总汇总、全盘日均、所有月汇总排在每日行之前。汇总行位于顶部但不随纵向滚动固定；双行表头固定 |
| 9.2-S06 | 行数与窗口 | 底部展示全部结果行数、其中汇总行数、当前查询起止日期。行数包括未渲染到当前视口的日行；不因虚拟滚动变成当前可见行数 |
| 9.2-S07 | 口径说明 | 保留底部信息图标和不同平台口径提示。列头有说明的指标必须能查看对应全文，不能仅展示一个没有内容的图标 |

人数类的基础去重由来源统计完成，平台接口按日合计分析表中的各渠道基础量，不在接口重新读取用户 ID 去重。Wild 自算指标按相应人群去重；Aigobet 上游计数沿原字段含义，不能保证所有列都等价于财务去重用户数。同一用户不同日充值或投注，会在多日日行中各计一次；总汇总与月汇总不能解释为整个期间的唯一用户数。

日均分母为当前查询返回的日行数，不是起止日期之间的日历天数。现有接口不补齐缺失日期，也不证明各日来源完整；有零值日行则参与日均，没有该日行则不参与。无日行时不构造汇总行，不能根据无行判断当天一定零业务。

### 3.3 历史累计及观察期

历史消耗、历史充提差在分析表全部可用历史上累计至该行日期，再截取查询区间。缩短查询起日不会把历史重置为零；页面当前没有完整历史起点校验，不能额外承诺覆盖开盘前缺失资料。历史总营收为历史充提差减历史广告消耗，历史盈利率为该差额除历史广告消耗；均不包含全部经营成本，不能解释成完整财务净利润。

LTV、首充 7 日 ARPPU 以及留存需要读取行日期之后的事实。结束日期只限制展示哪些日行，不把每行后续观察截在筛选结束日。留存是指定目标自然日的回访，不是此前若干天累计回访；次日、3日、7日、30日分别指 D+1、D+2、D+6、D+29，字典逐项列明。

现有页面没有观察期成熟状态：近期日行的留存可能显示 0%，较长周期 LTV 可能重复较短期间已有值。本文不据此认定未来留存为零或 N 日已经完整；这一限制逐项关联到 M024、M064、M067–M087，见差异说明。本次不增加新的成熟度接口或替换线上数值。

### 3.4 数字及热力表达

所有 dec 列当前使用所选货币符号、千分位及两位小数，负数保留负号；不缩写为 K/M。百分比保留一位小数，原值为比例时乘 100 展示；接口 null 显示浅色“—”。int 列使用千分位，日均可显示最多三位小数。某些来源缺项已在上游或公式中变为 0，页面不能反向恢复其缺失原因。

打码倍数的真实单位为“倍”，人均充值笔数为“笔/人”；原网页仍把二者作为 dec 加货币符号。字典分别标记真实单位和原显示格式；复现原网页时保留现状，业务纠正另行变更，不能把 $7.69 解释为货币金额。

五组表头颜色和热力表达按原网页复刻。只有首充人数、首充总金额、充值人数、充值金额使用绿色梯度，首充成本使用红色梯度；其他列不自动增加红绿盈亏色。汇总行不参与每日热力范围，也不套每日热力底色。

## 4. 操作规则

### 4.1 阅读与滚动（9.2-A1）

宽表同时支持横向与纵向滚动，日期列保持可见，双行表头保持上下层关系。全列顺序和分组不变；不能为了适配窄屏把指标折叠成卡片或从 DOM / 返回结果中漏掉未显示的列。日行不分页、不开放列排序、不新增行展开；长列表可以采用虚拟滚动，但总行数、头尾日行、汇总及滚动连续性必须正确。

### 4.2 列筛选（9.2-A2）

弹层标题“显示列”，顶部“全选 / 清空”，下方五个原始分组及各组“可见数/组列数”。单列即时切换；全组已全选时点击隐藏全组，未全选时点击显示全组。组内部分可见时按原网页呈现未全选状态，不自行改成另一款半选图标。剩余列保持原顺序，空组不留空白色带。

清空后显示 0/87 并保留日期 / 汇总列及各行标签，便于再次选择；不是无业务数据空态。全选恢复完整 87 列。弹层内纵向滚动可以到达最后的“下注7日留”，不能仅提供首屏字段。

### 4.3 查看口径（9.2-A3）

有说明的列头保留原 Info 图标，通过浏览器原生 title 悬停查看全文。现有提示是同时描述多个产品族的固定文本，并不随盘口切换改写；没有独立说明弹窗。原始提示逐列保存在指标来源映射中，提示与计算不一致的地方另见差异说明。相同列名不代表跨平台可直接比较，尤其是一级首充金额、一级新充、注充率、充值裂变率、代理佣金、LTV 和留存。

### 4.4 现有来源与读写边界（9.2-A4）

### 4.5 异常及权限（9.2-A5）

| 情况 | 页面结果 |
|---|---|
| 首次加载 | 展示原网页加载状态；不另外增加查询按钮 |
| 无有效日行 | 显示“所选窗口内无数据”，不生成伪造总汇总和日均 |
| 全部指标被隐藏 | 保留日期列及行标签，列筛选可恢复；不误报无数据 |
| 平台不支持 / 无权限 | 分别说明不可用原因；服务端拒绝越权，平台列表不泄露无权限平台 |
| 数据源缺失 / 未完整 | 现有页面无逐格缺失原因、完整性标志或成熟状态；接口 null 为“—”，被上游及公式转成 0 的缺项仍显示 0 |

现有接口通过 admin / ops 角色和平台授权校验。推广商筛选不构成权限隔离；本次不新增细粒度权限码，也不定义 Bingo 后台权限。
