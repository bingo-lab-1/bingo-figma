# M9 · 数据分析

## 1. 定位与边界

运营通过 Bingo 后台“报表管理”查看每日经营数据、比较获客成本和后续资金回收。本模块维护该菜单下的同期群分析与运营分析总表；Chartx 数据中台的同名页面只作 UI 参考，不是入口。

两页由后台任务从 Bingo 业务事实生成分析结果，页面只读已发布的结果。同期群按注册批次统计渠道、注册和成功充提事实；运营分析总表用一份字段字典维护 87 项指标的定义、分类与底色。两页均不改变钱包、订单、渠道归属或邀请关系；不编辑广告费，不执行广告投放、回传或同步任务。

同期群包括注册日口径、D0–D60 矩阵、平均回收和渠道明细，本版固定 Bingo、注册日和 USD；根用户关系及归属数据满足页面规则后才开放广告归因。运营分析总表字段字典覆盖充提、获客、投注、彩金、佣金、LTV 与留存，字段使用中文名称，定义直接说明业务含义。

广告消耗尚未接入。两页依赖消耗的成本、ROAS、ROI 和回收率均留空显示“—”，不使用占位或模拟数据。

同期群正文是实施和验收依据，UI 参考[Chartx 同期群页面](https://dash.chartxcloud.com/marketing/cohort)的布局、矩阵、色块、图例和交互。运营分析总表仅维护字段定义、分类和底色，分类颜色及五个字段的热力底色沿用原总表。独立留存 / LTV、渠道决策和其他分析页面不因总表包含相关指标而一并扩写。

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 同期群 / 批次 | 按同一个归属日期归到一起的用户集合 |
| 注册日口径 | 每名用户按自己的注册日期和注册渠道归组 |
| 广告归因口径 | 用户沿邀请关系找到根用户，按根用户的注册日期和渠道归组；包含后续裂变用户 |
| Dn | 距批次日期 n 个自然日；D0 是批次当天 |
| 净回收金额 | 纳入统计的累计充值金额减累计提现金额，不等于经营净利润 |
| 回收率 / ROI | 净回收金额除以该批次日期的广告消耗；100% 是广告费回收线 |
| 完整数据截至日 | 已保存的注册、成功充提和 USD 计价事实可用于分析的自然日边界，不包含未结束的今天 |
| 预测 / 外推 | 用已完整观察批次的增长规律估算较新批次在后续天数的回收，仅用于平均回收行 |
| 运营分析总表 | 一个平台每日一行，附总汇总、日均及月份汇总的 87 指标宽表 |
| 首充 / 注册当日新充 | 首充按第一次成功充值日期，新充按注册日与充值日相同判断；上游专列差异见 9.2 字典 |

上表 ROI、完整数据截至日和预测定义属于 9.1 同期群；9.2 采用自身公式，没有完整数据截至日，留存未到目标日留空。

## 4. 数据归属与读写边界

| 数据 | 归属与本模块使用方式 |
|---|---|
| 同期群分组、回收矩阵、汇总、预测和数据状态 | M9 维护分析定义；由后台统计任务生成已发布结果 |
| 用户及注册事实 | M2 拥有；经分析数据同步后只读消费 |
| 成功充提、账变、冲正和标准金额 | M5 拥有；统计只读消费，不重新判定支付成功或修改账务 |
| 邀请关系 | M7 拥有；统计只读关系，不改写绑定 |
| 渠道、推广商及广告成本 | 渠道能力拥有渠道和推广商，广告成本本版没有来源；本页面只读筛选和汇总 |
| 统计任务状态、发布版本及失败记录 | 统计任务提供事实；页面不能通过点击刷新宣称数据已更新 |
| 运营分析总表字段定义、分类与底色 | 9.2 维护字段业务含义及配色 |

查询只读取已发布的分析结果，不在请求时扫描用户、资金和投注流水。数据接入方式和接口结构由技术设计维护；本仓库只规定必须提供的业务事实与可对账结果。

## 6. 权限点汇总

| 权限标识 | 能力 | 数据范围 |
|---|---|---|
| `analytics:cohort:view` | 只读注册批次与回收矩阵 | 须与下一项同时具备 |
| `analytics:cohort:platform` | 同期群整个平台数据范围，含全平台渠道明细 | 仅向有整个平台数据权限的运营角色授权 |
| `reports:platform-daily:view` | 读取运营分析总表，不授予财务修改或重算权限 | 整个平台 |

同期群须同时具备前两项权限；只有 `analytics:cohort:view` 时不显示菜单，服务端也拒绝查询。同期群不对只有单个推广商数据权限的合作方开放；推广商筛选不是权限隔离，日期明细可以展示平台全部投流渠道。

运营分析总表的推广商、渠道控件不参与查询，也不提供权限隔离。

无权限时服务端拒绝主表和明细查询。报表权限不授予 Bingo 财务、用户修改或广告操作权限。
