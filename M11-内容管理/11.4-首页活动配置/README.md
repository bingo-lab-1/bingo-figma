# 11.4 · 首页活动配置

## 1. 用途

运营维护用于玩家首页和 Promotions 页的内容配置。后台表单和查询接口已实现，玩家 main 尚未接入四区配置，没有 `/promotions` 页面。页面分为轮播图、浮窗区、活动入口、Promotions 活动页四个页签，各自保存、各自维护配置版本。活动资格、奖励和开关仍由 M4 管理。

配置为平台公共内容，没有定时投放或人群投放表单。活动入口及 Promotions 卡片按访问者所属运营商和活动当前开关过滤，因此 API 对不同访问者返回的列表可能不同；此处不代表玩家 main 已展示该列表。

## 2. 配置项

| 区域 | 数量与内容 | 显示和排序 |
|---|---|---|
| 轮播图 | 保存时 1～6 张，至少 1 张启用；每张包含唯一标识、图片、跳转活动、启用开关，跳转活动可以不选 | 可拖动排序；中英文共用图片；点击打开所选活动，未选跳转活动的图不可点击。首次未配置时可以为空 |
| 浮窗区 | 固定 slot-1～slot-4 四个位置，填写活动、英文名称、中文名称、图标、启用开关 | 不可新增、删除或重排；固定顺序返回各项；主分支尚无快捷位及固定 Support 组合展示 |
| 活动入口 | 0～3 个，包含唯一标识、活动、两种名称、图标、启用开关 | 可拖动排序；主分支尚未在首页展示 |
| Promotions 活动页 | 0～20 张卡片，包含唯一标识、活动、两种名称、横幅、启用开关 | 可拖动排序；API 返回有序卡片，主分支 Bonus 尚未读取 |

标识长度 1～50，只能使用小写字母、数字及夹在它们之间的中划线，同一区域内不能重复。英文和中文名称各 1～30 字符，去首尾空格后都必填。上传图片支持 PNG、JPEG、WebP，后台上传大小不超过 10 MB，服务端验证可解码静态图片并生成优化后的发布图；保存的远程地址必须为不带账号密码的 HTTPS 地址，最长 3000 字符。轮播建议 343:140、活动卡片建议 343:114、图标建议 1:1。

跳转目标从活动目录选择，不接受任意站内路径或外部 URL。四个页签共用同一份活动目录，可选活动和顺序都相同（M11-D138）。目录中每个活动有一个后台名称和一个玩家端页面的英文名称，两者一一对应（M11-D132）：

| 后台名称 | 玩家端英文名称 |
|---|---|
| 签到奖励 | Daily Check-in |
| 首充破产补助 | Deposit Aid |
| 拼多多活动 | Spin & Invite |
| 幸运转盘 | Lucky Wheel |
| 每日挑战 | Daily Challenge |
| 七日奖励 | 7-Day Rewards |
| 排行榜活动 | Leaderboard |
| 邀请宝箱 | Invite & Earn |
| 注册送好礼 | Welcome Gift |
| 兑换码 | Redeem Code |
| 红包雨 | Cash Drop |
| 刮刮乐 | Scratch & Win |
| VIP 会员 | VIP Club |

「跳转活动」下拉和各列表的跳转活动一栏都显示为「后台名称（玩家端英文名称）」，例如「每日挑战（Daily Challenge）」。四个快捷位默认分别为每日挑战、七日奖励、幸运转盘、VIP 会员，并使用内置图标。

## 3. 操作规则

新增或编辑通过弹窗保存；启用开关、删除确认和拖动排序各自直接提交所属区域的整份列表，不需要再点击页面总保存。未提交的弹窗内容不会生效。切换页签保留已挂载区域，当前页签记录在地址中。

在浮窗区、活动入口和 Promotions 活动页的弹窗中选择或更换跳转活动时，名称按语言分别处理：某种语言的名称为空，或仍是上一个所选活动带入的名称，就填入新活动的名称（英文填玩家端英文名称，中文填后台名称）；运营已经输入的名称保持不变。带入的名称可以继续修改，保存时仍按名称的长度和必填规则校验。

服务端完整校验内容和版本后整份替换、版本加一，并记录操作人和修改前后配置。保存成功后重新读取服务端结果。不同区域的版本相互独立；同一区域并发保存时，旧版本被拒绝，须重新载入。

玩家 API 提供各区配置查询；活动入口和 Promotions 卡片只返回自身启用、标识有效且对应活动开放的项，兑换码没有统一活动开关；VIP 会员看 VIP 活动开关（[4.6](../../M4-活动管理/4.6-VIP配置/README.md)），全平台一个，不分运营商。运营商无法解析或活动关闭时过滤对应项。首充破产补助还要求访问者是持有宝箱的已登录玩家，未登录或没有宝箱时不返回该项，规则见[4.15](../../M4-活动管理/4.15-首充破产补助/README.md)（M4-D128）。快捷位按自身开关，不额外按活动开关过滤；首充破产补助快捷位由玩家端按是否持有宝箱决定是否显示。玩家主分支尚未消费这些查询，因此保存不会改变其首页固定组件或 Bonus 内容。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 关闭或删除最后一张启用轮播 | 页面阻止，服务端也拒绝整份配置无启用轮播的保存 |
| 活动入口或卡片为空 | 对应列表为空；浮窗区仍要求四个固定位置，可全部关闭 |
| 老入口没有可识别活动 | 后台标记需编辑，玩家查询接口不返回；重新保存须选择有效活动 |
| 读取内容损坏 | 后台提示读取失败，不提交无效配置；轮播与活动入口配置无效时返回空列表；快捷位未配置、损坏或读取失败时返回内置四项；Promotions 配置无效时返回不可用错误。主分支没有对应渲染及重试状态 |
| 未配置快捷位 | 返回内置四项；不能把取数失败当作运营主动关闭所有位置 |
| 图片不合规、上传失败 | 不替换为失败图片，不保存未完成上传 |
| 无编辑权限 | 服务端拒绝保存和上传；查看不代表有修改能力 |
| 版本冲突或版本达到上限 | 原配置不变，提示错误；冲突后刷新再操作 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 11.4-R1 | 新增两个活动入口并保存 | 当前区域保存成功，玩家 API 按顺序返回符合开关条件的入口；main 尚未展示 |
| 11.4-R2 | 已有三个入口或提交第四个 | 页面不能新增；服务端拒绝超限 |
| 11.4-R3 | 标识含大写、下划线，或提交任意 URL 作为活动 | 拒绝保存，原配置不变 |
| 11.4-R4 | 同一区域重复标识 | 拒绝保存 |
| 11.4-R5 | 上传超过 10 MB、非图片或仍在上传时保存 | 不产生包含失败图片的有效配置 |
| 11.4-R6 | 两人修改同一区域同一版本 | 后保存者收到版本冲突；不同区域不互相覆盖 |
| 11.4-R7 | 删除全部活动入口或卡片 | 对应 API 列表为空，其他区域的配置不变 |
| 11.4-R8 | 配置损坏或读取失败 | 各区域按第四节处理，不以示例活动卡片冒充成功结果 |
| 11.4-R9 | 检查玩家 main 首页 | 尚无竖排入口关闭及刷新恢复交互 |
| 11.4-R10 | 后台填写英文和中文名称 | 两种名称分别保存，图片共用；main en/tc 的接入另行处理 |
| 11.4-R11 | 只有查看权限的账号提交保存 | 服务端拒绝，内容不变 |
| 11.4-R12 | 保存后查询操作日志 | 存在对应 cms 操作及配置快照 |
| 11.4-R13 | 轮播达到六张、试图移除最后一张启用图片 | 第七张和零启用状态均被拒绝 |
| 11.4-R14 | 关闭快捷位二、三 | 接口结果按启用状态和固定顺序返回；不因活动关闭额外过滤，main 尚无对应布局 |
| 11.4-R15 | 运营商 A 开启、B 关闭同一活动 | 活动入口与 Promotions 按访问者运营商过滤，不暴露 B 的关闭活动 |
| 11.4-R16 | 卡片达到二十张、拖动或关闭其中一张 | 超限拒绝；顺序和开关立即保存，API 再次查询时更新 |
| 11.4-R17 | 新增活动入口，名称留空，跳转活动选择「每日挑战（Daily Challenge）」 | 英文名称填入 Daily Challenge，中文名称填入每日挑战；保存后列表的跳转活动显示「每日挑战（Daily Challenge）」 |
| 11.4-R18 | 接上一场景，把跳转活动改为「七日奖励（7-Day Rewards）」 | 两种名称随之改为 7-Day Rewards 和七日奖励 |
| 11.4-R19 | 英文名称已手动改为其他文字，中文名称仍是带入的名称，再更换跳转活动 | 英文名称保持手动输入的文字，中文名称改为新活动的后台名称 |
| 11.4-R20 | 依次打开轮播图、浮窗区、活动入口、Promotions 活动页的「跳转活动」下拉 | 四处的选项和顺序完全相同，最后一项都是「VIP 会员（VIP Club）」 |
| 11.4-R21 | 活动入口和 Promotions 活动页各保存一项跳转 VIP 会员，关闭 VIP 活动后查询玩家 API | 两处都不返回该项，重新开启后恢复返回；浮窗区和轮播图里跳转 VIP 会员的项不受影响 |
