# M11 · 内容管理

## 1. 定位与边界

**做什么**:维护站内通知、网站标题与分享信息，以及首页轮播、快捷位、活动入口和 Promotions 卡片配置。通知与 Metadata 已被玩家 main 消费，四区首页活动配置尚未接入。

**不做什么**
- 不做语言配置和界面文案翻译 —— 后台内容固定配置英文、简体中文两种语言，玩家 main 仍为 en/tc（D113）,固定文案随前端发版
- 不做推送、邮件、短信,也不做定时发布、草稿和已读统计 —— 通知保存后立即生效,玩家 main 首页重新查询后以轮播展示；当前没有已读状态或后台已读统计
- 不定义活动规则 —— 首页活动入口只是跳转,活动资格和奖励归 M4
- 不管理首页游戏内容 —— Hot Games 的游戏与供应商归 [M10 游戏管理](../M10-游戏管理/README.md)
- 不做后台账号、角色和权限配置 —— 归 M6

**铁律**
- **权限判定一律在服务端**。页面可能按权限禁用操作；无编辑权限的账号提交时仍由服务端拒绝
- **保存即生效**。本模块没有审批和发布步骤,玩家下一次加载页面就看到新内容
- **活动跳转从支持的活动目录选择**，不接受运营任填路径或外部链接

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 内容语言 | 后台内容固定填写英文 `en`、简体中文 `zh`，必填项两种都填；玩家 main 为 `en`/`tc`，通知及 Metadata 缺少 tc 时可取英文 |
| 全体通知 | 没有选择目标用户的通知 |
| 指定用户通知 | 选择了目标用户的通知 |
| 网站 Metadata | 全站一份的图片、标题和描述,用于页面标题和社交分享卡片 |
| 首页活动配置 | 轮播 1～6 张、四个固定快捷位、最多三个竖排入口、最多二十张 Promotions 卡片，详见 11.4 |
| 配置版本 | 所属区域配置每次保存加一的序号,用于发现两人同时修改 |

## 7. 决策清单

| # | 规则主题 | 涉及范围 | 执行结论 |
|---|---|---|---|
| D113 | 玩家端语言与多语言内容 | 11.2、11.3、11.4、M10、玩家语言切换 | **当前代码（2026-11-16）**：后台和内容校验固定 en/zh，后台无语言管理页；玩家 main 路由仍为 en/tc、默认 en，不能写成 tc 已删除。通知和 Metadata 缺少当前语言时会取英文，其他消费点以各组件为准。统一为 en/zh 是未完成的跨端接入，不能将后台保存成功等同于 tc 玩家看到中文。 |
| D131 | 谁可以切换玩家端语言 | 玩家语言切换、注册与游客创建、玩家资料接口 | 玩家端面向玩家只提供英文；后台用户可以把自己看到的玩家端切换为中文，供不读英文的运营核对页面。是否为后台用户由服务端判定，与登录后台使用同一条规则：账号持有角色且登录未被冻结。**当前代码**：切换语言的接口只接受后台用户，其他账号的请求被拒绝；玩家资料接口返回当前账号能否切换；注册和游客创建不再保存语言；非后台用户此前保存的中文已清除。玩家 main 的页面尚未按此限制语言，见[未落地需求](../未落地需求/README.md)。 |
| D132 | 活动的中英文名称 | 11.4、M4 各活动、玩家端活动页面 | 每个可跳转的活动只有一个后台名称（中文）和一个玩家端页面英文名称，对照表见 [11.4](11.4-首页活动配置/README.md)。后台名称与玩家端英文名称指向同一个活动，并按对照表维护；后台选择跳转活动时同时显示两个名称，并据此带入入口名称。玩家端各处统一使用同一份名称的要求见[未落地需求](../未落地需求/README.md)。 |
| D138 | 首页活动配置共用一份活动目录 | 11.4、4.6 | 轮播图、浮窗区、活动入口、Promotions 活动页四个页签的「跳转活动」从同一份活动目录选择，选项和顺序相同，VIP 会员在四处都可选。活动入口和 Promotions 活动页只返回活动开放的项；VIP 会员是否开放看 VIP 活动开关，全平台一个，不分运营商，关闭时这两处跳转 VIP 会员的项不返回。浮窗区和轮播图仍不按活动开关过滤。 |
