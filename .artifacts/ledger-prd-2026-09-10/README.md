# 账变记录网站采集与核对记录

采集日期：2026-09-10。页面：[开发后台账变记录](https://dev-app.bingox.io/admin/users/wallet)。对应归档文档：[2.2 账变记录](../../M2-用户管理/2.2-账变记录/README.md)。

本次通过用户已登录的浏览器查看实际页面，执行查询、类型选择、日期选择、分页和筛选区操作。没有充值、扣款、修改账本、修改权限或创建 Jira 任务。

## 页面观察

- 筛选：用户 ID、账变类型、币种、关联单据 ID、日期。没有独立渠道筛选。
- 结果共11列：序号、用户、账变时间、账变类型、币种、变动金额、变动前余额、变动后余额、标准计费 / 汇率、关联单据、备注。
- 三组金额均展示总额、本金、彩金、打码量。现场存在打码量为空而显示“—”的记录，也存在余额不变、仅调整打码量的记录。
- 类型下拉框包含“全部类型”及17个业务类型；每页条数选项为20、50、100。
- 用户和关联单据是文本，没有详情跳转；页面没有编辑、删除、补账、导出或批量操作入口。
- 浏览器时区为 Asia/Hong_Kong。页面时间显示与所选日期提交的UTC区间一致。

## 实际查询结果

请求为管理端 GraphQL 查询 `userWalletLedgers`。保留的[核对记录](checks.json)只包含请求条件摘要、条数、返回类型及核对结论；用户和单据标识已替换为说明文字，不包含登录凭据和完整玩家流水。

| 操作 | 观察结果 |
|---|---|
| 重置后查询 | 条件为空、offset为0、每页20条；现场总数2147，返回20条，时间降序 |
| 用户、币种、单据组合查询 | 返回1条，逐项符合填写条件 |
| 输入小写币种 | 输入框转为USDC，查询提交USDC |
| 输入不存在的关联单据 | 返回0条，页面显示“暂无数据”和调整筛选提示 |
| 输入关联单据中间一段 | 返回包含该片段的1条记录 |
| 查询2026-09-08一天 | 请求区间为UTC 2026-09-07 16:00:00.000至2026-09-08 15:59:59.999；总数32，本页20条均在区间内 |
| 下一页 | offset为20，每页20条 |
| 每页50条 | 回到offset 0，返回50条 |
| 恢复每页20条 | 回到offset 0，返回20条 |
| 查询打码量变动 | 共15条；一条样本余额变动为0，打码量由510减少500至10 |
| 收起筛选 | 输入区隐藏，查询按钮仍可见；随后恢复展开 |
| 最后恢复 | 清空所有条件，恢复第1页、每页20条，展开筛选 |

采集期间曾遇到网络请求失败，页面显示“账变记录加载失败”、错误说明及“重试”。后续请求恢复正常。没有通过故障注入验证所有错误分支。

## 源码补充核对

页面观察优先；匹配方式、相同时间的排序、换算展示分支等细节另与本地仓库的 `origin/main` 引用核对：前端为 `6913f02`，后端为 `cf381f4`。这些引用不单独作为部署版本证明。

- 前端 `bingo-saas-frontend`：`apps/web/src/components/tables/transactions-table/index.tsx`、`apps/web/src/lib/wallet-ledger-access.ts`、日期和金额格式化组件。用于核对本地日界、金额八位小数、换算标记及显示缺项处理。
- 后端 `bingo-backend`：`apps/admin-api/src/services/finance/wallet.service.ts` 中的 `pagingLedgers`。用户和币种为等值条件，关联单据为包含条件，日期包含起止时刻，排序为账变时间降序后按账本序号降序。
- 资金含义继续引用需求仓库的资金模型和标准计价文档，未重新设计底层资金规则。

页面没有渠道筛选，与模块原先概述的筛选范围存在差异。本次按网站现状更新2.2及模块导航，账号数据范围的公共权限约定保持原归属。
