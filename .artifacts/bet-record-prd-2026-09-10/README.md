# 投注明细网站采集与核对记录

采集日期：2026-09-10。页面：[开发后台投注明细](https://dev-app.bingox.io/admin/users/bet-record)。对应文档：[2.3 投注明细](../../M2-用户管理/2.3-投注明细/README.md)。

本次使用用户已登录的浏览器查看页面，并执行筛选、查询、分页、展开和收起筛选、打开和关闭局详情。操作只读取投注记录，没有下注、充值、修改派彩、修改权限或创建 Jira 任务。

## 页面观察

- 筛选共5类：会员账号、游戏、输赢结果、币种、投注时间。没有局号、用户ID、订单号或渠道的独立筛选框。
- 列表共11列：序号、局号、用户ID、会员账号、游戏厂商、游戏、投注金额、派彩金额、输赢、币种、投注时间。
- 游戏选项为 Dice、Crash、Limbo、Plinko、Roulette、Mines、Baccarat、Blackjack；输赢结果为全部、仅赢、高倍赢(≥4x)。
- 币种下拉现场包含 USDT、USD、USDC；列表中的币种值同时存在小写 `usdc`、`usdt` 和大写 `USD`。
- 点击局号打开“局详情 / 公平性”，共9项信息；现场有5个复制按钮，clientSeed 和 serverSeed 均显示 `[REDACTED]`。关闭后原列表和条件保持。
- 金额显示八位小数；实测当前页每条记录的“输赢”均等于派彩减投注。
- 页面没有导出、资金修改、重新结算、批量处理或公平性计算入口；用户ID和会员账号没有详情链接。

## 实际查询与操作

管理端 GraphQL 查询名为 `betRecords`。保留的[核对数据](checks.json)只包含条件摘要、条数、公开字段名称和判断结果，账号片段已替换为说明文字；不包含用户ID、局号、明文种子、完整流水或登录凭据。

| 操作 | 观察结果 |
|---|---|
| 清空条件 | 第1页、每页20条，现场总数1743；最近一页的币种为小写 `usdc` |
| 仅赢，每页100条 | 共353条，返回100条，所取样本的派彩倍数均大于0 |
| Plinko + 仅赢 | 共24条，本页20条中8条净亏损；样本投注2、派彩1.4、派彩倍数0.7 |

| Dice + 高倍赢 | 共129条，本页20条的派彩倍数均为9.9，符合至少4倍的条件 |
| USDC | 请求中的币种为大写 `USDC`，返回0条；存在漏查，详见下文 |

| 再限定2026-09-08一天 | 共21条；请求中的账号片段已去除首尾空格，本页20条均符合账号、游戏和日期条件 |
| 日期范围 | 浏览器时区为 Asia/Hong_Kong；当天范围提交为 UTC 2026-09-07 16:00:00.000 至 2026-09-08 15:59:59.999 |
| 下一页 | offset为20、limit为20，页面首行序号为21 |
| 改为每页50条 | 回到offset 0，显示50条；查询条件保持 |
| 每页100条后应用不同游戏条件 | 回到offset 0、每页20条 |
| 每页50条后以相同条件查询 | 保留每页50条，显示第1页 |

## 查询缺陷与口径说明

### 币种大小写不一致导致 USDC 漏查

复现步骤：

1. 清空筛选条件，列表中可以看到币种为 `usdc` 的投注记录。
2. 只将币种切换为 USDC，点击查询。请求提交 `currency: "USDC"`，返回0条，页面显示“暂无投注记录”。
3. 清空币种条件后，这些 `usdc` 记录重新出现；选择 USD 则能查到记录值为 `USD` 的14条数据。

前端直接提交币种配置中的代码，后端按记录币种精确匹配，两处均没有做大小写归一化。这与现场出现的大小写不一致和漏查现象一致。修复应确保同一种币种的筛选值与记录值一致，不将这次漏查定义为正常业务规则。

本次没有修改网站代码或历史数据。PRD中的币种验收项不能据此认定已通过全部币种场景。

### “仅赢”包含净亏损记录的含义

本页按玩法保存的派彩倍数筛选“仅赢”，按派彩减投注展示“输赢”。两者使用不同口径，现场已复现有派彩但净亏损的 Plinko 记录。

本次按现有行为写明含义，没有自行改成“净盈利”筛选，也没有增加新的筛选选项。

## 核对范围

本次用于补写网站功能记录，不作为完整后端验收结论。实际操作覆盖查询组合、分页、筛选区、详情开关和空结果；单边日期、历史字段缺失、请求失败及重试由源码补充核对，没有逐一构造对应现场场景。

现场确认了复制按钮及展示值，没有读取剪贴板验证复制成功，也没有验证浏览器禁止剪贴板时的行为。没有据种子字段的展示宣称已经验证游戏公平性。

采集使用已登录账号，没有运行无权限账号或跨渠道数据隔离测试。PRD引用的 `user:bet:view` 表示既有权限归属，不表示本次已经证明相关鉴权全部生效。

没有验证每一种玩法、投注结算准确性、资金入账或打码核销。第三方厂商记录覆盖也不在本次结论中；已观察的样本由当前内部玩法提供。
