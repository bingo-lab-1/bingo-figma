# 用户列表网站采集与核对记录

采集日期：2026-09-11。页面为[会员列表](https://dev-app.bingox.io/admin/users/list)，使用用户已登录的浏览器。本次配合[用户列表 PRD](../../M2-用户管理/2.1-用户列表/README.md)归档当前页面。

本次浏览器实际时区为 Australia/Sydney，后台选项显示“GMT+11(澳洲)”。默认日期请求实际按当地当时的 UTC+10 转换；显示名称中的固定 GMT 文案不作为日期偏移计算依据。前一轮用户详情核对时的时区记录不适用于本次采集。

执行范围为页面导航、真实查询、翻页、条件切换、查看表单与空原因校验，并在本浏览器页暂时阻断一次列表查询来验证失败与重试。没有保存测试账号标识，没有修改会员资料或资金，没有执行充值提现或历史汇总重算。用户标签的独立 E2E 另行归档。

[核对数据](checks.json)只保留字段名称、脱敏条件、请求条数、结果数量及观察结论。会员 ID、账号、手机号、标签 ID 等已替换，不保存完整会员数据、登录凭据、IP 或原始截图。下述条数仅代表采集当时的数据。

## 已发现的实现差异

### 时间的“不限”选项不能切换

1. 从默认的注册时间范围打开时间下拉。
2. 点击“不限”。
3. 控件仍显示“注册时间”和原日期范围，没有切换为不限。
4. 通过明确指定不限时间的分享链接打开时，请求不带时间条件，可以查询。

所读前端的时间选择回调仅在值为真时更新，“不限”使用空字符串，因而被忽略。这个源码原因与现场表现一致。PRD 保留选项及查询含义，不将切换失败定义为正常操作。

### 会员 ID 入口

会员 ID 作为详情入口是用户已确认的要求。前一轮[用户详情核对](../user-detail-prd-2026-09-11/README.md)已确认 ID 点击不打开、同行“详情”可用。本次列表挂载源码仍将 ID 直接展示，没有点击处理。主 PRD 保留这一入口要求及差异，不宣称当前入口已验收通过。

### 金额范围与空结果

充值金额上下限颠倒时，网站没有指出输入问题，直接查询并返回空结果。当前源码也没有为负值、非法 IP 或大于总页数的页码提供完整的查询前校验；没有在本次把这些未逐项构造的输入均称为已现场复现。

### 查询条件同步

现场复现如下：

1. 按一个完整会员 ID 查询，返回 1 人。
2. 改为不存在的 ID 并查询，返回 0 人。
3. 浏览器后退，链接恢复第一个 ID，实际请求也恢复第一个条件并返回 1 人。
4. 输入框仍保留第二个、不存在的 ID，没有随结果恢复。

顶栏在线人数快捷入口存在同类问题：请求已变为在线且不限时间，表单仍显示旧的注册日期范围。源码中已应用条件随链接变化，但输入状态只在首次打开和重置时赋值，与现场现象一致。

### 错误与重试的验证范围

仅在当前浏览器页临时阻断 `usersPaging` 请求，不改变服务器或其他页面。网站显示明确错误与重试；解除阻断后点击重试，服务返回正常空结果，错误消失。该项证明模拟网络失败时的页面分支，不代表服务端超时、权限拒绝和所有异常均已验证。阻断规则已移除，页面恢复默认查询。

## 汇总与服务端行为的源码依据

列表直接展示资金服务保存的充值、提现金额和次数。主要写入链路已补查，范围如下：

- 人工加款勾选“计入充值”时，写充值到账类型并增加充值汇总；不勾选时不增加该汇总。
- Crypto 入金完成入账后增加充值次数和可用的 USD 金额；链重组撤销时可减回对应次数与金额。
- 已核对的 Crypto 提币在链上执行成功、确认数和转账核对通过后结算，增加提现汇总。金额取钱包扣款额，而非链上净到账额。未据此承诺所有历史渠道都采用同一计入时点。
- 上述链路使用 USD 标准换算；缺汇率时可先增加次数、金额稍后补算。补算只补金额，不重复增加次数。列表没有汇总完整性或待补算标识。
- 是否充值、金额上下限使用资金汇总；首充/最后存款时间使用充值到账类账变。不能将时间筛选误解为按期间重算累计金额。

没有执行真实充值、提现、人工加款或全量对账，不证明所有历史汇总已完整、准确换算。当前实现与[标准计价](../../M2-用户管理/2.1-用户列表/标准计价.md)中更严格的换算、补算规则分别记录，不凭页面加了 USD 后缀判定其全部满足。

### 权限、隐私与设置测试账号

所读列表服务没有接收操作人进行渠道范围过滤；设置测试账号的调用链也未见细分操作权限或渠道范围校验。本次仅用已有管理会话操作，没有使用低权限或跨渠道会话，不构成越权复现或完整权限审计。

当前列表直接展示返回的账号资料，没有单独的脱敏解锁按钮。本次不保存真实会员资料，也未验证其他账号权限下的展示范围。

设置测试账号的服务会检查用户存在及原因去空格后非空；仅标识真正改变时记录操作人、原因和前后值。标识修改与日志写入分步执行，没有包在同一事务中，不能承诺任何错误都意味着标识未改变。这个结论来自源码，本次没有执行真实标识修改或构造日志故障。
