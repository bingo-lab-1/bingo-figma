## 封禁列表

### 网站实际观察

- 页面提供用户ID、会员账号、用户昵称、状态、封禁时间共5类筛选。
- 状态选项为全部、封禁中、已解封。初始文本和日期为空，状态为全部。
- 现场列表没有记录，显示“暂无数据”和“调整筛选条件后再试。”，没有表头和分页栏。因此，13列与有记录时的行操作由源码补充核对，未宣称现场逐行验证。
- 点击“封禁用户”打开表单，包含用户ID、封禁限制、到期时间、踢出当前登录和封禁原因。
- 限制可多选资金冻结、游戏冻结、登录冻结；默认只选择登录冻结，“踢出当前登录”默认开启，到期时间留空表示永久。

### 已确认的错误处理缺陷

日期范围无效时，错误提示与列表内容不同步：

1. 清空日期，选择总输赢榜，页面成功展示2名玩家。
2. 将开始日期设为2026-09-10、结束日期设为2026-09-09并查询。请求的起点与结束排除边界相等，服务返回日期范围错误。
3. 页面弹出“统计日期结束时间必须晚于开始时间（同日应为 [当日00:00, 次日00:00)）”。
4. 上一次成功查询的2行仍原样显示，没有出现“重试”按钮；这些行不是新日期条件的查询结果。
5. 清空错误日期并重新查询，可以恢复正常结果。

前端全局错误处理会弹出服务消息；排行榜的查询函数等待请求时没有捕获拒绝的异常，后续清空列表及显示重试的分支没有在该场景执行。源码与现场表现一致。PRD已记录该限制，没有将旧结果保留作为正常业务要求。

本次没有修改网站实现，也没有创建缺陷 Jira 任务。

### 指标说明与实现限制

以下口径由源码补充核对；现场验证了字段、精度、排序及查询范围，没有逐笔核对底层账务：

- 表头中的“当日”和“总”均受所选期间限制；充值、提现、赠送、佣金和投注按对应账变时间统计，总输赢按投注结算时间统计。
- 充值金额包含按充值入账的人工加款。赠送金额只统计“彩金发放”，不包含VIP奖励、普通人工加款、佣金或游戏派彩；不得理解为全部奖励总额。
- 充值、提现、赠送、佣金、投注金额与次数只纳入已完成标准折算的对应资金记录。次数按纳入的记录计数，不按业务订单去重。
- 提现、投注统计各自扣款，不以最终成功订单或有效投注替代；相应退款、投注取消返还不从扣款列中扣回。
- 总输赢按已结算投注汇总；缺失的投注或派彩标准金额按0参与计算，而结算记录仍可让玩家入榜。这可能导致折算不全时净输赢不完整，不是“全部折算齐全才显示用户”。
- 用户资料、余额和邀请人数取当前值。余额按当前汇率折算，缺少汇率的钱包被跳过，不能把显示值视为已验证完整的资产总额。
- 页面没有标明USD单位，且表头未随统计范围调整，存在阅读歧义；本次在PRD中明确解释，没有自行更改网站表头。
- 最近在线时间为空时，源码没有专门兜底，可能出现 `Invalid Date`；本次有数据的样本均有时间，未现场复现此问题。
