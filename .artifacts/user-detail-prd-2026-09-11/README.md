本次查询会员、切换标签、筛选翻页、查看编辑表单与修改历史，并在查看后取消。没有执行资料保存、密码修改、封禁解封、余额调整、打码增删、收款账号保存或平台余额转回。正文的保存结果是功能契约与源码行为，不代表已通过写入端到端测试。

### 编辑表单与修改记录

- 已逐一打开会员账号、显示用户名、手机号、VIP、备注和密码修改表单。页面提供修改内容与“修改记录”两个标签；密码可选登录密码或取款密码。

- 正常会员的账号状态修改打开预填会员 ID 的封禁表单，提供资金冻结、游戏冻结、登录冻结、到期时间、踢出当前登录与原因。本次没有已封禁会员的解封实测；解封逻辑沿用已核对的封禁模块源码。
- 新增打码量、清除任务、修改余额、新增法币账号、新增及修改虚拟币账号均已查看并取消。法币账号实际挂载的是新增/编辑表单，未将未挂载的旧账号弹窗及其历史标签写入 PRD。
- 表单必填、账号格式、密码长度与一致性、原因要求等由页面和源码确认。本次没有逐项提交所有非法输入，也没有用保存成功来验证后台资金、操作日志或活动影响。

## 与网页实现的差异和限制

这些是核对结论，不是产品配置项或可选择方案；不把错误表现写成正常资金规则。

| 项目 | 证据与影响 |
|---|---|
| 会员 ID 入口未生效 | 网页点击未打开，列表源码中的 ID 为普通内容；同行“详情”可用。PRD 按用户要求保留两个入口打开同一弹窗的验收场景，ID 入口尚未通过该场景 |
| 主资料无结果时没有明确结束态 | 挂载组件在主资料不存在时仍显示加载占位，没有独立的“会员不存在”或查询错误结果分支。由源码确认，未对真实用户构造删除、权限拒绝或网络错误 |
| 部分分页控件没有完成分页 | 打码任务、第三方钱包、虚拟币账号、提现账号的挂载实现中存在全部数组直接交给列表、未切片或页码固定的情况；显示条数选择不证明数据真的翻页。本次记录数不足以逐一复现大于一页的异常。充值、提款、资产变动与登录设备使用各自查询分页，不能一概视作同一问题 |
| 顶部打码量跨币种求和 | 源码直接汇总各钱包剩余打码量，没有折成 USD；该数值不能解释为标准币总额。分币种标签用于查看各币种剩余量 |
| 顶部提现提示范围有限 | “全部币种可提现”仅依据剩余打码量是否大于 0，空数据或加载阶段也可能落入这一分支。它没有覆盖钱包状态、资金冻结及其他提现限制，不能当作最终提现许可 |
| 查询错误处理不一致 | 虚拟币账号等挂载查询没有将错误完整传入列表；风控数量明细缺少独立查询错误分支；主资料异常见上项。不能承诺每个标签失败都会出现局部重试 |
| 打码操作成功与刷新失败可能混淆 | 新增可提示“数据刷新失败”；清除将写入和后续刷新放在同一错误处理内，可能在清除成功、刷新失败后提示“清除失败”。遇到结果不明应先查询任务与记录，不能据提示重复执行 |
| 金额与日期显示未统一 | 钱包和流水多使用八位小数；部分概览字段直接显示返回值。流水等使用浏览器本地时间，部分概览及风控使用后台所选时区。现场两时区相同，没有据此证明改变时区后所有区域同步 |
| 账号地址校验有限 | 虚拟币表单校验必填及去空格，没有完整地址格式校验；链为固定选项，历史记录可能包含其他链值。本次没有提交地址或验证链上归属 |

### 当前余额表单与通用资金规范

当前表单及所读后端允许加款倍数缺省为 0、备注为空；大于 0 时创建打码任务，0 倍不创建任务。加款与扣款都调整本金构成。扣款接口拒绝正倍数及“计入充值”为真；共用资金写入函数检查钱包、构成非负和版本，但本次所读调用链没有完整的可用余额、冻结及提现资格校验。

这与[资金模型 R8](../../M2-用户管理/2.1-用户列表/资金模型.md)原有的倍数不得缺省、0 倍须免打码权限与原因并创建已完成任务等约束有差异。新增打码量页面也只有表单提交，没有资金模型 R17 描述的另一层二次确认。此次依据用户认可的网页完善详情功能，不据此改写整个资金模型的 R6–R17 算法；这些接口不能直接宣称通过通用资金规则验收。

“计入充值”为真会更新充值统计并触发相关身份处理；不代表建立正常充值订单，也不证明所有活动都会将该笔人工加款计入资格。既有列表中“不含人工上分”的统计口径不能直接套用于这个选项；本次没有重做列表聚合或活动链路验收。

### 写入权限与服务端校验边界

对现有写表单的 resolver、service 及关联输入模型进行只读核对。在余额调整、打码新增/清除、资料与密码修改、封禁/解封这些已读调用链中，使用登录会话记录操作人，但未见对应细分业务权限、渠道范围或免打码授权的显式检查。后台注册了认证模块，不能据此声称没有登录认证。

此外，已读服务没有完整复现页面校验：多种原因参数虽为必传字符串，却没有非空白检查；VIP、备注使用的资料更新接口允许原因缺省，并在缺原因时跳过对应修改日志；密码服务校验非空白和两次一致，但没有页面“至少 6 位”的校验。账号格式、标准化和唯一性另有服务端检查。

封禁状态版本校验仅覆盖会员账号、显示用户名、手机号、VIP、备注；不能扩展为密码、余额或全部资料字段的并发保护。取款密码重置更新设置时间、清零错误次数与锁定时间，由服务源码确认，未执行真实重置。

风控标签的 `system:risk:view` 是已读前端检查，本次没有审查该查询完整的后端授权链。没有使用低权限账号或跨渠道账号发送写请求，上述结论不代表全站权限审计，也不代表越权漏洞已经复现。
