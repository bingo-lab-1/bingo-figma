# M2 · 点控策略与执行记录需求草案

## 1. 用途

运营为一条点控规则选择一个已有复合标签，再添加多个触发项。每个触发项分别设置什么时候开始养、养多少，以及多少把内完成。

“养”指用户在本次点控期间净赢指定金额。净赢等于本次统计范围内的实际返奖减去实际投注。例如，投注合计 100 USD、返奖合计 120 USD，净赢就是 20 USD。

本稿整理已确认的需求和表单，供运营、设计和开发讨论。文末列出需要补齐的执行规则；补齐前，本稿不作为完整的开发验收依据。

| 项目 | 规则 |
|---|---|
| 适用游戏 | 默认适用于第三方供应商提供的 Slot，不包含自研 Originals |
| 执行币种 | 使用用户当前默认选中的币种，运营不手动选择执行币种 |
| 切换币种 | 重置当前点控，历史记录保留 |
| 每日统计 | 沿用平台现有统计日口径，点控表单不增加业务时区设置 |
| 用户分层 | 直接选择用户标签模块已有复合标签，不在点控表单中重新编辑标签条件 |

## 2. 配置项

表单分为“全局设置、点控规则、触发项”三层。以下数字都是示例，不是默认值；金额示例使用 USD。

### 全局设置

| 字段 | 控件与示例 | 填写说明 |
|---|---|---|
| 最低参与余额 | 金额框：`1.00 USD` | 全局统一设置，所有点控规则共用；必填，不允许负数 |

### 点控规则

| 字段 | 控件与示例 | 填写说明 |
|---|---|---|
| 规则名称 | 文本框：`首充用户养规则` | 必填，用于识别规则 |
| 规则启用 | 开关：`开启 / 关闭` | 控制整条规则是否接受新的点控任务 |
| 用户复合标签 | 搜索下拉框：`请选择复合标签` | 必选，一个规则关联一个已有复合标签 |
| 触发项列表 | 多张触发项卡片 | 至少添加一个触发项；点击“添加触发项”继续添加 |

分层名称、分层开关、匹配条件和匹配顺序都不出现在本表单中。标签的条件和启停由用户标签模块维护。

### 每个触发项

每张触发项卡片都有“何时触发、养多少、多少局内完成”三个区域。“执行限制”是“何时触发”的子项。

| 区域 | 字段 | 控件与示例 | 填写说明 |
|---|---|---|---|
| 何时触发 | 触发事件 | 下拉框：`上线 / 当日第1次充值 / 当日第2次充值 / 当日第3次及以上充值 / 盈利 / 亏损` | 必选，每个触发项选择一个事件 |
| 何时触发 | 盈亏启动门槛 | 数值框：`50`，单位：`%` | 仅盈利、亏损事件显示；注明“当日净盈利／净亏损达到当日充值金额的 __%”；填写正数 |
| 何时触发 · 执行限制 | 每用户每日执行上限 | 数值框：`1`，或选择`不限` | 当前触发项独立计数；选择次数限制时填写正整数 |
| 何时触发 · 执行限制 | 投注／充值最大倍数 | 数值框：`10`，单位：`倍` | 仅适用该限制的触发项显示；填写正数 |
| 养多少 | 目标计算方式 | 下拉框：`固定金额 / 随机金额区间 / 比例` | 必选，选择后只显示对应的目标输入项 |
| 养多少 | 固定净赢金额 | 金额框：`100.00 USD` | 选择固定金额时必填；金额必须大于零 |
| 养多少 | 随机净赢金额区间 | 两个金额框：`80.00` 至 `100.00 USD` | 选择随机金额区间时必填；两端都大于零，下限不能大于上限 |
| 养多少 | 目标比例 | 数值框：`20`，单位：`%` | 选择比例时必填；填写正数 |
| 养多少 | 比例计算基数 | 只读说明，例如：`当日充值金额` | 选择比例时展示，明确百分比乘以什么；运营不手动填写 |
| 多少局内完成 | 达成局数区间 | 两个整数框：`3` 至 `5`，单位：`局` | 必填；两端都为正整数，下限不能大于上限 |

盈亏启动门槛决定什么时候开始养，目标净赢决定开始后养多少。两者分别填写，不使用同一个数值。

目标金额区间的两端相同，就使用这个金额。达成局数区间的两端相同，就使用这个局数。局数区间用于抽取计划局数，不表示用户必须至少玩到区间下限。

每张卡片提供“删除此触发项”按钮。规则表单提供“添加触发项”和“保存规则”按钮。

### 一条规则的填写示例

规则名称为“首充用户养规则”，选择已有的“首充用户”复合标签，添加以下触发项。

| 触发项 | 何时触发 | 执行限制 | 养多少 | 多少局内完成 |
|---|---|---|---|---|
| 触发项1 | 当日第1次充值 | 每用户每日1次 | 固定净赢100 USD | 3–5局 |
| 触发项2 | 当日净亏损达到当日充值的50% | 每用户每日2次 | 随机净赢80–100 USD | 4–6局 |
| 触发项3 | 上线 | 每用户每日1次 | 当日充值金额的20%，本例以此为计算基数 | 3–5局 |

### 执行记录

以下内容由系统生成，运营只读查看。

| 内容 | 说明 |
|---|---|
| 用户、规则、复合标签、触发项 | 说明本次点控针对谁、为什么开始 |
| 执行币种 | 记录本次任务实际使用的币种 |
| 目标净赢、计划局数 | 记录本次确定的 X 和 N；比例目标同时记录基数金额和比例 |
| 实际投注、实际返奖、实际净赢、已完成局数 | 记录本次执行进度和实际结果 |
| 任务状态、结束原因、开始时间、结束时间 | 说明任务是否完成，以及为什么结束 |

## 3. 操作规则

### 配置规则

运营先设置全局最低参与余额，再创建点控规则、选择复合标签，并逐个添加触发项。每个触发项的门槛、限制、目标和局数分别保存，不互相覆盖。

点击“保存规则”时检查必填项和数字范围。输入有误时说明具体字段，不保存错误配置。关闭规则后，该规则不再接受新任务。

点控读取用户标签模块提供的标签命中结果，不另建一套标签条件。标签继续按自身规则判断人群，点控执行币种不会改变标签现有的 USD 标准计价口径。

### 开始养

用户命中所选复合标签、满足触发条件，并通过全局最低余额及该触发项的执行限制后，才可开始本次点控。

任务开始时确定执行币种、目标净赢 X 和计划局数 N。固定金额直接使用填写值；随机金额从配置区间中取值；比例目标用确定的基数金额乘以填写比例。N 从达成局数区间中取值。

X 和 N 确定后保存到执行记录。同一任务重试或恢复时继续使用原值，不重新抽取。

### 在多局内完成

开发将一次养拆成多个游戏局执行，要求在 N 局内达成净赢 X。具体游戏局怎样划分由开发实现。

例如，用户当日充值 100 USD，亏损达到 50 USD，满足 50% 的启动门槛。本次随机确定 X 为 92 USD、N 为 4，需求就是从本次点控开始计算，在 4 局内净赢 92 USD。之前亏损的 50 USD 不是本次净赢目标。

Originals 的局数和输赢不计入本次点控。完成结果以实际游戏结算为准，不能把供应商接收控制请求当作用户已经净赢。

### 切换币种

用户切换币种后重置当前点控，新币种的任务不沿用旧币种的目标和进度。旧任务记录保留，记录“切换币种重置”原因。切回原币种也不继续旧任务。

## 4. 特殊情况

| 情况 | 处理结果 |
|---|---|
| 用户未命中所选复合标签 | 不按该规则开始点控 |
| 用户余额低于全局最低参与余额 | 不开始新的点控任务 |
| 当前触发项已达到每日执行上限 | 不再通过该触发项开始新任务；其他触发项按各自限制判断 |
| 金额、比例为负数，或局数不是正整数 | 拒绝保存，指出错误字段；固定目标和比例目标也不接受零 |
| 区间下限大于上限 | 拒绝保存，提示修改区间 |
| 用户进入 Originals | 不对该游戏执行本规则，也不把其局数和输赢加入当前进度 |
| 读取标签或必要数据失败 | 不把失败当作满足条件，保留异常原因 |
| 执行失败或结果还不明确 | 记录实际状态和原因，不展示为已完成 |

## 5. 验收场景

本表用于核对已经确认的需求，编号只用于本稿内追踪，不占用正式页面编号。

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 点控-R1 | 为两条规则设置不同目标，查看最低参与余额 | 两条规则共用同一个全局最低余额，不出现规则级最低余额字段 |
| 点控-R2 | 创建规则并选择一个已有复合标签 | 可以选择并保存；表单没有分层开关、标签条件编辑和匹配顺序 |
| 点控-R3 | 同一规则添加上线和充值两个触发项，分别设置限制和目标 | 保存后两项各自保留，不互相覆盖；执行限制位于对应触发项内 |
| 点控-R4 | 切换固定金额、随机金额区间和比例 | 只显示对应输入项；比例方式同时展示计算基数 |
| 点控-R5 | 当日充值100 USD，亏损启动门槛50%，分别模拟亏损49 USD和50 USD | 49 USD未达到该门槛，50 USD达到；该门槛不改变另行填写的养客目标 |
| 点控-R6 | 配置固定净赢100 USD、随机净赢80–100 USD | 固定方式使用100 USD；随机方式的目标落在80–100 USD区间内 |
| 点控-R7 | 配置3–5局，并恢复同一个已开始的任务 | N为3、4或5；恢复时X和N保持原值 |
| 点控-R8 | 输入反向区间、零局数或负目标金额 | 拒绝保存，说明错误字段，原配置不变 |
| 点控-R9 | 用户满足标签和事件，但余额不足或当前触发项次数已用完 | 不通过该触发项开始新任务 |
| 点控-R10 | 本次统计范围内投注100 USD、返奖120 USD | 实际净赢显示20 USD |
| 点控-R11 | 用户玩第三方Slot，再玩Originals | Originals不被控制，其局数和输赢不计入本次点控进度 |
| 点控-R12 | 用户在点控期间切换币种，再切回原币种 | 当前点控重置；新任务不继承旧进度，旧任务记录保留且不恢复 |

| 事项 | 需要明确的内容 |

| 修改、停用和重置 | 规则或标签变化怎样影响已经开始的任务；币种切换时旧局的后续结算及每日执行次数怎样处理 |
