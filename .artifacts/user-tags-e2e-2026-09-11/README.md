## 确认的缺陷

### TAG-E2E-01 · 新建失败仍落库，并默认启用

1. 点击“添加标签”，填写独立名称及净输赢 ≤ -500，试算确认 1 人。
2. 点击保存，响应为 `Internal server error`。
3. 取消弹窗并按名称查询：新标签已经存在，启用且待重算。

PRD 要求新建默认关闭，并清楚告知保存结果。当前失败结果没有反映已发生的写入，用户重试还会撞上重名。不能据此推断具体服务异常根因。

### TAG-E2E-02 · 启用失败仍改变状态，且启停缺二次确认

1. 停用自己的标签后再次点击启用。
2. 响应报错、界面显示“状态更新失败”，列表保留停用状态。
3. 刷新后变为待重算且已启用，命中仍为 0。

停用可以成功，但两个方向都直接发送请求，未出现 R4 要求的二次确认。本次因此无法完成“启用后建立命中 → 停用摘标 → 重启重建”的正向链路。

### TAG-E2E-03 · 条件编辑器未实现现行组合和属性规则

- 页面明确写“所有条件之间均为并且”，没有 AND / OR、指标时间范围或最近 N 天输入。
- 没有“基础指标 / 属性”分类；没有“已绑定手机”条件。VIP 等级用数字输入，而不是现有等级选择。
- 渠道来源只有 `=` / `≠` 及单选渠道，无法表达 PRD 的属于 / 不属于和同条件多渠道。
- 仍开放账户余额、待完成流水、距上次登录小时数、是否测试用户、下级 ID 数量、打码倍数等现行清单未开放的条件。
- 线上确实有净输赢、登录次数、登录天数、VIP 等级和六个比较符；净输赢负数也能试算成功，**这些不列为缺失**。

上述是界面及部署定义的差异，不代表后端完全没有新模型能力。

### TAG-E2E-04 · 指标右值没有按 PRD 白名单收窄

在新建表单选择“提现次数 = 基础标签 · 投注次数”，页面可选、`previewTag` 成功，返回 5 人。条件模型规定提现次数右侧仅允许常量，因此同单位组放行不满足 A12。测试未保存此规则。

条件模型自身还存在“投注次数 > 充值次数”示例与“其余指标右值仅常量”的冲突；本次没有用这一矛盾例子判定产品缺陷。

### TAG-E2E-05 · 试算失败无提示，修改条件后旧结果仍可见

- 充值金额输入 -1 或 0.001，点击试算；后端均拒绝：“金额必须是非负数且最多两位小数”，表单没有新增错误提示。
- 先试算净输赢 ≤ -500 得到 1 人，再改为 ≥ 999999999999；原“预计命中 1 人”继续显示，没有条件已变化或需要重新试算的说明。
- 重名保存被服务端拒绝“标签名称已存在”，页面仅显示“创建失败”，未呈现 PRD 指定的重名原因。

### TAG-E2E-06 · 互斥组合没有保存前警示

对自己的停用标签配置“净输赢 ≥ 999999999999 且 净输赢 < 0”。点击保存直接成功；保存前后均没有“条件互相排斥，人群将为空”的警示。PRD 要求警示但不阻断，而非禁止保存。

### TAG-E2E-07 · 界面删除入口无响应

点击自己的停用、零命中测试标签“删除”，没有 `tagDeleteImpact` 请求、确认框或提示。通过同会话真实查询调用引用预检、再调用删除接口可以成功，说明本次清理完成不等于 R5 的界面流程通过。

### TAG-E2E-08 · 列表与流水查询信息缺项

- 标签列表实际筛选为标签名、分组、状态、基础标签；缺更新时间条件。
- 实际列为标签名、组成、分组、命中人数、状态、更新人、更新时间、操作；缺最近重算时间。从未重算的测试标签显示“未开启”，并非 PRD 的“未成熟”；已停用行没有停用时间。
- 打开既有标签非空流水，读取到 10 条记录，列为用户 ID、方向、触发原因、判定值快照、时间；只有每页条数，无玩家或时间筛选。
- 页面时间没有就地时区标注。顶部的运营时区与流水判定快照中的业务时区应区分解释。

## 已验证的可用能力

- 标签名查询会去除首尾空格；状态和基础标签筛选传给后端并正确返回自己的标签。
- 默认请求 `limit=50`；切换“20 条”后请求 `limit=20`，返回原有 7 条。数据不足一页，未验证跨页排序稳定性。
- 单条条件不能删除；增加到 10 条后按钮禁用。同会话直接试算 11 条条件，服务端拒绝“标签必须包含 1 到 10 个基础标签”。
- 界面名称最长 20 字、备注最长 200 字；重名保存被服务端拒绝。后台超长名称和备注边界未单独验证。
- 非负金额及两位小数限制由真实试算接口校验；净输赢 ≤ -500 能成功试算。
- 自己的停用标签可以编辑保存、增加条件并更新版本；过期版本提交被后端拒绝。
- 点击自己标签的“0 人”会跳到会员列表、携带对应标签 ID，并显示空结果。这只证明零命中跳转，不证明成功重算后的非空筛选。
- 既有非空流水能显示进出方向、原因、判定值和时间；读取到部分新快照含组合、条件、版本与判定时区，也有旧数组快照。未因这些旧历史的存在宣称本次自动打标链路通过。

以下问题来自验收文档内部，分别影响规则解释、配置范围或处理顺序，单独记录为文档问题。

| 问题 | 具体冲突与本次处理 |
|---|---|
| 可比白名单与示例不一致 | 条件模型第 5 段只开放充值金额、充值次数作为指标间比较的左项，其余左项仅常量；同文多处示例却允许投注次数或投注金额作左项。本次用没有这种示例冲突的“提现次数 = 投注次数”验证白名单 |

| 摘标保护的流程图顺序相反 | 正文与 E6 要求超过阈值先暂停、不得批量摘除，流程图却先摘标并写流水再判断比例。本次未制造批量摘标，不能据任一图文顺序宣称系统保护已通过 |
| 重算期间的规则没有统一执行结论 | R6 的一段文字把新旧规则选择交给开发决定，后面的异常表又规定按本轮开始快照跑完、修改下一轮生效。相关正文须统一后才可用于这条边界的确定验收；本次启用错误已阻断自己的正向重算链路 |
