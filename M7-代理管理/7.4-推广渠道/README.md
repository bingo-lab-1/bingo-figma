# 7.4 · 推广渠道

## 1. 用途

运营在这里维护推广商和推广渠道，取得带渠道参数的推广链接。玩家打开链接注册后归属到对应渠道，渠道与推广商再被会员查询、账号数据范围、活动定向和同期群分析引用。网站中渠道独立成“推广渠道”一级菜单，不在“代理管理”分组下。

投放网站的渠道有两条链接：H5 推广链接直接进入游戏；PWA 链接先进入安装页，玩家可以把游戏安装到手机桌面，也可以直接在网页玩，规则见[安装到桌面](../../玩家端/安装到桌面/README.md)。运营在渠道行查看每天的安装统计。

投放合作方 App 的渠道只有一条 APP 链接，交给合作方配置为 App 打开的首页地址。合作方 App（俗称马甲包、上架包）是合作方开发并上架的安卓或 iOS App，App 内用网页打开本网站，并装有 Adjust 或 AppsFlyer 的统计工具；投放的是 App 的广告，安装来自哪条广告由 Adjust 或 AppsFlyer 判断。网站在 App 内的表现见[合作方 App](../../玩家端/合作方App/README.md)。

运营还可以为渠道配置广告回传。投放方在广告平台投放时，要让广告平台知道哪些广告带来了注册、首充和多少充值，才能按这些结果优化投放：按充值金额出价需要每笔充值的金额，按新增付费玩家优化需要单独的首充事件。每个渠道选一个投放平台：投放网站的渠道选 Facebook 或 TikTok，事件回传到渠道配置的像素，两个平台的配置项、事件和记录相同（见模块决策 D155）；投放合作方 App 的渠道（下称 App 渠道）选该 App 使用的 Adjust 或 AppsFlyer，事件由服务端直接发给 Adjust 或 AppsFlyer，再由它们转给 Meta、TikTok、Google 等广告平台（见模块决策 D153）。渠道开启回传后，玩家正式注册、每笔充值入账时，系统把事件回传到该渠道的投放平台，运营可以查看每一次回传的结果。回传三种事件，所有渠道相同，各平台使用自己的事件：

| 事件 | 回传记录中显示 | Facebook、TikTok | Adjust | AppsFlyer |
|---|---|---|---|---|
| 正式注册 | 完成注册 | 标准事件 CompleteRegistration | 完成注册的事件识别码 | 标准事件 af_complete_registration |
| 账号首充 | 订阅，App 渠道为首充 | 标准事件 Subscribe | 首充的事件识别码 | 标准事件 af_subscribe |
| 每笔充值 | 购物，App 渠道为充值 | 标准事件 Purchase | 充值的事件识别码 | 标准事件 af_purchase |

首充和每笔充值都带这笔充值的美元金额。首充也是一笔充值，所以首充同时回传订阅和购物。Facebook 和 TikTok 的这三个标准事件同名。Adjust 的三个事件识别码由合作方在 Adjust 后台创建，运营填在渠道里；AppsFlyer 使用固定的标准事件，不用配置。

创建游客、安装到桌面都不回传。

页面面向桌面端，界面为简体中文，时间按查看者浏览器时间显示。回传金额一律折成美元；安装统计按平台业务时区的自然日汇总。

系统预置默认推广商“官方推广商”和其下的“官方渠道”。首次打开带渠道参数的链接时，系统自动创建的游客账号归属该渠道。不带渠道参数公开注册或创建游客账号时，带了有效邀请码、且邀请人所在渠道启用，归属邀请人所在渠道；否则归属官方渠道（见模块决策 D137）。这样好友打开只带邀请码的分享链接注册后，和邀请人属于同一推广商。

本版不提供修改推广商名称、把渠道移到其他推广商、批量操作和导出。广告回传不提供：Facebook、TikTok、Adjust、AppsFlyer 以外的平台；一个渠道同时回传多个平台，或对应安卓和 iOS 两个 App；按渠道选择回传的事件；App 渠道的登录、首次打开 App、发起充值等其他事件；由合作方 App 自己上报事件；按广告名把同一个 App 的安装分到不同渠道（见模块决策 D154）；广告消耗导入、按广告计划的报表、手动重发和回传记录导出。PWA 链接不提供按渠道配置不同的名称和图标。

App 渠道的回传和网站在 App 内的表现以源码、Adjust 和 AppsFlyer 的公开文档为依据，尚未在真实的合作方 App 和 Adjust、AppsFlyer 账号上验证，联调前提见[未落地需求](../../未落地需求/README.md)的“等待外部能力联调”。TikTok 渠道的回传和像素以源码和 TikTok 的公开文档为依据，尚未用真实的 TikTok 广告和真机验证，联调前提同样见“等待外部能力联调”。

## 2. 配置项

### 推广商

| 配置项 | 含义和填写规则 |
|---|---|
| 推广商名称 | 文本必填，保存时去首尾空格，新增时不能与已有推广商同名 |
| 类型 | 系统标记：默认或普通，不能配置。预置的官方推广商为默认，新增的都是普通 |

### 推广渠道

| 配置项 | 含义和填写规则 |
|---|---|
| 所属推广商 | 新增时取当前选中的推广商 |
| 渠道名称 | 文本必填，保存时去首尾空格，系统不校验重名 |
| 域名 | 必选，选项来自域名管理 |
| 渠道状态 | 启用或停用，新增默认启用 |

### 广告回传

新增和编辑渠道的弹窗里有“广告回传”一组配置，每个渠道一份，随渠道一起保存。第一项是投放平台，下面只显示所选平台的配置项。

| 配置项 | 含义和填写规则 |
|---|---|
| 投放平台 | Facebook、TikTok、Adjust 或 AppsFlyer，按此顺序单选，新增渠道默认 Facebook。投放网站选 Facebook 或 TikTok；投放合作方 App 选该 App 使用的 Adjust 或 AppsFlyer。渠道还有回传记录时不能更换，见操作规则 |
| 回传开关 | 开或关，默认关。关闭时本渠道不回传，其余各项可以不填，已填内容保留；Facebook、TikTok 渠道关闭时也不加载像素。开关下方的说明：Facebook 和 TikTok 为“关闭时本渠道不加载像素、不回传，已填内容保留。”，Adjust 和 AppsFlyer 为“关闭时本渠道不回传，已填内容保留。” |

投放平台为 Facebook 时：

| 配置项 | 含义和填写规则 |
|---|---|
| 像素 ID | 广告平台分配给像素的数字编号。开启回传时必填；只要填写就只接受数字 |
| 回传令牌 | 广告平台为该像素生成的回传凭据。开启回传时必填。保存后不再显示内容：再次打开时输入框为空，占位文字为“不修改请留空”，下方显示“已设置 重新填写即覆盖，留空则保持原令牌” |
| 测试码 | 选填。填写后本渠道的全部回传都带测试码，用于在广告平台的测试事件页核对；联调结束后清空 |

投放平台为 TikTok 时，配置项的名称和规则与 Facebook 相同，只有像素 ID 的格式和测试码的说明不同：

| 配置项 | 含义和填写规则 |
|---|---|
| 像素 ID | TikTok 的像素代码，20 位大写字母或数字，占位文字为“TikTok 像素代码，20 位大写字母或数字”。开启回传时必填；只要填写就校验格式 |
| 回传令牌 | TikTok 为该像素生成的 Events API 访问令牌。开启回传时必填；保存后的显示和留空规则与 Facebook 的回传令牌相同 |
| 测试码 | 选填。填写后本渠道的全部回传都带测试码，下方提示“填写后本渠道的全部回传都带测试码，只在 TikTok 的测试事件页显示，不计入广告效果；联调结束后请清空。”。与 Facebook 不同，TikTok 不把带测试码的事件计入广告报表和优化：测试码不清空，广告收不到任何转化 |

投放平台为 Adjust 时：

| 配置项 | 含义和填写规则 |
|---|---|
| App Token | Adjust 分配给该 App 的识别码，12 位小写字母或数字，占位文字为“Adjust 分配给该 App 的 12 位识别码”。开启回传时必填；只要填写就校验格式 |
| S2S 令牌 | 选填，Adjust 开启了 S2S 安全时才需要，下方提示“仅在 Adjust 开启了 S2S 安全时需要”，并说明保存后不再显示内容。保存后的显示和留空规则与 Facebook 的回传令牌相同；已保存的令牌不能清空，只能重新填写覆盖 |
| 事件识别码 | 完成注册、首充、充值各一个，下方提示“在 Adjust 后台为每个事件创建，6 位小写字母或数字，三个不能相同。”。开启回传时三个都必填；只要填写就校验格式，三个不能相同 |
| 测试模式 | 开或关，默认关，下方提示“开启后按沙盒环境回传，须与 App 内 Adjust SDK 的环境一致。”。开启时事件发到 Adjust 的沙盒环境，关闭时发到正式环境 |

投放平台为 AppsFlyer 时：

| 配置项 | 含义和填写规则 |
|---|---|
| App ID | 下方提示“安卓填包名，iOS 填 id 开头的编号。”，占位文字为“如 com.example.app 或 id123456789”。开启回传时必填；只要填写就校验格式，iOS 的编号必须带 id |
| S2S 令牌 | AppsFlyer 的 S2S 令牌，下方提示它不是 Dev Key，并说明保存后不再显示内容。开启回传时必填，保存后的显示和留空规则与 Facebook 的回传令牌相同 |

AppsFlyer 没有测试模式。

回传的事件不能配置，所有渠道相同。“广告回传”标题下方有一行只读说明，回传开关打开或关闭时都显示，随投放平台写明回传内容：

| 投放平台 | 只读说明 |
|---|---|
| Facebook、TikTok | 回传内容：正式注册报“完成注册”；首充报“订阅”，每笔充值（含首充）报“购物”，均带金额。 |
| Adjust | 回传内容：正式注册报完成注册；首充报首充事件；每笔充值（含首充）报充值事件，充值带金额。 |
| AppsFlyer | 回传内容：正式注册报 af_complete_registration；首充报 af_subscribe；每笔充值（含首充）报 af_purchase，充值带金额。 |

### 列表

列表按创建时间倒序，默认每页 20 条，最多 100 条。

| 列表内容 | 规则 |
|---|---|
| 推广商页签 | 单选，默认第一个推广商，新建的排在前面；页签下方显示“当前推广商：推广商名称” |
| 筛选：渠道名称 | 包含匹配，不区分大小写。点“查询”生效，“清空筛选”清空并回到第 1 页 |
| 渠道名称 | 从同期群分析返回时，来源渠道标注“（来源渠道）” |
| 推广链接 | Facebook、TikTok 渠道和从未配置广告回传的渠道有两条链接，分别标注 H5 和 PWA，各带一个复制按钮。H5 是所选域名加 `ch=渠道ID` 参数；PWA 是该域名下的安装页地址加同一参数。网站管理没有配置应用图标时，PWA 链接下方提示“未配置应用图标，链接将直接进入游戏”。App 渠道只有一条链接，标注 APP，带复制按钮：所选域名的首页地址加 `ch=渠道ID` 和 `mApp=5` 两个参数；回传开关关闭时也是这一条。列标题“推广链接”旁的提示写明“APP 链接：配置为 App 打开的首页地址。” |
| 渠道状态 | 启用或停用 |
| 回传状态 | 未开启、已开启、测试中。回传开关打开时，Facebook、TikTok 渠道填了测试码、Adjust 渠道开启了测试模式显示测试中；AppsFlyer 没有测试模式。TikTok 渠道和 App 渠道在状态前加平台名，如“TikTok · 测试中”“TikTok · 已开启”“Adjust · 测试中”“AppsFlyer · 已开启”“Adjust · 未开启”；Facebook 渠道和从未配置广告回传的渠道只显示状态 |
| 创建时间 | 渠道创建时间 |
| 操作 | 同期群分析（有权限时显示）、回传记录、安装统计、编辑、启用或停用、删除 |

### 回传记录

渠道行点“回传记录”打开，只读。按事件发生时间倒序，默认每页 20 条。记录保留 90 天，时间按查看者浏览器时区显示。

| 内容 | 规则 |
|---|---|
| 筛选：事件 | Facebook、TikTok 渠道和从未配置广告回传的渠道：全部、完成注册、购物、订阅。App 渠道：全部、完成注册、首充、充值 |
| 筛选：状态 | 全部、等待回传、成功、重试中、失败、已过期 |
| 筛选：UID | 精确匹配 |
| 筛选：时间 | 按事件发生时间选起止日期，打开时默认近 7 天，含当天。点“查询”生效；“清空筛选”清空全部筛选，包括时间 |
| 时间 | 事件发生时间，即注册成功或充值入账的时间 |
| UID | 产生事件的账号，可复制 |
| 事件 | Facebook、TikTok 渠道：完成注册、购物或订阅。首充有订阅和购物两条记录，之后的每笔充值一条购物。改为固定事件（D151）之前生成的首充记录保留原来的事件，见特殊情况。App 渠道按记录的类别显示完成注册、首充或充值：首充有首充和充值两条记录，之后的每笔充值一条充值 |
| 金额 | 订阅和购物（App 渠道为首充和充值）回传的美元金额，即这笔充值的美元金额；完成注册不显示金额 |
| 广告点击信息 | 有或无。Facebook、TikTok 渠道：账号保存了本渠道平台的广告点击标识时为有，保存的是另一个平台的点击标识时为无，见“记录广告点击”。App 渠道这一列的标题为“App 设备”：生成记录时账号有该渠道 App 的设备为有，规则见“记录 App 设备” |
| 测试 | 是或否。最近一次发送带测试码，或发到 Adjust 的沙盒环境时为是；AppsFlyer 渠道都为否 |
| 状态 | 等待回传：尚未发送。成功：广告平台已接收。重试中：上次发送失败或还在等设备，等待下次重试。失败：Adjust 或 AppsFlyer 拒收了事件本身，重试也不会成功，不再发送。已过期：事件发生满 7 天仍在等待回传或重试中，不再发送 |
| 说明 | 最近一次发送失败的原因，通常是广告平台返回的说明；之后发送成功也保留。App 渠道的账号还没有该渠道 App 的设备时，显示“账号没有本渠道 App 的设备 ID：玩家在 App 内注册或登录后才会发送，7 天内没有则过期”。没有失败过显示“-” |

### 安装统计

渠道行点“安装统计”打开，只读。每行是平台业务时区的一个自然日，最近的日期在前，不分页。

| 内容 | 规则 |
|---|---|
| 筛选：日期 | 起止日期，打开时默认近 7 天，含平台今天；可以快捷选择近 7 天、近 30 天、近 90 天。一次最多 90 天，结束日期不能晚于平台今天。点“查询”生效 |
| 日期 | 平台业务时区的自然日 |
| 打开安装页人数 | 当天打开过该渠道安装页的浏览器数，同一浏览器一天计一次 |
| 安装成功数 | 当天安装的次数，每次安装计一次。安卓以浏览器告知安装页已安装为准，玩家确认安装后即计入，系统此时可能还在安装；iPhone 无法得知添加是否完成，以第一次从桌面图标打开为准 |
| 选择网页玩人数 | 当天在该渠道安装页点击网页入口（如“Play in browser”）的浏览器数，同一浏览器一天计一次 |

数据来自玩家端上报，按渠道和自然日汇总，没有数据的日期显示 0。

## 3. 操作规则

### 新增推广商与删除推广商

“新增推广商”弹窗同时列出推广商的名称、类型和创建时间。添加成功后留在弹窗，列表和页签同步刷新。

删除推广商只开放给系统角色，需要二次确认。默认推广商不显示删除按钮。推广商下有渠道，或已被业务配置、历史记录引用时不能删除。

### 新增与编辑渠道

保存成功后提示“保存成功”并刷新列表，修改立即生效。编辑可改渠道名称、域名和广告回传配置，不改所属推广商和渠道状态。渠道名称未填提示“请输入渠道名称”，域名未选提示“请选择域名”。保存被服务端拒绝时弹窗不关闭，在弹窗内显示拒绝原因；保存进行中不能关闭弹窗。

修改域名只改变后台显示的 H5 推广链接、PWA 链接和 APP 链接，已配置在合作方 App 里的首页地址不随之改变。注册时系统只校验渠道是否存在且启用，不校验访问域名，已发出的旧链接继续有效；已绑定的会员不受影响。

### 启用与停用渠道

点“停用”或“启用”需要二次确认。

- 停用后：新会员不能通过此渠道注册，后台也不能把会员改绑到此渠道；已绑定会员的渠道归属和充值结算保留。
- 启用后：新会员可通过此渠道注册，后台可将会员绑定到此渠道。

官方渠道也可以停用。停用后，不带渠道参数、也不能归属邀请人所在渠道的公开注册和游客创建都被拒绝。

停用不改变广告回传和安装页：已归属账号的回传按回传开关执行，安装页照常显示，安装统计照常计数。

### 删除渠道

删除前弹窗提示影响。官方渠道、已有会员的渠道、已被业务配置或历史记录引用的渠道都不能删除，应改为停用。渠道或推广商一旦被引用就永久保留，引用后来消失也不能再删除。首页分时汇总只为有业务数据的渠道写入记录，没有业务发生的新渠道不因汇总而失去删除资格。

回传记录和安装统计也是历史记录：产生过回传记录或安装统计的渠道不能删除，回传记录超过保留期被清理后仍不能删除。渠道的回传配置不算引用，随渠道一起删除。

### 查看同期群分析

账号能访问同期群分析时，行内显示“同期群分析”，带当前推广商和渠道跳转；返回时恢复推广商、筛选和页码，并标注来源渠道。

### 复制推广链接与 PWA 链接

Facebook、TikTok 渠道和从未配置广告回传的渠道有这两条链接，都带同一个渠道参数，点各自的复制按钮复制。玩家打开 PWA 链接看到什么取决于[11.3 网站管理](../../M11-内容管理/11.3-网站管理/README.md)：网站名称和应用图标都已配置时显示安装页；缺任意一项时直接进入游戏首页，链接上的参数原样保留，之后的注册仍归属该渠道。

没有配置应用图标时，列表在每条 PWA 链接下方提示“未配置应用图标，链接将直接进入游戏”。提示随每次列表查询重新读取，上传应用图标并保存后点“查询”即消失；玩家端在保存后约一分钟内才跟随新配置。

安装页不创建游客账号；玩家进入游戏后才创建，见[安装到桌面](../../玩家端/安装到桌面/README.md)。

### 复制 APP 链接

App 渠道只有 APP 链接，点复制按钮复制，交给合作方配置为 App 打开的首页地址。APP 链接是所选域名的首页地址加 `ch=渠道ID` 和 `mApp=5`：`ch` 让在 App 内创建的游客和注册的账号归属该渠道，`mApp` 让网站知道自己在 App 内打开。域名本身带的其他参数保留，域名里已有的 `ch` 和 `mApp` 以渠道的为准。

一个 App 对应一个渠道：同一个 App 的安装都归属它首页地址上的渠道，本版不按广告名把它们分到不同渠道（见模块决策 D154）。一个渠道只填一个 App 的 App Token 或 App ID，安卓和 iOS 是两个 App 时分别建渠道。合作方要做到：

1. App 打开的首页地址使用 APP 链接，渠道参数是 `ch`，不能换成其他名称。AppsFlyer 的 App 还要在打开的地址上加 `adid` 参数，值为该设备的 AppsFlyer 设备 ID。
2. Adjust 的 App 在页面第一次显示前准备好 Adjust 的设备数据。App 提供用外部浏览器打开链接的方法；安卓 App 还提供关闭启动页的方法，启动页另设超时，到时自行关闭。
3. App 开启 JavaScript 和网页本地存储，并持久保存 Cookie；Cookie 不持久时，玩家每次打开 App 都是新的游客。
4. App 自己不上报注册、首充和充值事件：Adjust、AppsFlyer 都不去重，App 和服务端各报一次就会计两次。
5. Adjust 的 App 提供 App Token、为服务端回传单独创建的三个事件识别码、开启 S2S 安全时的 S2S 令牌，并说明 App 内 Adjust SDK 使用沙盒还是正式环境；AppsFlyer 的 App 提供 App ID 和 S2S 令牌。
6. 合作方在 Adjust 或 AppsFlyer 后台把这些事件对应到 Meta、TikTok、Google 等广告平台；AppsFlyer 的标准事件会自动对应。
7. App 内跳转到其他支付 App、客服上传图片时选择文件和安卓的返回键，由 App 处理。

### 查看安装统计

渠道行点“安装统计”打开该渠道每天的三项数据，默认近 7 天。统计只读，不提供导出。安装不回传广告平台，只在这里按渠道统计。

### 保存广告回传配置

回传配置随渠道一起保存，保存后立即生效：之后发生的注册和充值按新配置回传；等待回传和重试中的记录也按发送时的最新配置发送，记录的测试列随之更新，事件不变。已经成功或失败的记录不再变化。

先选投放平台，再填该平台的配置项。切换投放平台时，配置项换成所选平台已保存的内容，从未在该平台保存过的为空，上一个平台已填的内容不带过去，原来的校验提示一并清除；切回原平台，恢复它已保存的内容。已保存的令牌只属于保存时的平台：换到其他平台不显示“已设置”，该平台需要令牌时要重新填写。在 Facebook 和 TikTok 之间切换也是这样：两者的配置项名称相同，像素 ID、测试码和已保存的回传令牌仍不带过去。保存后只留下所选平台的配置，其他平台的内容被清除。

渠道还有回传记录时（记录保留 90 天）不能更换投放平台：这些记录是按原平台生成和发送的，要换平台就新建渠道。弹窗里投放平台不能选，下方提示“已有回传记录，不能更换投放平台。”；服务端同样检查，提交更换时拒绝，提示“已有回传记录，不能更换投放平台，请新建渠道”。更换平台时正好有回传记录在写入的，提示“回传记录正在写入，请稍后再保存”，原配置不变，稍后重新保存即可。

回传开关打开时，所选平台标为必填的项都要填；只要填写就校验格式，开关关闭时同样校验。各平台的提示如下：

| 投放平台 | 必填和格式 |
|---|---|
| Facebook | 像素 ID 未填提示“请输入像素 ID”，含非数字字符提示“像素 ID 只能填写数字”；没有已保存的回传令牌又未填写时提示“请输入回传令牌” |
| TikTok | 像素 ID 未填提示“请输入像素 ID”，不是 20 位大写字母或数字（如含小写字母或符号、位数不对）提示“像素 ID 应为 20 位大写字母或数字”；没有已保存的回传令牌又未填写时提示“请输入回传令牌” |
| Adjust | App Token 未填提示“请输入 App Token”，不是 12 位小写字母或数字提示“App Token 应为 12 位小写字母或数字”。事件识别码按所在的事件提示，以首充为例：未填提示“请输入首充的事件识别码”，不是 6 位小写字母或数字提示“首充的事件识别码应为 6 位小写字母或数字”，与其他事件的相同时提示“首充的事件识别码不能与充值相同”（与两个都相同时为“不能与完成注册、充值相同”）：首充同时回传首充和充值两个事件，识别码相同会把一笔首充计两次。改动其中一个时，另外两个重新检查。S2S 令牌选填，不校验 |
| AppsFlyer | App ID 未填提示“请输入 App ID”；填了不带 id 的纯数字编号时提示“iOS 的 App ID 要以 id 开头，如 id123456789；不带 id 时 AppsFlyer 不报错，但会丢弃事件”；其他不是安卓包名或 id 加数字的，提示“App ID 应为安卓包名（如 com.example.app），或 iOS 的 id 加数字（如 id123456789）”。没有已保存的 S2S 令牌又未填写时提示“请输入 S2S 令牌” |

服务端按同样的规则再检查一次，格式提示与弹窗相同；不经弹窗直接提交时，必填和事件识别码相同的提示以服务端的文字为准，如“开启广告回传时请填写 App ID”“完成注册、首充、充值的事件识别码不能相同”。

已保存的令牌留空保存则保持不变，重新填写即覆盖。开关关闭时各项仍可填写并照常保存，清空的像素 ID、App Token、App ID、事件识别码和测试码随保存清除。

关闭回传后不再生成新记录，Facebook、TikTok 渠道的玩家端不再加载像素，尚未成功的记录停止发送并保留；重新开启后，事件发生未满 7 天的记录继续发送。关闭期间发生的注册和充值不生成记录，重新开启后也不补报。

### 配置 TikTok 渠道

做法与 Facebook 渠道相同：新增渠道，投放平台选 TikTok，填写投放方提供的像素 ID 和回传令牌，打开回传开关，把 H5 或 PWA 链接交给投放方。投放方要做到：

1. 提供 TikTok 的像素代码，以及为该像素生成的 Events API 访问令牌。令牌只对同一广告账户下的像素有效，不属于该像素所在广告账户的令牌会被 TikTok 拒收。
2. 联调时提供 TikTok 测试事件页上的测试码；联调结束后运营清空测试码，否则这个渠道的回传都不计入 TikTok 的广告效果。
3. 在 TikTok 的像素设置里打开第一方 Cookie：不打开时 TikTok 像素不写浏览器标识，回传不带它。
4. 在像素设置里关闭自动高级匹配：打开时 TikTok 像素会从页面的表单读取邮箱、手机号等资料发给 TikTok。网站自己不向 TikTok 发送这些资料。

### 记录广告点击

玩家打开带广告点击标识的链接时，玩家端记下这次点击。网站认两个平台的点击标识，并读取各平台像素在浏览器里写下的浏览器标识：

| 广告平台 | 点击标识 | 浏览器标识 |
|---|---|---|
| Facebook | 链接参数 `fbclid` | Facebook 像素写下的 Cookie `_fbp` |
| TikTok | 链接参数 `ttclid`，最长 1000 个字符，可以含点号，原样保存和发送 | TikTok 像素写下的 Cookie `_ttp`，像素设置里打开了第一方 Cookie 才有 |

玩家端把点击连同所属平台、首次看到它的时间和落地页地址保存下来，保存方式与渠道参数相同：之后的链接带了新的点击就替换，再次打开同一个点击不改首次看到的时间，不带点击则保留。链接同时带两个平台的点击标识时，保存地址里靠后的一个：广告平台把点击标识加在地址的末尾。

注册时提交保存的点击和一个浏览器标识，各自注明所属平台，两者可以属于不同平台。浏览器标识取页面最近加载的像素所属平台的；页面没有加载过像素时，取保存的点击所属平台的；两者都没有时，浏览器里只有一个平台的浏览器标识才提交。系统自动创建游客账号时只提交本次落地链接里的点击，浏览器标识按这次点击所属的平台取，链接里没有点击时同样只在浏览器里只有一个平台的浏览器标识时提交。服务端把它们保存在账号上，每个账号只保存一次，之后不再修改；每个标识按所属平台的格式检查，缺失、格式不对或没有注明平台的只是不保存，不影响注册。

每个标识只发给所属的平台：Facebook 渠道只发送账号保存的 Facebook 点击标识和浏览器标识，TikTok 渠道只发送 TikTok 的。账号保存的是另一个平台的标识时，回传不带这一项，记录的广告点击信息为无。链接里没有广告点击标识的账号照常回传，由广告平台自行判断归属。广告点击信息只用于 Facebook 和 TikTok 渠道的回传。

### 记录 App 设备

玩家在合作方 App 内打开网站时，玩家端读取 App 提供的设备标识：

| App | 读取的内容 |
|---|---|
| 装有 Adjust 的 App | Adjust 设备 ID；安卓的 Google 广告 ID 和 Android ID，iPhone 的 IDFA 和 IDFV；App Token、包名和安装归因 |
| 装有 AppsFlyer 的 App | 打开地址里 `adid` 参数的 AppsFlyer 设备 ID；安卓还是 iPhone 按浏览器信息判断 |

全为 0 的标识视为没有：玩家没有授权广告跟踪时，手机给出的广告 ID 是全 0。玩家端每次打开页面都重新读取，并把读到的保存在浏览器里，之后的页面使用保存的那份：iPhone 的 App 可能在页面显示之后才提供数据；AppsFlyer 设备 ID 保存后，玩家端把 `adid` 从地址里去掉，`ch`、`mApp` 等其他参数保留。网站在浏览器中打开时不提交设备标识。

玩家端在两种时候提交设备标识，服务端保存在账号上：

- 创建游客、邮箱或手机注册、邮箱或手机登录时，随请求提交。
- 账号已经登录（游客也算）时，玩家端发现 App 提供的设备标识与上次为该账号提交的不同，就单独提交一次：知道账号后马上检查，每个页面打开后的第一分钟内每 5 秒检查一次，页面回到前台时再检查。随创建游客、注册和登录成功提交过的算已提交；服务端判定为不可用的也算已提交，不再重复。单独提交失败时，本页不再按时检查，等下一个页面或页面回到前台再试。iPhone 的 App 在创建游客之后才提供数据、玩家一直保持登录，设备都靠这样补上。

服务端的保存规则：

- 每个账号只保留最近一次提交的设备，整份替换；玩家后来关闭了广告跟踪的，原来的广告 ID 随之清除。
- 同时保存这次请求的 IP 地址，只保存 IPv4：Adjust、AppsFlyer 都不收 IPv6。iPhone 另保存浏览器信息里的系统版本。
- 设备 ID 缺失、全为 0 或格式不对时，这次不保存设备；其他某一项格式不对时只舍去这一项。设备标识的问题不影响创建游客、注册和登录。
- 不保存邮箱、手机号、姓名和请求里的其他内容。

App 设备只用于 App 渠道的回传，并且只用属于该渠道 App 的设备：

| 投放平台 | 算作该渠道 App 的设备 |
|---|---|
| Adjust | 装有 Adjust 的 App 提供的设备；App 提供了 App Token 时，须与渠道的 App Token 相同 |
| AppsFlyer | 装有 AppsFlyer 的 App 提供的设备。App ID 是 id 开头的 iOS 编号时只算 iPhone 的设备；是安卓包名时只算安卓的设备，App 提供了包名时须与 App ID 相同 |

账号的设备不符合时，按账号没有该渠道 App 的设备处理。安装归因原样保存，本版不用它分渠道（见模块决策 D154）。

### 加载像素与浏览器事件

访客或账号所属的渠道投放平台为 Facebook 或 TikTok 且开启了回传时，玩家端加载该渠道的像素，并从浏览器上报下表四种事件：已有账号的看账号注册时所属的渠道，还没有账号的访客看落地链接里的渠道。页面只加载渠道所属平台的像素：Facebook 渠道加载 Facebook 的，TikTok 渠道加载 TikTok 的，两个平台的事件名称和上报时机相同。注册和充值的转化只由服务端回传。

| 事件 | 玩家的动作 | 金额 |
| --- | --- | --- |
| 浏览 | 打开页面上报一次，之后在站内每打开一个页面再上报一次 | 无 |
| 查看内容 | 进入任意游戏，自研游戏和第三方游戏都算。在同一个游戏里切换牌桌或合约不另报；换一个游戏或重新进入再报一次 | 无 |
| 加入购物车 | 打开充值页。一次访问只报一次，在法币和加密货币之间切换、改金额或方式都不另报；离开后再进入另报 | 无 |
| 发起结账 | 提交充值：法币充值订单创建成功时报一次，同一订单再次打开或重试不重复报；加密货币点“复制地址”且复制成功时报一次，同一次访问里同一地址只报一次 | 法币带订单金额和币种；加密货币无 |

这些浏览器事件只出现在广告平台的事件管理工具里，不进回传记录；浏览器拦截广告脚本时不会发出。转盘充值弹窗和首充补助付款页走各自的下单流程，提交时不报发起结账。

TikTok 的像素加载后还会按 TikTok 自己的规则上报落地页浏览、停留较久的访问和按钮点击等数据，网站不能关闭；这些不是网站上报的事件，也不进回传记录。

渠道没有开启回传，或是 App 渠道时，玩家端不加载任何广告脚本，也不向广告平台发送请求；App 渠道的事件只由服务端回传。

### 注册回传

玩家完成正式注册时，回传一次“完成注册”，邮箱注册和手机注册都算。游客绑定邮箱后在 Settings 设置登录密码、原地转为会员（[M4 决策 D143](../../M4-活动管理/README.md#7-决策清单)），同样回传一次完成注册，记在原 UID 上。系统自动创建游客账号不回传；游客用邮箱或手机注册的是新账号，按新账号的正式注册回传。

### 充值回传

每笔充值入账时，回传一次“购物”。账号的第一笔充值是首充，另外再回传一次“订阅”：一笔首充生成订阅和购物两条记录，时间和金额相同，各自发送、各自重试。金额为这笔充值的本金按[标准计价](../../M2-会员管理/2.1-会员列表/标准计价.md)折成的美元金额，不含赠送和活动奖励。

充值沿用财务的充值事实，三种来源都算：链上入金、法币充值订单、后台人工加款时勾选“计入充值”的本金。首充按账号计，每个账号只回传一次订阅；之后的每笔充值只回传购物。

### 回传去向

事件回传到账号注册时所属渠道的投放平台：Facebook、TikTok 渠道回传到配置的像素；App 渠道回传到配置的 App，用账号的 App 设备让 Adjust 或 AppsFlyer 对应到这台手机的安装。后台之后把会员改绑到其他渠道，不改变该账号的回传去向。

只回传渠道开启回传之后发生的注册和充值。测试账号的注册和充值不回传，也不生成记录。是否为测试账号，注册看注册时的标记，充值看入账时的标记。

### 发送与重试

回传与注册、充值入账分开执行：记录通常在事件发生后一分钟左右生成并发送；回传失败或广告平台不可用，不影响注册成功和充值入账。玩家关闭页面、浏览器拦截广告脚本，都不影响注册和充值的回传。

App 渠道的记录在事件发生满 60 秒后才发送：在安装后很快到达的事件可能被当成自然量，App 的首次打开也可能还没有到达 Adjust；Facebook、TikTok 渠道的记录不等待。Adjust 渠道同一账号的同类事件按发生先后发送：更早的同类记录还在等待回传或重试中时，后面的保持等待回传；更早的记录成功、失败或过期后，后面的照常发送。Adjust 渠道的一笔充值还要等该账号更早入账的充值生成记录后，才生成自己的记录。Adjust 拒收比已收到的更早的同类事件，所以不能乱序；AppsFlyer 不要求先后。

每次发送的结果：

| 投放平台 | 发送结果 | 记录 |
|---|---|---|
| Facebook、TikTok | 已接收。TikTok 的回答带返回码，返回码为 0 才算已接收 | 成功 |
| Facebook、TikTok | 其他回答，包括 TikTok 带其他返回码的回答和没有回应 | 重试中；改正配置后，下一次重试按新配置发送 |
| Adjust、AppsFlyer | 已接收；Adjust 回答该事件是唯一事件、这台设备已经记过，也算已接收 | 成功 |
| Adjust、AppsFlyer | 没有回应、超时、请求太多或平台出错 | 重试中 |
| Adjust | 设备不存在：App 的首次打开可能还没有到达 Adjust | 重试中 |
| Adjust、AppsFlyer | 拒收配置或鉴权：S2S 令牌缺失、不对、尚未生效或已更换；Adjust 的 App 已停用、事件识别码被屏蔽、App Token 或事件识别码不存在；AppsFlyer 的 App ID 与 S2S 令牌不属于同一账号 | 重试中；说明列显示平台的回答，改正配置后，下一次重试按新配置发送 |
| Adjust、AppsFlyer | 拒收事件本身：Adjust 的事件早于这台设备的安装或早于已收到的同类事件、金额不对、设备已退出跟踪、请求过大；AppsFlyer 的请求内容不对；以及其他回答 | 失败，不再发送 |
| Adjust、AppsFlyer | 账号没有该渠道 App 的设备，不发送 | 重试中，说明列显示“账号没有本渠道 App 的设备 ID：玩家在 App 内注册或登录后才会发送，7 天内没有则过期” |

发送失败后自动重试，间隔逐次加长，最长一小时一次。事件发生满 7 天仍在等待回传或重试中的，记录标记为已过期，不再发送；失败的记录保持失败。确认成功后不再发送；Facebook、TikTok 的同一条记录每次发送使用同一个事件编号。

配置或鉴权填错时，记录显示重试中，改正后下一次重试按新配置发送，事件发生未满 7 天的都能补发；一直没有改正的满 7 天过期。失败只用于平台拒收事件本身的情况，改配置也不会成功，所以不再发送。

账号没有该渠道 App 的设备的记录不发送，过一段时间再找设备：事件发生满 1 分钟后第一次找，之后的间隔是已经等待时长的六分之一，最短 1 分钟、最长 1 小时。玩家在 App 内注册、登录，或玩家端补交了设备之后，下一次查找时发出；满 7 天仍没有设备则过期。

### 随事件发送的资料

Facebook 渠道每次回传发送：事件名称、发生时间、事件编号、订阅和购物的美元金额、账号保存的 Facebook 广告点击标识和浏览器标识、账号创建时（注册或系统创建游客时）的 IP 地址和浏览器类型、不含链接参数的落地页地址，以及由 UID 经不可逆处理得到的账号标识。账号没有保存 IP 地址和浏览器类型时取最近一次登录的；没有保存落地页时用注册所在站点的首页。

TikTok 渠道每次回传发送的资料与 Facebook 渠道相同，只是点击标识和浏览器标识换成账号保存的 TikTok 的。

Adjust 渠道每次回传发送：App Token 和这类事件的事件识别码，账号 App 设备的 Adjust 设备 ID 和 App 提供的其他标识（安卓的 Google 广告 ID 和 Android ID，iPhone 的 IDFA 和 IDFV），发生时间，设备保存的 IPv4 地址，首充和充值事件的美元金额，以及测试模式对应的沙盒或正式环境。

AppsFlyer 渠道每次回传发送：AppsFlyer 设备 ID、由 UID 经不可逆处理得到的账号标识（与 Facebook 渠道相同）、标准事件名、发生时间、设备保存的 IPv4 地址、af_subscribe 和 af_purchase 的美元金额，iPhone 另发送系统版本。装有 AppsFlyer 的 App 只提供设备 ID，所以不发送广告 ID 和包名。

本版不发送邮箱、手机号和姓名。

### 查看回传记录

渠道行点“回传记录”打开该渠道的记录，可按事件、状态、UID 和时间筛选。记录只读，本版不提供手动重发和导出。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 推广商同名 | 新增时提示“已存在同名推广商，请更换名称”，不提交 |
| 删除默认推广商 | 服务端拒绝，提示“默认推广商不能删除” |
| 删除下有渠道的推广商 | 拒绝，提示“推广商下存在渠道，不能删除”，停用的渠道也算 |
| 删除已有业务配置或历史记录的推广商 | 拒绝，提示“推广商已有业务配置或历史记录，不能删除” |
| 非系统角色删除推广商 | 拒绝，提示“仅超级管理员可执行此操作” |
| 删除官方渠道 | 拒绝，提示“官方默认渠道用于直接注册，不能删除；如需停止新注册，请停用渠道” |
| 删除已有会员的渠道 | 拒绝，提示“推广渠道已关联会员，请停用渠道” |
| 删除已有业务配置或历史记录的渠道 | 拒绝，提示“推广渠道已有业务配置或历史记录，请停用渠道”；产生过回传记录或安装统计的渠道同样处理 |
| 操作期间渠道所属推广商发生变化 | 拒绝，提示“推广渠道已变化，请刷新后重试”，原数据不变；编辑保存时提示显示在弹窗内 |
| 玩家用已停用渠道的链接注册 | 注册被拒绝，玩家端提示“The invitation code or registration link is invalid. Check the code or ask for a new link.” |
| 玩家用不存在的渠道参数注册 | 注册被拒绝，玩家端提示同上 |
| 创建游客时渠道已停用或不存在 | 不创建游客账号，登录弹窗提示“Unable to start a guest account. Log in to an existing account or contact support.” |
| 不带渠道参数注册，邀请码无效或邀请人所在渠道已停用 | 归属官方渠道，注册照常（官方渠道也停用时按上文拒绝）；邀请码无效时不建立邀请关系 |
| 链接同时带渠道参数和邀请码 | 归属链接中的渠道，不按邀请人改归属 |
| 账号没有 `system:domain:view` | 域名下拉没有选项，无法新增渠道 |
| 没有推广商 | “新增推广渠道”不可用，列表为空 |
| 当前推广商下没有渠道或筛选无结果 | 列表显示“暂无数据”和“调整筛选条件后再试。” |
| 操作成功但列表刷新失败 | 提示“渠道状态已更新，列表刷新失败，请重试”“推广渠道已删除，列表刷新失败，请重试”“推广商已删除，列表刷新失败，请重试”或“保存成功，推广商列表刷新失败，请重试”。操作已生效，不用重复操作 |
| Facebook 或 TikTok 渠道开启回传但像素 ID 或回传令牌未填 | 不提交，分别提示“请输入像素 ID”“请输入回传令牌” |
| Facebook 的像素 ID 含非数字字符，如填了 TikTok 的像素代码 | 不提交，提示“像素 ID 只能填写数字”；回传开关关闭时同样校验 |
| TikTok 的像素 ID 不是 20 位大写字母或数字，如含小写字母或符号、位数不对 | 不提交，提示“像素 ID 应为 20 位大写字母或数字”；回传开关关闭时同样校验，不经弹窗直接提交时服务端同样拒绝，原配置不变 |
| Adjust 或 AppsFlyer 渠道开启回传但必填项未填，或某项格式不对 | 不提交，按操作规则“保存广告回传配置”中的提示；格式在回传开关关闭时同样校验 |
| Adjust 的三个事件识别码有相同的 | 不提交，相同的字段下方提示不能与哪个相同，如“首充的事件识别码不能与充值相同”；不经弹窗直接提交时服务端拒绝，提示“完成注册、首充、充值的事件识别码不能相同”，原配置不变 |
| AppsFlyer 的 App ID 填了 iOS 编号但没有带 id | 不提交，提示“iOS 的 App ID 要以 id 开头，如 id123456789；不带 id 时 AppsFlyer 不报错，但会丢弃事件” |
| 渠道还有回传记录时更换投放平台 | 弹窗里投放平台不能选，下方提示“已有回传记录，不能更换投放平台。”；服务端同样拒绝，提示“已有回传记录，不能更换投放平台，请新建渠道”，原配置不变 |
| 更换投放平台时正好有回传记录在写入 | 等待最多两秒；仍在写入时保存被拒绝，提示“回传记录正在写入，请稍后再保存”，原配置不变，稍后重新保存即可。写入的是本渠道的记录时，之后按有回传记录处理，不能再更换 |
| 渠道的回传记录都超过保留期被清理 | 渠道没有回传记录了，投放平台可以更换 |
| 切换投放平台后保存，包括在 Facebook 和 TikTok 之间切换 | 只保存所选平台的配置，其他平台的内容被清除；原平台已保存的令牌不带到新平台 |
| Facebook 或 TikTok 的像素 ID 或回传令牌填错，或 TikTok 的令牌不属于该像素所在的广告账户，广告平台拒绝 | 注册和充值入账不受影响；记录显示重试中，说明列显示广告平台返回的原因；改正配置后，未过期的记录在下一次重试时发送成功；一直没有改正的满 7 天过期，不标记为失败 |
| TikTok 渠道联调后没有清空测试码 | 回传照常发送，记录成功、测试为是，列表显示“TikTok · 测试中”；但 TikTok 不把这些事件计入广告报表和优化，广告收不到转化。清空测试码后发送的回传才计入，已经成功的记录不再发送 |
| Adjust 或 AppsFlyer 的 App Token、事件识别码、App ID 或 S2S 令牌填错，平台拒收 | 注册和充值入账不受影响；记录显示重试中，说明列显示平台返回的原因；改正配置后，事件发生未满 7 天的记录在下一次重试时发送；一直没有改正的满 7 天过期 |
| Adjust 开启了 S2S 安全，渠道没有填 S2S 令牌或填错；新换的 S2S 令牌尚未生效（AppsFlyer 最长约 30 分钟） | 平台拒收，记录显示重试中；填好正确的令牌或令牌生效后，下一次重试发送 |
| 广告平台、Adjust 或 AppsFlyer 暂时不可用或超时 | 记录显示重试中，自动重试 |
| Adjust 回答设备不存在 | 记录显示重试中，说明列显示 Adjust 返回的原因，一直重试到满 7 天过期。App 的首次打开还没有到达 Adjust 时会这样，之后能发送成功；测试模式与 App 内 Adjust SDK 的环境不一致时不会成功 |
| Adjust 渠道的一条记录一直重试中，如设备不存在或配置被拒 | 该账号之后的同类记录保持等待回传，直到这一条成功、失败或过期 |
| AppsFlyer 的记录显示成功 | AppsFlyer 接收时只做简单检查，成功不代表事件已经记入，以 AppsFlyer 的原始数据为准 |
| App 渠道的账号没有该渠道 App 的设备：只在浏览器里注册和充值，App 没有提供设备数据，或账号的设备不属于该渠道的 App（另一个平台的 App、App Token 不同的 Adjust App、安卓和 iOS 不对应或包名不同的 AppsFlyer App） | 不发送，记录显示重试中，说明列显示“账号没有本渠道 App 的设备 ID：玩家在 App 内注册或登录后才会发送，7 天内没有则过期”，App 设备为无；玩家之后在 App 内注册、登录或玩家端补交设备后，下一次查找时发送（最多一小时后）；满 7 天仍没有则过期 |
| App 打开的首页地址没有使用 APP 链接，或渠道参数不叫 `ch` | 账号按不带渠道参数的规则归属，事件不会回传到该 App 渠道 |
| 装有 AppsFlyer 的 App 打开的地址没有带 `adid` | 网站拿不到设备，记录按账号没有设备处理 |
| 玩家先在浏览器注册，之后才安装 App 并在 App 内登录 | 设备保存后，之前的记录在下一次查找设备时发送；Adjust 拒收发生在安装之前的事件，这类记录显示失败 |
| iPhone 的 App 在创建游客之后才提供设备数据 | 这次创建游客不带设备；数据出现后玩家端单独提交，页面打开后第一分钟内每 5 秒检查一次，之后在下一个页面、页面回到前台或下一次注册登录时提交。设备保存前生成的记录在设备保存后的下一次查找时发送，但 App 设备为无 |
| 玩家保持登录状态，再次打开 App | 设备标识与上次为该账号提交的相同时不提交；不同时玩家端单独提交，账号的设备随之更新 |
| 游客在 Settings 设置登录密码，原地转为会员 | 这个请求不带设备，沿用之前保存的设备；设备标识有变化时玩家端单独提交 |
| 同一账号先后在两个合作方 App 内登录 | 只保留最近一次的设备，之后的回传都用它；这台设备不属于渠道的 App 时，按账号没有该渠道 App 的设备处理 |
| Adjust 渠道：同一台手机先后登录两个账号 | 两个账号的事件各按本账号的先后发送；Adjust 按设备检查先后，可能拒收其中较早的事件，记录显示失败 |
| 玩家的 IP 地址是 IPv6 | 设备照常保存，回传不带 IP 地址；Adjust 把事件转给 TikTok、Google 时需要 IP 地址，这类事件可能转不出去 |
| App 渠道的玩家打开网站 | 不加载像素，不从浏览器上报任何事件 |
| 账号保存的广告点击标识或浏览器标识属于另一个平台，如点了 Facebook 广告进入网站，之后用 TikTok 渠道的链接注册 | 账号照常归属 TikTok 渠道；回传不带另一个平台的标识，广告点击信息为无，由 TikTok 按其他资料判断归属。反过来点了 TikTok 广告、在 Facebook 渠道注册的同样处理 |
| 链接同时带 `fbclid` 和 `ttclid` | 保存地址里靠后的一个，另一个不保存 |
| 玩家在玩家端开始按平台保存点击之前打开过带 `fbclid` 的链接，之后才注册 | 浏览器里那次点击没有注明平台，不再提交，账号的广告点击信息为无；之后再打开带点击标识的链接，新的点击照常保存 |
| 浏览器里同时有 Facebook 和 TikTok 的浏览器标识 | 注册时提交页面最近加载的像素所属平台的那个；页面没有加载过像素、也没有保存的点击时，两个都不提交 |
| TikTok 的点击标识超过 1000 个字符或含字母、数字、下划线、连字符和点号以外的字符 | 不保存，注册照常；回传不带点击标识，广告点击信息为无 |
| 投放方没有在 TikTok 的像素设置里打开第一方 Cookie | 浏览器里没有 TikTok 的浏览器标识，回传不带它；注册和回传照常 |
| 页面已加载一个渠道的像素，之后登录了另一个渠道注册的账号 | 之后网站上报的浏览器事件只报给该账号所属渠道的像素，平台不同时另外加载该平台的像素；该渠道没有像素时不再上报 |
| 充值的币种暂时折不出美元金额 | 这笔充值的记录保持等待回传、不显示金额，取得标准计价后发送；满 7 天仍取不到则标记为已过期。首充的订阅和购物两条都这样处理 |
| 首充的订阅和购物一条成功、一条失败 | 两条记录分开处理：失败的一条按重试规则继续发送，成功的一条不再发送 |
| 同一账号两笔充值几乎同时入账 | 两笔都回传购物；只有业务时间较早的一笔是首充，另外回传订阅 |
| 一笔充值入账晚于已回传订阅的首充，业务时间却更早 | 只回传购物；每个账号只有一次订阅，已有的首充不变 |
| 首充是勾选“计入充值”的人工加款 | 回传订阅和购物，金额为加款本金折成的美元金额 |
| 人工加款未勾选“计入充值” | 不算充值，不回传；之后第一笔计入充值的入账才是首充 |
| 充值入账后被冲正 | 已回传的事件不撤回，广告平台没有撤回事件的办法。被冲正的首充仍是首充：该账号之后的充值只回传购物，不再回传订阅 |
| 玩家打开网站，系统自动创建游客账号 | 不回传完成注册，也不生成记录；玩家之后完成正式注册或原地转为会员时才回传 |
| 游客账号充值 | 按该账号回传：第一笔回传订阅和购物，之后每笔回传购物。游客原地转为会员后 UID 不变，首充不另算；游客用邮箱或手机注册得到的新账号另算首充 |
| 开启回传前已注册或已充值的账号 | 开启前的注册和充值不补报，开启后的每笔充值回传购物。开启前已有充值的账号不再回传订阅；开启前没有充值的账号，开启后的首充回传订阅和购物 |
| 关闭回传时仍有未成功的记录 | 停止发送并保留；重新开启且事件发生未满 7 天的继续发送，满 7 天的标记为已过期 |
