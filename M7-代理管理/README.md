# M7 · 代理管理

## 1. 定位与边界

**做什么**:代理返佣活动的配置与结算、佣金记录查询,以及后续的代理关系与代理列表。
**首版只做一级(直属)代理**:玩家邀请直属下级,按下级的充值与投注获得返佣。

**收入本仓库的理由**:返佣的判档、打码与冲回全部踩在资金语义上(打码任务、标准计价、
账变来源标识),文档必须与 `资金模型.md`、`标准计价.md` 同仓演进,拆开引用立刻断链 ——
与财务收入本仓库同一个道理。

**不做什么**
- 不做二级返佣、团队模式、三级分销 —— 模式枚举预留,首版不开放(7.1-A1)
- 不做渠道管理 —— 渠道仍在本仓库范围外,本模块只读引用
- 不做玩家端代理中心 —— 本仓库只写运营后台,玩家端按 7.1 口径另出文档
- 不做高RTP投注折算比例的配置 —— owner=游戏管理(**本仓库范围外**),7.1 只读引用

**铁律**
- **资金域不得反向依赖活动域**(00-公共约定 依赖铁律):佣金入账与冲回一律通过财务账变完成,
  账变带来源标识,本模块不直接改钱包余额
- **佣金记录是审计数据**:计算依据入账后不可改,状态流转逐笔留痕

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 代理关系 | 玩家之间由**邀请码**建立的上下级绑定,绑定后**不可换绑**(D28);完整规则归 7.3 承载(未开工) | 代理关系 |

| 佣金 | 按下级充值或投注计算、发给上级的返佣金额 | 佣金记录 |

## 3. 依赖关系

**上游依赖(我引用)**
- 财务(M5 与 `资金模型.md`):充值订单、钱包与账变、打码任务、标准计价换算记录 ——
  佣金的计算、入账与冲回全部依赖
- 玩法:注单与有效投注(**本仓库范围外**)
- 游戏管理:投注折算比例(**本仓库范围外,缺文档**;7.1-A12 只读引用,未配置按 100% 处理)
- M2 用户管理:用户标签当前命中集(2.5)、玩家档案与封禁状态
- 渠道(owner=代理渠道,**本仓库范围外**):玩家的渠道归属
- M6 账号管理:权限模型与全站操作日志

**下游被依赖(谁引用我)** ← 改代理关系或佣金数据前先看这行
- M2 用户管理:渠道与代理的只读引用(00-公共约定 归属表)
- 玩家端代理中心(**本仓库范围外**):读佣金记录与代理关系

## 4. 数据模型

**拥有的数据**(owner=M7)

| 数据 | 说明 | 现状 |
|---|---|---|
| 返佣活动配置 | 开关、名称、人群、模式、比例、档位、打码倍数,含修改历史 | 缺失 |
| 佣金记录 | 每笔佣金的来源、计算依据快照、状态与流转流水 | 缺失 |
| 结算批次 | 投注返佣日结的批次与断点信息 | 缺失 |
| 佣金挂账 | 已领取佣金冲回不足额的差额:应冲、已冲、差额、处理状态与留痕,关联原佣金记录;展示与处理入口在 7.2 | 缺失 |
| 代理关系 | 上下级绑定;规则待 7.3 定义(D28) | 缺失 |

**只读引用**:充值订单 · 钱包 · 打码任务 · 换算记录(owner=财务)·
注单与有效投注(owner=玩法,**范围外**)· 投注折算比例(owner=游戏管理,**范围外**)·
标签命中集(owner=M2)· 渠道(owner=代理渠道,**范围外**)。
