# 7.3 · 代理列表

<a id="1-背景与目标"></a>

## 1. 用途

定清玩家之间的邀请绑定规则,并让运营与客服查得到「谁邀请了谁、下级贡献了多少」——
它是代理返佣的计算地基,关系不清,佣金争议就无法查证。

### 使用者

| 角色 | 用来做什么 | 没有会怎样 |
|---|---|---|
| 运营 | 看代理结构与产出,评估返佣活动效果 | 只看得到佣金总数,不知道钱发给了什么样的代理 |
| 客服 | 处理「我下级充值了为什么没佣金」 | 查不到绑定关系与贡献明细,只能升级工单 |
| 风控 | 识别自邀、互刷的账号结构 | 刷佣结构靠人工猜 |

绑定规则一次定清,返佣、玩家端邀请页、风控共用同一事实;
客服凭邀请用户与佣金记录自助答复佣金争议,不再升级。

### 本次范围

- 提供代理列表与代理详情的查询(R1、R2),以及绑定与邀请码的后台逻辑(R3、R5);4.16 邀请宝箱另需 R6、4.17 拼多多活动另需 R7 的只读关系事实输出
- **不做换绑** —— 绑定终身有效(D28 已定)
- **本版不提供人工解除入口**(R4)
- **不做补填** —— 仅注册时绑定,注册后不能再认上级(A3)
- 不做多码与活动码 —— 每人一个固定邀请码(A1)
- 不做玩家端邀请页本身 —— 规则以本页为准,玩家端照此实现
- 不做佣金计算与发放 —— 归 7.1,本页只读聚合展示

### 适用范围

| 维度 | 取值 |
|---|---|
| 终端 | Web 后台,桌面优先(设计基准 1440px) |
| 响应式 | 最小支持 1280px;不做移动端适配 |
| 界面语言 | 后台界面简体中文 |
| 时区 | 时间按浏览器本地时区展示 |
| 货币 | 金额列按标准计价币种展示,见 A8 |

## 3. 处理规则

### 邀请码形态(A1)

每玩家一个**固定个人码**,玩家登录后首次读取代理信息(侧边栏或邀请页)时自动生成,8 位大写字母与数字,去除 0、O、1、I 等易混字符,全局唯一、终身不变;不可自定义、不可多码。

配置或来源：(最简方案,D28)。

### 绑定途径(A2)

新玩家端首次落地时由邀请链接带码，自动创建游客账号时完成绑定；游客注册正式账号时不提供手输或改码，新UID读取本浏览器首次落地保存的邀请码；已建号后访问其他邀请链接不补绑。游客建号的来源记「链接」，正式注册接口的来源记「手输」；手输来源不作为新游客流程入口。

配置或来源：(最简方案,D28)。

### 绑定时点(A3)

**仅注册时**绑定,注册后不可补填;上级必然先于下级注册,循环绑定天然不可能;存量玩家不追溯补绑。

配置或来源：(最简方案,D28)。

### 换绑与解除(A4)

不可换绑(D28 已定);关系解除后该下级不再计入原上级且**不可重绑**任何上级。本版后台不提供解除入口(R4)。

配置或来源：D28。

### 注册绑定关系(7.3-R3)

新玩家首次落地自动创建游客账号，来源携带邀请码(链接带入,A2)；无码则不进入绑定。游客在登录弹窗内注册正式账号是另一次注册，新UID按首次落地保存的邀请码建立关系，游客号的关系不变。

输入信息：邀请码 · 新玩家注册信息(owner=M2,只读)。

1. 注册流程携码进入绑定判定;无码直接结束,玩家无上级
2. 校验码存在(A5);不存在则不绑定
3. 校验非自我绑定 —— A3 下天然不可能(属主必已存在、新玩家尚无码),服务端仍兜底校验
4. 写关系:上级、下级、邀请码、绑定时间、来源途径(链接 / 手输),终身有效;绑定时间取玩家注册时间,同时写绑定流水
5. 同一玩家注册重复提交,幂等只产生一条关系
6. 无码或码无效不影响注册结果(A5);关系与账号初始化同事务写入,写入异常时本次注册初始化失败,提示联系客服

```mermaid
flowchart TD
    A[注册携码进入绑定判定] --> B{有邀请码?}
    B -->|无| C[不绑定, 结束]
    B -->|有| D{码存在? A5}
    D -->|否| E[不绑定]
    D -->|是| F[写关系: 上级/下级/码/途径]
    F --> G[写绑定留痕, 下游可读]

    classDef risk fill:#ffe0e0,stroke:#c62828,color:#000
    classDef safe fill:#e3f2fd,stroke:#1565c0,color:#000
    class E risk
    class F,G safe
```

> 配色:红色为不绑定分支,不单独留痕,
> 蓝色为写入与留痕步骤。无码与无效码都不阻断注册(A5)。

### 人工解除关系(7.3-R4)

本版不提供。代理列表、用户详情都没有解除入口,权限目录也没有对应节点。

关系保留「有效 / 已解除」两种状态:7.1 只对有效关系计佣,解除后该下级不可再绑定任何上级,关系记录不删除。

### 邀请宝箱读取关系事实(7.3-R6)

[4.16 邀请宝箱](../../M4-活动管理/4.16-邀请宝箱/README.md)按直属关系接纳新下级并认定有效人数,
M7 为其提供同一运营方内稳定且唯一的关系标识、上下级、注册绑定业务时点、当前关系状态以及解除业务时点与原因。
重复投递或补发保持原标识和原业务时点,不能按接收时间伪造新的绑定或解除。

- M4 消费失败不影响注册、绑定或解除结果;恢复后按原时点补处理,并以关系标识去重,不产生重复下级或奖励。关系读取失败与确实无绑定必须区分,失败可恢复,不静默认作无上级。
- 解除前已被活动认定为有效的下级,其有效人数及已解锁奖励保留;解除前仍未满足条件的下级停止继续达标。若达标事实发生在解除前而通知迟到,M4 使用原业务时点及其资格依据恢复判断;解除时点起的新达标不算入原上级。
- 活动不写关系、不补绑或换绑,不把资格不符改成关系解除。设备去重和活动有效人数不改变本页的直属下级数,也不改变 7.1 的返佣计算。
- 此处只提供事实读取与恢复依据,不新增人工解除界面或活动侧解除入口;原 R4 界面范围保持不变。

### 拼多多活动读取关系事实(7.3-R7)

[4.17 拼多多活动](../../M4-活动管理/4.17-拼多多活动/README.md)复用 R6 的稳定关系标识、同一运营方内的上下级、注册绑定业务时点、状态及解除业务时点,注册成功事实由 M2 提供。M4 根据活动规则决定是否赠次,每名好友在整个活动内至多贡献一次邀请机会;重复、延迟或补发不得形成新好友或新机会。

- M4 按玩家本轮首次旋转与统计上界,只将本轮首抽后新注册的合格直属好友纳入本轮加速;统计上界取实际结束与有效截止时刻的较早者。其充值和有效投注还须发生于本轮内及关系有效期间;旧轮好友与贡献不能随跨轮保留的邀请机会一起转入新轮。M7 只提供关系事实,不计算活动 P 人数、R 充值、W 投注或判断加速条件。
- 解除前合法产生的邀请机会及本轮贡献按活动规则保留;解除业务时点起的新充值、投注不再贡献原上级的加速条件。读取失败与无绑定严格区分,未知保持待恢复;迟到事实使用原业务时点归属原轮,不以消息到达时的新轮重新赠次或累计。原轮是否仍能旋转、领奖及系统实际阻塞的顺延,由 M4 按4.17-A18决定;M7关系恢复本身不改活动期限。
- 活动同 IP 名额、参与标签、渠道、机会余额和轮次均归 M4,不写关系、不补绑或换绑,也不修改本页直属下级数或 7.1 佣金。原绑定或解除写入失败仍按 R3/R4 处理,不得使注册依赖活动消费成功。

## 4. 特殊情况

### 无效码处理(A5)

码不存在时,**注册照常完成、仅不绑定**,不阻断注册。

### 封禁与注销影响(A6)

关系保留;封禁不影响关系、邀请码与计佣(7.1-E5)。

### 边界处理

| # | 场景 | 触发条件 | 预期处理 |
|---|---|---|---|
| E1 | 越权 | 无权限账号访问列表 | 跳转无权限页,服务端拒绝;隐藏菜单不作为唯一防线 |
| E2 | 无效码注册 | 码不存在 | 注册照常、不绑定(A5),不得报错打断注册 |
| E3 | 自我与循环绑定 | 构造请求试图绑自己或成环 | A3 下天然不可能,服务端仍兜底拒绝 |
| E4 | 重复绑定 | 同一玩家注册重复提交 / 二次尝试换上级 | 幂等只留一条关系;已有关系时不改变上级,不报错 |
| E5 | 解除遗留 | 解除时仍有待领取佣金 | 佣金不动(7.1-E4);解除只影响之后的计佣 |
| E6 | 存量玩家 | 功能上线前注册的玩家 | 无上级,不追溯补绑(A3);用户详情的上级代理显示「官方」 |

### 注册绑定关系遇到异常时(7.3-R3)

| 错误状况 | 处理 |
|---|---|
| 码不存在 | 不绑定,注册照常 |
| 重复提交 | 幂等,只绑一次 |
| 关系写入失败 | 本次注册初始化失败,提示联系客服 |

### 页面状态

四态按全局默认。本页特有态:

| 状态 | 表现 |
|---|---|
| 无上级 | 用户详情的上级代理显示「官方」,不留白 |

### 依赖与数据流

**数据流向**:玩家注册(携码)→ 服务端绑定判定,写关系与留痕 → 7.1 计佣读关系判归属 →
本页展示邀请关系与佣金汇总 → 客服与运营查证。

**系统串接**:注册流程与玩家档案(owner=M2;绑定判定嵌在注册流程内,**不得使注册失败**)·
代理返佣(7.1,读关系计佣)· 佣金记录(7.2,详情内嵌)·
玩家端邀请页(**范围外**,展示邀请码与下级,规则以本页为准)·
渠道(owner=M7,见 7.4)。

- 关系是 7.1 计佣的唯一归属依据;**只有 R3 能写关系**,其余环节一律只读
- 佣金数字是 7.1 数据的只读聚合,本页不重复定义口径
