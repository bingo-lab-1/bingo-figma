# M7 · 权限与审计

## 1. 定位与边界

**做什么**:后台账号、角色权限、操作留痕。**横切所有模块的基础设施。**

**不做什么**
- 不管玩家账号(那是 M2 的 `User`)
- 不做业务逻辑,只提供鉴权与留痕能力

**铁律**:财务(M3)与活动配置(M4)的**所有写操作必须留痕**。这是合规底线,不是可选项。

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 后台账号 | 运营人员账号,**不是玩家** | `Account` |
| 角色 | 权限集合 | `Role` |
| 权限点 | 最小授权单元,格式 `模块:对象:动作` | `Permission` |
| 菜单权限 | 能否看到/进入某页面 | — |
| 数据权限 | 能看到哪些行(行级) | 待定 |
| 操作日志 | 谁·何时·改了什么 | `OperationLog` |

## 3. 依赖关系

**上游依赖(我引用)**
- 无。基础设施模块,不依赖任何业务模块。

**下游被依赖(谁引用我)** ← 所有模块
- 全部模块:`Account.id` 作为 `operatorId`
- 全部模块:菜单级权限校验
- `M3` `M4`:写操作强制写 `OperationLog`
