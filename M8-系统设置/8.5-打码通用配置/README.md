# 8.5 · 打码通用配置

## 1. 用途

运营按收入类型配置打码倍数,用于累计玩家资金汇总上的“待完成流水”。这个累计值当前没有业务消费方,**不是提现门槛**;[用户标签](../../M2-用户管理/2.5-用户标签/README.md)同名条件取的是当前有效打码任务的剩余金额。

玩家能否提现看打码任务余量。充值打码倍数在 [5.5 充值商品配置](../../M5-财务管理/5.5-充值商品配置/README.md)维护,活动彩金倍数在各活动维护,都不读取本页。

当前只有“代理”类型有实际累计,“VIP”和“充值”保存后不产生任何累计,详见第 3 段。

后台桌面端使用,界面简体中文,时间按操作人浏览器时区展示,累计金额按 USD 标准金额计算。

## 2. 配置项

**筛选条件**(可组合,留空表示不限)

| 条件 | 含义和填写规则 |
|---|---|
| 名称 | 包含匹配,不区分大小写 |
| 类型 | 代理 / VIP / 充值 |
| 状态 | 已开启 / 已关闭 |

**列表字段**:名称、类型、打码倍数、状态、创建时间、更新时间、操作。按创建时间倒序。

**新增与编辑表单**

| 配置项 | 含义和填写规则 |
|---|---|
| 名称 | 必填,保存时去除首尾空格 |
| 类型 | 必选,代理 / VIP / 充值。每种类型只能有一条配置 |
| 打码倍数 | 必填,0 至 2147483647 的整数,默认 0 |
| 是否启用 | 开关,默认开启 |

系统没有预置配置,未配置的类型不累计。

## 3. 操作规则

### 累计规则

| 类型 | 触发时机 | 结果 |
|---|---|---|
| 代理 | 每日佣金结算入账时 | 待完成流水增加“佣金 USD 金额 × 打码倍数” |
| VIP | 当前没有触发时机 | 不累计 |
| 充值 | 当前没有触发时机 | 不累计 |

玩家原创游戏下注时,待完成流水按下注 USD 金额扣减,最低扣到 0。第三方游戏下注不扣减。

### 修改与生效

保存后立即生效,只影响之后的累计,已累计的待完成流水不回算。

“是否启用”只做展示,不参与计算:关闭后仍按倍数累计。要停止累计,把倍数改为 0 或删除该条配置。

### 删除

确认后删除,之后该类型不再累计,已累计的待完成流水保留。

## 4. 特殊情况

| 情况 | 如何处理 |
|---|---|
| 名称为空 | 提示“请输入名称”,不提交 |
| 类型未选 | 提示“请选择类型”,不提交 |
| 打码倍数不是 0 至 2147483647 的整数 | 提示“打码倍数须为 0～2147483647 的整数”,不提交 |
| 该类型已有配置 | 提示保存失败,原数据不变 |
| 玩家佣金没有 USD 标准金额 | 该笔不累计 |

## 5. 验收场景

| 需求编号 | 场景与操作 | 预期结果 |
|---|---|---|
| 8.5-R1 | 新增类型“代理”、倍数 2;玩家结算佣金 10 USD | 该玩家待完成流水增加 20 |
| 8.5-R2 | 新增类型“充值”、倍数 2;玩家充值成功 | 待完成流水不变,打码任务仍按 5.5 的倍数生成 |
| 8.5-R3 | 已有“代理”配置,再新增一条“代理” | 提示保存失败,列表不变 |
| 8.5-R4 | 打码倍数填 `1.5` 或 `-1` | 提示“打码倍数须为 0～2147483647 的整数”,不提交 |
| 8.5-R5 | 关闭“代理”配置后结算佣金 | 待完成流水仍按倍数增加 |
| 8.5-R6 | 把“代理”倍数改为 0 后结算佣金 | 待完成流水不增加,已累计值不变 |
| 8.5-R6 | 删除“代理”配置后结算佣金 | 待完成流水不增加,已累计值不变 |
| 8.5-R7 | 待完成流水为 5 的玩家在原创游戏下注 8 USD | 待完成流水变为 0 |
| 8.5-R8 | 待完成流水大于 0、打码任务已全部完成的玩家发起提现 | 不因待完成流水被拦截 |
| 8.5-R9 | 账号没有 `system:coding-multiple:view` | 菜单不显示,直接访问进入无权限页 |
| 8.5-R9 | 账号有查看权限但没有 `system:coding-multiple:edit`,提交修改 | 服务端拒绝,提示保存失败,原数据不变 |

## 6. 相关资料

- 入口与关联页面:系统管理 > 打码通用配置。[用户标签](../../M2-用户管理/2.5-用户标签/README.md)的待完成流水条件不读取本页累计值。
- 权限:查看 `system:coding-multiple:view`,新增 `system:coding-multiple:create`,编辑 `system:coding-multiple:edit`,删除 `system:coding-multiple:delete`。
- 数据与责任:倍数配置归 M8,佣金结算归 M7。
- 共用规则:打码任务与提现门槛的唯一定义见[资金模型](../../M2-用户管理/2.1-用户列表/资金模型.md)。
