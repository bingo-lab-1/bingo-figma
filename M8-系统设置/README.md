# M8 · 系统设置

## 1. 定位与边界

**做什么**:全站系统级参数配置的归口。**首版只收「风控参数」一页**:同IP/同设备注册分段限制、
风控统计窗口、CPF 绑定账号上限 —— 对应现有后台「系统设置-其他设置」页的「审核相关」区块。

**收入本仓库的理由**:同IP/同设备统计窗口是 M2 用户详情「风控数据」计数的**唯一口径出处**;
注册多号限制是 M7 代理返佣防自邀刷佣的配套防线。配置与消费方拆在两个仓库,口径立刻断链 ——
与财务、代理收入本仓库同一个道理。

**不做什么**
- 不做 RTP 取值范围 —— 与风控参数在现有后台同屏,但归玩法/游戏域(**本仓库范围外**),不收入
- 不做现有后台系统设置下的其他页面(数值配置、下载记录)—— 未收入,需要时按页另立
- 不做注册与 CPF 绑定流程本身 —— 执行在平台玩家端(**范围外**),本模块只定义参数与判定口径
- 不做设备码采集 —— 归客户端(**范围外**),只读引用(D30)
- 不做登录环节的限制 —— 首版只管注册与 CPF 绑定;登录事件只用于统计展示

**铁律**
- **拦截必须留痕**:每次超限拒绝都要可查(时间、维度、命中段位、当时计数),
  否则误伤无法定位、申诉无法核实;不留痕的拦截不得上线
- 拦截提示不得向玩家暴露具体风控规则与阈值

## 2. 术语表

| 术语 | 定义 | 代码标识 |
|---|---|---|
| 设备码 | 客户端采集上报的设备标识,用于同设备判定;采集与生成规则归客户端(**范围外**,D30) | 设备码 |
| 注册事件 | 一次注册成功的留痕:玩家、IP、设备码、时间 —— 判定与统计的数据基础 | 注册事件 |
| 分段限制 | 「时间窗 + 人数上限」的组合,最多 3 段;任一段达到上限即超限 | — |
| 统计窗口 | 用户详情「风控数据」计数的检索时长,不参与拦截 | — |

## 3. 依赖关系

**平台基础设置的只读契约**:业务已确认该处有“充值投注限制 / 无限制投注”两种模式,
语义见 [资金模型·平台充值前投注资格](../M2-用户管理/2.1-用户列表/资金模型.md#平台充值前投注资格),
执行规则见 [M4-D73](../M4-活动管理/README.md#7-决策清单)。模式归平台基础设置,
游戏/投注服务端执行,4.8 注册送好礼只读解释。基础设置页面本轮未展开,不把该开关加到 8.1 风控参数或活动配置中。

**上游依赖(我引用)**
- 平台注册/登录流程(**本仓库范围外**):注册与登录的事件留痕(IP、设备码、时间)——
  判定与统计都建立在这张事件流水上,上线验收必须验证成功事件完整记录且重复消息不重复计数(8.1-A8)
- 客户端(**范围外**):设备码采集与上报(D30)
- M2 用户管理:玩家档案与 CPF 绑定关系
- M6 账号管理:权限模型与全站操作日志

**下游被依赖(谁引用我)** ← 改参数语义前先看这行
- 平台注册与 CPF 绑定流程(**范围外**):读拦截参数并执行(8.1-R3/R4)
- M2 用户详情「风控数据」:读统计窗口(8.1-R5、8.1-A4)
